# 3.1 create_heap() 深度分析

> 源码位置：`universe.cpp:926` → `gcConfig.cpp` → `g1Arguments.cpp` → `g1CollectedHeap.cpp`

---

## 功能定位

**一句话说明**：`create_heap()` 负责根据 JVM 参数选择合适的 GC，创建对应的堆对象（如 G1CollectedHeap），但**此时只是创建对象，还没有分配实际的堆内存**。

**在整体流程中的位置**：
```
universe_init()
    └── Universe::initialize_heap()
            ├── create_heap()           ← 【当前分析】创建 G1CollectedHeap 对象
            └── _collectedHeap->initialize()  ← 后续：真正分配堆内存
```

**如果没有它会怎样？** JVM 无法确定使用哪种 GC，也无法创建管理堆内存的核心对象。

### GC 选择流程

GC 的选择发生在 `GCConfig::initialize()`（在 `universe_init()` 之前调用）：

```cpp
// gcConfig.cpp:191
void GCConfig::initialize() {
  _arguments = select_gc();  // 选择并返回对应的 GCArguments
}
```

**select_gc() 的完整逻辑**：

```
select_gc()
│
├─① 检查是否选择了不支持的 GC
│   fail_if_unsupported_gc_is_selected();
│
├─② 如果用户没有指定任何 GC
│   if (is_no_gc_selected()) {
│       select_gc_ergonomically();  // 自动选择
│   }
│
├─③ 检查是否只选择了一个 GC（不能同时用 -XX:+UseG1GC -XX:+UseSerialGC）
│   if (!is_exactly_one_gc_selected()) {
│       vm_exit: "Multiple garbage collectors selected"
│   }
│
└─④ 返回选中的 GCArguments
    FOR_EACH_SUPPORTED_GC(gc) {
        if (gc->_flag) return &gc->_arguments;
    }
```

### 自动选择逻辑 (select_gc_ergonomically)

```cpp
// gcConfig.cpp:108
void GCConfig::select_gc_ergonomically() {
  if (os::is_server_class_machine()) {  // 服务器级机器
    FLAG_SET_ERGO_IF_DEFAULT(bool, UseG1GC, true);  // 选 G1
  } else {
    FLAG_SET_ERGO_IF_DEFAULT(bool, UseSerialGC, true);  // 选 Serial
  }
}
```

**什么是服务器级机器？**

```cpp
// os.cpp:1717
bool os::is_server_class_machine() {
  // 条件：CPU ≥ 2 且 内存 ≥ (2GB - 256MB)
  const unsigned int server_processors = 2;
  const julong server_memory = 2UL * G;
  const julong missing_memory = 256UL * M;  // 允许丢失的内存

  if ((os::active_processor_count() >= server_processors) &&
      (os::physical_memory() >= (server_memory - missing_memory))) {
    return true;
  }
  return false;
}
```

### 构造函数体做了什么

```cpp
// 1. 创建 GC 工作线程池
_workers = new WorkGang("GC Thread", ParallelGCThreads,
                        true,   // are_GC_task_threads
                        false); // are_ConcurrentGC_threads
_workers->initialize_workers();

// 2. 创建堆验证器
_verifier = new G1HeapVerifier(this);

// 3. 创建分配器
_allocator = new G1Allocator(this);

// 4. 创建堆大小调整策略
_heap_sizing_policy = G1HeapSizingPolicy::create(this, _g1_policy->analytics());

// 5. 计算巨型对象阈值（Region 大小的一半）
_humongous_object_threshold_in_words = humongous_threshold_for(HeapRegion::GrainWords);
// 8GB 堆：4MB Region / 2 = 2MB，对象 ≥ 2MB 就是巨型对象

// 6. 设置填充数组最大大小
_filler_array_max_size = _humongous_object_threshold_in_words;

// 7. 创建任务队列（每个 GC 线程一个）
uint n_queues = ParallelGCThreads;
_task_queues = new RefToScanQueueSet(n_queues);
_evacuation_failed_info_array = NEW_C_HEAP_ARRAY(EvacuationFailedInfo, n_queues, mtGC);

// 8. 初始化每个队列
for (uint i = 0; i < n_queues; i++) {
    RefToScanQueue* q = new RefToScanQueue();
    q->initialize();
    _task_queues->register_queue(i, q);
    ::new(&_evacuation_failed_info_array[i]) EvacuationFailedInfo();
}

// 9. 初始化 GC 追踪器
_gc_tracer_stw->initialize();
```

## 3.1.3 G1Policy 是什么？什么时候创建的

### G1CollectorPolicy vs G1Policy

JVM 中有**两个**策略类，容易混淆：

| 类名 | 继承关系 | 作用 | 创建时机 |
|------|---------|------|----------|
| `G1CollectorPolicy` | `CollectorPolicy` | 堆大小/对齐配置 | `create_heap_with_policy()` |
| `G1Policy` | `CHeapObj<mtGC>` | GC 决策核心 | `G1CollectedHeap` 构造函数 |

### G1CollectorPolicy 的作用

```cpp
// g1CollectorPolicy.cpp:35
G1CollectorPolicy::G1CollectorPolicy() {
  // 设置 HeapRegion 大小（这是最早设置的地方！）
  HeapRegion::setup_heap_region_size(InitialHeapSize, MaxHeapSize);
  
  // 设置 RemSet 大小
  HeapRegionRemSet::setup_remset_size();
}
```

**关键点**：`HeapRegion::GrainBytes`（Region 大小）是在 `G1CollectorPolicy` 构造函数中设置的！

```
create_heap_with_policy()
    ├── new G1CollectorPolicy()
    │       └── HeapRegion::setup_heap_region_size()  ← 设置 Region 大小
    │       └── HeapRegionRemSet::setup_remset_size()
    │
    ├── policy->initialize_all()
    │       └── initialize_alignments()  ← 设置堆对齐
    │
    └── new G1CollectedHeap(policy)
```

### G1Policy 的作用

`G1Policy` 是 G1 GC 的**决策大脑**：

```cpp
// G1CollectedHeap 构造函数中创建
_g1_policy(new G1Policy(_gc_timer_stw))
```

**G1Policy 的核心职责**：

1. **决定何时 GC**：IHOP（Initiating Heap Occupancy Percent）控制
2. **选择收集集 (CSet)**：选择哪些 Region 参与本次 GC
3. **暂停时间预测**：根据历史数据预测 GC 耗时
4. **年轻代大小调整**：动态调整 Eden/Survivor 区大小

**G1Policy 的关键字段**：

```cpp
class G1Policy: public CHeapObj<mtGC> {
  G1Predictions _predictor;           // 预测器（基于衰减平均）
  G1Analytics* _analytics;            // 分析器（历史数据）
  G1MMUTracker* _mmu_tracker;         // MMU 追踪器
  G1IHOPControl* _ihop_control;       // IHOP 控制器
  
  uint _young_list_target_length;     // 年轻代目标 Region 数
  uint _young_list_max_length;        // 年轻代最大 Region 数
  
  SurvRateGroup* _short_lived_surv_rate_group;  // 存活率统计
  SurvRateGroup* _survivor_surv_rate_group;
  
  G1YoungGenSizer _young_gen_sizer;   // 年轻代大小调整器
};
```

## 总结

### 3.1.1 GC 选择流程

```
用户参数            自动选择                       结果
───────────────────────────────────────────────────────────
-XX:+UseG1GC    →  跳过自动选择            →  G1Arguments
未指定 GC       →  is_server_class_machine()
                   ├─ CPU≥2 且 内存≥2GB   →  G1Arguments
                   └─ 否则                 →  SerialArguments
```

### 3.1.2 G1CollectedHeap 构造时创建的对象

| 对象 | 类型 | 数量 | 作用 |
|------|------|------|------|
| G1Policy | 决策核心 | 1 | GC 决策 |
| WorkGang | 线程池 | 1 | ParallelGCThreads 个工作线程 |
| RefToScanQueue | 任务队列 | ParallelGCThreads | 对象引用扫描 |
| G1Allocator | 分配器 | 1 | 对象分配 |
| G1HeapVerifier | 验证器 | 1 | 堆验证 |

### 3.1.3 G1CollectorPolicy vs G1Policy

- **G1CollectorPolicy**：配置类，设置 Region 大小和堆对齐
- **G1Policy**：决策类，控制何时 GC、选择 CSet、预测暂停时间
