## 1. 功能定位

### 1.1 一句话概述

**栈信息记录**是 JVM 获取线程栈的基址和大小，并设置栈溢出检测机制的过程，是 **StackOverflowError** 实现的基础。

### 1.2 核心问题

```
问题：Java 是如何检测栈溢出的？
答案：
  1. 记录每个线程的栈基址和大小
  2. 在栈底设置多层保护区域（Guard Pages）
  3. 当栈指针接近保护区时触发 StackOverflowError

问题：为什么栈溢出不会导致程序直接崩溃？
答案：
  - JVM 在栈底设置了 Red/Yellow/Reserved Zone
  - Yellow Zone 触发时抛出 StackOverflowError（可恢复）
  - 只有 Red Zone 触发时才会导致 VM 崩溃
```

### 3.3 Linux 平台 current_stack_region() 实现

```cpp
// 源码位置: src/hotspot/os/linux/os_linux.cpp:6776-6830

static void current_stack_region(address *bottom, size_t *size) {
    if (os::is_primordial_thread()) {
        // 主线程（shell 创建）特殊处理
        *bottom = os::Linux::initial_thread_stack_bottom();
        *size = os::Linux::initial_thread_stack_size();
    } else {
        // 子线程（JVM 创建）
        pthread_attr_t attr;
        
        // 获取当前线程属性
        pthread_getattr_np(pthread_self(), &attr);
        
        // 获取栈地址和大小
        // bottom = 栈底（低地址），size = 总大小
        pthread_attr_getstack(&attr, (void**)bottom, size);
        
        // 修正 Guard Page
        // pthread 返回的范围包含 Guard Page，需要排除
        size_t guard_size = 0;
        pthread_attr_getguardsize(&attr, &guard_size);
        
        *bottom += guard_size;  // 底部上移，跳过 guard page
        *size -= guard_size;    // 大小减小
        
        pthread_attr_destroy(&attr);
    }
}
```

// 源码位置: src/hotspot/share/runtime/thread.hpp:1634-1657

// Guard Zone = Red + Yellow + Reserved
static size_t stack_guard_zone_size() {
    return stack_red_zone_size() + 
           stack_yellow_zone_size() + 
           stack_reserved_zone_size();
}

// 栈溢出检测点
void set_stack_overflow_limit() {
    _stack_overflow_limit =
        stack_end() + MAX2(stack_guard_zone_size(), 
                           stack_shadow_zone_size());
}

// 为什么用 MAX2？
// - 编译器检测点 (_stack_overflow_limit) 应该在两个区域之上
// - 这样软件检测可以在硬件保护触发之前发现问题

// 红区
static size_t stack_red_zone_size() {
    assert(_stack_red_zone_size > 0, "Don't call this before the field is initialized.");
    return _stack_red_zone_size;
}

// 红区基址
address stack_red_zone_base() {
    return (address)(stack_end() + stack_red_zone_size());
}

// 检查地址是否在红区
bool in_stack_red_zone(address a) {
    return a <= stack_red_zone_base() && a >= stack_end();
}

// 黄区 + 保留区
static size_t stack_yellow_reserved_zone_size() {
    return _stack_yellow_zone_size + _stack_reserved_zone_size;
}

// 保留区基址
address stack_reserved_zone_base() {
    return (address)(stack_end() +
                     stack_red_zone_size() + 
                     stack_yellow_zone_size() + 
                     stack_reserved_zone_size());
}

## 5. Stack Banging 机制 ⭐⭐⭐⭐

### 5.1 什么是 Stack Banging？

```
Stack Banging 是编译器在方法入口生成的栈溢出检测代码：
1. 在方法入口，向栈的 Shadow Zone 写入数据
2. 如果栈空间不足，会触发 SIGSEGV
3. JVM 捕获信号后抛出 StackOverflowError

这是一种"主动探测"机制，比等待触发硬件保护更安全。
```

### 5.2 编译器生成的检测代码

```
方法入口伪代码：

method_entry:
    // Stack Banging：向 Shadow Zone 写入
    // 检测栈是否足够容纳当前栈帧
    for (int i = 0; i < shadow_pages; i++) {
        touch(sp - page_size * i);  // 访问内存
    }
    
    // 如果上面没有触发异常，说明栈空间足够
    // 继续执行方法体...
```

## 6. StackOverflowError 处理流程 ⭐⭐⭐⭐

### 6.1 Yellow Zone 触发后的处理

```cpp
// 伪代码展示 StackOverflowError 处理流程

void signal_handler(int sig, siginfo_t* info, void* context) {
    if (sig == SIGSEGV) {
        address fault_addr = (address)info->si_addr;
        JavaThread* thread = JavaThread::current();
        
        // 检查是否是栈溢出
        if (thread->in_stack_yellow_reserved_zone(fault_addr)) {
            // 是栈溢出
            
            // 1. 临时解除 Yellow Zone 保护
            thread->disable_stack_yellow_reserved_zone();
            
            // 2. 抛出 StackOverflowError
            throw_stack_overflow_error();
            
            // 3. 恢复 Yellow Zone 保护（在异常处理后）
            thread->enable_stack_yellow_reserved_zone();
        } else {
            // 不是栈溢出，是真正的段错误
            vm_crash();
        }
    }
}
```

## 7. @ReservedStackAccess 注解 ⭐⭐⭐

### 7.1 用途说明

```java
// java.util.concurrent.locks.ReentrantLock

public void unlock() {
    // 如果在 unlock() 期间发生栈溢出怎么办？
    // 锁永远不会释放！
    sync.release(1);
}
```

为了解决这个问题，JDK 引入了 `@ReservedStackAccess` 注解：

```java
@Target({ElementType.METHOD})
@Retention(RetentionPolicy.RUNTIME)
public @interface ReservedStackAccess {
    // 标记的方法可以使用 Reserved Zone 中的栈空间
}
```

class Thread {
protected:
    // 基本栈信息
    address    _stack_base;   // 栈顶地址（高地址）
    size_t     _stack_size;   // 栈大小

    // 获取栈范围
    address stack_base() const { return _stack_base; }
    size_t  stack_size() const { return _stack_size; }
    address stack_end()  const { return stack_base() - stack_size(); }  // 栈底（低地址）

    bool on_local_stack(address adr) const {

## 9. 面试高频问题 ⭐⭐⭐⭐

### Q1: StackOverflowError 是如何触发的？

**答案**：
JVM 使用多层保护机制检测栈溢出：
1. **软件检测（Stack Banging）**：编译器在方法入口生成代码，主动访问 Shadow Zone
2. **硬件保护**：使用 mprotect 将 Yellow Zone 设为不可访问
3. 当栈指针进入 Yellow Zone 时，触发 SIGSEGV
4. JVM 信号处理器捕获信号，抛出 StackOverflowError

### Q2: 为什么有 Red Zone 和 Yellow Zone 两层保护？

**答案**：
- **Yellow Zone**：触发时抛出 StackOverflowError，Java 程序可以捕获处理
- **Red Zone**：最后防线，触发时 VM 直接崩溃
- 如果只有一层，可能在异常处理过程中再次溢出，导致无限递归

### Q3: @ReservedStackAccess 注解有什么作用？

**答案**：
该注解用于标记关键系统方法（如 `unlock()`）。当线程即将栈溢出时，允许这些方法继续使用 Reserved Zone 中的栈空间，确保关键操作能够完成，避免死锁。

### Q4: Stack Banging 和硬件保护有什么区别？

**答案**：
| 特性 | Stack Banging | 硬件保护 |
|------|--------------|---------|
| 实现方式 | 编译器生成代码 | mprotect 系统调用 |
| 检测时机 | 方法入口主动检测 | 实际访问时被动触发 |
| 性能 | 有少量开销 | 无开销（直到触发） |
| 检测范围 | Shadow Zone | Red/Yellow/Reserved Zone |

### Q5: 如何调整栈溢出检测的敏感度？

**答案**：
通过 JVM 参数调整各区域大小：
- `-XX:StackRedPages=N`：Red Zone 页数
- `-XX:StackYellowPages=N`：Yellow Zone 页数
- `-XX:StackReservedPages=N`：Reserved Zone 页数
- `-XX:StackShadowPages=N`：Shadow Zone 页数
