# 2.7 throw_exception_entrypoints（具体异常入口点）

## 概述

`generate_all()` 中的 "throw exception entrypoints" 部分生成**6 种具体异常的入口点**。这些入口点是解释器在执行字节码时检测到错误后直接跳转的目标，它们负责：

1. 创建对应类型的异常对象
2. 跳转到 `_throw_exception_entry` 统一处理

## 6 种异常入口点

| 入口点 | 异常类型 | 触发场景 | 生成方法 |
|--------|----------|----------|----------|
| `_throw_ArrayIndexOutOfBoundsException_entry` | ArrayIndexOutOfBoundsException | 数组越界 | `generate_ArrayIndexOutOfBounds_handler()` |
| `_throw_ArrayStoreException_entry` | ArrayStoreException | 数组存储类型不匹配 | `generate_klass_exception_handler()` |
| `_throw_ArithmeticException_entry` | ArithmeticException | 整数除零 | `generate_exception_handler()` |
| `_throw_ClassCastException_entry` | ClassCastException | checkcast 失败 | `generate_ClassCastException_handler()` |
| `_throw_NullPointerException_entry` | NullPointerException | 空指针解引用 | `generate_exception_handler()` |
| `_throw_StackOverflowError_entry` | StackOverflowError | 栈溢出 | `generate_StackOverflowError_handler()` |

## 生成方法详解

### 1. generate_exception_handler（通用异常处理器）

**使用场景**：
- `ArithmeticException: "/ by zero"`

### 3. generate_exception_handler_common（核心实现）

```cpp:142:173:src/hotspot/cpu/x86/templateInterpreterGenerator_x86.cpp
address TemplateInterpreterGenerator::generate_exception_handler_common(
        const char* name, const char* message, bool pass_oop) {
  assert(!pass_oop || message == NULL, "either oop or message but not both");
  address entry = __ pc();

  Register rarg = NOT_LP64(rax) LP64_ONLY(c_rarg1);
  Register rarg2 = NOT_LP64(rbx) LP64_ONLY(c_rarg2);

  if (pass_oop) {
    // object is at TOS
    __ pop(rarg2);  // 弹出导致异常的对象
  }
  
  // 清空表达式栈
  __ empty_expression_stack();
  
  // 设置参数
  __ lea(rarg, ExternalAddress((address)name));  // 异常类名
  
  if (pass_oop) {
    // 调用 create_klass_exception (带对象)
    __ call_VM(rax, CAST_FROM_FN_PTR(address,
                                     InterpreterRuntime::create_klass_exception),
               rarg, rarg2);
  } else {
    // 调用 create_exception (带消息)
    __ lea(rarg2, ExternalAddress((address)message));
    __ call_VM(rax,
               CAST_FROM_FN_PTR(address, InterpreterRuntime::create_exception),
               rarg, rarg2);
  }
  
  // 跳转到统一异常处理入口
  __ jump(ExternalAddress(Interpreter::throw_exception_entry()));
  return entry;
}
```

**关键点**：
1. 最后都跳转到 `_throw_exception_entry`
2. 异常对象存储在 `rax`
3. 不直接处理异常，只负责创建异常对象

### 4. generate_ArrayIndexOutOfBounds_handler

```cpp:105:121:src/hotspot/cpu/x86/templateInterpreterGenerator_x86.cpp
address TemplateInterpreterGenerator::generate_ArrayIndexOutOfBounds_handler() {
  address entry = __ pc();
  
  // 清空表达式栈
  __ empty_expression_stack();
  
  // 参数设置:
  // rarg (c_rarg1): 数组对象
  // rbx: 越界的索引
  Register rarg = NOT_LP64(rax) LP64_ONLY(c_rarg1);
  __ call_VM(noreg,
             CAST_FROM_FN_PTR(address,
                              InterpreterRuntime::throw_ArrayIndexOutOfBoundsException),
             rarg, rbx);
  return entry;
}
```

**特殊点**：
- 需要传递**数组对象**和**越界索引**
- VM 运行时会构建详细的错误消息，如 `"Index 5 out of bounds for length 3"`

### 5. generate_ClassCastException_handler

```cpp:123:140:src/hotspot/cpu/x86/templateInterpreterGenerator_x86.cpp
address TemplateInterpreterGenerator::generate_ClassCastException_handler() {
  address entry = __ pc();
  
  // 对象在栈顶
  Register rarg = NOT_LP64(rax) LP64_ONLY(c_rarg1);
  __ pop(rarg);  // 弹出导致转换失败的对象
  
  // 清空表达式栈
  __ empty_expression_stack();
  
  __ call_VM(noreg,
             CAST_FROM_FN_PTR(address, InterpreterRuntime::throw_ClassCastException),
             rarg);
  return entry;
}
```

**特殊点**：
- 需要传递**尝试转换的对象**
- VM 运行时会生成详细消息，如 `"class A cannot be cast to class B"`

### 6. generate_StackOverflowError_handler

```cpp:75:103:src/hotspot/cpu/x86/templateInterpreterGenerator_x86.cpp
address TemplateInterpreterGenerator::generate_StackOverflowError_handler() {
  address entry = __ pc();

#ifdef ASSERT
  {
    Label L;
    // 断言：确保解释器栈帧已正确建立
    __ lea(rax, Address(rbp, frame::interpreter_frame_monitor_block_top_offset * wordSize));
    __ cmpptr(rax, rsp);
    __ jcc(Assembler::aboveEqual, L);
    __ stop("interpreter frame not set up");
    __ bind(L);
  }
#endif // ASSERT

  // 恢复 bcp
  __ restore_bcp();
  
  // 清空表达式栈
  __ empty_expression_stack();
  
  // 调用 VM 抛出 StackOverflowError
  __ call_VM(noreg,
             CAST_FROM_FN_PTR(address, InterpreterRuntime::throw_StackOverflowError));
  return entry;
}
```

**特殊点**：
- **不需要创建新异常对象**，直接调用 VM
- StackOverflowError 可能使用**预分配的异常对象**（避免在栈溢出时再分配内存）

## 触发场景分析

### ArrayIndexOutOfBoundsException

**触发字节码**：`aaload`, `aastore`, `baload`, `bastore`, `caload`, `castore`, 等

```java
int[] arr = new int[3];
int x = arr[5];  // 触发 ArrayIndexOutOfBoundsException
```

**字节码模板中的检查**：
```cpp
// aaload 模板中
__ movl(rbx, Address(rax, arrayOopDesc::length_offset_in_bytes()));
__ cmpl(index, rbx);  // 比较 index 和 length
__ jcc(Assembler::aboveEqual, _throw_ArrayIndexOutOfBoundsException_entry);
```

---

### ArrayStoreException

**触发字节码**：`aastore`

```java
Object[] arr = new String[3];
arr[0] = new Integer(1);  // 触发 ArrayStoreException
```

---

### ArithmeticException

**触发字节码**：`idiv`, `irem`, `ldiv`, `lrem`

```java
int a = 10;
int b = 0;
int c = a / b;  // 触发 ArithmeticException: / by zero
```

**字节码模板中的检查**：
```cpp
// idiv 模板中
__ testl(rcx, rcx);  // 检查除数是否为 0
__ jcc(Assembler::zero, _throw_ArithmeticException_entry);
```

---

### ClassCastException

**触发字节码**：`checkcast`

```java
Object obj = "hello";
Integer i = (Integer) obj;  // 触发 ClassCastException
```

---

### NullPointerException

**触发字节码**：几乎所有涉及对象引用的字节码

```java
String s = null;
int len = s.length();  // 触发 NullPointerException
```

**隐式检查**：x86 上使用**内存保护**实现
- 访问 null 地址触发 SIGSEGV
- VM 的 signal handler 转换为 NullPointerException

---

### StackOverflowError

**触发时机**：方法调用时栈空间不足

```java
public void recursive() {
    recursive();  // 无限递归，触发 StackOverflowError
}
```

**检查位置**：方法入口的栈溢出检查
```cpp
// 方法入口中
__ cmpptr(rsp, Address(thread, JavaThread::stack_overflow_limit_offset()));
__ jcc(Assembler::belowEqual, _throw_StackOverflowError_entry);
```

## 总结

| 入口点 | 特点 | 消息来源 |
|--------|------|----------|
| AIOOBE | 传递数组+索引 | VM 运行时生成详细消息 |
| ASE | 传递对象 | VM 运行时生成 |
| AE | 固定消息 | "/ by zero" |
| CCE | 传递对象 | VM 运行时生成详细消息 |
| NPE | 无消息 | JDK 14+ 有 helpful NPE |
| SOE | 无参数 | 使用预分配对象 |

**关键点**：
1. 所有入口点最终都跳转到 `_throw_exception_entry`
2. `StackOverflowError` 特殊处理，不创建新对象
3. 字节码模板中的检查代码直接跳转到这些入口
