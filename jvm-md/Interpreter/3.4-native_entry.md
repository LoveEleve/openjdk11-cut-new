# 3.4 native（本地方法入口）

## 概述

`generate_native_entry()` 生成 JNI 本地方法的入口代码。本地方法入口与普通 Java 方法入口有显著不同：

1. **没有字节码执行** - 直接调用 C/C++ 函数
2. **JNI 环境准备** - 设置 JNIEnv*，处理参数转换
3. **线程状态切换** - `_thread_in_Java` → `_thread_in_native` → `_thread_in_native_trans` → `_thread_in_Java`
4. **安全点协调** - 从本地代码返回时检查 safepoint

## 关键步骤详解

### 1. 特殊栈槽分配

```cpp:817:823:src/hotspot/cpu/x86/templateInterpreterGenerator_x86.cpp

// initialize result_handler slot

// slot for oop temp

```

**native 栈帧额外槽位**：
| 槽位 | 用途 |
|------|------|
| result_handler | 返回值处理函数指针 |
| oop_temp | 静态方法的 Class mirror / OOP 返回值 |

---

### 2. Signature Handler

**作用**：将 Java 参数转换为 JNI 调用约定格式。

```cpp:932:945:src/hotspot/cpu/x86/templateInterpreterGenerator_x86.cpp
// get signature handler
{
  Label L;
  __ movptr(t, Address(method, Method::signature_handler_offset()));
  __ testptr(t, t);
  __ jcc(Assembler::notZero, L);
  
  // 没有 handler，需要生成
  __ call_VM(noreg,
             CAST_FROM_FN_PTR(address, InterpreterRuntime::prepare_native_call),
             method);
  __ get_method(method);
  __ movptr(t, Address(method, Method::signature_handler_offset()));
  __ bind(L);
}
// 调用 signature handler
__ call(t);
```

**Signature Handler 功能**：
1. 从 Java 局部变量表读取参数
2. 按照 x86-64 ABI 放入寄存器或栈
3. 返回 result_handler 地址

**x86-64 参数传递约定**：
| 参数位置 | 整数/指针 | 浮点 |
|----------|-----------|------|
| 第 1 个 | rdi (JNIEnv*) | xmm0 |
| 第 2 个 | rsi (this/Class) | xmm1 |
| 第 3 个 | rdx | xmm2 |
| 第 4 个 | rcx | xmm3 |
| 第 5 个 | r8 | xmm4 |
| 第 6 个 | r9 | xmm5 |
| 更多 | 栈 | 栈 |

### 4. 线程状态转换（核心）

```
状态转换时序：

┌──────────────────┐
│ _thread_in_Java  │  初始状态
└────────┬─────────┘
         │ movl(thread_state, _thread_in_native)
         ▼
┌──────────────────┐
│ _thread_in_native│  ← 调用本地方法期间
└────────┬─────────┘
         │ call(native_function)
         │ ... 本地代码执行 ...
         │ movl(thread_state, _thread_in_native_trans)
         ▼
┌──────────────────┐
│_thread_in_native │  ← 转换中（检查 safepoint）
│     _trans       │
└────────┬─────────┘
         │ safepoint_poll()
         │ movl(thread_state, _thread_in_Java)
         ▼
┌──────────────────┐
│ _thread_in_Java  │  返回 Java 执行
└──────────────────┘
```

**为什么需要 _thread_in_native_trans**：
- GC 需要在安全点停止所有 Java 线程
- 处于 `_thread_in_native` 的线程不会被 GC 扫描其 Java 栈
- 但从 native 返回时必须检查是否需要在安全点停止
- `_thread_in_native_trans` 是这个检查阶段的状态

---

### 5. 安全点检查

```cpp:1113:1151:src/hotspot/cpu/x86/templateInterpreterGenerator_x86.cpp
// check for safepoint operation in progress
{
  Label Continue;
  Label slow_path;
  
  // 检查 safepoint 轮询标志
  __ safepoint_poll(slow_path, r15_thread, rscratch1);
  
  // 检查线程挂起标志
  __ cmpl(Address(thread, JavaThread::suspend_flags_offset()), 0);
  __ jcc(Assembler::equal, Continue);
  
  __ bind(slow_path);
  // 慢路径：调用 VM 运行时处理
  __ call(RuntimeAddress(CAST_FROM_FN_PTR(address, 
                         JavaThread::check_special_condition_for_native_trans)));
  
  __ bind(Continue);
}
```

### 6. OOP 返回值处理

```cpp:1168:1186:src/hotspot/cpu/x86/templateInterpreterGenerator_x86.cpp
// If result is an oop unbox and store it in frame
{
  Label no_oop;
  __ lea(t, ExternalAddress(AbstractInterpreter::result_handler(T_OBJECT)));
  __ cmpptr(t, Address(rbp, frame::interpreter_frame_result_handler_offset*wordSize));
  __ jcc(Assembler::notEqual, no_oop);
  
  // retrieve result
  __ pop(ltos);
  
  // Unbox oop result (JNIHandles::resolve)
  __ resolve_jobject(rax, thread, t);
  
  // Store in oop_temp for GC visibility
  __ movptr(Address(rbp, frame::interpreter_frame_oop_temp_offset*wordSize), rax);
  
  __ push(ltos);
  __ bind(no_oop);
}
```

**JNI 返回值处理**：
- JNI 返回的对象是 jobject（handle）
- 需要调用 `JNIHandles::resolve()` 转换为真实 oop
- 存储在 oop_temp 槽位供 GC 可见

## Native 栈帧布局

```
    高地址
    ┌─────────────────────────────┐
    │     caller's frame          │
    ├─────────────────────────────┤ ← rbp + 8
    │     return address          │
    ├─────────────────────────────┤ ← rbp
    │     saved rbp               │
    ├─────────────────────────────┤
    │     sender sp               │
    ├─────────────────────────────┤
    │     last_sp (NULL)          │
    ├─────────────────────────────┤
    │     Method*                 │
    ├─────────────────────────────┤
    │     mirror (Class oop)      │
    ├─────────────────────────────┤
    │     mdp                     │
    ├─────────────────────────────┤
    │     ConstantPoolCache*      │
    ├─────────────────────────────┤
    │     locals pointer          │
    ├─────────────────────────────┤
    │     bcp (0 for native)      │  ← native 没有字节码
    ├─────────────────────────────┤
    │     expression stack bottom │
    ├═════════════════════════════┤  ← 以下是 native 特有
    │     result_handler          │  frame::interpreter_frame_result_handler_offset
    ├─────────────────────────────┤
    │     oop_temp                │  frame::interpreter_frame_oop_temp_offset
    ├─────────────────────────────┤
    │     monitor (if sync)       │
    │       _obj                  │
    │       _lock                 │
    ├─────────────────────────────┤
    │     JNI 参数区域            │  (按 ABI 对齐)
    │       arg0 (JNIEnv*)        │
    │       arg1 (this/Class)     │
    │       ...                   │
    └─────────────────────────────┘ ← rsp
    低地址
```

## 使用场景示例

### 普通 native 方法

```java
public class NativeDemo {
    // 声明
    public native int compute(int a, int b);
    
    // 对应 C 函数
    // JNIEXPORT jint JNICALL Java_NativeDemo_compute
    //   (JNIEnv *env, jobject obj, jint a, jint b)
}
```

**调用流程**：
```
1. 进入 native 入口
2. signature_handler 将 (a, b) 从 locals 移到 (rdx, rcx)
3. 设置 JNIEnv* 到 rdi, this 到 rsi
4. _thread_in_native
5. call Java_NativeDemo_compute
6. _thread_in_native_trans
7. safepoint 检查
8. _thread_in_Java
9. 返回
```

### 静态 native 方法

```java
public class Math {
    public static native double sin(double a);
    
    // JNIEXPORT jdouble JNICALL Java_java_lang_StrictMath_sin
    //   (JNIEnv *env, jclass cls, jdouble a)
}
```

**调用流程**：
```
1. 进入 native 入口
2. load_mirror → 获取 Math.class
3. 存储到 oop_temp
4. signature_handler 将 (a) 移到 xmm0
5. 设置 JNIEnv* 到 rdi, Math.class handle 到 rsi
6. ... 其余同上 ...
```

## Result Handler

每种返回类型有对应的 result_handler：

| 返回类型 | Handler 功能 |
|----------|--------------|
| T_BOOLEAN | rax & 0xFF |
| T_BYTE | rax & 0xFF (sign extend) |
| T_CHAR | rax & 0xFFFF |
| T_SHORT | rax & 0xFFFF (sign extend) |
| T_INT | rax (32-bit) |
| T_LONG | rax (64-bit) |
| T_FLOAT | xmm0 → ftos |
| T_DOUBLE | xmm0 → dtos |
| T_OBJECT | resolve + 存入 oop_temp |
| T_VOID | 无操作 |

## 与 zerolocals 的主要区别

| 方面 | zerolocals | native |
|------|------------|--------|
| 字节码执行 | 有 | 无 |
| 本地变量 | 需要分配 | 无 |
| JNI 参数准备 | 无 | 需要 |
| 线程状态切换 | 无 | 需要 |
| 安全点协调 | 不同机制 | 返回时检查 |
| 返回值处理 | 直接使用 | 需要 result_handler |
| 代码大小 | 1984 bytes | 3808 bytes |

## 总结

| 方面 | 说明 |
|------|------|
| 入口点大小 | native: 3808 bytes, native_synchronized: 4448 bytes |
| 特殊栈槽 | result_handler + oop_temp |
| 核心特性 | 线程状态转换、JNI 参数准备、安全点协调 |
| 安全点 | 返回时在 _thread_in_native_trans 状态检查 |
| 返回值 | 通过 result_handler 处理类型转换 |
