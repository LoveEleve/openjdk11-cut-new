# 4. 字节码模板生成详解

> 源码位置: `src/hotspot/share/interpreter/templateInterpreterGenerator.cpp:276`
>
> 这是解释器的**核心机制**：为每个字节码生成对应的机器码模板，使得字节码执行无需解释，直接运行本机代码。

---

## 1. 核心入口函数

```cpp
// templateInterpreterGenerator.cpp:276
void TemplateInterpreterGenerator::set_entry_points_for_all_bytes() {
    for (int i = 0; i < DispatchTable::length; i++) {  // 256 次循环
        Bytecodes::Code code = (Bytecodes::Code)i;
        if (Bytecodes::is_defined(code)) {
            set_entry_points(code);   // 为有效字节码生成模板
        } else {
            set_unimplemented(i);     // 未定义字节码指向错误处理
        }
    }
}
```

**关键数据**：
- `DispatchTable::length = 256`（1 字节能表示的所有值）
- 实际定义的字节码约 **203 个**（标准 + wide + 内部优化）

## 2. Template 结构

```cpp
// templateTable.hpp:44
class Template {
private:
    int       _flags;     // 标志位（4个）
    TosState  _tos_in;    // 执行前栈顶状态
    TosState  _tos_out;   // 执行后栈顶状态
    generator _gen;       // 代码生成函数指针
    int       _arg;       // 生成器参数
};
```

### 2.1 标志位含义

| 位 | 名称 | 宏 | 含义 |
|----|------|----|------|
| 0 | `uses_bcp_bit` | `ubcp` | 模板需要 bcp 指向当前字节码 |
| 1 | `does_dispatch_bit` | `disp` | 模板自己负责分发下一字节码 |
| 2 | `calls_vm_bit` | `clvm` | 模板会调用 VM 运行时 |
| 3 | `wide_bit` | `iswd` | 这是 wide 指令版本 |

### 2.2 TosState（栈顶状态）

```cpp
// globalDefinitions.hpp
enum TosState {
    btos = 0,  // byte
    ztos = 1,  // boolean (zero)
    ctos = 2,  // char
    stos = 3,  // short
    itos = 4,  // int        ← btos/ztos/ctos/stos 实际都用 itos
    ltos = 5,  // long
    ftos = 6,  // float
    dtos = 7,  // double
    atos = 8,  // address (object reference)
    vtos = 9,  // void (empty)
    number_of_states = 10,
    ilgl = 11  // illegal (用于断言)
};
```

**优化**: `btos`/`ztos`/`ctos`/`stos` 在 x86-64 上都映射到 `itos` 入口点，因为都用 32 位寄存器 `eax`。

### 3.2 典型字节码定义

#### 常量加载类

```cpp
def(Bytecodes::_aconst_null,  ____|____|____|____, vtos, atos, aconst_null,  _);
def(Bytecodes::_iconst_m1,    ____|____|____|____, vtos, itos, iconst,      -1);

def(Bytecodes::_lconst_0,     ____|____|____|____, vtos, ltos, lconst,       0);
def(Bytecodes::_fconst_0,     ____|____|____|____, vtos, ftos, fconst,       0);
def(Bytecodes::_dconst_0,     ____|____|____|____, vtos, dtos, dconst,       0);
```

**特点**: 无标志位，vtos → xtos（从空栈顶到特定类型）

#### 局部变量加载类

```cpp
def(Bytecodes::_iload,        ubcp|____|clvm|____, vtos, itos, iload,        _);
def(Bytecodes::_aload,        ubcp|____|clvm|____, vtos, atos, aload,        _);
def(Bytecodes::_iload_0,      ____|____|____|____, vtos, itos, iload,        0);
def(Bytecodes::_aload_0,      ubcp|____|clvm|____, vtos, atos, aload_0,      _);
```

**注意**: 
- `iload` 需要 ubcp（读取操作数）+ clvm（可能触发JVMTI）
- `iload_0` 无标志位（槽位已知，不需要读取操作数）
- `aload_0` 有特殊处理（用于优化 getter 模式）

#### 算术运算类

```cpp
def(Bytecodes::_iadd,         ____|____|____|____, itos, itos, iop2,        add);
def(Bytecodes::_isub,         ____|____|____|____, itos, itos, iop2,        sub);
def(Bytecodes::_imul,         ____|____|____|____, itos, itos, iop2,        mul);
def(Bytecodes::_idiv,         ____|____|____|____, itos, itos, idiv,         _);
def(Bytecodes::_ladd,         ____|____|____|____, ltos, ltos, lop2,        add);
```

**特点**: 输入输出 TOS 相同，无标志位（纯 CPU 计算）

#### 数组操作类 ⭐G1 屏障

```cpp
def(Bytecodes::_aaload,       ____|____|____|____, itos, atos, aaload,       _);
def(Bytecodes::_aastore,      ____|____|clvm|____, vtos, vtos, aastore,      _);
```

**注意**: `aastore` 有 `clvm` 标志——存储对象引用可能触发 G1 屏障和 VM 调用。

#### 字段访问类 ⭐G1 屏障

```cpp
def(Bytecodes::_getfield,     ubcp|____|clvm|____, vtos, vtos, getfield,   f1_byte);
def(Bytecodes::_putfield,     ubcp|____|clvm|____, vtos, vtos, putfield,   f2_byte);
def(Bytecodes::_getstatic,    ubcp|____|clvm|____, vtos, vtos, getstatic,  f1_byte);
def(Bytecodes::_putstatic,    ubcp|____|clvm|____, vtos, vtos, putstatic,  f2_byte);
```

**参数含义**:
- `f1_byte`: 使用 ConstantPoolCache 的 f1 字段
- `f2_byte`: 使用 ConstantPoolCache 的 f2 字段

#### 方法调用类 ⭐重要

```cpp
def(Bytecodes::_invokevirtual,   ubcp|disp|clvm|____, vtos, vtos, invokevirtual,   f2_byte);
def(Bytecodes::_invokespecial,   ubcp|disp|clvm|____, vtos, vtos, invokespecial,   f1_byte);
def(Bytecodes::_invokestatic,    ubcp|disp|clvm|____, vtos, vtos, invokestatic,    f1_byte);
def(Bytecodes::_invokeinterface, ubcp|disp|clvm|____, vtos, vtos, invokeinterface, f1_byte);
def(Bytecodes::_invokedynamic,   ubcp|disp|clvm|____, vtos, vtos, invokedynamic,   f1_byte);
```

**关键标志**: `disp` — 这些指令自己负责分发（跳转到被调用方法）

#### 返回指令类

```cpp
def(Bytecodes::_ireturn,      ____|disp|clvm|____, itos, itos, _return,    itos);
def(Bytecodes::_lreturn,      ____|disp|clvm|____, ltos, ltos, _return,    ltos);
def(Bytecodes::_areturn,      ____|disp|clvm|____, atos, atos, _return,    atos);
def(Bytecodes::_return,       ____|disp|clvm|____, vtos, vtos, _return,    vtos);
```

**关键标志**: `disp` — 返回指令跳转回调用者，不分发下一字节码

#### 控制流类

```cpp
def(Bytecodes::_ifeq,         ubcp|____|clvm|____, itos, vtos, if_0cmp,    equal);
def(Bytecodes::_if_icmpeq,    ubcp|____|clvm|____, itos, vtos, if_icmp,    equal);
def(Bytecodes::_goto,         ubcp|disp|clvm|____, vtos, vtos, _goto,       _);

```

**后向跳转**: `goto` 有 `clvm` 标志，因为后向跳转需要检查安全点。

## 4. 为字节码生成入口点

### 4.1 set_entry_points()

```cpp
// templateInterpreterGenerator.cpp:304
void TemplateInterpreterGenerator::set_entry_points(Bytecodes::Code code) {
    CodeletMark cm(_masm, Bytecodes::name(code), code);  // 创建 Codelet
    
    // 初始化所有入口点为错误处理
    address bep = _illegal_bytecode_sequence;  // byte entry point
    address zep = _illegal_bytecode_sequence;  // boolean entry point
    address cep = _illegal_bytecode_sequence;  // char entry point
    address sep = _illegal_bytecode_sequence;  // short entry point
    address aep = _illegal_bytecode_sequence;  // atos (object) entry point
    address iep = _illegal_bytecode_sequence;  // itos (int) entry point
    address lep = _illegal_bytecode_sequence;  // ltos (long) entry point
    address fep = _illegal_bytecode_sequence;  // ftos (float) entry point
    address dep = _illegal_bytecode_sequence;  // dtos (double) entry point
    address vep = _unimplemented_bytecode;     // vtos (void) entry point
    address wep = _unimplemented_bytecode;     // wide entry point
    
    // 根据模板生成短版本入口点
    if (Bytecodes::is_defined(code)) {
        Template* t = TemplateTable::template_for(code);
        set_short_entry_points(t, bep, cep, sep, aep, iep, lep, fep, dep, vep);
    }
    
    // 如果有 wide 版本，生成 wide 入口点
    if (Bytecodes::wide_is_defined(code)) {
        Template* t = TemplateTable::template_for_wide(code);
        set_wide_entry_point(t, wep);
    }
    
    // 注册到分发表
    EntryPoint entry(bep, zep, cep, sep, aep, iep, lep, fep, dep, vep);
    Interpreter::_normal_table.set_entry(code, entry);
    Interpreter::_wentry_point[code] = wep;
}
```

### 4.2 set_short_entry_points()

```cpp
// templateInterpreterGenerator.cpp:345
void TemplateInterpreterGenerator::set_short_entry_points(Template* t, ...) {
    switch (t->tos_in()) {
        case atos:
            vep = __ pc(); __ pop(atos);  // vtos → atos: 从栈弹出对象到 rax
            aep = __ pc(); 
            generate_and_dispatch(t);
            break;
        case itos:
            vep = __ pc(); __ pop(itos);  // vtos → itos: 从栈弹出 int 到 eax
            iep = __ pc();
            generate_and_dispatch(t);
            break;
        case vtos:
            set_vtos_entry_points(t, bep, cep, sep, aep, iep, lep, fep, dep, vep);
            break;
        // ... 其他类型类似
    }
}
```

### 4.3 set_vtos_entry_points() (x86-64)

当字节码的 `tos_in = vtos` 时，需要为**所有可能的当前栈顶状态**生成入口点：

```cpp
// templateInterpreterGenerator_x86.cpp:1765
void TemplateInterpreterGenerator::set_vtos_entry_points(Template* t, ...) {
    Label L;
    
    // 为每种非 vtos 状态生成：先 push 到栈，然后跳转到统一执行点
    aep = __ pc();  __ push_ptr();    __ jmp(L);   // atos: push 对象引用
    fep = __ pc();  __ push_f(xmm0);  __ jmp(L);   // ftos: push float
    dep = __ pc();  __ push_d(xmm0);  __ jmp(L);   // dtos: push double
    lep = __ pc();  __ push_l();      __ jmp(L);   // ltos: push long
    bep = cep = sep =
    iep = __ pc();  __ push_i();                   // itos: push int (共享入口)
    vep = __ pc();                                 // vtos: 无需 push
    __ bind(L);
    
    generate_and_dispatch(t);  // 生成字节码模板代码
}
```

**生成的代码布局**:

```
aep: push_ptr()       ; 把 rax 中的对象引用压入栈
     jmp L
fep: push_f(xmm0)     ; 把 xmm0 中的 float 压入栈
     jmp L
dep: push_d(xmm0)     ; 把 xmm0 中的 double 压入栈
     jmp L
lep: push_l()         ; 把 rax:rdx 中的 long 压入栈
     jmp L
iep: push_i()         ; 把 eax 中的 int 压入栈 (bep/cep/sep 共享此入口)
vep:                  ; 栈顶已空，无需操作
L:
     ; 字节码模板代码...
     dispatch_next()  ; 分发到下一个字节码
```

## 5. generate_and_dispatch()

```cpp
// templateInterpreterGenerator.cpp:367
void TemplateInterpreterGenerator::generate_and_dispatch(Template* t, TosState tos_out) {
    // 调试支持
    if (TraceBytecodes) trace_bytecode(t);
    
    int step = 0;
    if (!t->does_dispatch()) {
        // 计算字节码长度（用于 bcp 前进）
        step = t->is_wide() ? Bytecodes::wide_length_for(t->bytecode())
                            : Bytecodes::length_for(t->bytecode());
        if (tos_out == ilgl) tos_out = t->tos_out();
        
        // 分发前导码（在某些平台有特殊处理）
        __ dispatch_prolog(tos_out, step);
    }
    
    // ⭐ 生成字节码模板代码
    t->generate(_masm);
    
    if (t->does_dispatch()) {
        // 自分发指令（如 invoke/return/goto）：不生成分发代码
        __ should_not_reach_here();  // 断言：不应执行到这里
    } else {
        // ⭐ 生成分发到下一字节码的代码
        __ dispatch_epilog(tos_out, step);
    }
}
```

## 6. 具体字节码模板实现示例

### 6.1 iconst (最简单的字节码)

```cpp
// templateTable_x86.cpp:260
void TemplateTable::iconst(int value) {
    transition(vtos, itos);           // 断言: vtos → itos
    if (value == 0) {
        __ xorl(rax, rax);            // 优化: xor 比 mov 快
    } else {
        __ movl(rax, value);          // mov eax, imm32
    }
}
```

**生成的机器码 (iconst_0)**:
```asm
xor    eax, eax       ; 2 字节
```

**生成的机器码 (iconst_1)**:
```asm
mov    eax, 0x1       ; 5 字节
```

### 6.2 aastore (含 G1 屏障) ⭐重要

```cpp
// templateTable_x86.cpp:1114
void TemplateTable::aastore() {
    Label is_null, ok_is_subtype, done;
    transition(vtos, vtos);
    
    // 栈: ..., array, index, value
    __ movptr(rax, at_tos());      // rax = value
    __ movl(rcx, at_tos_p1());     // rcx = index
    __ movptr(rdx, at_tos_p2());   // rdx = array
    
    // 计算元素地址
    Address element_address(rdx, rcx,
                            UseCompressedOops ? Address::times_4 : Address::times_ptr,
                            arrayOopDesc::base_offset_in_bytes(T_OBJECT));
    
    // 1. 越界检查
    index_check_without_pop(rdx, rcx);
    
    // 2. null 检查
    __ testptr(rax, rax);
    __ jcc(Assembler::zero, is_null);
    
    // 3. 类型检查 (ArrayStoreException)
    __ load_klass(rbx, rax);       // rbx = value's Klass
    __ load_klass(rax, rdx);       // rax = array's Klass
    __ movptr(rax, Address(rax, ObjArrayKlass::element_klass_offset()));  // 元素 Klass
    __ gen_subtype_check(rbx, ok_is_subtype);  // 子类型检查
    
    // 类型不匹配 → 抛出 ArrayStoreException
    __ jump(ExternalAddress(Interpreter::_throw_ArrayStoreException_entry));
    
    // 4. 类型检查通过 → 执行存储 (带 G1 屏障)
    __ bind(ok_is_subtype);
    __ movptr(rax, at_tos());      // 重新加载 value
    __ movl(rcx, at_tos_p1());     // 重新加载 index
    do_oop_store(_masm, element_address, rax, IS_ARRAY);  // ⭐ G1 屏障
    __ jmp(done);
    
    // 5. value 为 null 的快速路径
    __ bind(is_null);
    do_oop_store(_masm, element_address, noreg, IS_ARRAY);  // 存储 NULL
    
    // 6. 清理栈
    __ bind(done);
    __ addptr(rsp, 3 * Interpreter::stackElementSize);  // 弹出 3 个槽位
}
```

**do_oop_store 调用链**:
```
do_oop_store(element_address, rax, IS_ARRAY)
  └── __ store_heap_oop(dst, val, ..., IS_ARRAY)
        └── access_store_at(T_OBJECT, IN_HEAP | IS_ARRAY, ...)
              └── G1BarrierSetAssembler::store_at()
                    ├── g1_write_barrier_pre()   // SATB 前置屏障
                    ├── movq [dst], val          // 实际存储
                    └── g1_write_barrier_post()  // dirty card 后置屏障
```

## 7. 分发表结构

### 7.1 DispatchTable

```cpp
// abstractInterpreter.hpp
class DispatchTable {
public:
    static const int length = 1 << BitsPerByte;  // 256
private:
    address _table[number_of_states][length];    // [TosState][bytecode]
};
```

**内存布局**:
```
_table[vtos][0x00] → nop 的 vtos 入口地址
_table[vtos][0x01] → aconst_null 的 vtos 入口地址
_table[vtos][0x03] → iconst_0 的 vtos 入口地址
_table[itos][0x60] → iadd 的 itos 入口地址
...
```

### 7.2 分发示意图

```
           ┌─────────────────────────────────────────────────────────┐
```

### 7.3 字节码分发过程

```cpp
// 执行完当前字节码后:
dispatch_next(tos_out, step):
    1. rbcp += step          ; bcp 前进到下一字节码
    2. bytecode = *rbcp      ; 读取下一字节码
    3. entry = _table[tos_out][bytecode]  ; 查表获取入口
    4. jmp entry             ; 跳转执行
```

**x86-64 汇编**:
```asm
; dispatch_next(itos, 1)
add    r13, 1                          ; r13 = bcp, 前进 1 字节
movzbl ebx, BYTE PTR [r13]             ; ebx = 下一字节码
mov    rax, QWORD PTR [r15 + disp_offset + rbx*8]  ; 查表
jmp    rax                             ; 跳转
```

## 10. 关键点总结

1. **每个字节码最多 11 个入口点**：
   - 10 个短版本 (bep/zep/cep/sep/aep/iep/lep/fep/dep/vep)
   - 1 个 wide 版本 (wep)
   - 实际上 bep/zep/cep/sep 共享 iep

2. **TOS 状态缓存**：
   - 解释器用寄存器缓存栈顶值
   - 避免每次都 push/pop 内存

3. **does_dispatch 标志**：
   - 大多数字节码由框架负责分发
   - invoke/return/goto 等自己负责分发

4. **G1 屏障集成**：
   - `aastore`/`putfield` 等存储引用的字节码
   - 通过 `do_oop_store()` 调用 G1 屏障

5. **生成代码大小**：
   - 整个字节码模板区域约 **100KB**
   - 简单字节码（如 iconst）约 **32-64 bytes**
   - 复杂字节码（如 aastore）约 **256+ bytes**
