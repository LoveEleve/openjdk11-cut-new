# 3.3 zerolocals_synchronized（同步方法入口）

## 概述

`zerolocals_synchronized` 是同步 Java 方法的入口点。它与普通方法入口 `zerolocals` 的唯一区别是在方法开始时调用 `lock_method()` 获取监视器锁。

**只在一个地方不同**：`synchronized` 参数为 `true` 时调用 `lock_method()`。

## lock_method() 详解

### 函数签名

```cpp:587:596:src/hotspot/cpu/x86/templateInterpreterGenerator_x86.cpp
// Allocate monitor and lock method (asm interpreter)
//
// Args:
//      rbx: Method*
//      r14/rdi: locals
//
// Kills:
//      rax
//      c_rarg0, c_rarg1, c_rarg2, c_rarg3, ...(param regs)
//      rscratch1, rscratch2 (scratch regs)
void TemplateInterpreterGenerator::lock_method()
```

### 执行流程

```cpp:597:647:src/hotspot/cpu/x86/templateInterpreterGenerator_x86.cpp
void TemplateInterpreterGenerator::lock_method() {
  // 1. 获取同步对象
  {
    Label done;
    __ movl(rax, access_flags);
    __ testl(rax, JVM_ACC_STATIC);
    
    // 假设是实例方法（更常见），加载 this
    __ movptr(rax, Address(rlocals, Interpreter::local_offset_in_bytes(0)));
    __ jcc(Assembler::zero, done);
    
    // 静态方法：加载 Class mirror 对象
    __ load_mirror(rax, rbx);
    
    __ bind(done);
  }
  // rax 现在包含要锁定的对象
  
  // 2. 分配监视器空间
  __ subptr(rsp, entry_size);  // BasicObjectLock 大小
  __ movptr(monitor_block_top, rsp);  // 更新 monitor_block_top
  
  // 3. 存储锁定对象
  __ movptr(Address(rsp, BasicObjectLock::obj_offset_in_bytes()), rax);
  
  // 4. 调用 lock_object 获取锁
  __ movptr(lockreg, rsp);  // lockreg 指向 BasicObjectLock
  __ lock_object(lockreg);
}
```

## 锁定对象的确定

| 方法类型 | 锁定对象 | 获取方式 |
|----------|----------|----------|
| 实例方法 | `this` 引用 | `locals[0]` |
| 静态方法 | `Class` 对象 | `Method::mirror()` |

```cpp
// 实例方法: synchronized void foo()
// 锁定 this
__ movptr(rax, Address(rlocals, 0));

// 静态方法: static synchronized void bar()
// 锁定 Class 对象
__ load_mirror(rax, rbx);  // 从 Method* 加载 mirror
```

## BasicObjectLock 结构

```cpp
// hotspot/share/runtime/basicLock.hpp
class BasicObjectLock {
  BasicLock _lock;  // 保存 displaced header
  oop       _obj;   // 锁定的对象引用
};
```

**内存布局**：

## lock_object 实现

`lock_object` 是一个宏汇编函数，实现轻量级锁获取：

```cpp
// InterpreterMacroAssembler::lock_object
void lock_object(Register lock_reg) {
    // lock_reg 指向 BasicObjectLock
    
    // 1. 获取对象指针
    movptr(obj_reg, Address(lock_reg, obj_offset));
    
    // 2. 尝试轻量级锁（偏向锁或 CAS）
    // ... 使用 UseBiasedLocking 检查
    
    // 3. 如果轻量级锁失败，调用 VM 运行时
    call_VM(InterpreterRuntime::monitorenter);
}
```

**锁获取策略**：
1. **偏向锁**（如果启用）：检查 mark word 是否偏向当前线程
2. **轻量级锁**：CAS 尝试将 mark word 替换为锁记录指针
3. **重量级锁**：如果失败，膨胀为重量级锁

## 使用场景示例

### 实例同步方法

```java
public class Counter {
    private int count = 0;
    
    public synchronized void increment() {  // 锁 this
        count++;
    }
}
```

**生成的入口流程**：
```
1. 创建栈帧
2. lock_method():
   - 从 locals[0] 获取 this
   - 分配 BasicObjectLock
   - 调用 lock_object(this)
3. 执行方法体
4. return 时自动解锁
```

### 静态同步方法

```java
public class Utils {
    public static synchronized void process() {  // 锁 Utils.class
        // ...
    }
}
```

**生成的入口流程**：
```
1. 创建栈帧
2. lock_method():
   - load_mirror(Method*) 获取 Utils.class
   - 分配 BasicObjectLock
   - 调用 lock_object(Utils.class)
3. 执行方法体
4. return 时自动解锁
```

## 性能考虑

| 方面 | 影响 |
|------|------|
| 栈空间 | 每个同步方法额外 16 字节 |
| 方法入口 | 额外 ~100 条指令 |
| 轻量级锁成功 | 快速（CAS 成功） |
| 锁竞争 | 需要 VM 运行时介入 |

**优化建议**：
- JIT 编译后，偏向锁可以消除大部分开销
- 对于热点同步方法，C2 编译器会进行锁消除/粗化

## 相关 JVM 参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `-XX:+UseBiasedLocking` | true (JDK15 前) | 启用偏向锁 |

**注意**：JDK 15 开始偏向锁默认禁用，JDK 18 移除。
