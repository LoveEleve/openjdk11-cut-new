# Phase 2: vm_init_globals() 深度分析

> 源码位置: `src/hotspot/share/runtime/init.cpp:90`

## 1. 功能定位

### 1.1 一句话概括

**`vm_init_globals()` 是 JVM 启动早期的全局数据结构初始化，由 VMThread 在主线程创建之前执行，负责初始化类型系统、全局锁、内存池和性能监控等基础设施。**

### 1.2 在整体流程中的位置

```
Threads::create_vm()
    │
    ├── os::init_2()                  // OS 模块二次初始化 ✅
    ├── SafepointMechanism::initialize() // Polling Page ✅
    │
    ├──► vm_init_globals()            // 【当前分析】VM 全局数据结构初始化
    │       ├── basic_types_init()    //   基本类型初始化
    │       ├── mutex_init()          //   全局锁初始化 (60+ 锁)
    │       ├── chunkpool_init()      //   内存块池初始化
    │       └── perfMemory_init()     //   性能监控内存初始化
    │
    └── JavaThread* main_thread = new JavaThread() // Phase 3
```

### 1.3 与 init_globals() 的区别

| 函数 | 执行时机 | 主要职责 |
|------|----------|----------|
| `vm_init_globals()` | 主线程创建**之前** | 基础设施初始化 |
| `init_globals()` | 主线程创建**之后** | 核心模块初始化（堆、解释器等）|

## 3. 核心子模块详解

### 3.1 basic_types_init() - 基本类型初始化

> 源码位置: `src/hotspot/share/utilities/globalDefinitions.cpp:53`

#### 3.1.1 设计目的

**验证编译时假设的类型大小与运行时一致，并根据指针压缩设置调整相关变量。**

#### 3.1.2 类型大小验证

```c++
void basic_types_init() {
#ifdef ASSERT
  // 64位平台验证
  assert(min_intx == (intx)CONST64(0x8000000000000000), "correct constant");
  assert(max_intx == CONST64(0x7FFFFFFFFFFFFFFF), "correct constant");
  assert(max_uintx == CONST64(0xFFFFFFFFFFFFFFFF), "correct constant");
  assert(8 == sizeof(intx), "wrong size for basic type");
  assert(8 == sizeof(jobject), "wrong size for basic type");
  
  // 基本类型大小验证
  assert(1 == sizeof(jbyte), "wrong size for basic type");
  assert(2 == sizeof(jchar), "wrong size for basic type");
  assert(2 == sizeof(jshort), "wrong size for basic type");
  assert(4 == sizeof(jint), "wrong size for basic type");
  assert(8 == sizeof(jlong), "wrong size for basic type");
  assert(4 == sizeof(jfloat), "wrong size for basic type");
  assert(8 == sizeof(jdouble), "wrong size for basic type");
#endif
  // ...
}
```

#### 3.1.3 指针压缩设置

```c++
// 如果开启了指针压缩 (-XX:+UseCompressedOops)
if (UseCompressedOops) {
    // 对象引用大小为 4 字节
    heapOopSize        = jintSize;        // 4
    LogBytesPerHeapOop = LogBytesPerInt;  // 2
    LogBitsPerHeapOop  = LogBitsPerInt;   // 5
    BytesPerHeapOop    = BytesPerInt;     // 4
    BitsPerHeapOop     = BitsPerInt;      // 32
} else {
    // 对象引用大小为 8 字节
    heapOopSize        = oopSize;         // 8
    LogBytesPerHeapOop = LogBytesPerWord; // 3
    LogBitsPerHeapOop  = LogBitsPerWord;  // 6
    BytesPerHeapOop    = BytesPerWord;    // 8
    BitsPerHeapOop     = BitsPerWord;     // 64
}
```

#### 3.1.4 关键全局变量

| 变量 | 含义 | 未压缩值 | 压缩值 |
|------|------|----------|--------|
| `heapOopSize` | 对象引用大小 | 8 | 4 |
| `LogBytesPerHeapOop` | log2(引用大小) | 3 | 2 |
| `BytesPerHeapOop` | 引用字节数 | 8 | 4 |
| `BitsPerHeapOop` | 引用位数 | 64 | 32 |

### 3.2 mutex_init() - 全局锁初始化

> 源码位置: `src/hotspot/share/runtime/mutexLocker.cpp:194`

#### 3.2.1 设计目的

**JVM 是多线程系统，需要 60+ 个全局锁来保护各种共享数据结构。`mutex_init()` 在启动时一次性创建这些锁。**

#### 3.2.2 锁分类与等级

```
┌─────────────────────────────────────────────────────────────────────┐
│                        JVM 全局锁等级体系                            │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  等级 (rank)     说明                 典型锁                         │
│  ─────────────────────────────────────────────────────────────────  │
│  tty            最低级，TTY 输出      tty_lock                       │
│  special        特殊用途             CodeCache_lock, Patching_lock   │
│  access         快速访问             SATB_Q_FL_lock                  │
│  leaf           叶子锁               SystemDictionary_lock           │
│  safepoint      安全点相关           Safepoint_lock                  │
│  barrier        屏障相关             Threads_lock                    │
│  nonleaf        非叶子锁             VMOperationQueue_lock           │
│  max_nonleaf    最高非叶子           CDSClassFileStream_lock         │
│                                                                      │
│  【锁获取规则】: 只能按等级从低到高获取，防止死锁                      │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

#### 3.2.3 核心锁分类

**1. 内存管理相关锁**

```c++
def(Heap_lock              , PaddedMonitor, nonleaf+1, false, Monitor::_safepoint_check_sometimes);
def(ExpandHeap_lock        , PaddedMutex  , leaf,      true,  Monitor::_safepoint_check_always);
def(CodeCache_lock         , PaddedMutex  , special,   true,  Monitor::_safepoint_check_never);
def(MetaspaceExpand_lock   , PaddedMutex  , leaf-1,    true,  Monitor::_safepoint_check_never);
```

| 锁 | 保护对象 | 等级 |
|----|----------|------|
| `Heap_lock` | Java 堆分配 | nonleaf+1 |
| `ExpandHeap_lock` | 堆扩展操作 | leaf |
| `CodeCache_lock` | JIT 代码缓存 | special |
| `MetaspaceExpand_lock` | 元空间扩展 | leaf-1 |

**2. 类加载相关锁**

```c++
def(SystemDictionary_lock  , PaddedMonitor, leaf, true, Monitor::_safepoint_check_always);
def(ClassLoaderDataGraph_lock, PaddedMutex, nonleaf, true, Monitor::_safepoint_check_always);
def(Module_lock            , PaddedMutex  , leaf+2, true, Monitor::_safepoint_check_always);
```

**3. 线程管理相关锁**

```c++
def(Threads_lock           , PaddedMonitor, barrier, true, Monitor::_safepoint_check_sometimes);
def(VMOperationQueue_lock  , PaddedMonitor, nonleaf, true, Monitor::_safepoint_check_sometimes);
def(VMOperationRequest_lock, PaddedMonitor, nonleaf, true, Monitor::_safepoint_check_sometimes);
def(Safepoint_lock         , PaddedMonitor, safepoint, true, Monitor::_safepoint_check_sometimes);
```

**4. GC 相关锁 (G1)**

```c++
if (UseG1GC) {
    def(SATB_Q_FL_lock     , PaddedMutex  , access,   true, Monitor::_safepoint_check_never);
    def(SATB_Q_CBL_mon     , PaddedMonitor, access,   true, Monitor::_safepoint_check_never);
    def(DirtyCardQ_FL_lock , PaddedMutex  , access,   true, Monitor::_safepoint_check_never);
    def(DirtyCardQ_CBL_mon , PaddedMonitor, access,   true, Monitor::_safepoint_check_never);
    def(FreeList_lock      , PaddedMutex  , leaf,     true, Monitor::_safepoint_check_never);
    def(OldSets_lock       , PaddedMutex  , leaf,     true, Monitor::_safepoint_check_never);
    def(RootRegionScan_lock, PaddedMonitor, leaf,     true, Monitor::_safepoint_check_never);
    def(MarkStackFreeList_lock, PaddedMutex, leaf,    true, Monitor::_safepoint_check_never);
    def(MarkStackChunkList_lock, PaddedMutex, leaf,   true, Monitor::_safepoint_check_never);
}
```

#### 3.2.4 锁定义宏

```c++
#define def(var, type, pri, vm_block, safepoint_check_allowed) {       \
  var = new type(Mutex::pri, #var, vm_block, safepoint_check_allowed); \
  assert(_num_mutex < MAX_NUM_MUTEX, "increase MAX_NUM_MUTEX");        \
  _mutex_array[_num_mutex++] = var;                                    \
}
```

参数说明：
- `var`: 全局锁指针变量
- `type`: `PaddedMutex` 或 `PaddedMonitor`
- `pri`: 锁等级（防止死锁）
- `vm_block`: 是否可以在 VM 线程中阻塞
- `safepoint_check_allowed`: 安全点检查策略

#### 3.2.5 PaddedMutex vs PaddedMonitor

| 类型 | 说明 | 使用场景 |
|------|------|----------|
| `PaddedMutex` | 互斥锁，无条件变量 | 简单的互斥保护 |
| `PaddedMonitor` | 互斥锁 + 条件变量 | 需要 wait/notify 的场景 |
| `Padded*` | 填充到 cache line | 防止伪共享 |

### 3.4 perfMemory_init() - 性能监控内存初始化

> 源码位置: `src/hotspot/share/runtime/perfMemory.cpp:58`

#### 3.4.1 设计目的

**创建共享内存区域，存储 JVM 性能数据，供外部工具（jstat、jcmd、VisualVM）读取。**

#### 3.4.2 内存区域结构

```
┌─────────────────────────────────────────────────────────────────────┐
│                      PerfMemory 内存布局                             │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  _start                                             _end             │
│  │                                                  │                │
│  ▼                                                  ▼                │
│  ┌──────────────────┬────────────────────────────────┐              │
│  │  PerfDataPrologue │     性能数据条目区域            │              │
│  │    (头部元数据)    │  (PerfData entries)           │              │
│  └──────────────────┴────────────────────────────────┘              │
│  │                  │                                │              │
│  └── _prologue      └── _top (初始位置)              └── _capacity  │
│                                                                      │
│  【PerfDataPrologue 结构】                                           │
│  ┌─────────────────────────────────────────────────────────────┐    │
│  │ magic          │ 0xcafec0c0 (大端) / 0xc0c0feca (小端)       │    │
│  │ byte_order     │ 大端/小端标识                               │    │

│  │ used           │ 已使用字节数                                 │    │
│  │ overflow       │ 溢出字节数                                   │    │
│  │ mod_time_stamp │ 最后修改时间戳                               │    │
│  └─────────────────────────────────────────────────────────────┘    │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

#### 3.4.3 实现方式

```c++
void PerfMemory::initialize() {
    if (is_initialized()) return;
    
    // 计算容量（默认 32KB，按页对齐）
    size_t capacity = align_up(PerfDataMemorySize,
                               os::vm_allocation_granularity());
    
    // 通过 mmap 创建共享内存（文件映射）
    // 文件路径: /tmp/hsperfdata_<user>/<pid>
    create_memory_region(capacity);
    
    // 初始化头部
    _prologue = (PerfDataPrologue*)_start;
    _prologue->magic = 0xcafec0c0;  // 或 0xc0c0feca
    _prologue->byte_order = PERFDATA_BIG_ENDIAN;
    _prologue->major_version = PERFDATA_MAJOR_VERSION;
    _prologue->minor_version = PERFDATA_MINOR_VERSION;
    _prologue->accessible = 0;
    _prologue->entry_offset = sizeof(PerfDataPrologue);
    _prologue->num_entries = 0;
    _prologue->used = 0;
    _prologue->overflow = 0;
    _prologue->mod_time_stamp = 0;
    
    _initialized = 1;
}
```

#### 3.4.4 外部工具访问


|------|--------|------|

## 8. 总结

### 8.1 核心要点

1. **基础类型初始化是后续所有操作的前提**
   - 类型大小必须验证正确
   - 指针压缩设置影响对象布局

2. **60+ 全局锁按等级组织，防止死锁**
   - 只能从低等级向高等级获取锁
   - G1 GC 有自己的一套锁

3. **ChunkPool 提供高效小内存分配**
   - 类似 Netty 的设计思想
   - 周期性清理避免内存膨胀

4. **PerfMemory 是外部监控工具的数据来源**
   - 通过共享内存文件暴露
   - jstat、jcmd 等工具依赖此机制

### 8.2 学习建议

| 方向 | 说明 |
|------|------|

| 具体锁的使用场景 | 在后续模块分析中结合理解 |
| PerfData 具体指标 | 结合 jstat 输出理解 |
