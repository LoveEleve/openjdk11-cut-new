## 第一部分：基础配置参数

### 1.1 堆大小配置 -Xms / -Xmx

#### 参数说明

| 参数 | 说明 | 推荐值 |
|-----|------|-------|
| `-Xms` | 初始堆大小 | 与 `-Xmx` 相同 |
| `-Xmx` | 最大堆大小 | 根据应用内存需求设置 |

#### 源码分析

```cpp
// g1CollectedHeap.cpp
// G1 推荐 -Xms = -Xmx，避免运行时堆扩展带来的性能开销
```

#### 调优建议

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【为什么 -Xms 要等于 -Xmx？】

1. 避免运行时堆扩展
   - 堆扩展需要申请内存、初始化数据结构
   - 触发 STW，导致应用卡顿

2. G1 的 Region 预分配
   - 启动时一次性划分所有 Region
   - 后续 GC 无需处理堆扩展逻辑

3. 内存连续性
   - 一次性申请大内存更容易获得连续空间
   - 减少内存碎片

推荐配置：
  -Xms8g -Xmx8g  ✅ 推荐
  -Xms2g -Xmx8g  ❌ 避免
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 1.2 Region 大小 G1HeapRegionSize

#### 参数说明

```cpp
// g1_globals.hpp:196-199
product(size_t, G1HeapRegionSize, 0,
        "Size of the G1 regions.")
        range(0, 32*M)
        constraint(G1HeapRegionSizeConstraintFunc,AfterMemoryInit)
```

| 参数 | 默认值 | 范围 | 说明 |
|-----|-------|------|------|
| `G1HeapRegionSize` | 0 (自动) | 0 或 1-32MB | Region 大小，必须是 2 的幂次 |

#### 自动计算逻辑

```cpp
// heapRegion.cpp
// G1 根据堆大小自动计算 Region 大小
// 目标：大约 2048 个 Region

uint G1HeapRegion::calculate_region_size(size_t heap_size) {
  // 目标 Region 数量
  const size_t target_num_regions = 2048;
  
  // 计算初始大小
  size_t region_size = heap_size / target_num_regions;
  
  // 对齐到 2 的幂次
  region_size = 1 << log2_intptr(region_size);
  
  // 限制范围：1MB - 32MB
  region_size = MAX2(region_size, (size_t)1 << 20);  // 最小 1MB
  region_size = MIN2(region_size, (size_t)32 << 20); // 最大 32MB
  
  return region_size;
}
```

#### Region 大小对照表

| 堆大小 | 自动计算的 Region 大小 | Region 数量 |
|-------|----------------------|------------|
| < 4GB | 1MB | ~4000+ |
| 4-8GB | 2MB | ~2000-4000 |
| 8-16GB | 4MB | ~2000-4000 |
| 16-32GB | 8MB | ~2000-4000 |
| 32-64GB | 16MB | ~2000-4000 |
| > 64GB | 32MB | ~2000+ |

#### 调优建议

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【什么时候需要手动设置 Region 大小？】

1. 大对象居多时
   - 场景：应用频繁分配 1MB+ 对象
   - 问题：大量 Humongous 对象导致内存碎片
   - 解决：增大 Region 大小，如 -XX:G1HeapRegionSize=16m

2. 超大堆时
   - 场景：堆 > 64GB
   - 问题：32MB Region 仍可能导致 Region 数量过多
   - 解决：手动设置 32MB（最大值）

3. 与 HBase/Cassandra 等配合
   - 场景：底层存储有固定块大小
   - 解决：对齐 Region 大小，如 16MB

推荐配置：
  # 默认（自动计算）
  不设置 G1HeapRegionSize  ✅ 推荐
  
  # 大对象场景
  -XX:G1HeapRegionSize=16m  ✅ 大对象多
  
  # 超大堆
  -XX:G1HeapRegionSize=32m  ✅ 堆 > 64GB
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【G1ReservePercent 的作用】

1. 防止晋升失败
   - 场景：年轻代对象晋升时，老年代空间不足
   - 后果：对象留在原地（Evacuation Failure），产生碎片

2. 保留空间计算
   - 默认 10%，8GB 堆保留约 800MB
   - 约 200 个 Region（4MB Region）

3. 调优场景
   
   高存活率应用：
   - 特征：每次 GC 存活对象多，晋升压力大
   - 建议：增大到 15-20%
   - 配置：-XX:G1ReservePercent=15
   
   大堆低存活率：
   - 特征：堆大，但每次 GC 存活少
   - 建议：降低到 5%
   - 配置：-XX:G1ReservePercent=5

4. 注意事项
   - 设置过大：浪费内存
   - 设置过小：增加 Full GC 风险

推荐配置：
  # 默认
  -XX:G1ReservePercent=10  ✅ 大多数场景
  
  # 高存活率
  -XX:G1ReservePercent=15  ✅ 存活率高
  
  # 大堆低存活
  -XX:G1ReservePercent=5   ✅ 大堆，存活率低
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

#### 作用机制

```cpp
// g1Policy.cpp 关键逻辑
// G1 根据 MaxGCPauseMillis 计算 CSet 大小

void G1Policy::finalize_collection_set(...) {
  // 目标暂停时间
  double target_pause_time_ms = (double) MaxGCPauseMillis;
  
  // 预测 GC 时间
  // 包括：存活对象复制时间 + RSet 扫描时间 + 其他开销
  double predicted_pause_time = 
      predict_object_copy_time(bytes_to_copy) +
      predict_rset_scan_time(rset_size) +
      predict_other_time();
  
  // 调整 CSet 大小，使预测时间接近目标
  while (predicted_pause_time > target_pause_time_ms) {
    // 减少 CSet 中的 Region 数量
    reduce_collection_set();
    recalculate_predicted_time();
  }
}
```

#### 调优建议

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 理解"目标" vs "保证"

  # 默认
  -XX:MaxGCPauseMillis=200  ✅ 平衡
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 2.2 GC 时间占比 GCTimeRatio

#### 参数说明

```cpp
// 定义在 globals.hpp（通用 GC 参数）
product(intx, GCTimeRatio, 12, ...)
```

| 参数 | 默认值 | 说明 |
|-----|-------|------|
| `GCTimeRatio` | 12 | GC 时间与应用时间比例 |

#### 计算公式

```
GC 时间占比目标 = 1 / (1 + GCTimeRatio)

默认值 12：
  GC 占比 = 1 / (1 + 12) = 1/13 ≈ 7.7%

常用值对照：
  GCTimeRatio=9  → GC 占比 ≈ 10%
  GCTimeRatio=19 → GC 占比 ≈ 5%
  GCTimeRatio=99 → GC 占比 ≈ 1%
```

#### 与 MaxGCPauseMillis 的关系

```
MaxGCPauseMillis：控制单次 GC 暂停时间
GCTimeRatio：     控制单位时间内 GC 总时间

两者配合：
- MaxGCPauseMillis 决定单次 GC 的 Region 数量
- GCTimeRatio 决定 GC 频率

示例：
  目标暂停 200ms，GC 占比 10%
  → 每 2 秒可以执行一次 GC（200ms / 10% = 2000ms）
```

#### 调优建议

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【GCTimeRatio 调优指南】

1. 吞吐优先 vs 延迟优先

   吞吐优先（批处理、大数据）：
   - 降低 GC 频率，减少总 GC 时间
   - 配置：-XX:GCTimeRatio=19（GC 占比 5%）
   - 效果：更多时间用于业务处理
   
   延迟优先（Web、微服务）：
   - 允许更高 GC 频率，降低单次暂停
   - 配置：-XX:GCTimeRatio=9（GC 占比 10%）
   - 效果：响应更及时

2. 与 MaxGCPauseMillis 配合

   高吞吐场景：
   -XX:MaxGCPauseMillis=500 -XX:GCTimeRatio=19
   → 单次 500ms，但频率低
   
   低延迟场景：
   -XX:MaxGCPauseMillis=100 -XX:GCTimeRatio=9
   → 单次 100ms，频率较高

3. 实际效果
   GCTimeRatio 影响的是 GC 触发阈值
   - 值越大，越不容易触发 GC
   - 值越小，越容易触发 GC

推荐配置：
  # 吞吐优先
  -XX:GCTimeRatio=19  ✅ 批处理/大数据
  
  # 延迟优先
  -XX:GCTimeRatio=9   ✅ Web/微服务
  
  # 默认
  -XX:GCTimeRatio=12  ✅ 平衡
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

#### 8GB 堆示例计算

```
堆大小：8GB
Region 大小：4MB
Region 数量：2048

最小年轻代：
  2048 * 5% = 102 个 Region = 408 MB

最大年轻代：
  2048 * 60% = 1228 个 Region = 4.9 GB

实际年轻代：
  在 102 - 1228 之间动态调整
  根据分配速率和 GC 效果自适应
```

#### 源码分析

```cpp
// g1Policy.cpp:93-133

  // 确保年轻代最大大小不超过堆的总Region数
  _young_gen_sizer.adjust_max_new_size(_g1h->max_regions());
  
  // 更新年轻代目标长度
  update_young_list_max_and_target_length();
}

// g1YoungGenSizer.cpp
uint G1YoungGenSizer::calculate_default_min_length(uint num_regions) {
  return (uint)(num_regions * G1NewSizePercent / 100);
}

uint G1YoungGenSizer::calculate_default_max_length(uint num_regions) {
  return (uint)(num_regions * G1MaxNewSizePercent / 100);
}
```

```
【年轻代大小调优指南】

1. 理解 G1 的自适应机制

   G1 会动态调整年轻代大小，目标是：
   - 在 MaxGCPauseMillis 内完成 GC
   - 同时满足 GCTimeRatio 的占比要求

   - 对象分配速率

   - 历史 GC 时间
```

### 3.2 浪费空间容忍度 G1HeapWastePercent

#### 参数说明

```cpp
// g1_globals.hpp:241-244
product(uintx, G1HeapWastePercent, 5,
        "Amount of space, expressed as a percentage of the heap size, "
        "that G1 is willing not to collect to avoid expensive GCs.")
        range(0, 100)
```

| 参数 | 默认值 | 范围 | 说明 |
|-----|-------|------|------|
| `G1HeapWastePercent` | 5 | 0-100% | 可容忍的堆浪费百分比 |

#### 作用机制

```cpp
// g1Policy.cpp
// Mixed GC 选择 Region 时，考虑回收效率

bool G1Policy::should_collect_region(HeapRegion* r) {
  // 计算可回收字节
  size_t reclaimable = r->reclaimable_bytes();
  
  // 如果可回收空间 < 浪费阈值，跳过
  size_t waste_threshold = heap_size * G1HeapWastePercent / 100;
  
  if (reclaimable < waste_threshold) {
    return false;  // 不值得回收
  }
  
  return true;
}
```

#### 调优建议

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【G1HeapWastePercent 调优指南】

1. 参数含义

   G1 允许不回收的内存比例
   - 默认 5%，8GB 堆允许 400MB 不回收
   - 目的是避免回收收益低的 Region

2. 影响因素

   值越大：
   - Mixed GC 频率越低（跳过的 Region 多）
   - 但内存碎片可能增加
   - 可能提前触发 Full GC
   
   值越小：
   - Mixed GC 频率越高
   - 内存回收更积极
   - 但 GC 开销增加

3. 调优场景

   大堆，内存充足：
   - 配置：-XX:G1HeapWastePercent=10
   - 效果：减少 Mixed GC 频率
   
   内存紧张，碎片敏感：
   - 配置：-XX:G1HeapWastePercent=2
   - 效果：更积极回收，减少碎片

4. 与 G1MixedGCLiveThresholdPercent 配合

   - G1HeapWastePercent：空间角度
   - G1MixedGCLiveThresholdPercent：存活率角度
   
   两者共同决定是否回收某个 Region

推荐配置：
  # 默认
  -XX:G1HeapWastePercent=5  ✅ 平衡
  
  # 大堆，内存充足
  -XX:G1HeapWastePercent=10 ✅ 减少 Mixed GC
  
  # 内存紧张
  -XX:G1HeapWastePercent=2  ✅ 积极回收
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 3.3 Mixed GC 目标次数 G1MixedGCCountTarget

#### 参数说明

```cpp
// g1_globals.hpp:246-248
product(uintx, G1MixedGCCountTarget, 8,
        "The target number of mixed GCs after a marking cycle.")
        range(0, max_uintx)
```

| 参数 | 默认值 | 说明 |
|-----|-------|------|
| `G1MixedGCCountTarget` | 8 | 并发标记后 Mixed GC 的目标次数 |

#### 作用机制

```
并发标记完成后：
  识别出大量可回收的老年代 Region
  
  G1MixedGCCountTarget = 8 意味着：
  - 目标分 8 次 Mixed GC 回收
  - 每次回收 1/8 左右
  - 控制每次暂停时间

如果设置过大：
  - 每次回收量少，暂停短
  - 但回收周期长，可能标记过期

如果设置过小：
  - 每次回收量多，暂停长
  - 可能超过 MaxGCPauseMillis
```

#### 调优建议

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【G1MixedGCCountTarget 调优指南】

1. 参数影响

   值越大：
   - 每次 Mixed GC 工作量越少
   - 单次暂停越短
   - 但回收周期越长
   
   值越小：
   - 每次 Mixed GC 工作量越多
   - 单次暂停可能超标
   - 回收更快完成

2. 调优场景

   低延迟优先：
   - 配置：-XX:G1MixedGCCountTarget=16
   - 效果：每次回收更少，暂停更短
   
   快速回收：
   - 配置：-XX:G1MixedGCCountTarget=4
   - 效果：更快完成老年代回收

3. 注意事项

   - 实际次数可能不等于目标值
   - G1 会根据暂停时间动态调整
   - 如果存活率变化，可能提前结束

推荐配置：
  # 默认
  -XX:G1MixedGCCountTarget=8  ✅ 平衡
  
  # 低延迟
  -XX:G1MixedGCCountTarget=16 ✅ 更短暂停
  
  # 快速回收
  -XX:G1MixedGCCountTarget=4  ✅ 更快完成
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
