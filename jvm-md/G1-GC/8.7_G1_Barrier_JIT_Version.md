## 1. 问题引入：为什么 JIT 编译需要单独实现写屏障？

### 1.1 解释器屏障的局限

解释器通过 `G1BarrierSetAssembler::oop_store_at()` 在**每次引用写入**时插入 pre-barrier 和 post-barrier。这是一段固定的汇编模板，**没有任何编译时优化**：

- 不知道写入的新值是否为 NULL → 每次都做跨 Region 检查
- 不知道对象是否刚分配 → 每次都写卡表
- 不知道字段是否曾被写过 → 每次都做 SATB 记录

### 1.2 JIT 编译器的优化机会

C1/C2 编译器**在编译时就能看到程序的控制流和数据流**，因此能做出解释器做不到的优化：

| 优化 | 说明 | 适用编译器 |
|------|------|-----------|
| **常量 NULL 消除** | `obj.field = null` → 跳过整个 post-barrier | C1, C2 |
| **新分配对象消除** | 刚 `new` 出来的对象 → pre-barrier 无意义（字段为 NULL），post-barrier 在 Eden 中无意义 | C2 |
| **初始化写消除** | 对象在 `<init>` 中的首次写入 → 不需要 pre-barrier（之前是 NULL） | C2 |
| **SATB 标记消除** | 编译期证明不在标记阶段 → 折叠 pre-barrier | C2 (eliminate_gc_barrier) |

### 1.3 架构差异

```
解释器: 固定汇编模板 → 每次执行都走完整路径
C1:     LIR 指令 + Stub → 快路径内联 + 慢路径跳出
C2:     Ideal 图节点 → 编译期优化 + 死代码消除 + 运行时最小路径
```

## 2. Barrier Set 架构：JEP 304 GC 接口

### 2.1 三层继承体系

JDK 10 引入的 JEP 304 (Garbage Collector Interface) 将 GC 屏障抽象为三层接口。每个编译层级（Assembler / C1 / C2）都有独立的继承链：

```
┌─ Assembler 层 (解释器 / 通用汇编) ─────────────────────────────────┐
│  BarrierSetAssembler                                               │
│    └─ ModRefBarrierSetAssembler                                    │
│         └─ G1BarrierSetAssembler          ← x86 实现              │
│              g1_write_barrier_pre()       ← SATB pre-barrier       │
│              g1_write_barrier_post()      ← 脏卡 post-barrier      │
│              gen_pre_barrier_stub()       ← C1 stub 汇编           │
│              gen_post_barrier_stub()      ← C1 stub 汇编           │
│              generate_c1_pre_barrier_runtime_stub()                 │
│              generate_c1_post_barrier_runtime_stub()                │
└────────────────────────────────────────────────────────────────────┘

┌─ C1 层 (客户端编译器) ─────────────────────────────────────────────┐
│  BarrierSetC1                                                      │
│    └─ ModRefBarrierSetC1                                           │
│         store_at_resolved(): pre_barrier → store → post_barrier    │
│         └─ G1BarrierSetC1                                          │
│              pre_barrier()   → 生成 LIR + G1PreBarrierStub         │
│              post_barrier()  → 生成 LIR + G1PostBarrierStub        │
│              load_at_resolved() → 弱引用 SATB 处理                  │
│              generate_c1_runtime_stubs() → 创建运行时 blob          │
└────────────────────────────────────────────────────────────────────┘

┌─ C2 层 (服务端编译器) ─────────────────────────────────────────────┐
│  BarrierSetC2                                                      │
│    └─ ModRefBarrierSetC2                                           │
│         store_at_resolved(): pre_barrier → store → post_barrier    │
│         └─ CardTableBarrierSetC2                                   │
│              └─ G1BarrierSetC2                                     │
│                   pre_barrier()    → IdealKit 构建 Ideal 图        │
│                   post_barrier()   → IdealKit 构建 Ideal 图        │
│                   g1_mark_card()   → storeCM + DCQ 入队            │
│                   g1_can_remove_pre_barrier()  → 编译时消除        │
│                   g1_can_remove_post_barrier() → 编译时消除        │
│                   eliminate_gc_barrier()        → 宏扩展时消除     │
│                   insert_pre_barrier() → Unsafe.getObject 守卫     │
│                   load_at_resolved()   → 弱引用 SATB               │
└────────────────────────────────────────────────────────────────────┘
```

### 2.2 调用入口统一

无论 C1 还是 C2，引用写入的入口都是 `store_at()`，由基类分发到 `store_at_resolved()`：

**C1 路径** (`modRefBarrierSetC1.cpp:35-52`):
```
LIRGenerator::access_store_at()
  → BarrierSetC1::store_at()
    → ModRefBarrierSetC1::store_at_resolved()
      → G1BarrierSetC1::pre_barrier()     // SATB pre-barrier
      → BarrierSetC1::store_at_resolved() // 实际存储
      → G1BarrierSetC1::post_barrier()    // 脏卡 post-barrier
```

**C2 路径** (`modRefBarrierSetC2.cpp:33-59`):
```
GraphKit::access_store_at()
  → BarrierSetC2::store_at()
    → ModRefBarrierSetC2::store_at_resolved()
      → G1BarrierSetC2::pre_barrier()     // SATB pre-barrier（IdealKit）
      → BarrierSetC2::store_at_resolved() // 实际存储
      → G1BarrierSetC2::post_barrier()    // 脏卡 post-barrier（IdealKit）
```

两者的关键区别在于：C1 生成**线性 LIR 指令序列 + 延迟 Stub**，C2 直接在 **Ideal 图上构建屏障控制流节点**，后续被全局优化 Pass 优化。

## 3. C1 编译器的 G1 写屏障

### 3.1 Pre-Barrier：SATB 快照记录

**源码**: `g1BarrierSetC1.cpp:51-108`

#### 3.1.1 核心逻辑

Pre-barrier 确保在并发标记期间，**被覆盖的旧值**被记录到 SATB 缓冲区，维护 SATB 快照一致性。

```
pre_barrier(LIRAccess& access, LIR_Opr addr_opr, LIR_Opr pre_val, CodeEmitInfo* info)
```

有两种使用模式：
- **do_load = true**：`pre_val` 为 `illegalOpr`，需要 stub 加载旧值（普通字段写入）
- **do_load = false**：`pre_val` 已有值（如 `load_at_resolved` 中的引用读取）

#### 3.1.2 生成的 LIR 序列

```asm
; ===== 快路径（内联在 C1 生成的代码中）=====
; 1. 检查标记是否激活
load [thread + satb_mark_queue_active_offset] → flag_val    ; 加载 marking 标志
cmp flag_val, 0                                              ; 是否在标记中？
bne G1PreBarrierStub                                         ; 如果是 → 跳到 stub

; ===== marking 未激活 → 直接跳过 =====
continuation:
  ; ... 继续正常执行 ...
```

关键点：

1. **标记标志宽度检测**（第 60-68 行）：`SATBMarkQueue::byte_width_of_active()` 返回 1 或 4 字节。在 x86-64 上通常为 1 字节，用 `T_BOOLEAN` 类型加载。

2. **do_load 决定 stub 类型**（第 83-104 行）：
   - `do_load = true`：创建 `G1PreBarrierStub(addr_opr, pre_val, patch_code, info)`，stub 会加载旧值
   - `do_load = false`：创建 `G1PreBarrierStub(pre_val)`，旧值已在寄存器中

3. **条件跳转**（第 106-107 行）：`marking != 0` 时跳入 stub（慢路径），否则 fall through 到 continuation。

### 3.2 Post-Barrier：脏卡更新

**源码**: `g1BarrierSetC1.cpp:110-176`

#### 3.2.1 快速过滤

```cpp
void G1BarrierSetC1::post_barrier(LIRAccess& access, LIR_OprDesc* addr, LIR_OprDesc* new_val) {
    // 过滤 1: 非堆内存写入 → 不需要 barrier
    if (!in_heap) return;

    // 过滤 2: 常量 NULL → 不需要 barrier
    if (new_val->is_constant() && new_val->as_constant_ptr()->as_jobject() == NULL) return;
    // ... 继续 ...
```

#### 3.2.2 跨 Region 检测（XOR + Shift）

这是 G1 post-barrier 最核心的优化 —— 如果 store_addr 和 new_val 在同一个 Region 中，则不需要更新 RSet：

```asm
; ===== 快路径（内联在 C1 生成的代码中）=====
; 跨 Region 检测
xor_res = addr XOR new_val                    ; 地址异或
xor_shift_res = xor_res >>> LogOfHRGrainBytes ; 右移 22 位（Region=4MB → log2=22）
cmp xor_shift_res, 0                          ; 高位相同 → 同一 Region
bne G1PostBarrierStub                         ; 不同 Region → 跳到 stub

; ===== 同一 Region → 不需要更新 RSet =====
continuation:
  ; ... 继续正常执行 ...
```

**为什么 XOR + Shift 能检测跨 Region？**
- Region 大小 4MB = 2^22 字节
- 如果两个地址在同一 Region，它们的高 42 位（64-22）相同
- XOR 后高位全 0，右移 22 位后结果为 0
- 结果不为 0 → 跨 Region

这里有一个与 x86 `TwoOperandLIRForm` 相关的分支（第 148-162 行）。x86 是二操作数架构（`dst = dst OP src`），所以需要先 `move addr → xor_res`，再做 `xor xor_res, new_val`。非 x86 平台可以直接 `xor addr, new_val → xor_res`。

### 3.3 C1 Stub 结构

C1 使用 **CodeStub** 机制实现屏障的慢路径。Stub 是延迟发射的代码片段，在主代码之后生成，避免污染热路径。

#### 3.3.1 G1PreBarrierStub

**定义**: `g1BarrierSetC1.hpp:31-87`

```cpp
    LIR_Opr _pre_val;       // 旧值寄存器
    LIR_PatchCode _patch_code;  // 补丁类型

```

**汇编发射** (`g1BarrierSetAssembler_x86.cpp:415-437`):

### 3.4 C1 运行时 Blob

C1 的 pre/post stub 最终调用的不是直接的 runtime 函数，而是两个**预生成的 CodeBlob**。这些 blob 在 C1 初始化时创建（`g1BarrierSetC1.cpp:218-225`），包含了 SATB/DCQ 的快路径入队逻辑，只在队列满时才调用真正的 runtime。

#### 3.4.1 g1_pre_barrier_slow Blob

**源码**: `g1BarrierSetAssembler_x86.cpp:456-515`

```asm
generate_c1_pre_barrier_runtime_stub:
    prologue "g1_pre_barrier"         ; 栈帧
    push rax
    push rdx
    
    ; === 再次检查 marking 是否仍然激活 ===
    ; （从 stub 跳过来可能经历了 safepoint）
    cmp [thread + satb_mark_queue_active_offset], 0
    je done                            ; 已不在标记中 → 退出
    
    ; === SATB 缓冲区快路径 ===
    mov tmp, [thread + satb_mark_queue_index]
    test tmp, tmp
    jz runtime                         ; index == 0 → 队列满 → 慢路径
    
    sub tmp, 8                         ; index -= wordSize
    mov [thread + satb_mark_queue_index], tmp
    add tmp, [thread + satb_mark_queue_buffer]
    
    ; 加载参数中的 pre_val
    load_parameter 0, rax              ; pre_val
    mov [tmp], rax                     ; buffer[index] = pre_val
    jmp done
    
runtime:
    save_live_registers
    load_parameter 0, rcx
    call write_ref_field_pre_entry(rcx, thread)
    restore_live_registers
    
done:
    pop rdx
    pop rax
    epilogue
```

**关键细节**：

1. **二次 marking 检查**：从 C1 快路径跳过来可能已经经历了 safepoint，marking 可能已经关闭。因此 blob 中再检查一次，是运行正确性保证。

2. **SATB 快路径**：`index != 0` 时直接 `index -= 8`，将 pre_val 写入 `buffer[index]`。这是无锁操作，因为 SATB 缓冲区是线程私有的（Thread-local）。

3. **寄存器保存/恢复**：只在调用 runtime（`write_ref_field_pre_entry`）时才保存所有活跃寄存器，快路径只保存 rax/rdx。

#### 3.4.2 g1_post_barrier_slow Blob

**源码**: `g1BarrierSetAssembler_x86.cpp:517-594`

```asm
generate_c1_post_barrier_runtime_stub:
    prologue "g1_post_barrier"
    
    push rax
    push rcx
    
    ; === 计算卡地址 ===
    load_parameter 0, card_addr        ; 加载 store_addr
    shr card_addr, CardTable::card_shift  ; card_shift = 9（512 字节一张卡）
    mov cardtable, byte_map_base       ; 卡表基地址
    add card_addr, cardtable           ; card_addr = byte_map_base + (store_addr >> 9)
    
    ; === Young Card 检查 ===
    cmpb [card_addr], g1_young_card_val  ; 卡在年轻代区域？
    je done                              ; 是 → 不需要更新（年轻代 Region 整体扫描）
    
    ; === StoreLoad 屏障 ===
    mfence                               ; 确保 store 可见后再 load card
    
    ; === Dirty Card 检查 ===
    cmpb [card_addr], dirty_card_val     ; 卡已经脏了？
    je done                              ; 是 → 不需要重复弄脏
    
    ; === 标脏并入队 ===
    movb [card_addr], dirty_card_val     ; 写脏
    
    push rdx
    mov tmp, [thread + dirty_card_queue_index]
    test tmp, tmp
    jz runtime                           ; DCQ 队列满 → 慢路径
    
    ; DCQ 快路径入队
    sub tmp, 8
    mov [thread + dirty_card_queue_index], tmp
    add tmp, [thread + dirty_card_queue_buffer]
    mov [tmp], card_addr                 ; buffer[index] = card_addr
    jmp enqueued
    
runtime:
    save_live_registers
    call write_ref_field_post_entry(card_addr, thread)
    restore_live_registers
    
enqueued:
    pop rdx
done:
    pop rcx
    pop rax
    epilogue
```

**Post-Barrier 的四层过滤**（从外到内）:

```
外层(C1 LIR): 非 IN_HEAP → 跳过
外层(C1 LIR): 常量 NULL → 跳过
外层(C1 LIR): 同 Region (XOR+Shift==0) → 跳过
Stub:          new_val == NULL → 跳过
Blob:          young_card → 跳过
Blob:          已 dirty → 跳过
最终:          写脏 + DCQ 入队
```

## 4. C2 编译器的 G1 写屏障

C2（Server Compiler）的屏障实现与 C1 有本质区别：C2 不生成 LIR 指令，而是**在 Ideal 图（Sea-of-Nodes IR）上直接插入屏障相关的控制流和数据流节点**。后续的优化 Pass（GVN、IGVN、CCP 等）可以对屏障代码做全局优化。

### 4.1 IdealKit：构建 Ideal 图的 DSL

C2 使用 `IdealKit` 工具类来简化 Ideal 图的构建。IdealKit 提供了类似高级语言的 `if_then/else_/end_if` 接口：

```cpp
#define __ ideal.

IdealKit ideal(kit, true);
__ if_then(marking, BoolTest::ne, zero, unlikely); {
    // 生成 marking != 0 分支的 Ideal 节点
} __ end_if();
kit->final_sync(ideal);
```

每个 `if_then` / `else_` / `end_if` 实际上都在创建 `IfNode`、`IfTrueNode`、`IfFalseNode`、`RegionNode` 等 Ideal 图节点，将屏障逻辑编织到整个方法的 Ideal 图中。

### 4.2 Pre-Barrier：SATB 快照记录

**源码**: `g1BarrierSetC2.cpp:175-275`

#### 4.2.1 编译时消除检查

在构建屏障之前，C2 首先尝试**编译期消除**：

```cpp
if (do_load) {
    if (use_ReduceInitialCardMarks()
        && g1_can_remove_pre_barrier(kit, &kit->gvn(), adr, bt, alias_idx)) {
        return;  // 编译期证明不需要 pre-barrier
    }
} else {
    if (pre_val->bottom_type() == TypePtr::NULL_PTR) return;  // 已知为 NULL
}
```

- `marking != 0` 标注为 `unlikely (0.001)`：绝大多数时间不在并发标记阶段
- `index != 0` 标注为 `likely (0.999)`：SATB 缓冲区满的概率极低

这些概率影响编译后代码布局：unlikely 分支会被放到远处（cold code），减少 icache 压力。

```
LOAD  [card_addr]           ← 读卡状态
```

- 将卡值设为 0（dirty_card_val）
- 带有对 `oop_store` 的内存依赖，确保顺序正确
- 使用 `AliasIdxRaw` 避免与堆内存别名分析混淆

## 5. C2 屏障消除优化

C2 的一大优势是能在编译期**证明某些屏障不需要**，从而完全消除屏障代码。这分为两个阶段：

### 5.1 图构建阶段：can_remove 系列

#### 5.1.1 g1_can_remove_pre_barrier()

**源码**: `g1BarrierSetC2.cpp:86-172`

**核心思路**: 如果能证明被覆盖的字段值**一定是 NULL**（对象刚分配，字段从未被写过），则不需要 SATB 记录。

**算法**:

```
1. 获取写入地址的 base 和 offset
2. 通过 Ideal_allocation() 找到 base 对应的 AllocateNode
3. 如果没找到 AllocateNode → 不能消除（返回 false）
4. 从当前内存状态 mem 开始，沿内存链向上走（最多 50 步）：
   a. 如果遇到 StoreNode：
      - 同 base + 同 offset → 说明之前写过这个字段 → 不能消除
      - 不同 offset 且无重叠 → 独立写入 → 继续向上
      - 不同 base 且可证明独立 → 继续向上
   b. 如果遇到 Initialize 节点且对应同一个 AllocateNode：
      - 检查 captured_store：如果为 NULL 或 zero_memory → 字段确实是 NULL → 可以消除！
   c. 其他情况（Call 等不透明节点）→ 不能消除
```

**50 步限制**: 为了防止编译开销失控，最多沿内存链回溯 50 步。超过 50 步仍未到达 Initialize 节点就放弃消除。

#### 5.1.2 g1_can_remove_post_barrier()

**源码**: `g1BarrierSetC2.cpp:306-335`

**核心思路**: 如果 store 紧跟在同一个对象的 Initialize 之后（即对象构造函数中的首次字段写入），且对象还在 Eden 中，则不需要 post-barrier。

```cpp
bool G1BarrierSetC2::g1_can_remove_post_barrier(...) const {
    // 获取 base 的 AllocateNode
    AllocateNode* alloc = AllocateNode::Ideal_allocation(base, phase);
    if (alloc == NULL) return false;

    // 检查 store 的控制输入是否直接来自 Initialize
    Node* mem = store->in(MemNode::Control);
    if (mem->is_Proj() && mem->in(0)->is_Initialize()) {
        InitializeNode* st_init = mem->in(0)->as_Initialize();
        if (alloc == st_init->allocation()) {
            return true;  // store 直接跟在同一 alloc 的 Initialize 之后
        }
    }
    return false;
}
```

**比 pre_barrier 的消除简单得多**: 只检查一层 —— store 的控制输入直接来自 Initialize。这是因为 Eden 中的对象不需要 RSet 跟踪（年轻代整体扫描），但这个条件很严格：控制输入必须**直接**来自 Initialize。

### 5.2 宏扩展阶段：eliminate_gc_barrier()

**源码**: `g1BarrierSetC2.cpp:658-737`

在 Ideal 图优化的后期（`PhaseMacroExpand`），当发现某个 `AllocateNode` 可以被标量替换或消除时，其关联的屏障代码也需要消除。`eliminate_gc_barrier()` 被调用来消除已经构建好的屏障节点模式。

#### 5.2.1 Post-Barrier 消除

搜索 `CastP2X → XorX → URShiftX → CmpX` 模式：

```cpp
Node* xorx = node->find_out_with(Op_XorX);
if (xorx != NULL) {
    Node* shift = xorx->unique_out();
    Node* cmpx = shift->unique_out();
    // 将 CmpX 替换为 CC_EQ（始终相等 → 条件永假 → 屏障分支被消除）
    macro->replace_node(cmpx, macro->makecon(TypeInt::CC_EQ));
```

将跨 Region 比较结果替换为 `CC_EQ`（始终相等），意味着 `ne` 条件永远不成立 → 整个 post-barrier 分支变成死代码，被后续 DCE Pass 清除。

#### 5.2.2 Pre-Barrier 消除

在消除 post-barrier 的同时，查找关联的 pre-barrier 标记检查：

```cpp
if (this_region->is_Region() && this_region->req() == 3) {
    // 查找 "if (marking != 0)" 的 CmpI 节点
    // 验证：load from thread+marking_offset, compared with 0
    if (adr->is_AddP() && adr->in(AddPNode::Base) == macro->top() &&
        adr->in(AddPNode::Address)->Opcode() == Op_ThreadLocal &&
        adr->in(AddPNode::Offset) == macro->MakeConX(marking_offset)) {
        // 将 marking 比较也替换为 CC_EQ → pre-barrier 也被消除
        macro->replace_node(cmpx, macro->makecon(TypeInt::CC_EQ));
    }
}
```

**识别模式**: 查找 Region 节点的 IfFalse 输入 → If 节点 → Bool (ne) → Cmp → Load → AddP(top, ThreadLocal, marking_offset)。如果匹配，说明这是一个 SATB marking 检查，替换为常量 CC_EQ。

#### 5.2.3 Object.clone() 路径消除

当没有 XorX 节点时（说明是 clone() 的简化 post-barrier），搜索 `CastP2X → URShiftX → AddP → LoadB → Cmp` 模式：

```cpp
Node* shift = node->find_out_with(Op_URShiftX);
Node* addp = shift->unique_out();
Node* load = addp->find_out_with(Op_LoadB);
Node* cmpx = load->unique_out();
macro->replace_node(cmpx, macro->makecon(TypeInt::CC_EQ));
```

最终，CastP2X 节点本身也被替换为 top（死节点）：
```cpp
macro->replace_node(node, macro->top());
```

### 5.3 step_over_gc_barrier()

**源码**: `g1BarrierSetC2.cpp:739-772`

当 C2 需要识别循环中的归纳变量或做控制流简化时，屏障代码可能干扰分析。`step_over_gc_barrier()` 允许优化 Pass "跨过" 屏障代码的 Region/CallLeaf 节点，直接看到屏障之前的控制流：

```

    // 查找 Region 中包含 write_ref_field_post_entry 调用的路径
    // 如果找到，返回另一条路径的前驱节点
}
```

这主要用于 `!ReduceInitialCardMarks` 的情况下（默认 ReduceInitialCardMarks=true 所以这个路径很少走到）。

## 6. 引用类型的特殊处理

### 6.1 问题：Reference.referent 字段

`java.lang.ref.Reference` 的 `referent` 字段需要特殊处理。当读取这个字段时，如果 G1 正在并发标记，需要将读到的值记录到 SATB 缓冲区，防止引用处理（Reference Processing）阶段遗漏活跃对象。

这涉及到 **load barrier**，而不是通常的 **store barrier**。

### 6.2 C1: load_at_resolved()

**源码**: `g1BarrierSetC1.cpp:178-200`

```cpp
void G1BarrierSetC1::load_at_resolved(LIRAccess& access, LIR_Opr result) {
    bool is_weak = (decorators & ON_WEAK_OOP_REF) != 0;
    bool is_phantom = (decorators & ON_PHANTOM_OOP_REF) != 0;
    bool is_anonymous = (decorators & ON_UNKNOWN_OOP_REF) != 0;

    // 先执行正常的 load
    BarrierSetC1::load_at_resolved(access, result);

    // 对弱/幻象/未知引用加 SATB pre-barrier
    if (access.is_oop() && (is_weak || is_phantom || is_anonymous)) {
        if (is_anonymous) {
            // 需要运行时检查是否真的是 Reference 子类
            generate_referent_check(access, Lcont_anonymous);
        }
        // 用已加载的 result 作为 pre_val（do_load = false）
        pre_barrier(access, illegalOpr, result, info);
    }
}
```

三种修饰符的含义：
- `ON_WEAK_OOP_REF`: `WeakReference.referent`、`SoftReference.referent` — 编译时已知
- `ON_PHANTOM_OOP_REF`: `PhantomReference.referent` — 编译时已知
- `ON_UNKNOWN_OOP_REF`: 通过 `Unsafe.getObject()` 等途径访问，可能是也可能不是 referent 字段 — 需要运行时守卫

### 6.3 C2: load_at_resolved() 和 insert_pre_barrier()

**源码**: `g1BarrierSetC2.cpp:595-641`

C2 的处理更精细：

```cpp
Node* G1BarrierSetC2::load_at_resolved(C2Access& access, const Type* val_type) const {
    Node* load = CardTableBarrierSetC2::load_at_resolved(access, val_type);

    bool need_read_barrier = in_heap && (on_weak ||
                                          (unknown && offset != kit->top() && obj != kit->top()));
    if (!access.is_oop() || !need_read_barrier) return load;

    if (on_weak) {
        // 已知是弱引用 → 直接加 pre-barrier + MemBarCPUOrder
        pre_barrier(kit, false, kit->control(), NULL, NULL, max_juint, NULL, NULL, load, T_OBJECT);
        kit->insert_mem_bar(Op_MemBarCPUOrder);
    } else if (unknown) {
        // 未知引用 → 需要运行时守卫
        insert_pre_barrier(kit, obj, offset, load, !need_cpu_mem_bar);
    }
    return load;
}
```

**insert_pre_barrier()** (`g1BarrierSetC2.cpp:499-591`) 用于 `ON_UNKNOWN_OOP_REF` 的情况，生成两层运行时守卫：

```
; 编译时过滤
if (offset 是常量且不等于 referent_offset) → 直接返回
if (base 类型是数组) → 直接返回
if (base 类型已加载且不是 Reference 子类) → 直接返回

; 运行时守卫
if (offset == referent_offset) {            ← unlikely
    if (instanceof(base, Reference)) {      ← unlikely
        pre_barrier(load);                  ← 记录到 SATB
        if (need_mem_bar):
            insert_mem_bar(Op_MemBarCPUOrder);
    }
}
```

**MemBarCPUOrder**: 防止对 referent 字段的读取被跨 safepoint 合并。GC 可能在 safepoint 时修改 referent（如 Reference Processing 清理弱引用），如果 load 被提升到 safepoint 之前，可能读到陈旧的值。

## 7. x86 汇编层：解释器共用的屏障实现

### 7.1 g1_write_barrier_pre() 详解

**源码**: `g1BarrierSetAssembler_x86.cpp:142-259`

这是解释器使用的 SATB pre-barrier 汇编实现。C1 的 runtime stub 和这段代码逻辑相同但独立生成。

```asm
g1_write_barrier_pre(obj, pre_val, thread, tmp, tosca_live, expand_call):
    ; ============================================
    ; 步骤 1: 检查 marking 是否激活
    ; ============================================
    ; obj != noreg → 需要从 [obj] 加载旧值
    ; obj == noreg → pre_val 已包含旧值
    
    cmpb [thread + satb_mark_queue_active_offset], 0   ; 1 字节比较
    je done                                             ; 未在标记 → 结束
    
    ; ============================================
    ; 步骤 2: 加载旧值（如果需要）
    ; ============================================
    if (obj != noreg):
        load_heap_oop pre_val, [obj + 0]    ; 从字段加载旧值（处理压缩指针）
    
    ; ============================================
    ; 步骤 3: NULL 检查
    ; ============================================
    cmp pre_val, NULL
    je done                                  ; 旧值为 NULL → 不需要记录
    
    ; ============================================
    ; 步骤 4: SATB 缓冲区快路径
    ; ============================================
    mov tmp, [thread + satb_mark_queue_index]  ; index
    cmp tmp, 0
    je runtime                               ; index == 0 → 队列满
    
    sub tmp, 8                               ; index -= wordSize
    mov [thread + satb_mark_queue_index], tmp ; 更新 index
    add tmp, [thread + satb_mark_queue_buffer]; tmp = buffer + index
    mov [tmp], pre_val                       ; buffer[index] = pre_val
    jmp done
    
runtime:
    ; ============================================
    ; 步骤 5: 慢路径 → 调用运行时函数
    ; ============================================
    if (tosca_live) push rax        ; 保存可能被覆盖的寄存器
    if (obj != noreg) push obj
    if (pre_val != rax) push pre_val
    
    ; expand_call = true 时直接生成 call 指令（不检查 last_sp）
    ; expand_call = false 时通过 call_VM_leaf 生成
    call write_ref_field_pre_entry(pre_val, thread)
    
    if (pre_val != rax) pop pre_val
    if (obj != noreg) pop obj
    if (tosca_live) pop rax
    
done:
```

**expand_call 参数**: 当从非解释器栈帧调用时（如 Reference.get() 内联），ebp 可能指向调用者栈帧，此时 `InterpreterMacroAssembler::call_VM_leaf_base` 中的 `last_sp` 检查会失败。`expand_call = true` 绕过这个检查。

### 7.2 g1_write_barrier_post() 详解

**源码**: `g1BarrierSetAssembler_x86.cpp:261-347`

```asm
g1_write_barrier_post(store_addr, new_val, thread, tmp, tmp2):
    ; ============================================
    ; 步骤 1: 跨 Region 检测
    ; ============================================
    mov tmp, store_addr
    xor tmp, new_val
    shr tmp, 22                ; LogOfHRGrainBytes = 22 (Region = 4MB)
    je done                    ; 同一 Region → 不需要更新 RSet
    
    ; ============================================
    ; 步骤 2: NULL 检查
    ; ============================================
    cmp new_val, NULL
    je done                    ; 写入 NULL → 不需要更新 RSet
    
    ; ============================================
    ; 步骤 3: 计算卡地址
    ; ============================================
    mov card_addr, store_addr
    shr card_addr, 9           ; CardTable::card_shift = 9（512 字节/卡）
    mov cardtable, byte_map_base  ; 卡表基地址（运行时常量）
    add card_addr, cardtable   ; card_addr = &card_table[store_addr >> 9]
    
    ; ============================================
    ; 步骤 4: Young Card 检查
    ; ============================================
    cmpb [card_addr], g1_young_card_val  ; young_card_val 通常 = 4
    je done                              ; 年轻代卡 → 跳过（整体扫描）
    
    ; ============================================
    ; 步骤 5: StoreLoad 内存屏障
    ; ============================================
    mfence                     ; 确保 store 可见后才 load card
    
    ; ============================================
    ; 步骤 6: Dirty Card 检查
    ; ============================================
    cmpb [card_addr], dirty_card_val     ; dirty_card_val = 0
    je done                              ; 已脏 → 不重复入队
    
    ; ============================================
    ; 步骤 7: 标脏并入队
    ; ============================================
    movb [card_addr], dirty_card_val     ; 写脏
    
    ; DCQ 快路径
    cmp [thread + dirty_card_queue_index], 0
    je runtime                           ; 队列满
    
    sub [thread + dirty_card_queue_index], 8
    mov tmp2, [thread + dirty_card_queue_buffer]
    movslq rscratch1, [thread + dirty_card_queue_index]  ; 符号扩展（LP64）
    add tmp2, rscratch1
    mov [tmp2], card_addr                ; buffer[index] = card_addr
    jmp done
    
runtime:
    push store_addr
    push new_val
    call write_ref_field_post_entry(card_addr, thread)
    pop new_val
    pop store_addr
    
done:
```

### 7.3 oop_store_at()：解释器的完整写入序列

**源码**: `g1BarrierSetAssembler_x86.cpp:349-408`

```
oop_store_at(dst, val, ...):
    ; 1. 计算目标地址
    lea tmp1, [dst]  或  mov tmp1, dst.base
    
    ; 2. Pre-barrier
    if (as_normal):
        g1_write_barrier_pre(tmp1/*obj*/, tmp2/*pre_val*/, thread, tmp3, ...)
    
    ; 3. 实际存储（处理压缩指针）
    if (val == noreg):
        store NULL → [tmp1]
    else:
        if (UseCompressedOops):
            new_val = tmp2; mov new_val, val  ; 保存未压缩版本
        store val → [tmp1]                     ; 可能压缩
    
    ; 4. Post-barrier（需要未压缩的 new_val 做跨 Region 检测）
    if (val != noreg && in_heap):
        g1_write_barrier_post(tmp1/*store_addr*/, new_val, thread, tmp3, tmp2)
```

注意压缩指针的处理：G1 的跨 Region 检测需要**未压缩**的指针（因为 XOR 后右移比较的是完整地址的高位）。如果启用了 `UseCompressedOops`，在 store 之前保存一份未压缩的 `new_val` 给 post-barrier 使用。

## 8. 运行时慢路径

### 8.1 write_ref_field_pre_entry()

**源码**: `g1BarrierSetRuntime.cpp:48-56`

```cpp
JRT_LEAF(void, G1BarrierSetRuntime::write_ref_field_pre_entry(oopDesc* orig, JavaThread *thread))
    if (orig == NULL) {
        assert(false, "should be optimized out");
        return;
    }
    assert(oopDesc::is_oop(orig, true), "Error");
    G1ThreadLocalData::satb_mark_queue(thread).enqueue(orig);
JRT_END
```

**JRT_LEAF**: 标记为 "leaf" 调用 —— 不需要 safepoint 检查、不需要切换到 VM 线程，直接在当前线程执行。

`enqueue(orig)` 做的事情：
1. 如果线程本地的 SATB 缓冲区还有空间 → 直接入队（但这个路径通常已在汇编快路径中处理）
2. 如果满了 → 将当前缓冲区提交到全局的 `SATBMarkQueueSet`，分配新缓冲区，再入队

### 8.2 write_ref_field_post_entry()

**源码**: `g1BarrierSetRuntime.cpp:59-61`

```cpp
JRT_LEAF(void, G1BarrierSetRuntime::write_ref_field_post_entry(void* card_addr, JavaThread* thread))
    G1ThreadLocalData::dirty_card_queue(thread).enqueue(card_addr);
JRT_END
```

将脏卡地址入队到线程本地的 DCQ（Dirty Card Queue）。当 DCQ 满时，提交到全局 `DirtyCardQueueSet`，触发 Concurrent Refinement 线程处理。

### 8.3 数组复制的屏障

**源码**: `g1BarrierSetRuntime.cpp:32-45`

数组复制（`System.arraycopy`）有专门的批量屏障：

```cpp
write_ref_array_pre_oop_entry(oop* dst, size_t length)   // Pre: 记录目标区域的旧值
write_ref_array_post_entry(HeapWord* dst, size_t length)  // Post: 标脏目标区域的所有卡
```

这些由 `G1BarrierSetAssembler::gen_write_ref_array_pre/post_barrier()` 调用，在 arraycopy stub 的前后插入。

## 9. 解释器 vs C1 vs C2 屏障对比

### 9.1 总体对比表

| 特征 | 解释器 | C1 | C2 |
|------|--------|----|----|
| **代码形式** | 固定汇编模板 | LIR + Stub + Runtime Blob | Ideal 图节点 |
| **优化程度** | 无优化 | 基本过滤 | 全局优化 + 消除 |
| **常量 NULL 消除** | ✗ | ✓ (编译时) | ✓ (编译时) |
| **新分配对象消除** | ✗ | ✗ | ✓ (can_remove + just_allocated) |
| **初始化写消除** | ✗ | ✗ | ✓ (g1_can_remove_pre/post) |
| **SATB/Post 宏消除** | ✗ | ✗ | ✓ (eliminate_gc_barrier) |
| **代码布局** | 线性 | 快路径内联 + 慢路径 stub | 编译器决定 hot/cold |
| **cross-region 检测** | XOR+Shift（汇编） | XOR+Shift（LIR） | XOR+Shift（Ideal 图，可优化） |
| **SATB 快路径** | 内联 | 在 blob 中 | 内联（Ideal 图展开） |
| **DCQ 快路径** | 内联 | 在 blob 中 | 内联（Ideal 图展开） |
| **mfence** | 始终 | 始终 | 仅 card != young 时 |
| **Reference.referent** | load_at() 中处理 | load_at_resolved() | load_at_resolved() + insert_pre_barrier() |

### 9.2 性能影响分析

**解释器**: 每次引用写入都执行完整的 pre + store + post，无任何跳过。在解释模式下开销显著。

**C1**: 快路径很短（marking 检查 + XOR+Shift），大部分情况直接 fall through。Stub 和 blob 是 cold code，对 icache 友好。但不做编译期消除。

**C2**:
- 大量 barrier 在编译期就被消除（特别是构造函数中的初始化写入）
- 未消除的 barrier 被嵌入 Ideal 图，参与全局优化（公共子表达式消除、循环提升等）
- `unlikely` 概率标注让热路径最短
- `mfence` 只在必要时出现

在典型的分配密集型应用中，C2 编译后的屏障开销可以比解释器降低 **50-80%**。

## 12. 设计哲学总结

### 12.1 分层设计（JEP 304）

```
抽象层:  BarrierSet / BarrierSetC1 / BarrierSetC2
                    │
模板方法: ModRef 层 → store_at_resolved() 定义 pre→store→post 框架
                    │
具体实现: G1 层 → 实现 SATB pre-barrier 和跨 Region post-barrier
                    │
平台相关: x86 Assembler 层 → 生成实际的机器码
```

每一层只关心自己的职责：
- **BarrierSet** 抽象层定义接口
- **ModRef** 层定义"引用修改需要前后屏障"的模板
- **G1** 层实现 SATB + RSet 的具体逻辑
- **x86** 层处理寄存器分配、内存屏障指令等平台细节

### 12.2 快慢路径分离

所有层级都遵循同一设计模式：
1. **编译时过滤**：常量 NULL、新分配对象、同 Region（C2 最强）
2. **运行时快路径**：marking 检查、SATB/DCQ 直接入队
3. **运行时慢路径**：队列满时调用 `JRT_LEAF` 函数

这种设计使**99%+ 的引用写入**在快路径就完成，只有极少数走到慢路径。

### 12.3 正确性保证

- **SATB 二次检查**: C1 blob 中再次检查 marking 标志，防止跨 safepoint 后标记已停止
- **mfence**: 确保 store 可见后才检查 card 状态，避免 lost update
- **CastP2X + ctrl**: 防止整数化的指针穿越 safepoint
- **storeCM 内存依赖**: 确保 card mark 不被重排序到 store 之前
