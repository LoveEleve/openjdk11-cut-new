## 1. 调优方法论

### 1.1 调优黄金法则

```
┌─────────────────────────────────────────────────────────────────┐
│                     G1 调优黄金法则                              │
└─────────────────────────────────────────────────────────────────┘

1. 先监控，后调优
   └── 不了解现状的调优是盲目的

2. 一次只改一个参数
   └── 便于定位问题，避免相互干扰

3. 从基础参数开始
   └── -Xms/-Xmx → MaxGCPauseMillis → 其他

4. 验证后再上线
   └── 压测环境验证，逐步灰度

5. 持续监控
   └── 调优不是一次性工作，需要持续关注
```

```

    └──────────────┬───────────────────────┘

    ┌──────────────────────────────────────┐
    │ 2. 识别瓶颈                          │
    │   - 暂停时间过长？                    │
    │   - 吞吐下降？                        │
```

## 2. 场景一：低延迟应用 (< 100ms)

### 2.1 场景特点

- **应用类型**：API 网关、交易服务、实时计算
- **SLA 要求**：P99 延迟 < 100ms
- **核心诉求**：最小化 GC 暂停时间

### 2.2 调优策略

```
┌─────────────────────────────────────────────────────────────────┐
│                    低延迟调优策略                                │
└─────────────────────────────────────────────────────────────────┘

1. 收紧暂停时间目标
   └── MaxGCPauseMillis=100

2. 提前触发并发标记
   └── InitiatingHeapOccupancyPercent=35
   └── 避免堆满导致的长时间暂停

3. 控制年轻代大小
   └── G1NewSizePercent=20, G1MaxNewSizePercent=30
   └── 限制单次 Young GC 工作量

4. 增加 Mixed GC 回收效率
   └── G1MixedGCLiveThresholdPercent=80
   └── 只回收垃圾最多的 Region

5. 增大堆浪费容忍度
   └── G1HeapWastePercent=10
   └── 减少 Mixed GC 频率
```

### 2.3 推荐配置

```bash
# 基础配置
-Xms8g -Xmx8g \
-XX:+UseG1GC \
-XX:MaxGCPauseMillis=100 \

# 年轻代控制
-XX:G1NewSizePercent=20 \
-XX:G1MaxNewSizePercent=30 \

# 并发标记触发
-XX:InitiatingHeapOccupancyPercent=35 \
-XX:+G1UseAdaptiveIHOP \

# Mixed GC 优化
-XX:G1MixedGCLiveThresholdPercent=80 \
-XX:G1OldCSetRegionThresholdPercent=5 \
-XX:G1HeapWastePercent=10 \

# RSet 优化（如果跨 Region 引用多）
-XX:G1RSetUpdatingPauseTimePercent=20 \

# 日志配置
-Xlog:gc*:file=/var/log/gc.log:time,uptime,level,tags:filecount=10,filesize=100m \
-Xlog:gc+phases=debug \
-Xlog:safepoint=debug
```

### 2.4 预期效果

| 指标 | 调优前 | 调优后 |
|-----|-------|-------|
| Young GC 平均暂停 | 30-50ms | 20-30ms |
| Young GC 最大暂停 | 80-150ms | 50-80ms |
| Mixed GC 暂停 | 60-100ms | 40-70ms |
| Full GC 频率 | 每周数次 | 每月 < 1 次 |

## 3. 场景二：高吞吐应用

### 3.1 场景特点

- **应用类型**：批处理、数据分析、后台服务
- **SLA 要求**：最大化吞吐量
- **核心诉求**：减少 GC 总时间，提高 CPU 利用率

### 3.2 调优策略

```
┌─────────────────────────────────────────────────────────────────┐
│                    高吞吐调优策略                                │
└─────────────────────────────────────────────────────────────────┘

1. 放宽暂停时间目标
   └── MaxGCPauseMillis=500
   └── GCTimeRatio=19 (允许 5% GC 时间)

2. 增大年轻代
   └── 让 Young GC 更少但更久
   └── 提高 CPU 利用率

3. 减少 Mixed GC 频率
   └── G1HeapWastePercent=15
   └── 容忍更多垃圾，减少回收频率

4. 提高 IHOP，延迟标记
   └── InitiatingHeapOccupancyPercent=50
   └── 减少并发标记次数

5. 增大并发标记步骤时长
   └── G1ConcMarkStepDurationMillis=20
   └── 减少步骤切换开销
```

### 3.3 推荐配置

```bash
# 基础配置
-Xms32g -Xmx32g \
-XX:+UseG1GC \
-XX:MaxGCPauseMillis=500 \
-XX:GCTimeRatio=19 \

# 年轻代配置（较大）
-XX:G1NewSizePercent=15 \
-XX:G1MaxNewSizePercent=45 \

# 延迟并发标记
-XX:InitiatingHeapOccupancyPercent=50 \
-XX:+G1UseAdaptiveIHOP \

# 减少 Mixed GC 频率
-XX:G1HeapWastePercent=15 \
-XX:G1MixedGCCountTarget=4 \

# 并发标记优化
-XX:G1ConcMarkStepDurationMillis=20 \

# 日志配置
-Xlog:gc*:file=/var/log/gc.log:time,uptime,level,tags:filecount=10,filesize=200m
```

### 3.4 预期效果

| 指标 | 调优前 | 调优后 |
|-----|-------|-------|
| GC 时间占比 | 8-12% | 3-5% |
| 吞吐量 | 基准 | +10-20% |
| GC 频率 | 高 | 降低 30-50% |
| 平均暂停 | 30ms | 80ms |

## 4. 场景三：大堆应用 (> 32GB)

### 4.1 场景特点

- **堆大小**：32GB - 数百 GB
- **挑战**：元数据开销大、标记时间长、Region 数量多
- **核心诉求**：高效管理大堆，控制元数据开销

### 4.2 调优策略

```
┌─────────────────────────────────────────────────────────────────┐
│                    大堆调优策略                                  │
└─────────────────────────────────────────────────────────────────┘

1. 增大 Region 大小
   └── G1HeapRegionSize=16m (或 32m)
   └── 减少 Region 数量，降低元数据开销

2. 调整年轻代比例
   └── G1NewSizePercent=10, G1MaxNewSizePercent=40
   └── 绝对值增大，但比例降低

3. 增加 Mixed GC 次数
   └── G1MixedGCCountTarget=16
   └── 分散老年代回收压力

4. 预触达辅助内存
   └── G1PretouchAuxiliaryMemory=true
   └── 避免运行时 page fault

5. 渐进堆扩展
   └── G1ExpandByPercentOfAvailable=10
```

### 4.3 推荐配置

```bash
# 基础配置
-Xms64g -Xmx64g \
-XX:+UseG1GC \
-XX:MaxGCPauseMillis=200 \

# 大 Region
-XX:G1HeapRegionSize=16m \

# 年轻代配置
-XX:G1NewSizePercent=10 \
-XX:G1MaxNewSizePercent=40 \

# Mixed GC 配置
-XX:G1MixedGCCountTarget=16 \
-XX:G1MixedGCLiveThresholdPercent=85 \
-XX:G1OldCSetRegionThresholdPercent=10 \

# 大对象优化
-XX:+G1EagerReclaimHumongousObjects \
-XX:+G1EagerReclaimHumongousObjectsWithStaleRefs \

# 性能优化
-XX:+G1PretouchAuxiliaryMemory \
-XX:G1ExpandByPercentOfAvailable=10 \

# 并发标记
-XX:InitiatingHeapOccupancyPercent=40 \
-XX:ConcGCThreads=8 \

# 日志配置
-Xlog:gc*:file=/var/log/gc.log:time,uptime,level,tags:filecount=20,filesize=500m \
-Xlog:gc+phases=debug \
-Xlog:gc+region=debug
```

### 4.4 64GB 堆配置示例

| 参数 | 值 | 说明 |
|-----|---|------|
| Region 大小 | 16MB | 共 4096 个 Region |
| 年轻代最小 | 6.4GB (10%) | G1NewSizePercent=10 |
| 年轻代最大 | 25.6GB (40%) | G1MaxNewSizePercent=40 |
| Humongous 阈值 | 8MB | RegionSize/2 |
| 并发标记线程 | 8 | 根据 CPU 调整 |

## 5. 场景四：容器化部署

### 5.1 场景特点

- **环境**：Docker / Kubernetes
- **限制**：内存限制、CPU 限制
- **核心诉求**：在资源受限环境下稳定运行

### 5.2 调优策略

```
┌─────────────────────────────────────────────────────────────────┐
│                    容器环境调优策略                              │
└─────────────────────────────────────────────────────────────────┘

1. 启用容器支持
   └── UseContainerSupport=true
   └── 自动识别容器资源限制

2. 使用 MaxRAMPercentage
   └── 替代 -Xmx，更容器友好

3. 降低保留空间
   └── G1ReservePercent=5
   └── 提高内存利用率

4. 控制堆扩展
   └── G1ExpandByPercentOfAvailable=10
   └── 避免触及容器内存限制

5. 日志输出到 stdout
   └── 方便日志收集
```

### 5.3 推荐配置

```bash
# 基础配置（K8s 限制 4GB 内存）
-XX:+UseContainerSupport \
-XX:MaxRAMPercentage=75.0 \
-XX:+UseG1GC \
-XX:MaxGCPauseMillis=100 \

# 内存优化
-XX:G1ReservePercent=5 \
-XX:G1ExpandByPercentOfAvailable=10 \
-XX:G1HeapWastePercent=10 \

# 年轻代
-XX:G1NewSizePercent=20 \
-XX:G1MaxNewSizePercent=35 \

# 并发标记
-XX:InitiatingHeapOccupancyPercent=40 \

# 日志输出到 stdout
-Xlog:gc:stdout:time,uptime,level,tags
```

### 5.4 K8s Deployment 示例

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  template:
    spec:
      containers:
      - name: app
        image: my-app:latest
        resources:
          requests:
            memory: "4Gi"
            cpu: "2"
          limits:
            memory: "4Gi"
            cpu: "2"
        env:
        - name: JAVA_OPTS
          value: |
            -XX:+UseContainerSupport
            -XX:MaxRAMPercentage=75.0
            -XX:+UseG1GC
            -XX:MaxGCPauseMillis=100
            -XX:G1ReservePercent=5
            -Xlog:gc:stdout:time,uptime,level,tags
```

## 6. 场景五：大对象密集型

### 6.1 场景特点

- **应用类型**：缓存服务、大数据处理、图像处理
- **特征**：频繁分配 > 2MB 的大对象
- **核心诉求**：减少 Humongous 对象带来的碎片和 GC 压力

### 6.2 调优策略

```
┌─────────────────────────────────────────────────────────────────┐
│                   大对象场景调优策略                             │
└─────────────────────────────────────────────────────────────────┘

1. 增大 Region 大小
   └── G1HeapRegionSize=8m (或更大)
   └── 提高 Humongous 阈值，减少大对象数量

2. 确保积极回收开启
   └── G1EagerReclaimHumongousObjects=true
   └── 在 Young GC 回收死亡大对象

3. 提前触发标记
   └── InitiatingHeapOccupancyPercent=35
   └── 避免老年代过快填满

4. 优化 Mixed GC
   └── 更快回收老年代，释放大对象空间
```

### 6.3 推荐配置

```bash
# 基础配置
-Xms16g -Xmx16g \
-XX:+UseG1GC \
-XX:MaxGCPauseMillis=200 \

# 大 Region，提高 Humongous 阈值到 4MB
-XX:G1HeapRegionSize=8m \

# 大对象积极回收
-XX:+G1EagerReclaimHumongousObjects \
-XX:+G1EagerReclaimHumongousObjectsWithStaleRefs \

# 提前触发标记
-XX:InitiatingHeapOccupancyPercent=35 \

# Mixed GC 优化
-XX:G1MixedGCLiveThresholdPercent=80 \
-XX:G1OldCSetRegionThresholdPercent=10 \

# 监控 Humongous
-Xlog:gc+humongous=debug
```

## 7. 场景六：高并发写入

### 7.1 场景特点

- **应用类型**：消息队列、写入密集型服务
- **特征**：高频率对象创建，大量跨 Region 引用
- **核心诉求**：减少写屏障和 RSet 更新开销

### 7.2 调优策略

```
┌─────────────────────────────────────────────────────────────────┐
│                   高并发写入调优策略                             │
└─────────────────────────────────────────────────────────────────┘

1. 增加 Refine 线程
   └── G1ConcRefinementThreads=16
   └── 加快脏卡处理

2. 调整三色阈值
   └── 提高 Red Zone，避免 mutator 处理

3. 增大 Update RS 暂停时间占比
   └── G1RSetUpdatingPauseTimePercent=20
   └── 在暂停期间处理更多脏卡

4. 增大 RSet 容量
   └── G1RSetRegionEntries=1024
   └── 减少 Coarse 模式使用
```

### 7.3 推荐配置

```bash
# 基础配置
-Xms16g -Xmx16g \
-XX:+UseG1GC \
-XX:MaxGCPauseMillis=200 \

# Refine 线程优化
-XX:G1ConcRefinementThreads=16 \
-XX:G1RSetUpdatingPauseTimePercent=20 \

# RSet 配置
-XX:G1RSetRegionEntries=1024 \
-XX:G1RSetSparseRegionEntries=16 \

# 年轻代（快速回收新对象）
-XX:G1NewSizePercent=25 \
-XX:G1MaxNewSizePercent=35 \

# 三色阈值（激进）
-XX:G1ConcRefinementGreenZone=32 \
-XX:G1ConcRefinementYellowZone=96 \
-XX:G1ConcRefinementRedZone=160 \

# 监控 RSet
-XX:G1SummarizeRSetStatsPeriod=1 \
-Xlog:gc+remset=debug
```

## 8. 综合调优案例

### 8.1 案例背景

**应用**：电商订单服务
**问题**：
- P99 延迟 200ms+，不满足 SLA (< 100ms)
- 每天 3-5 次 Full GC
- 高峰期频繁 Mixed GC

**环境**：
- 16 核 64GB 内存
- 堆大小：32GB
- JDK 11

### 8.2 现状分析

```
GC 日志分析结果：

Young GC:
- 平均暂停: 45ms
- 最大暂停: 120ms  
- 频率: 8-10 次/分钟

Mixed GC:
- 平均暂停: 80ms
- 最大暂停: 180ms
- 频率: 2-3 次/分钟

Full GC:
- 平均暂停: 2-5s
- 频率: 3-5 次/天

问题识别：
1. MaxGCPauseMillis=200 过于宽松
2. IHOP=45，标记触发太晚
3. 年轻代占比过高 (平均 50%)
4. Mixed GC 选择 Region 过多
```

### 8.3 调优过程

**第一步：收紧暂停时间**

```bash
-XX:MaxGCPauseMillis=100
```
效果：Young GC 最大暂停从 120ms 降到 80ms

**第二步：调整年轻代**

```bash
-XX:G1NewSizePercent=15
-XX:G1MaxNewSizePercent=30
```
效果：年轻代更稳定，减少大 Young GC

**第三步：提前触发标记**

```bash
-XX:InitiatingHeapOccupancyPercent=35
```
效果：Full GC 频率从每天 3-5 次降到每周 1 次

**第四步：优化 Mixed GC**

```bash
-XX:G1MixedGCLiveThresholdPercent=80
-XX:G1OldCSetRegionThresholdPercent=5
-XX:G1HeapWastePercent=10
```
效果：Mixed GC 暂停从 80ms 降到 50ms

### 8.4 最终配置

```bash
#!/bin/bash
# 电商订单服务 GC 配置

JAVA_OPTS="
-Xms32g -Xmx32g
-XX:+UseG1GC
-XX:MaxGCPauseMillis=100
-XX:GCTimeRatio=9

# 年轻代
-XX:G1NewSizePercent=15
-XX:G1MaxNewSizePercent=30

# 并发标记
-XX:InitiatingHeapOccupancyPercent=35
-XX:+G1UseAdaptiveIHOP

# Mixed GC
-XX:G1MixedGCLiveThresholdPercent=80
-XX:G1OldCSetRegionThresholdPercent=5
-XX:G1HeapWastePercent=10
-XX:G1MixedGCCountTarget=8

# RSet
-XX:G1RSetUpdatingPauseTimePercent=15

# 大对象
-XX:+G1EagerReclaimHumongousObjects
-XX:+G1EagerReclaimHumongousObjectsWithStaleRefs

# 日志
-Xlog:gc*:file=/var/log/order-service/gc.log:time,uptime,level,tags:filecount=20,filesize=200m
-Xlog:gc+phases=debug:file=/var/log/order-service/gc-phases.log:filecount=10,filesize=100m
-XX:+HeapDumpOnOutOfMemoryError
-XX:HeapDumpPath=/var/log/order-service/heapdump.hprof
"

java $JAVA_OPTS -jar order-service.jar
```

### 8.5 调优效果

| 指标 | 调优前 | 调优后 | 改善 |
|-----|-------|-------|-----|
| Young GC P99 | 80ms | 35ms | -56% |
| Young GC Max | 120ms | 60ms | -50% |
| Mixed GC P99 | 100ms | 45ms | -55% |
| Mixed GC Max | 180ms | 75ms | -58% |
| Full GC | 3-5次/天 | 0-1次/周 | -95% |
| P99 延迟 | 200ms | 80ms | -60% |
| 吞吐量 | 基准 | +8% | +8% |

## 9. 参数组合速查表

### 9.1 按场景快速选择

| 场景 | 核心参数组合 |
|-----|-------------|
| **低延迟** | `MaxGCPauseMillis=100` + `IHOP=35` + `G1NewSizePercent=20` |
| **高吞吐** | `MaxGCPauseMillis=500` + `GCTimeRatio=19` + `G1HeapWastePercent=15` |
| **大堆** | `G1HeapRegionSize=16m` + `G1PretouchAuxiliaryMemory` + `G1MixedGCCountTarget=16` |
| **容器** | `UseContainerSupport` + `MaxRAMPercentage=75` + `G1ReservePercent=5` |
| **大对象** | `G1HeapRegionSize=8m` + `G1EagerReclaimHumongousObjects` + `IHOP=35` |
| **高并发写入** | `G1ConcRefinementThreads=16` + `G1RSetUpdatingPauseTimePercent=20` |

### 9.2 参数优先级

```
┌─────────────────────────────────────────────────────────────────┐
│                      参数优先级                                 │
└─────────────────────────────────────────────────────────────────┘

必须配置（影响最大）：
├── -Xms/-Xmx (固定堆大小)
├── MaxGCPauseMillis (暂停目标)
```
