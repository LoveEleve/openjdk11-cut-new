## 1. Humongous 对象基础

### 1.1 什么是 Humongous 对象

**定义**：在 G1 中，当一个对象的大小超过 Region 大小的一半时，被定义为 Humongous（巨型）对象。

```cpp
// src/hotspot/share/gc/g1/g1CollectedHeap.hpp:1252-1254

// Returns the humongous threshold for a specific region size
static size_t humongous_threshold_for(size_t region_size) {
    return (region_size / 2);
}
```

**不同 Region 大小下的 Humongous 阈值**：

| Region 大小 | Humongous 阈值 (>=) | 典型场景 |
|------------|-------------------|---------|
| 1MB | 512KB | 小对象为主 |
| 2MB | 1MB | |
| **4MB** | **2MB** | **标准环境** |
| 8MB | 4MB | |
| 16MB | 8MB | 大堆应用 |
| 32MB | 16MB | 超大堆 |

### 1.2 Humongous 对象分配方式

```
┌─────────────────────────────────────────────────────────────────┐
│                    Humongous 对象内存布局                        │
└─────────────────────────────────────────────────────────────────┘

单个 Region 可容纳的 Humongous 对象：
┌──────────────────────────────────────────────────────────────┐
│                    StartsHumongous Region                    │
│  ┌──────────────────────────────────────────────────────┐    │
│  │         Humongous Object (size <= RegionSize)        │    │
│  │                                                      │    │
│  └──────────────────────────────────────────────────────┘    │
│                           ┌──────────────┐                   │
│                           │   Filler     │ (可能)            │
│                           │   Object     │                   │
│                           └──────────────┘                   │
└──────────────────────────────────────────────────────────────┘

跨多个 Region 的 Humongous 对象：
┌──────────────────┬──────────────────┬──────────────────┐
│  StartsHumongous │ ContinuesHumongous│ ContinuesHumongous│
│     Region       │     Region 1      │     Region 2      │
├──────────────────┼──────────────────┼──────────────────┤
│ ┌──────────────┐ │ ┌──────────────┐ │ ┌──────────────┐ │
│ │   Object     │ │ │   Object     │ │ │   Object     │ │
│ │    Part 1    │ │ │    Part 2    │ │ │    Part 3    │ │
│ └──────────────┘ │ └──────────────┘ │ └──────────────┘ │
│      ...         │      ...         │   ┌──────────┐   │
│                  │                  │   │  Filler  │   │
│                  │                  │   └──────────┘   │
└──────────────────┴──────────────────┴──────────────────┘
```

### 1.3 Humongous 对象的特点与问题

**特点**：
1. **直接分配到老年代**：Humongous 对象直接在老年代分配，不经过 Eden
2. **连续 Region 分配**：需要连续的 Region，可能导致内存碎片
3. **特殊回收机制**：默认只在 Full GC 时回收，除非开启积极回收
4. **无 RSet 优化**：Humongous Region 的 RSet 管理与普通 Region 不同

**潜在问题**：

| 问题 | 说明 | 影响 |
|-----|-----|-----|
| 内存碎片 | 需要连续 Region，可能触发提前 GC | 堆利用率下降 |
| 分配失败 | 找不到足够连续 Region | 触发 Full GC |
| 回收延迟 | 默认只在 Full GC 回收 | 大对象长期占用内存 |

## 2. 大对象回收参数

### 2.1 参数总览

| 参数 | 默认值 | 说明 | 调优建议 |
|-----|-------|------|---------|
| `G1EagerReclaimHumongousObjects` | true | 在 Young GC 时积极回收死亡的大对象 | 建议开启 |
| `G1EagerReclaimHumongousObjectsWithStaleRefs` | true | 允许回收有陈旧引用的大对象 | 建议开启 |

### 2.2 参数定义

```cpp
// src/hotspot/share/gc/g1/g1_globals.hpp:253-258

experimental(bool, G1EagerReclaimHumongousObjects, true,
        "Try to reclaim dead large objects at every young GC.")

experimental(bool, G1EagerReclaimHumongousObjectsWithStaleRefs, true,
        "Try to reclaim dead large objects that have a few stale "
        "references at every young GC.")
```

### 2.3 积极回收机制详解

**关键源码**：`src/hotspot/share/gc/g1/g1CollectedHeap.cpp:3283-3288`

```cpp
// 判断 Humongous Region 是否可以被回收
bool can_reclaim_humongous_region(HeapRegion* r) {
    HeapRegionRemSet* rem_set = r->rem_set();
    
    // G1EagerReclaimHumongousObjectsWithStaleRefs=true:
    // 只要 RSet 占用率不超过 Sparse 阈值即可回收
    return G1EagerReclaimHumongousObjectsWithStaleRefs ?
           rem_set->occupancy_less_or_equal_than(G1RSetSparseRegionEntries) :
           // G1EagerReclaimHumongousObjectsWithStaleRefs=false:
           // RSet 必须完全为空
           G1EagerReclaimHumongousObjects && rem_set->is_empty();
}
```

**回收条件对比**：

| 参数组合 | 回收条件 | 适用场景 |
|---------|---------|---------|
| `Eager=true, StaleRefs=false` | RSet 完全为空 | 保守回收 |
| `Eager=true, StaleRefs=true` | RSet 占用率 <= Sparse 阈值 | 积极回收（推荐） |
| `Eager=false` | 只在 Full GC 回收 | 不推荐 |

### 2.4 积极回收流程图

```
┌─────────────────────────────────────────────────────────────────┐
│                   Young GC 积极回收大对象流程                    │
└─────────────────────────────────────────────────────────────────┘

        Young GC 开始
              │
              ▼
    ┌───────────────────┐
    │ 注册 Humongous    │  (Humongous Register)
    │ Region 到 CSet    │  - 遍历所有 Humongous Region
    └─────────┬─────────┘  - 检查是否为回收候选
              │
              ▼
    ┌───────────────────┐
    │ 检查回收候选条件  │  
    │                   │  is_candidate_for_reclaim()?
    │ ┌───────────────┐ │
    │ │1. G1Eager     │ │  true
    │ │   Reclaim开启 │ ├──────────────────┐
    │ └───────────────┘ │                  │
    │ ┌───────────────┐ │                  ▼
    │ │2. 对象已死亡   │ │      ┌───────────────────────┐
    │ │   (bitmap未标记)│       │ 加入回收集合          │
    │ └───────────────┘ │      │ (humongous_candidates)│
    │ ┌───────────────┐ │      └───────────┬───────────┘
    │ │3. RSet 条件   │ │                  │
    │ │   满足        │ │                  ▼
    │ └───────────────┘ │      ┌───────────────────────┐
    └───────────────────┘      │ 执行回收              │
              │                │ (Humongous Reclaim)   │
              │ false          │ - 释放 Region         │
              ▼                │ - 清理 RSet           │
    ┌───────────────────┐      │ - 重置 Card Table     │
    │ 不回收            │      └───────────┬───────────┘
    │ 等待 Full GC      │                  │
    └───────────────────┘                  ▼
                                  继续 Young GC 流程
```

## 3. 堆扩展参数

### 3.1 参数总览

| 参数 | 默认值 | 说明 | 调优建议 |
|-----|-------|------|---------|
| `G1ExpandByPercentOfAvailable` | 20 | 堆扩展时占可用空间的比例 | 大堆可适当降低 |

### 3.2 参数定义

```cpp
// src/hotspot/share/gc/g1/g1_globals.hpp:107-109

experimental(intx, G1ExpandByPercentOfAvailable, 20,
        "When expanding, % of uncommitted space to claim.")
        range(0, 100)
```

### 3.3 工作机制

```
┌─────────────────────────────────────────────────────────────────┐
│                     G1 堆扩展策略                                │
└─────────────────────────────────────────────────────────────────┘

当堆需要扩展时：

扩展量 = min(未提交空间, 扩展请求量)
         
实际扩展量 = 扩展量 × G1ExpandByPercentOfAvailable / 100

示例：
- 当前堆大小：4GB
- 最大堆大小：8GB
- 未提交空间：4GB
- 需要扩展：1GB
- G1ExpandByPercentOfAvailable = 20

实际扩展 = min(4GB, 1GB) × 20% = 200MB
```

### 3.4 调优建议

| 堆大小 | 建议值 | 说明 |
|-------|-------|-----|
| < 8GB | 20 (默认) | 快速响应扩展需求 |
| 8-32GB | 15 | 平衡扩展速度和内存分配 |
| > 32GB | 10 | 大堆渐进扩展，避免内存抖动 |

## 4. 其他特殊场景参数

### 4.1 辅助内存预触达

| 参数 | 默认值 | 说明 | 调优建议 |
|-----|-------|------|---------|
| `G1PretouchAuxiliaryMemory` | false | 预触达大辅助数据结构 | 大堆且需要稳定延迟时开启 |

```cpp
// src/hotspot/share/gc/g1/g1_globals.hpp:250-251

experimental(bool, G1PretouchAuxiliaryMemory, false,
        "Pre-touch large auxiliary data structures used by the GC.")
```

**说明**：
- 启动时预触达 G1 的辅助数据结构（如 Remembered Set、Card Table 等）
- 避免运行时的 page fault 导致延迟毛刺
- 增加启动时间，但提高运行时稳定性

### 4.2 保留内存百分比

回顾之前的基础参数：

| 参数 | 默认值 | 说明 | 大堆调优建议 |
|-----|-------|------|-------------|
| `G1ReservePercent` | 10 | 堆保留空间百分比 | 可降至 5-8 |

**大堆场景**：
```bash
# 64GB 堆示例
-XX:G1ReservePercent=5  # 保留 3.2GB 而非 6.4GB
```

## 5. 源码深度解析

### 5.1 Humongous 对象分配源码

```cpp
// src/hotspot/share/gc/g1/g1CollectedHeap.cpp

// 判断是否为 Humongous 对象
bool G1CollectedHeap::is_humongous(size_t word_size) {
    return word_size >= _humongous_object_threshold_in_words;
}

// Humongous 对象分配入口
HeapWord* G1CollectedHeap::allocate_humongous(size_t word_size) {
    // 1. 计算需要的 Region 数量
    uint num_regions = (uint)((word_size + HeapRegion::GrainWords - 1) 
                             / HeapRegion::GrainWords);
    
    // 2. 分配连续的 StartsHumongous + ContinuesHumongous Region
    HeapRegion* first_region = alloc_humongous_regions(num_regions);
    
    // 3. 初始化 Region 类型
    first_region->set_humongous_start();
    for (uint i = 1; i < num_regions; i++) {
        HeapRegion* cont_region = region_at(first_region->hrm_index() + i);
        cont_region->set_humongous_continuation();
    }
    
    return first_region->bottom();
}
```

### 5.2 积极回收实现源码

```cpp
// src/hotspot/share/gc/g1/g1CollectedHeap.cpp:5362-5400

void G1CollectedHeap::eagerly_reclaim_humongous_regions() {
    assert_at_safepoint_on_vm_thread();
    
    // 快速路径：如果没有候选区域，直接返回
    if (!G1EagerReclaimHumongousObjects ||
        (!_has_humongous_reclaim_candidates && !log_is_enabled(Debug, gc, humongous))) {
        g1_policy()->phase_times()->record_fast_reclaim_humongous_time_ms(0.0, 0);
        return;
    }
    
    double start_time = os::elapsedTime();
    uint reclaimed_count = 0;
    
    // 遍历所有 Humongous Region
    for (uint i = 0; i < _hrm->length(); i++) {
        HeapRegion* r = _hrm->at(i);
        
        if (r->is_starts_humongous() && is_candidate_for_reclaim(r)) {
            // 回收该 Humongous 对象占用的所有 Region
            reclaim_humongous_region_chain(r);
            reclaimed_count++;
        }
    }
    
    double end_time = os::elapsedTime();
    g1_policy()->phase_times()->record_fast_reclaim_humongous_time_ms(
        (end_time - start_time) * 1000.0, reclaimed_count);
}
```

### 5.3 Humongous 对象与 RSet

```cpp
// Humongous Region 的 RSet 特点：

// 1. StartsHumongous Region 有完整的 RSet
// 2. ContinuesHumongous Region 的 RSet 指向 StartsHumongous
// 3. 跨 Region 引用只记录在 StartsHumongous 的 RSet 中

class HeapRegion {
    // 对于 Humongous Continuation Region
    // RSet 操作会转发到对应的 StartsHumongous Region
    HeapRegionRemSet* rem_set() {
        if (is_continues_humongous()) {
            return humongous_start_region()->rem_set();
        }
        return _rem_set;
    }
};
```

## 6. 实战调优场景

### 6.1 场景一：应用产生大量临时大对象

**症状**：
- GC 日志显示大量 Humongous 分配
- 老年代快速填满，频繁触发 Mixed GC

**诊断**：
```bash
# 查看 Humongous 分配情况
-Xlog:gc+humongous=debug
```

**调优方案**：

```bash
# 确保积极回收已开启（默认开启）
-XX:+G1EagerReclaimHumongousObjects
-XX:+G1EagerReclaimHumongousObjectsWithStaleRefs

# 增大 Region 大小，减少 Humongous 对象数量
-XX:G1HeapRegionSize=8m  # 阈值变为 4MB

# 调整 IHOP，提前开始标记
-XX:InitiatingHeapOccupancyPercent=35
```

### 6.2 场景二：大对象分配导致内存碎片

**症状**：
- 有足够总内存但分配 Humongous 对象失败
- 频繁触发 Full GC

**诊断**：
```bash
# 查看 Region 分布
-Xlog:gc+region=debug
```

**调优方案**：

```bash
# 增大 Region 大小
-XX:G1HeapRegionSize=16m

# 增加堆保留空间，确保有大块连续空间
-XX:G1ReservePercent=15

# 调整 Mixed GC 存活率阈值，更快回收老年代
-XX:G1MixedGCLiveThresholdPercent=75
```

### 6.3 场景三：大堆启动慢，需要稳定延迟

**症状**：
- 大堆（64GB+）启动时间长
- 初期出现延迟毛刺

**调优方案**：

```bash
# 预触达辅助内存
-XX:+G1PretouchAuxiliaryMemory

# 渐进堆扩展
-XX:G1ExpandByPercentOfAvailable=10

# 固定堆大小，避免扩展
-Xms64g -Xmx64g

# 大 Region 减少元数据开销
-XX:G1HeapRegionSize=16m
```

### 6.4 场景四：容器环境内存限制

**症状**：
- 在 K8s/Docker 中运行时 OOM
- 实际堆使用未达限制但被 Kill

**调优方案**：

```bash
# 降低保留空间百分比
-XX:G1ReservePercent=5

# 启用容器感知
-XX:+UseContainerSupport

# 限制堆扩展速度
-XX:G1ExpandByPercentOfAvailable=10

# 设置最大堆为容器限制的 75%
-XX:MaxRAMPercentage=75.0
```

### 6.5 参数配置对照表

| 场景 | G1HeapRegionSize | G1EagerReclaimHumongousObjects | G1ReservePercent | G1ExpandByPercentOfAvailable |
|-----|-----------------|--------------------------------|-----------------|------------------------------|
| 默认 | 自动 | true | 10 | 20 |
| 大量临时大对象 | 8m+ | true | 10 | 20 |
| 内存碎片问题 | 16m+ | true | 15 | 15 |
| 大堆稳定延迟 | 16m | true | 10 | 10 |
| 容器环境 | 自动 | true | 5 | 10 |

### 7.5 常见问题诊断

| 问题 | 可能原因 | 解决方案 |

| Humongous 回收率低 | 大对象实际存活 | 检查对象生命周期 |
