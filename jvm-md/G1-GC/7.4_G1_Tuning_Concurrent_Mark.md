## 1. 并发标记基础参数

### 1.1 参数总览

| 参数 | 默认值 | 说明 | 调优建议 |
|-----|-------|------|---------|
| `G1ConcMarkStepDurationMillis` | 10.0 | 单个并发标记步骤目标时长 | 降低可提高响应性，但增加总标记时间 |
| `G1ConcRefinementServiceIntervalMillis` | 300 | Refine 线程唤醒间隔 | 通常无需调整 |

### 1.2 参数定义

```cpp
        "The last concurrent refinement thread wakes up every "

```

### 1.3 G1ConcMarkStepDurationMillis 工作机制

**关键源码**：`src/hotspot/share/gc/g1/g1ConcurrentMark.cpp:938-940`


**工作原理**：

```
└─────────────────────────────────────────────────────────────────┘

         │
         ▼
    ┌─────────┐
    │ 记录开始 │

    └────┬────┘
         │
         ▼
    ┌─────────┐     超过      ┌─────────┐

    │         │   Millis     │          │
    └────┬────┘              └─────────┘
         │
         │ 时间未到且
         │ 队列不为空
         └───────────────┐

                    ┌─────────┐

                    │ 下一个对象│
                    └─────────┘
```

**调优影响**：

| 参数值 | 优点 | 缺点 | 适用场景 |
|-------|-----|-----|---------|
| 较小 (5ms) | 更好的应用响应性，更短的每次停顿 | 总标记时间更长，更多步骤切换开销 | 低延迟应用 |
| 默认 (10ms) | 平衡响应性和效率 | - | 大多数场景 |
| 较大 (20ms+) | 更短的总标记时间，更少上下文切换 | 单次占用 CPU 时间长，可能影响响应 | 高吞吐应用 |

### 2.3 SATB 机制回顾

**Snapshot-At-The-Beginning (SATB)** 是 G1 并发标记的核心算法：

```
┌─────────────────────────────────────────────────────────────────────┐
│                        SATB 工作原理                                │
└─────────────────────────────────────────────────────────────────────┘

并发标记周期开始 (Initial Mark)
         │
         ▼
    创建堆快照 (Snapshot)
    记录所有存活对象的"快照"
         │
         ▼
┌─────────────────────────────────────────────────────────────────────┐
│  应用线程执行期间：                                                  │
│                                                                     │
│  写屏障 (Pre-Write Barrier) 拦截引用修改：                          │
│                                                                     │
│  Object x = obj.field;  // 读取旧值                                │
│  [SATB 屏障记录旧值到缓冲区]                                         │
│  obj.field = new_value; // 写入新值                                │
│                                                                     │
│  目的：确保并发标记期间被修改的引用关联的对象不会被漏标               │
└─────────────────────────────────────────────────────────────────────┘
         │
         ▼
    并发标记处理 SATB 队列
    标记被记录的对象为存活
         │
         ▼
    Remark 暂停处理剩余 SATB 队列
```

### 2.4 SATB 缓冲区管理机制

**关键源码**：`src/hotspot/share/gc/g1/satbMarkQueue.cpp:153-170`

```cpp
bool SATBMarkQueue::should_enqueue_buffer() {
    // 先执行过滤，移除已经标记的对象
    filter();
    
    size_t cap = capacity();
    size_t percent_used = ((cap - index()) * 100) / cap;
    
    // 如果使用率超过阈值（默认60%），则将缓冲区入队
    bool should_enqueue = percent_used > G1SATBBufferEnqueueingThresholdPercent;
    return should_enqueue;
}
```

**过滤机制说明**：

```
┌──────────────────────────────────────────────────────────────┐
│                    SATB 缓冲区过滤                           │
└──────────────────────────────────────────────────────────────┘

原始缓冲区（已满）
┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
│ A   │ B   │ C   │ D   │ E   │ F   │ G   │ H   │ I   │ J   │  10 个条目
│已标记│未标记│已标记│已标记│未标记│未标记│已标记│未标记│已标记│未标记│
└─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
         │
         │ filter() - 移除已标记的对象
         ▼
过滤后缓冲区
┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
│ B   │ E   │ F   │ H   │ J   │     │     │     │     │     │  5 个有效条目
└─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘

使用率 = 5/10 = 50%
与阈值（60%）比较：50% < 60% → 不入队，直接复用缓冲区
```

### 2.5 G1SATBBufferSize 内存影响

| 参数值 | 每个缓冲区大小 | 100 线程总内存（100 个缓冲区） | 适用场景 |
|-------|--------------|---------------------------|---------|
| 1K (默认) | 8KB (1K × 8 字节指针) | ~800KB | 大多数场景 |
| 2K | 16KB | ~1.6MB | 高并发引用修改 |
| 4K | 32KB | ~3.2MB | 极端写入密集型 |

**调优建议**：
- 默认 1K 适用于大多数场景
- 如果观察到频繁的 SATB 缓冲区分配（日志中出现大量 SATB enqueue），可适当增大
- 增大缓冲区会减少入队频率，但会增加单次处理时间

### 3.3 工作机制

**关键源码**：`src/hotspot/share/gc/g1/g1ConcurrentMark.cpp:1509-1530`

```cpp
class G1CMKeepAliveAndDrainClosure : public OopClosure {
    G1ConcurrentMark* _cm;
    G1CMTask* _task;
    uint _ref_counter_limit;  // G1RefProcDrainInterval
    uint _ref_counter;
    
public:
    G1CMKeepAliveAndDrainClosure(G1ConcurrentMark* cm, G1CMTask* task, bool is_serial) :
        _cm(cm), _task(task), _is_serial(is_serial),
        _ref_counter_limit(G1RefProcDrainInterval) {
        _ref_counter = _ref_counter_limit;
    }
    
    virtual void do_oop(narrowOop* p) { do_oop_work(p); }
    virtual void do_oop(oop* p) { do_oop_work(p); }
    
    template <class T> void do_oop_work(T* p) {
        // 处理引用...
        
        // 每处理 G1RefProcDrainInterval 个引用，
        // 就 drain（处理）一次并发标记队列
        if (--_ref_counter == 0) {
            _task->drain_local_queue(true);  // 处理本地队列
            _ref_counter = _ref_counter_limit;
        }
    }
};
```

**处理流程图**：

```

│                  引用处理与队列 draining                         │
└─────────────────────────────────────────────────────────────────┘

发现引用对象（Soft/Weak/Phantom）
         │
         ▼
    ┌─────────┐
    │ 处理引用 │ ◀────────────────────────────┐
    │ 对象    │                              │
    └────┬────┘                              │
         │                                   │
         │ 计数器减 1                         │
         ▼                                   │
    ┌─────────┐     计数器 > 0               │
    │计数器=0?│──────────────────────────────┤
    └────┬────┘                              │
         │ 计数器 == 0                        │
         ▼                                   │
    ┌─────────┐                              │
    │ Drain   │                              │
    │ 本地队列 │                              │
    │         │  避免队列积压                  │
    └────┬────┘                              │
         │                                   │
         │ 重置计数器                          │
         │ 计数器 = G1RefProcDrainInterval    │
         │                                   │
         └───────────────────────────────────┘
```

**调优影响**：

| 参数值 | 效果 | 适用场景 |
|-------|-----|---------|
| 较小 (500) | 更频繁地 draining，防止队列积压 | 大量引用对象 |
| 默认 (1000) | 平衡 | 大多数场景 |
| 较大 (5000) | 减少 draining 开销，但队列可能积压 | 引用对象较少 |

## 5. 源码深度解析

### 5.1 并发标记任务执行流程

```cpp
// src/hotspot/share/gc/g1/g1ConcurrentMark.cpp:920-957

class G1CMConcurrentMarkingTask : public AbstractGangTask {
    G1ConcurrentMark* _cm;

public:
    void work(uint worker_id) {
        ResourceMark rm;
        double start_vtime = os::elapsedVTime();
        
        {
            SuspendibleThreadSetJoiner sts_join;  // 加入可暂停线程集
            
            G1CMTask* task = _cm->task(worker_id);
            task->record_start_time();
            
            if (!_cm->has_aborted()) {
                do {
                    // 执行标记步骤，目标时长 10ms
                    task->do_marking_step(G1ConcMarkStepDurationMillis,
                                          true  /* do_termination */,
                                          false /* is_serial */);
                    
                    _cm->do_yield_check();  // 检查是否需要让出 CPU
                    
                } while (!_cm->has_aborted() && task->has_aborted());
            }
            
            task->record_end_time();
        }
        
        double end_vtime = os::elapsedVTime();
        _cm->update_accum_task_vtime(worker_id, end_vtime - start_vtime);
    }
};
```

### 5.2 标记步骤详细实现

```cpp
// 简化的 do_marking_step 逻辑

void G1CMTask::do_marking_step(double mark_step_duration_ms,
                               bool do_termination,
                               bool is_serial) {
    
    double start_time_ms = os::elapsedVTime() * MILLIUNITS;
    
    // 1. 处理本地队列中的对象
    while (!has_aborted() && !local_queue_empty()) {
        oop obj = pop_from_local_queue();
        scan_object(obj);  // 扫描对象引用
        
        // 检查是否超过目标时间
        double elapsed_ms = os::elapsedVTime() * MILLIUNITS - start_time_ms;
        if (elapsed_ms >= mark_step_duration_ms) {
            set_has_aborted(true);
            return;
        }
    }
    
    // 2. 从全局队列获取工作
    if (!has_aborted()) {
        steal_work_from_other_tasks();  // 工作窃取
    }
    
    // 3. 终止协议（同步所有线程）
    if (do_termination) {
        termination_protocol();
    }
}
```

### 5.3 SATB 写屏障实现

```cpp
// SATB (Snapshot-At-The-Beginning) 写屏障

void satb_write_barrier_pre(oop* field, oop new_value) {
    // 只在并发标记阶段且 SATB 队列激活时执行
    if (!SATBMarkQueueSet::is_active()) return;
    
    // 读取旧值
    oop old_value = *field;
    if (old_value == NULL) return;
    
    // 将旧值加入 SATB 队列
    JavaThread* thread = JavaThread::current();
    SATBMarkQueue& queue = G1ThreadLocalData::satb_mark_queue(thread);
    
    // 如果缓冲区已满，执行过滤并可能入队
    if (!queue.is_full()) {
        queue.enqueue(old_value);
    } else {
        handle_full_satb_buffer(queue);
    }
}
```

## 6. 实战调优场景

### 6.1 场景一：并发标记时间过长

**症状**：
- GC 日志显示 `Concurrent Mark` 阶段耗时很长
- 应用整体吞吐量下降

**诊断**：
```bash
# 查看详细标记日志
-Xlog:gc+marking=debug
```

**调优方案**：

```bash
# 增加并发标记线程数
-XX:ConcGCThreads=4

# 减少每个步骤的时间（让出更多 CPU 给应用）
-XX:G1ConcMarkStepDurationMillis=5

# 或者相反：增加每个步骤时间，减少总步骤数
-XX:G1ConcMarkStepDurationMillis=20
```

### 6.2 场景二：Remark 暂停时间过长

**症状**：
- GC 日志显示 `Remark` 阶段停顿时间长
- 通常是因为 SATB 队列积压

**诊断**：
```bash
# 查看 SATB 队列处理情况
-Xlog:gc+marking=trace
```

**调优方案**：

```bash
# 增大 SATB 缓冲区，减少入队频率
-XX:G1SATBBufferSize=2048

# 降低入队阈值，让更多缓冲区被过滤后复用
-XX:G1SATBBufferEnqueueingThresholdPercent=50

# 增加并发标记线程，加快 SATB 处理
-XX:ConcGCThreads=4
```

### 6.3 场景三：大量引用对象导致标记慢

**症状**：
- 应用使用大量 SoftReference/WeakReference
- 并发标记阶段 CPU 使用率高但进展慢

**调优方案**：

```bash
# 减少引用处理间隔，更频繁地 draining 标记队列
-XX:G1RefProcDrainInterval=500

# 同时检查引用处理参数
-XX:+ParallelRefProcEnabled  # 并行处理引用
```

### 6.4 场景四：低延迟要求的标记优化

**症状**：
- 并发标记期间应用响应时间波动

**调优方案**：

```bash
# 激进的步骤时长控制
-XX:G1ConcMarkStepDurationMillis=3

# 增加标记线程数
-XX:ConcGCThreads=4

# 提前触发标记，避免堆满
-XX:InitiatingHeapOccupancyPercent=30

# 配合 RSet 调优
-XX:G1RSetUpdatingPauseTimePercent=20
```

### 6.5 参数配置对照表

| 场景 | G1ConcMarkStepDurationMillis | G1SATBBufferSize | ConcGCThreads | 备注 |
|-----|------------------------------|------------------|---------------|-----|
| 默认 | 10 | 1024 | 自动 | 适用于大多数场景 |
| 低延迟 | 3-5 | 2048 | 4+ | 更频繁的步骤切换 |
| 高吞吐 | 20 | 1024 | 自动 | 减少步骤切换开销 |
| 大量引用 | 10 | 1024 | 自动 | G1RefProcDrainInterval=500 |
| 大堆 | 10-15 | 2048 | 4+ | 大缓冲区减少入队频率 |

### 7.5 常见问题诊断

| 问题 | 可能原因 | 解决方案 |
|-----|---------|---------|
| Concurrent Mark 过长 | 步骤时间太短/线程太少 | 增加 ConcGCThreads 或 G1ConcMarkStepDurationMillis |
| Remark 停顿长 | SATB 队列积压 | 增大 G1SATBBufferSize，增加 ConcGCThreads |
| 标记阶段 CPU 高 | 正常行为 | 确认 G1ConcMarkStepDurationMillis 设置是否合理 |
| 频繁 GC 启动 | IHOP 设置不当 | 调整 InitiatingHeapOccupancyPercent |
