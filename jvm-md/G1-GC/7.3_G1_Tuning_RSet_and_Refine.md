## 1. RSet 内存配置参数

### 1.1 参数总览

| 参数 | 默认值 | 说明 | 调优建议 |
|-----|-------|------|---------|
| `G1RSetRegionEntries` | 0 (自动) | Fine 模式最大 Region 数 | 大堆且跨 Region 引用多可适当增大 |
| `G1RSetSparseRegionEntries` | 0 (自动) | Sparse 模式每个 Region 最大条目数 | 通常保持自动 |

### 1.2 参数定义与源码位置


### 1.3 动态计算公式

**关键源码**：`src/hotspot/share/gc/g1/heapRegionRemSet.cpp:632-641`


**内存占用估算（4MB Region）**：

- Sparse 模式：12 条目 × 8 字节 ≈ 96 字节

- Coarse 模式：2048 Region / 8 = 256 字节

## 2. 并发 Refine 线程配置

### 2.1 参数总览

| 参数 | 默认值 | 说明 | 调优建议 |
|-----|-------|------|---------|
| `G1ConcRefinementThreads` | 0 (自动) | Refine 线程数 | 通常等于 GC 线程数 |

### 2.3 Refine 线程数量计算

**关键源码**：`src/hotspot/share/gc/g1/g1ConcurrentRefine.cpp`

```cpp
    // G1ConcRefinementThreads = 0 时，使用自动计算
    if (FLAG_IS_DEFAULT(G1ConcRefinementThreads)) {
        // 默认等于 ParallelGCThreads
        return ParallelGCThreads;
    }
    return G1ConcRefinementThreads;
```

**实际配置示例**：

```bash

ConcGCThreads = 2      # 计算：ParallelGCThreads / 4
G1ConcRefinementThreads = 0  # 使用 ParallelGCThreads = 8

# 实际运行时

```

### 2.4 G1RSetUpdatingPauseTimePercent 工作机制

**关键源码**：`src/hotspot/share/gc/g1/g1Policy.cpp:768-775`

```cpp
// 计算 Update RS 时间目标
double update_rs_time_goal_ms = _mmu_tracker->max_gc_time() * 
                                MILLIUNITS * 
                                G1RSetUpdatingPauseTimePercent / 100.0;

// 示例：MaxGCPauseMillis=200ms，G1RSetUpdatingPauseTimePercent=10%
// update_rs_time_goal_ms = 200 * 1.0 * 10 / 100 = 20ms
```

**作用说明**：

- 控制 GC 暂停期间用于处理脏卡队列（Update RS）的时间比例
- 剩余时间用于对象复制（Evacuation）和 RSet 扫描
- 增大此值 → 暂停中处理更多脏卡 → 减少并发 Refine 线程负担
- 减小此值 → 更多脏卡留给并发 Refine 线程处理 → 可能延长 GC 暂停

## 3. 三色阈值机制

### 3.1 参数总览

| 参数 | 默认值 | 说明 | 调优建议 |
|-----|-------|------|---------|
| `G1ConcRefinementGreenZone` | 0 (自动) | 绿色阈值，Refine 线程正常工作 | 保持自动 |
| `G1ConcRefinementYellowZone` | 0 (自动) | 黄色阈值，逐渐激活 Refine 线程 | 保持自动 |
| `G1ConcRefinementRedZone` | 0 (自动) | 红色阈值，应用线程参与处理 | 保持自动 |

### 3.2 参数定义

```cpp
// src/hotspot/share/gc/g1/g1_globals.hpp:115-131

product(size_t, G1ConcRefinementYellowZone, 0,
        "Number of enqueued update buffers that will "
        "trigger concurrent processing. Will be selected ergonomically "
        "by default.")
        range(0, max_intx)

product(size_t, G1ConcRefinementRedZone, 0,
        "Maximum number of enqueued update buffers before mutator "
        "threads start processing new ones instead of enqueueing them. "
        "Will be selected ergonomically by default.")
        range(0, max_intx)

product(size_t, G1ConcRefinementGreenZone, 0,
        "The number of update buffers that are left in the queue by the "
        "concurrent processing threads. Will be selected ergonomically "
        "by default.")
        range(0, max_intx)
```

### 3.3 三色阈值计算公式

**关键源码**：`src/hotspot/share/gc/g1/g1ConcurrentRefine.cpp:245-275`

```cpp
// Green Zone 计算
static size_t calc_init_green_zone() {
    size_t green = G1ConcRefinementGreenZone;
    if (FLAG_IS_DEFAULT(G1ConcRefinementGreenZone)) {
        green = ParallelGCThreads;  // 默认等于 ParallelGCThreads
    }
    return MIN2(green, max_green_zone);
}

// Yellow Zone 计算
static size_t calc_init_yellow_zone(size_t green, size_t min_size) {
    size_t config = G1ConcRefinementYellowZone;
    size_t size = 0;
    if (FLAG_IS_DEFAULT(G1ConcRefinementYellowZone)) {
        size = green * 2;  // 默认 = green * 2
    } else if (green < config) {
        size = config - green;
    }
    size = MAX2(size, min_size);
    size = MIN2(size, max_yellow_zone);
    return MIN2(green + size, max_yellow_zone);
}

// Red Zone 计算
static size_t calc_init_red_zone(size_t green, size_t yellow) {
    size_t size = yellow - green;
    if (!FLAG_IS_DEFAULT(G1ConcRefinementRedZone)) {
        size_t config = G1ConcRefinementRedZone;
        if (yellow < config) {
            size = MAX2(size, config - yellow);
        }
    }
    return MIN2(yellow + size, max_red_zone);
}
```

### 3.4 计算示例（8 核机器）

| 参数 | 计算过程 | 结果 |
|-----|---------|-----|
| `ParallelGCThreads` | min(8, (8 + 3) / 4 取最大值) | 8 |
| `Green Zone` | 默认 = 8 | 8 |
| `min_yellow_zone_size` | G1ConcRefinementThresholdStep * max_num_threads = 2 * 8 | 16 |
| `Yellow Zone` | MAX2(green * 2, 16) = MAX2(16, 16) | 16 → green + size = 24 |
| `Red Zone` | yellow + (yellow - green) = 24 + 16 | 40 |

> **注意**：实际计算更复杂，涉及 `max_yellow_zone` 等限制

### 3.5 三色阈值工作机制图

```
脏卡队列缓冲区数量
│
│                                          ┌─────────────────┐
│                                          │   Red Zone      │
│                                          │  应用线程必须   │
│                              ┌───────────┤  参与处理脏卡   │
│                              │           │  (mutator处理)  │
│                  ┌───────────┴───────────┴─────────────────┤
│                  │           Yellow Zone                   │
│                  │      逐渐激活 Refine 线程               │
│      ┌───────────┴─────────────────────────────────────────┤
│      │                  Green Zone                        │
│      │            Refine 线程正常工作                      │
│      │         (保持此数量的缓冲区在队列中)                │
├──────┴─────────────────────────────────────────────────────┴──────
│
│
└──────────────────────────────────────────────────────────────────────► 时间

Refine 线程激活策略：
- 队列长度 ≤ Green Zone: 保持最低限度处理
- Green < 队列长度 ≤ Yellow: 逐个激活 Refine 线程
- Yellow < 队列长度 ≤ Red: 全速处理，所有线程激活
- 队列长度 > Red Zone: 应用线程被迫参与处理（性能下降）
```

### 3.6 线程激活阈值计算

**关键源码**：`src/hotspot/share/gc/g1/g1ConcurrentRefine.cpp:199-216`

```cpp
static Thresholds calc_thresholds(size_t green_zone,
                                  size_t yellow_zone,
                                  uint worker_i) {
    double yellow_size = yellow_zone - green_zone;
    double step = yellow_size / G1ConcurrentRefine::max_num_threads();
    
    if (worker_i == 0) {
        // Worker 0 更积极激活
        step = MIN2(step, ParallelGCThreads / 2.0);
    }
    
    size_t activate_offset = static_cast<size_t>(ceil(step * (worker_i + 1)));
    size_t deactivate_offset = static_cast<size_t>(floor(step * worker_i));
    
    return Thresholds(green_zone + activate_offset,
                      green_zone + deactivate_offset);
}
```

**示例（Green=8, Yellow=24, 8 个线程）**：

| Worker ID | 激活阈值 | 去激活阈值 | 说明 |
|----------|---------|-----------|-----|
| 0 | 8 + 1 = 9 | 8 + 0 = 8 | 最早激活，最迟去激活 |
| 1 | 8 + 2 = 10 | 8 + 1 = 9 | |
| 2 | 8 + 4 = 12 | 8 + 2 = 10 | |
| ... | ... | ... | |
| 7 | 8 + 16 = 24 | 8 + 14 = 22 | 最晚激活 |

### 4.1 G1ConcurrentRefine 类结构

```cpp
class G1ConcurrentRefine : public CHeapObj<mtGC> {
private:
    G1ConcurrentRefineThreadControl _thread_control;  // 线程控制器

    size_t _yellow_zone;  // 黄色阈值

public:

    // 根据缓冲区数量获取需要的线程数
    uint worker_id_for_num_cards(size_t num_cards) const;
    
    // 检查是否需要 mutator 线程处理
    bool should_mutator_process(size_t num_cards) const {
        return num_cards >= _red_zone;
    }
```

### 4.2 Refine 线程控制器

```cpp
// src/hotspot/share/gc/g1/g1ConcurrentRefine.cpp:52-91

class G1ConcurrentRefineThreadControl : public CHeapObj<mtGC> {
    G1ConcurrentRefine* _cr;
    G1ConcurrentRefineThread** _threads;  // 线程指针数组
    uint _num_max_threads;                // 最大线程数
    
public:
    // 初始化线程池
    jint initialize(G1ConcurrentRefine* cr, uint num_max_threads) {
        _num_max_threads = num_max_threads;
        _threads = NEW_C_HEAP_ARRAY(G1ConcurrentRefineThread*, num_max_threads, mtGC);
        
        // 动态线程创建策略
        for (uint i = 0; i < num_max_threads; i++) {
            if (UseDynamicNumberOfGCThreads && i != 0) {
                // 动态扩展：初始只创建第 0 个线程
                _threads[i] = NULL;
            } else {
                _threads[i] = create_refinement_thread(i, true);
            }
        }
    }
    
    // 激活下一个线程
    void maybe_activate_next(uint cur_worker_id);
};
```

## 5. 实战调优场景

### 5.1 场景一：高并发写入，RSet 成为瓶颈

**症状**：
- GC 日志显示 `Update RS` 时间过长
- 并发 Refine 线程 CPU 使用率高
- 应用线程偶尔被迫处理脏卡（"Red Zone" 触发）

**调优方案**：

```bash
# 增加 Refine 线程数
-XX:G1ConcRefinementThreads=16

# 增大 Update RS 暂停时间占比，让更多工作在暂停期间完成
-XX:G1RSetUpdatingPauseTimePercent=20

# 调整三色阈值（如果自动值不够）
-XX:G1ConcRefinementGreenZone=16
-XX:G1ConcRefinementYellowZone=48
-XX:G1ConcRefinementRedZone=80
```

### 5.2 场景二：跨 Region 引用极多，RSet 内存占用大

**症状**：
- 堆外内存占用高
- RSet 统计信息显示大量 Fine/Coarse 条目
- GC 暂停时间长（扫描 RSet）

**调优方案**：

```bash
# 增加 RSet 容量，减少 Coarse 模式使用
-XX:G1RSetRegionEntries=1024
-XX:G1RSetSparseRegionEntries=16

# 同时增加 Region 大小，减少 Region 数量
-XX:G1HeapRegionSize=8m
```

### 5.3 场景三：低延迟要求，避免应用线程处理脏卡

**症状**：
- 偶尔出现应用线程处理脏卡（mutator refinement）
- 应用响应时间出现毛刺

**调优方案**：

```bash
# 激进的阈值配置，确保 Red Zone 不会轻易触发
-XX:G1ConcRefinementGreenZone=32
-XX:G1ConcRefinementYellowZone=96
-XX:G1ConcRefinementRedZone=160

# 增加 Refine 线程，加快处理速度
-XX:G1ConcRefinementThreads=16

# 增加 Update RS 暂停时间占比
-XX:G1RSetUpdatingPauseTimePercent=25
```

### 5.4 场景四：大堆（64GB+）优化

**症状**：
- Region 数量多（16k+），RSet 开销大
- Mixed GC 扫描 RSet 时间长

**调优方案**：

```bash
# 增大 Region 大小，减少 Region 数量
-XX:G1HeapRegionSize=16m  # 或 32m

# 这将自动调整 G1RSetRegionEntries
# (256 * (log2(16M/1M) + 1) = 256 * 5 = 1280)

# 减少 Refine 线程（大堆通常写入频率较低）
-XX:G1ConcRefinementThreads=8

# 放宽 Update RS 时间占比
-XX:G1RSetUpdatingPauseTimePercent=15
```

### 5.5 参数配置对照表

| 场景 | G1ConcRefinementThreads | G1RSetUpdatingPauseTimePercent | G1RSetRegionEntries | 备注 |
|-----|------------------------|-------------------------------|--------------------|-----|
| 默认 | 0 (自动) | 10 | 0 (自动) | 适用于大多数场景 |
| 高并发写入 | 2×GCThreads | 20-25 | 0 (自动) | 增加并发处理能力 |
| 低延迟 | 1.5×GCThreads | 15-20 | 0 (自动) | 激进阈值配置 |
| 大堆 (64GB+) | 0.5×GCThreads | 15 | 1024+ | 大 Region，减少 RSet 数量 |
| 内存受限 | GCThreads | 5-8 | 512 | 减少 RSet 内存占用 |

| Mutator Refine 次数 | 日志/统计 | 接近 0 | 应用线程被迫处理次数 |
