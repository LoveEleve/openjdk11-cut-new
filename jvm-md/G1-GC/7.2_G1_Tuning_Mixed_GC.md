# G1 调优参数详解（二）：Mixed GC 调优

## 第五部分：并发标记触发（IHOP）

### 5.1 InitiatingHeapOccupancyPercent (IHOP)

#### 参数说明

```cpp
// g1_globals.hpp
product(uintx, InitiatingHeapOccupancyPercent, 45,
        "Percentage of the (entire) heap occupancy to start a concurrent "
        "marking cycle.")
        range(0, 100)
```

| 参数 | 默认值 | 范围 | 说明 |
|-----|-------|------|------|
| `InitiatingHeapOccupancyPercent` | 45 | 0-100% | 触发并发标记的堆占用率阈值 |

#### 作用机制

```
┌─────────────────────────────────────────────────────────────────┐
│                    IHOP 触发机制                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  堆内存使用情况                                                  │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  0%                                                     │   │
│  │  │                                                      │   │
│  │  │                                                      │   │
│  │  ▼                                                      │   │
│  │  年轻代 (Young)                                          │   │
│  │  │                                                      │   │
│  │  ▼                                                      │   │
│  │  Survivor                                                │   │
│  │  │                                                      │   │
│  │  ▼                                                      │   │
│  │  老年代 (Old)  ◄── 占用率达到 IHOP (45%)                 │   │
│  │  │                    ↓                                  │   │
│  │  │              触发并发标记                             │   │
│  │  │              Concurrent Mark Start                   │   │
│  │  ▼                                                      │   │
│  │  空闲                                                   │   │
│  │                                                      100% │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                  │
│  注意：IHOP 基于整个堆的占用率，不只是老年代！                   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

#### 源码分析

```cpp
// g1IHOPControl.hpp:94-97
// 静态 IHOP 计算
class G1StaticIHOPControl : public G1IHOPControl {
  size_t get_conc_mark_start_threshold() {
    // 计算触发阈值
    // _initial_ihop_percent = InitiatingHeapOccupancyPercent
    // _target_occupancy = 堆大小
    return (size_t) (_initial_ihop_percent * _target_occupancy / 100.0);
  }
};

// 8GB 堆示例
// IHOP = 45%，堆 = 8GB
// 触发阈值 = 45% * 8GB = 3.6GB
// 当堆占用达到 3.6GB 时，开始并发标记
```

#### 调优建议

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【IHOP 调优指南】

1. IHOP 的核心作用

   - 控制并发标记启动时机
   - 目标：在堆满之前完成标记，避免 Full GC
   - 平衡：启动太早（浪费资源）vs 启动太晚（Full GC）

2. 调优场景

   降低 IHOP（提前启动标记）：
   - 场景：老年代增长快，容易出现 Full GC
   - 配置：-XX:InitiatingHeapOccupancyPercent=35
   - 效果：提前开始标记，降低 Full GC 风险
   - 代价：更多并发标记开销
   
   提高 IHOP（推迟启动标记）：
   - 场景：内存充足，想减少并发标记开销
   - 配置：-XX:InitiatingHeapOccupancyPercent=55
   - 效果：减少并发标记次数
   - 代价：增加 Full GC 风险

3. IHOP 与 Full GC 的关系

   如果 IHOP 设置过高：
   - 并发标记开始时，老年代已接近满
   - 标记过程中，老年代可能溢出
   - 结果：触发 Full GC
   
   推荐策略：
   - 出现 Full GC 时，尝试降低 IHOP 5-10%
   - 直到 Full GC 消失或稳定

4. 计算示例

   8GB 堆，IHOP=45%：
   - 触发阈值 = 3.6GB
   - 并发标记需在剩余 4.4GB 用完前完成
   
   如果标记需要 2GB 空间：
   - 安全余量 = 4.4GB - 2GB = 2.4GB
   - 如果应用分配快，余量可能不足
   - 建议降低 IHOP 到 35%，增加余量

推荐配置：
  # 默认（推荐大多数场景）
  -XX:InitiatingHeapOccupancyPercent=45  ✅ 平衡
  
  # 容易出现 Full GC
  -XX:InitiatingHeapOccupancyPercent=35  ✅ 提前标记
  
  # 内存充足，减少并发开销
  -XX:InitiatingHeapOccupancyPercent=55  ✅ 推迟标记
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 5.2 自适应 IHOP (G1UseAdaptiveIHOP)

#### 参数说明

```cpp
// g1_globals.hpp:48-52
product(bool, G1UseAdaptiveIHOP, true,
        "Adaptively adjust the initiating heap occupancy from the "
        "initial value of InitiatingHeapOccupancyPercent. The policy "
        "attempts to start marking in time based on application "
        "behavior.")
```

| 参数 | 默认值 | 说明 |
|-----|-------|------|
| `G1UseAdaptiveIHOP` | true | 自适应调整 IHOP |

#### 自适应算法

```cpp
// g1IHOPControl.hpp:109-150
class G1AdaptiveIHOPControl : public G1IHOPControl {
  // 历史数据
  TruncatedSeq _marking_times_s;      // 标记耗时历史
  TruncatedSeq _allocation_rate_s;    // 分配速率历史
  
  size_t get_conc_mark_start_threshold() {
    // 基于预测计算最佳触发时机
    // 目标：在堆满之前刚好完成标记
    
    // 1. 预测标记耗时
    double predicted_marking_time = predict_marking_time();
    
    // 2. 预测分配速率
    double predicted_alloc_rate = predict_allocation_rate();
    
    // 3. 计算需要预留的空间
    size_t space_needed = predicted_marking_time * predicted_alloc_rate;
    
    // 4. 计算触发阈值
    // 触发阈值 = 堆大小 - 预留空间 - 安全余量
    return heap_size - space_needed - safety_margin;
  }
};
```

#### 自适应 vs 静态 IHOP

```
┌─────────────────────────────────────────────────────────────────┐
│              自适应 IHOP vs 静态 IHOP                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  静态 IHOP（G1UseAdaptiveIHOP=false）                           │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 固定阈值：45%                                            │   │
│  │                                                          │   │
│  │ 优点：                                                   │   │
│  │ - 简单可预测                                             │   │
│  │ - 适合负载稳定的应用                                     │   │
│  │                                                          │   │
│  │ 缺点：                                                   │   │
│  │ - 无法适应负载变化                                       │   │
│  │ - 高峰期可能 Full GC                                     │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                  │
│  自适应 IHOP（G1UseAdaptiveIHOP=true，默认）                    │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 动态调整：根据历史数据预测                               │   │
│  │                                                          │   │
│  │ 优点：                                                   │   │
│  │ - 自动适应负载变化                                       │   │
│  │ - 高峰期自动提前标记                                     │   │
│  │ - 低负载期减少并发开销                                   │   │
│  │                                                          │   │
│  │ 缺点：                                                   │   │
│  │ - 初期（历史数据不足）可能不稳定                         │   │
│  │ - 调试时不易预测                                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

#### 调优建议

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【自适应 IHOP 调优指南】

1. 推荐配置

   大多数场景：
   -XX:G1UseAdaptiveIHOP=true  ✅ 强烈推荐
   
   开启自适应后：
   - InitiatingHeapOccupancyPercent 作为初始值
   - JVM 会根据运行数据自动调整
   - 通常几个 GC 周期后达到最优

2. 什么时候关闭自适应？

   负载极其稳定的应用：
   - 场景：批处理，每次执行模式相同
   - 配置：-XX:G1UseAdaptiveIHOP=false
   - 然后手动调优 IHOP 到最佳值
   
   需要确定性行为的场景：
   - 场景：性能测试，需要可重复结果
   - 配置：关闭自适应，固定 IHOP

3. 验证自适应效果

   GC 日志中查看：
   [gc,ihop] IHOP: 45.0% (静态初始值)
   [gc,ihop] IHOP: adjusted to 38.5% (自适应调整后)
   
   如果调整后仍出现 Full GC：
   - 尝试降低初始 IHOP
   - 或检查老年代是否存在内存泄漏

推荐配置：
  # 默认（强烈推荐）
  -XX:G1UseAdaptiveIHOP=true  ✅ 几乎所有场景
  
  # 负载极其稳定
  -XX:G1UseAdaptiveIHOP=false ✅ 特殊场景
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

| 参数 | 默认值 | 范围 | 说明 |
|-----|-------|------|------|

#### 作用机制

```
┌─────────────────────────────────────────────────────────────────┐
│              G1MixedGCLiveThresholdPercent 作用                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Region 存活率计算：                                             │
│  存活率 = 存活对象大小 / Region 大小                             │
│                                                                  │
│  默认值 85% 意味着：                                             │
│                                                                  │
│  可回收 Region（存活率 < 85%）：                                 │
│  ┌─────────────┐                                                │
│  │████████░░░░░│  存活 70%，可回收 30%                           │
│  │████████░░░░░│  → 加入 CSet                                     │
│  └─────────────┘                                                │
│                                                                  │
│  跳过 Region（存活率 >= 85%）：                                  │
│  ┌─────────────┐                                                │
│  │████████████░│  存活 90%，可回收 10%                           │
│  │████████████░│  → 跳过（回收收益低）                          │
│  └─────────────┘                                                │
│                                                                  │
│  目的：避免回收收益低的 Region，减少无效工作                     │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

#### 源码分析

```cpp
// collectionSetChooser.hpp
// CSet 选择时的存活率检查

bool should_select_region(HeapRegion* r) {
  // 计算存活率
  double live_percent = 
      (double)r->live_bytes() * 100.0 / HeapRegion::GrainBytes;
  
  // 与阈值比较
  if (live_percent >= G1MixedGCLiveThresholdPercent) {
    return false;  // 存活率太高，跳过
  }
  
  // 其他检查...
  return true;  // 可以加入 CSet
}
```

#### 调优建议

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【G1MixedGCLiveThresholdPercent 调优指南】

1. 参数影响

   值越低（如 70%）：
   - 更多 Region 被认为可回收
   - Mixed GC 工作量增加
   - 单次暂停可能变长
   - 内存碎片回收更积极
   
   值越高（如 95%）：
   - 更少 Region 被回收
   - Mixed GC 工作量减少
   - 单次暂停变短
   - 可能留下更多碎片

2. 调优场景

   碎片敏感（长时间运行）：
   - 场景：长时间运行的服务，内存碎片导致效率下降
   - 配置：-XX:G1MixedGCLiveThresholdPercent=75
   - 效果：更积极回收，减少碎片
   - 代价：单次 GC 可能稍长
   
   低延迟优先：
   - 场景：要求单次 GC 尽可能短
   - 配置：-XX:G1MixedGCLiveThresholdPercent=90
   - 效果：减少每次回收工作量
   - 代价：可能产生更多碎片

3. 与 G1HeapWastePercent 的配合

   两个参数共同决定是否回收：
   - G1HeapWastePercent：空间角度（可回收字节）
   - G1MixedGCLiveThresholdPercent：比例角度（存活率）
   
   Region 被回收的条件：
   - 可回收空间 > G1HeapWastePercent
   - 存活率 < G1MixedGCLiveThresholdPercent
   - 回收效率足够高

4. 实际案例

   场景：8GB 堆，4MB Region，阈值 85%
   
   Region A：存活 3.2MB (80%)
   - 可回收 0.8MB
   - 80% < 85% → 可以回收
   
   Region B：存活 3.6MB (90%)
   - 可回收 0.4MB
   - 90% >= 85% → 跳过
   
   如果阈值改为 75%：
   - Region A：80% > 75% → 跳过（不划算）
   - Region B：90% > 75% → 跳过
   - 实际上可能被跳过的更多

推荐配置：
  # 默认（平衡）
  -XX:G1MixedGCLiveThresholdPercent=85  ✅ 大多数场景
  
  # 碎片敏感
  -XX:G1MixedGCLiveThresholdPercent=75  ✅ 积极回收
  
  # 低延迟优先
  -XX:G1MixedGCLiveThresholdPercent=90  ✅ 减少工作量
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

#### 调优建议

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【G1OldCSetRegionThresholdPercent 调优指南】

1. 参数影响

   值越大（如 20%）：
   - 每次 Mixed GC 回收更多老年代
   - 更快完成老年代回收
   - 单次暂停可能变长
   - 可能超过 MaxGCPauseMillis
   
   值越小（如 5%）：
   - 每次回收更少老年代
   - 单次暂停更可控
   - 需要更多 Mixed GC 次数
   - 回收周期变长

2. 与 G1MixedGCCountTarget 的区别

   G1MixedGCCountTarget：
   - 目标次数（期望分几次完成）
   - 软目标，实际可能不同
   
   G1OldCSetRegionThresholdPercent：
   - 硬性上限（每次最多回收多少）
   - 确保不超过，保护暂停时间

3. 调优场景

   快速回收老年代：
   - 场景：希望尽快回收老年代，释放空间
   - 配置：-XX:G1OldCSetRegionThresholdPercent=20
   - 注意：需确保 MaxGCPauseMillis 足够大
   
   严格控制暂停：
   - 场景：对单次暂停时间要求严格
   - 配置：-XX:G1OldCSetRegionThresholdPercent=5
   - 效果：每次回收更少，暂停更短

4. 计算示例

   场景：32GB 堆，16MB Region
   - Region 数量：2048 个
   - 默认值 10%：每次最多 204 个 Region
   - 改为 5%：每次最多 102 个 Region
   
   如果每次回收 100 个 Region 需要 100ms：
   - 默认值：204 个 → 约 200ms
   - 可能超过 MaxGCPauseMillis=100ms
   - 建议改为 5%，确保不超过 100ms

推荐配置：
  # 默认（平衡）
  -XX:G1OldCSetRegionThresholdPercent=10  ✅ 大多数场景
  
  # 快速回收
  -XX:G1OldCSetRegionThresholdPercent=20  ✅ 注意暂停时间
  
  # 严格控制暂停
  -XX:G1OldCSetRegionThresholdPercent=5   ✅ 低延迟优先
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 第七部分：Mixed GC 实战配置

### 7.1 避免 Full GC 的配置

```bash
# 场景：应用频繁出现 Full GC，需要优化

java \
  -Xms16g -Xmx16g \
  -XX:+UseG1GC \
  \
  # 1. 提前触发并发标记
  -XX:InitiatingHeapOccupancyPercent=35 \
  -XX:G1UseAdaptiveIHOP=true \
  \
  # 2. 更积极回收老年代
  -XX:G1MixedGCLiveThresholdPercent=75 \
  -XX:G1HeapWastePercent=5 \
  \
  # 3. 增加 Mixed GC 次数，减少单次压力
  -XX:G1MixedGCCountTarget=12 \
  -XX:G1OldCSetRegionThresholdPercent=8 \
  \
  # 4. 适当放宽暂停时间，确保回收完成
  -XX:MaxGCPauseMillis=300 \
  \
  -jar application.jar
```

### 7.2 快速回收老年代配置

```bash
# 场景：需要快速回收老年代，释放空间

java \
  -Xms32g -Xmx32g \
  -XX:+UseG1GC \
  \
  # 1. 单次回收更多老年代
  -XX:G1OldCSetRegionThresholdPercent=20 \
  -XX:G1MixedGCCountTarget=4 \
  \
  # 2. 降低存活率阈值，回收更多 Region
  -XX:G1MixedGCLiveThresholdPercent=70 \
  \
  # 3. 放宽暂停时间限制
  -XX:MaxGCPauseMillis=500 \
  \
  # 4. 减少浪费容忍
  -XX:G1HeapWastePercent=2 \
  \
  -jar batch-job.jar
```

### 7.3 低延迟 Mixed GC 配置

```bash
# 场景：对每次 GC 暂停时间要求严格

java \
  -Xms8g -Xmx8g \
  -XX:+UseG1GC \
  \
  # 1. 严格暂停时间
  -XX:MaxGCPauseMillis=50 \
  \
  # 2. 每次回收更少老年代
  -XX:G1OldCSetRegionThresholdPercent=5 \
  -XX:G1MixedGCCountTarget=16 \
  \
  # 3. 提高存活率阈值，只回收高价值 Region
  -XX:G1MixedGCLiveThresholdPercent=90 \
  \
  # 4. 提前标记，预留充足时间
  -XX:InitiatingHeapOccupancyPercent=40 \
  \
  -jar microservice.jar
```

## 总结

### Mixed GC 参数对照表

| 参数 | 默认值 | 避免 Full GC | 快速回收 | 低延迟 | 说明 |
|-----|-------|-------------|---------|-------|------|
| `InitiatingHeapOccupancyPercent` | 45 | 35 | 45 | 40 | 标记触发阈值 |
| `G1UseAdaptiveIHOP` | true | true | true | true | 自适应 IHOP |
| `G1MixedGCLiveThresholdPercent` | 85 | 75 | 70 | 90 | 存活率阈值 |
| `G1OldCSetRegionThresholdPercent` | 10 | 8 | 20 | 5 | 每次回收上限 |
| `G1MixedGCCountTarget` | 8 | 12 | 4 | 16 | 目标回收次数 |
| `G1HeapWastePercent` | 5 | 5 | 2 | 5 | 浪费容忍度 |
| `MaxGCPauseMillis` | 200 | 300 | 500 | 50 | 暂停时间目标 |

### 参数关系图

```
IHOP (45%) 
    ↓ 触发
并发标记完成
    ↓ 识别可回收 Region
CSet 选择
    ├── G1MixedGCLiveThresholdPercent (85%) ──→ 筛选可回收 Region
    ├── G1HeapWastePercent (5%) ──────────────→ 筛选高价值 Region
    └── G1OldCSetRegionThresholdPercent (10%) ─→ 限制单次回收量
                      ↓
              Mixed GC 执行
                      ↓
              G1MixedGCCountTarget (8) ────────→ 控制总次数
```
