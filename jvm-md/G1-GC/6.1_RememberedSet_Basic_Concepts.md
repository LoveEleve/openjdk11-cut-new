# G1 Remembered Set (RSet) 基础概念与架构

## 1. 为什么需要 Remembered Set

### 1.1 问题的引入

在 G1 垃圾收集器中，堆被划分为多个 Region（默认 2048 个）。这带来了一个核心问题：

```
┌─────────────────────────────────────────────────────────────────┐
│                      跨 Region 引用问题                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   Region A (Young)          Region B (Old)                      │
│   ┌─────────┐              ┌─────────┐                          │
│   │ 对象X    │─────────────►│ 对象Y   │                          │
│   │  (存活)  │   引用        │        │                          │
│   └─────────┘              └─────────┘                          │
│                                                                  │
│   问题：Young GC 时只回收 Region A，但对象X引用了对象Y         │
│         如果 Y 被移动，X 中的引用如何更新？                      │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 解决方案对比

| 方案 | 原理 | 缺点 |
|-----|------|------|
| **遍历整个堆** | GC 时扫描所有 Region | 时间复杂度 O(N)，太慢 |
| **记录引用来源** | 只扫描引用了当前 Region 的 Card | 时间复杂度 O(M)，M=引用数量 |

**Remembered Set 就是第二种方案**：
- 每个 Region 维护自己的 RSet
- RSet 记录了**哪些 Card** 中的对象**引用了本 Region 的对象**
- GC 时只需扫描 RSet，无需扫描整个堆

### 1.3 核心思想

```
┌─────────────────────────────────────────────────────────────────┐
│                    Remembered Set 核心思想                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   Region A ──ref──► Region B                                    │
│                                                                  │
│   记录方式（谁指向我）：                                          │
│   - Region B 的 RSet 记录 Region A 的 Card 地址                │
│   - 而不是记录 Region A 的引用                                   │
│                                                                  │
│   Region B RSet = { Card_A1, Card_A2, Card_A3, ... }           │
│                    ▲                                              │
│                    │                                              │
│            这些是 Card Table 的索引                              │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 记忆集 vs 卡表

### 2.1 概念区分

```
┌─────────────────────────────────────────────────────────────────┐
│                  Remembered Set vs Card Table                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   ┌─────────────────┐         ┌─────────────────┐              │
│   │   Remembered    │         │   Card Table    │              │
│   │     Set         │         │                 │              │
│   ├─────────────────┤         ├─────────────────┤              │
│   │ 每个 Region 一个 │         │ 整个堆共享一个   │              │
│   │ 记录指向我的引用 │         │ 记录我指向谁的脏卡│              │
│   │ 结构复杂（3种）  │         │ 简单字节数组     │              │
│   │ 用于 GC Root 扫描│         │ 用于触发 RSet 更新│              │
│   └─────────────────┘         └─────────────────┘              │
│                                                                  │
│   关系：Card Table 是 Write Barrier 的基础设施                   │
│         Remembered Set 是 GC 时的查询结构                        │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 工作流程协作

```
┌─────────────────────────────────────────────────────────────────┐
│              Write Barrier → Card Table → RSet                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   1. 应用线程执行：obj.field = new_value                         │
│           │                                                      │
│           ▼                                                      │
│   2. 写后屏障（Write Barrier）                                   │
│      - 检查是否是跨 Region 引用                                  │
│      - 将对应 Card 标记为 "dirty"                               │
│           │                                                      │
│           ▼                                                      │
│   3. Card Table 字节数组                                         │
│      _byte_map[card_index] = dirty_card_val                     │
│           │                                                      │
│           ▼                                                      │
│   4. Refine 线程 / GC 线程                                       │
│      - 扫描 dirty card                                           │
│      - 更新目标 Region 的 RSet                                  │
│           │                                                      │
│           ▼                                                      │
│   5. Remembered Set                                              │
│      - 记录引用关系                                              │
│      - GC 时快速查找                                             │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 3. G1 RSet 整体架构

### 3.1 三层存储结构

G1 的 RSet 采用**自适应存储策略**，根据引用数量选择不同结构：

```
┌─────────────────────────────────────────────────────────────────┐
│                    RSet 三层存储结构                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │                    HeapRegionRemSet                      │   │
│   │                      (每个 Region 一个)                   │   │
│   └────────────────────┬────────────────────────────────────┘   │
│                        │                                         │
│           ┌────────────┼────────────┐                           │
│           ▼            ▼            ▼                           │
│   ┌──────────┐  ┌──────────┐  ┌──────────┐                     │
│   │  Sparse  │  │   Fine   │  │  Coarse  │                     │
│   │  (稀疏)  │  │ (细粒度)  │  │ (粗粒度)  │                     │
│   ├──────────┤  ├──────────┤  ├──────────┤                     │
│   │ 哈希表   │  │ Card BM  │  │ Region BM│                     │
│   │ ~1-10条 │  │ ~10-1K条 │  │ >1K条    │                     │
│   │ 精确到Card│  │ 精确到Card│  │ 精确到Region│                   │
│   └──────────┘  └──────────┘  └──────────┘                     │
│                                                                  │
│   自动升级：引用增多时从 Sparse → Fine → Coarse               │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 三种模式详解

| 模式 | 数据结构 | 精度 | 适用场景 | 内存开销 |
|-----|---------|------|---------|---------|
| **Sparse** | 开放寻址哈希表 | Card 级别 | 极少引用（<10） | 最低 |
| **Fine** | PerRegionTable + Card Bitmap | Card 级别 | 中等引用（10~1K） | 中等 |
| **Coarse** | Region Bitmap | Region 级别 | 大量引用（>1K） | 较低但精度下降 |

## 5. 总结

### 5.1 核心要点

1. **Remembered Set 是 G1 解决跨 Region 引用的关键结构**
2. **每个 Region 有一个 RSet，记录指向本 Region 的 Card**
3. **三种存储模式自动适配：Sparse → Fine → Coarse**
4. **Card Table 是 Write Barrier 的基础设施**
5. **Dirty Card Queue + Refine 线程实现异步更新**

### 5.2 面试高频问题

| 问题 | 答案要点 |
|-----|---------|
| G1 如何管理跨 Region 引用？ | 每个 Region 维护 RSet，记录引用来源 Card |
| RSet 和 Card Table 区别？ | RSet 是 GC 查询结构，Card Table 是屏障标记结构 |
| 为什么需要三种存储模式？ | 空间自适应，少量引用用 Sparse，中等用 Fine，大量用 Coarse |
| RSet 何时更新？ | 写屏障标记脏卡 → Refine 线程/GC 线程更新 RSet |
