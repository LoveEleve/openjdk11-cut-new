## 1. 解决什么问题？

G1 GC 有一个核心承诺：**暂停时间可控**（默认 200ms）。但 GC 暂停时间取决于回收了多少 Region、每个 Region 有多少存活对象、RSet 有多大……这些在 GC 开始之前都是未知的。

**核心矛盾**：
- 年轻代太大 → 一次 GC 要回收的 Region 多、复制的对象多 → 暂停时间超标
- 年轻代太小 → GC 太频繁、吞吐量下降
- 不回收 Old Region → 堆会被耗尽；回收太多 Old Region → 暂停时间超标

**G1Policy 要做的事**：根据历史 GC 数据，**预测**下一次 GC 的各项耗时，在暂停时间预算内**最大化回收效率**。

这就需要一套完整的预测模型：
1. **数据采集**：每次 GC 后收集各阶段耗时、RSet 大小、对象复制量等
2. **统计建模**：用衰减平均算法追踪历史趋势
3. **保守预测**：预测值 = 平均 + σ × 标准差，留出安全余量
4. **自适应决策**：用预测值做二分搜索，找到暂停时间内能回收的最大年轻代长度

## 3. 底层基石：TruncatedSeq 衰减序列

### 3.1 为什么要用衰减序列而不是普通平均？

GC 行为随应用运行不断变化。普通平均对所有历史数据等权重——半小时前的数据和刚刚的数据同等重要，这不合理。衰减平均给**近期数据更大权重**，能更快跟踪趋势变化。

### 3.2 类层次

```
AbsSeq (CHeapObj<mtInternal>)
  │  _num, _sum, _sum_of_squares    // 基础统计
  │  _davg, _dvariance               // 衰减平均/方差
  │  _alpha = 0.7                    // 衰减因子
  │
  ├── NumberSeq                       // 记录全部历史，不截断
  │     _last, _maximum
  │
  └── TruncatedSeq                    // ← G1 使用这个
        _sequence[L]                  // 环形缓冲区，L=10
        _length = 10                  // 缓冲区长度
        _next                         // 下一个写入位置
```

> 源码: `utilities/numberSeq.hpp:107-132`

### 3.3 衰减平均的更新公式

每次 `add(val)` 时，`AbsSeq::add()` 更新衰减统计：

```
_davg = (1 - alpha) * val + alpha * _davg
      = 0.3 * val + 0.7 * _davg

_dvariance = (1 - alpha) * (val - _davg)² + alpha * _dvariance
```

**解读**：
- `alpha = 0.7` 意味着新数据占 30% 权重，历史占 70%
- 约 3 次更新后，旧数据权重降到 `0.7³ ≈ 34%`
- 约 7 次更新后，旧数据权重降到 `0.7⁷ ≈ 8%`，基本被"遗忘"

**为什么选 0.7？** 既不是太激进（容易被噪声干扰），也不是太保守（无法跟踪变化）。对于 GC 这种每几秒发生一次的事件，用 10 次左右的窗口来平滑是合理的。

### 3.4 TruncatedSeq 的环形缓冲区

```
缓冲区 (L=10):
┌────┬────┬────┬────┬────┬────┬────┬────┬────┬────┐
│ v0 │ v1 │ v2 │ v3 │ v4 │ v5 │ v6 │ v7 │ v8 │ v9 │
└────┴────┴────┴────┴────┴────┴────┴────┴────┴────┘
                                              ▲
                                           _next = 0（循环回到开头）

add(new_val) → _sequence[_next] = new_val; _next = (_next + 1) % L;
```

**要点**：
- 只保留最近 L=10 个原始值，用于计算精确标准差（`dsd()`）
- 同时维护 `AbsSeq` 的衰减统计（`davg`, `dvariance`）——这两个不受截断影响
- 还支持 `predict_next()` 做线性回归预测（G1 未使用）

## 4. 预测引擎：G1Predictions

### 4.1 核心公式

```cpp
// g1Predictions.hpp:57-59
double get_new_prediction(TruncatedSeq const* seq) const {
  return seq->davg() + _sigma * stddev_estimate(seq);
}
```

即：**预测值 = 衰减平均 + σ × 标准差估计**

- `seq->davg()`：衰减平均值，反映最近趋势
- `_sigma`：置信因子，`G1ConfidencePercent / 100.0 = 50 / 100 = 0.5`
- `stddev_estimate(seq)`：标准差估计，考虑小样本

**这个公式的直觉**：在平均值基础上加一个安全余量。σ=0.5 表示偏保守——预测值会比平均值高半个标准差，大约 69% 的实际值会低于预测值。

### 4.2 小样本特殊处理

```cpp
// g1Predictions.hpp:41-48
double stddev_estimate(TruncatedSeq const* seq) const {
  double estimate = seq->dsd();      // 衰减标准差
  int const samples = seq->num();
  if (samples < 5) {
    estimate = MAX2(seq->davg() * (5 - samples) / 2.0, estimate);
  }
  return estimate;
}
```

| 样本数 | 估计值 | 效果 |
|--------|--------|------|
| 1 | `MAX2(davg * 2.0, dsd)` | 非常保守：标准差 = 2× 平均值 |
| 2 | `MAX2(davg * 1.5, dsd)` | 很保守 |
| 3 | `MAX2(davg * 1.0, dsd)` | 保守 |
| 4 | `MAX2(davg * 0.5, dsd)` | 稍保守 |
| ≥5 | `dsd` | 使用真实标准差 |

**为什么？** 样本太少时，标准差不可靠（可能为 0），用平均值的倍数兜底。随着样本增多，逐渐信任真实标准差。

### 4.3 预测精度分析

以默认配置为例，假设某项指标的衰减平均 `davg=5.0ms`、衰减标准差 `dsd=1.0ms`（≥5 个样本）：

```
prediction = 5.0 + 0.5 * 1.0 = 5.5ms
```

如果应用行为稳定（dsd 小），预测值接近平均值。如果应用行为波动大（dsd 大），预测值会留出更多余量。

**调优参数**：`-XX:G1ConfidencePercent=50`（默认）
- 调高（如 80）→ 更保守，年轻代更小，GC 更频繁但暂停更短
- 调低（如 30）→ 更激进，年轻代更大，暂停可能偶尔超标

### 5.2 Young 与 Mixed 的分离统计

G1Analytics 对 Young GC 和 Mixed GC 分别统计三类指标：

```cpp
// g1Analytics.cpp:169-175  cards_per_entry_ratio
void G1Analytics::report_cost_per_entry_ms(double cost_per_entry_ms, bool for_young_gc) {
  if (for_young_gc) {
    _cost_per_entry_ms_seq->add(cost_per_entry_ms);      // Young 专用
  } else {
    _mixed_cost_per_entry_ms_seq->add(cost_per_entry_ms); // Mixed 专用
  }
}
```

**为什么分开？** Mixed GC 扫描的 Old Region 的 RSet 结构和大小与 Young Region 差异很大。Old Region 通常有更大的 RSet、更多的跨代引用，扫描成本明显不同。

**Mixed 预测的降级策略**：当 Mixed 样本不足时，降级使用 Young 数据：

```cpp
// g1Analytics.cpp:265-270
double G1Analytics::predict_mixed_rs_scan_time_ms(size_t card_num) const {
  if (_mixed_cost_per_entry_ms_seq->num() < 3) {
    return card_num * get_new_prediction(_cost_per_entry_ms_seq);  // 降级用 Young
  } else {
    return card_num * get_new_prediction(_mixed_cost_per_entry_ms_seq);
  }
}
```

类似地，并发标记期间的复制成本有 1.1× 安全系数：

```cpp
// g1Analytics.cpp:273-278
double G1Analytics::predict_object_copy_time_ms_during_cm(size_t bytes_to_copy) const {
  if (_cost_per_byte_ms_during_cm_seq->num() < 3) {
    return (1.1 * bytes_to_copy) * get_new_prediction(_cost_per_byte_ms_seq);  // 1.1× 系数
  } else {
    return bytes_to_copy * get_new_prediction(_cost_per_byte_ms_during_cm_seq);
  }
}
```

**1.1× 的原因**：并发标记期间，SATB 屏障会产生额外的写入开销，且标记线程与 GC 线程竞争 CPU，复制通常比非标记期间慢约 10%。

## 6. 暂停时间目标：G1MMUTracker

### 6.1 MMU 的概念

MMU = Minimum Mutator Utilization（最小 Mutator 利用率）。通俗地说：**在任意时间窗口内，应用线程至少能运行多少时间比例**。

- 时间窗口 `_time_slice = GCPauseIntervalMillis / 1000.0 = 201ms / 1000 = 0.201s`
- 最大 GC 时间 `_max_gc_time = MaxGCPauseMillis / 1000.0 = 200ms / 1000 = 0.200s`
- MMU = 1 - (max_gc_time / time_slice) = 1 - 200/201 ≈ 0.5%

### 6.2 数据结构

```cpp
// g1MMUTracker.hpp
class G1MMUTrackerQueue : public G1MMUTracker {
  enum { QueueLength = 64 };       // 环形队列大小
  G1MMUTrackerQueueElem _array[QueueLength];  // 暂停记录
  int _head_index, _tail_index, _no_entries;
};

struct G1MMUTrackerQueueElem {
  double _start_time;
  double _end_time;
};
```

### 6.3 核心方法：when_sec()

`when_sec()` 回答一个关键问题：**从现在开始，至少要等多久才能再做一次 GC？**

```cpp
// g1MMUTracker.cpp:115-139
double G1MMUTrackerQueue::when_sec(double current_time, double pause_time) {
  double adjusted_pause_time = min(pause_time, max_gc_time());
  double earliest_end = current_time + adjusted_pause_time;
  double limit = earliest_end - _time_slice;
  double gc_time = calculate_gc_time(earliest_end);      // 窗口内已有的 GC 时间
  double diff = gc_time + adjusted_pause_time - max_gc_time();
  if (diff <= 0) return 0.0;   // 还有预算，可以立即开始

  // 否则，找到最早的过期暂停记录，计算需要等多久
  // ...遍历队列，逐个减去过期暂停时间直到 diff <= 0...
}
```

**工作原理**：在 201ms 的滑动窗口内，GC 总时间不能超过 200ms。如果刚做完一次 150ms 的 GC，窗口内只剩 50ms 的 GC 预算。`when_sec()` 会告诉你要等多久让旧的暂停记录"滑出"窗口。

### 6.4 对 G1Policy 的影响

G1Policy 在两个地方使用 MMU Tracker：

**1) 获取暂停时间目标**：

**2) 计算最小年轻代长度（基于下次 GC 可等待时间）**：

```cpp
// g1Policy.cpp:221-236

  if (adaptive_young_list_length()) {
    if (_analytics->num_alloc_rate_ms() > 3) {
      double when_ms = _mmu_tracker->when_max_gc_sec(now_sec) * 1000.0;
```

## 7. 年轻代大小决策：二分搜索

### 7.1 决策入口

每次 GC 结束后，`record_collection_pause_end()` 会调用 `update_young_list_max_and_target_length()` 重新计算年轻代目标长度。

### 7.2 目标长度计算流程

```
update_young_list_max_and_target_length()
  └─▶ update_young_list_target_length(rs_lengths)
       └─▶ young_list_target_lengths(rs_lengths)
            ├── base_min_length = survivor 数量
            ├── desired_min_length = MAX2(sizer.min, base + alloc_rate * when_ms)
            ├── desired_max_length = sizer.max = 1228
            │
            ├── if (adaptive && in_young_only_phase):
            │     └─▶ calculate_young_list_target_length()  ← 二分搜索
            ├── elif (adaptive && in_mixed_phase):
            │     └─▶ target = 0, 被 desired_min_length 兜底  ← 尽量小
            ├── else (!adaptive):
            │     └─▶ target = _young_list_fixed_length      ← 用户固定
            │
            └── 边界约束: desired_min ≤ target ≤ desired_max
```

> 源码: `g1Policy.cpp:261-324`

### 7.3 二分搜索核心

```cpp
// g1Policy.cpp:326-426
uint G1Policy::calculate_young_list_target_length(
    size_t rs_lengths, uint base_min, uint desired_min, uint desired_max) const
{
  // 1. 计算基础耗时（不含年轻代扫描/复制的固定开销）
  const double target_pause_time_ms = _mmu_tracker->max_gc_time() * 1000.0;  // 200ms
  const double survivor_regions_evac_time = predict_survivor_regions_evac_time();
  const size_t pending_cards = _analytics->predict_pending_cards();
  const size_t adj_rs_lengths = rs_lengths + _analytics->predict_rs_length_diff();
  const size_t scanned_cards = _analytics->predict_card_num(adj_rs_lengths, true);
  const double base_time_ms = predict_base_elapsed_time_ms(pending_cards, scanned_cards)
                              + survivor_regions_evac_time;

  // 2. 创建预测器
  G1YoungLengthPredictor p(mark_or_rebuild_in_progress(),
                           base_time_ms, base_free_regions,
                           target_pause_time_ms, this);

  // 3. 二分搜索
  uint min_young = desired_min - base_min;
  uint max_young = desired_max - base_min;

  if (p.will_fit(min_young)) {
    if (p.will_fit(max_young)) {
      min_young = max_young;        // 最大值也能装下，直接用最大
    } else {
      // 二分搜索 [min_young, max_young]
      uint diff = (max_young - min_young) / 2;
      while (diff > 0) {
        uint young_length = min_young + diff;
        if (p.will_fit(young_length)) {
          min_young = young_length;   // 能装下，增大
        } else {
          max_young = young_length;   // 装不下，缩小
        }
        diff = (max_young - min_young) / 2;
      }
    }
  }
  // 即使最小值也装不下，也返回最小值（保证至少有 1 个 Eden Region）
  return base_min + min_young;
}
```

### 7.4 will_fit() 的三个终止条件

```cpp
// g1Policy.cpp:169-206
bool will_fit(uint young_length) const {
  // 条件1：空间不足
  if (young_length >= _base_free_regions) return false;

  // 条件2：预测暂停时间超标
  const double accum_surv_rate = _policy->accum_yg_surv_rate_pred(young_length - 1);
  const size_t bytes_to_copy = (size_t)(accum_surv_rate * HeapRegion::GrainBytes);
  const double copy_time = analytics->predict_object_copy_time_ms(bytes_to_copy, _during_cm);
  const double young_other = analytics->predict_young_other_time_ms(young_length);
  const double pause_time = _base_time_ms + copy_time + young_other;
  if (pause_time > _target_pause_time_ms) return false;

  // 条件3：复制后空间不足（含安全系数）
  const size_t free_bytes = (_base_free_regions - young_length) * GrainBytes;
  const double safety_factor = (100.0 / G1ConfidencePercent) * (100 + TargetPLABWastePct) / 100.0;
  // safety_factor = (100/50) * (100+10)/100 = 2.0 * 1.1 = 2.2
  const size_t expected_bytes_to_copy = (size_t)(safety_factor * bytes_to_copy);
  if (expected_bytes_to_copy > free_bytes) return false;

  return true;
}
```

**三个判断维度**：

| 条件 | 检查内容 | 约束 |
|------|---------|------|
| ① 空间充足 | `young_length < free_regions - reserve` | 不能把空闲 Region 全用完 |
| ② 暂停时间 | `base_time + copy_time + young_other ≤ 200ms` | 核心约束 |
| ③ 复制安全 | `bytes_to_copy × 2.2 ≤ free_bytes` | 考虑 PLAB 浪费和预测不确定性 |

### 7.5 具体数值示例

假设 8GB 堆稳定运行一段时间后：

```
已知：
  target_pause_time = 200ms
  base_time (RSet update + RSet scan + constant_other) = 30ms
  survivor_evac_time = 5ms
  base_time_total = 35ms

  剩余预算 = 200 - 35 = 165ms

  假设每个 Eden Region 平均耗时:
    copy_time_per_region ≈ 0.5ms (存活率 40%, 4MB*40%=1.6MB, 1.6MB*0.000009ms/B ≈ 0.014ms... 实际取决于 GC 线程并行)
    young_other_per_region ≈ 0.1ms

  每个 Region 总耗时 ≈ 0.6ms
  可容纳 Region 数 ≈ 165 / 0.6 ≈ 275 个

  min = 102, max = min(1228, free - reserve)
  → 二分搜索会收敛到 ~275 个 Region = 1.07GB 年轻代
```

## 8. 暂停时间预测公式

### 8.1 总暂停时间分解

```
total_pause = base_time + Σ region_time(young_regions) + Σ region_time(old_regions)
```

### 8.2 base_time 预测

```cpp
// g1Policy.cpp:860-866
double G1Policy::predict_base_elapsed_time_ms(size_t pending_cards, size_t scanned_cards) const {
  return _analytics->predict_rs_update_time_ms(pending_cards)    // RSet 更新
       + _analytics->predict_rs_scan_time_ms(scanned_cards, in_young_only_phase())  // RSet 扫描
       + _analytics->predict_constant_other_time_ms();           // 固定开销
}
```

展开各项：

```
RS_update_time = pending_cards × predict(cost_per_card_ms) + predict(scan_hcc)
RS_scan_time   = card_num × predict(cost_per_entry_ms)
constant_other = predict(constant_other_time_ms)
```

### 8.3 单个 Region 预测

```cpp
// g1Policy.cpp:887-907
double G1Policy::predict_region_elapsed_time_ms(HeapRegion* hr, bool for_young_gc) const {
  size_t rs_length = hr->rem_set()->occupied();
  size_t card_num = _analytics->predict_card_num(rs_length, for_young_gc);
  size_t bytes_to_copy = predict_bytes_to_copy(hr);

  double region_time =
    _analytics->predict_rs_scan_time_ms(card_num, in_young_only_phase()) +  // RSet 扫描
    _analytics->predict_object_copy_time_ms(bytes_to_copy, mark_in_progress());  // 对象复制

  if (hr->is_young()) {
    region_time += _analytics->predict_young_other_time_ms(1);     // Young 其他开销
  } else {
    region_time += _analytics->predict_non_young_other_time_ms(1); // Old 其他开销
  }
  return region_time;
}
```

### 8.4 bytes_to_copy 的计算

对于 Young Region 和 Old Region，预测方式不同：

```cpp
// g1Policy.cpp:874-885
size_t G1Policy::predict_bytes_to_copy(HeapRegion* hr) const {
  if (!hr->is_young()) {
    return hr->max_live_bytes();    // Old Region: 直接用并发标记得到的存活字节数
  } else {
    int age = hr->age_in_surv_rate_group();
    double yg_surv_rate = predict_yg_surv_rate(age, hr->surv_rate_group());
    return (size_t)(hr->used() * yg_surv_rate);  // Young Region: used × 预测存活率
  }
}
```

## 9. 存活率追踪：SurvRateGroup

### 9.1 为什么要按年龄追踪存活率？

不同年龄的 Young Region 存活率差异很大：
- age=0（新分配的 Eden）：通常存活率低（很多短命对象）
- age=1+（Survivor）：已经经历过一次 GC 的对象，存活率更高

按年龄分别追踪，预测更准确。

### 9.2 数据结构

```cpp

class SurvRateGroup {
  TruncatedSeq** _surv_rate_pred;     // 每个年龄一个 TruncatedSeq(10)
  double*        _accum_surv_rate_pred; // 累积存活率预测
  size_t         _stats_arrays_length;  // 数组长度
  double         _last_pred;            // 最后一个年龄的预测值
};
```

### 9.3 初始种子值

```cpp

_last_pred = _accum_surv_rate_pred[0] = initial_surv_rate;
```

### 9.4 数据收集

每次 GC 后，记录每个年龄的实际存活字数：

```cpp

  double surv_rate = (double) surv_words / (double) HeapRegion::GrainWords;

```

`GrainWords = GrainBytes / HeapWordSize = 4MB / 8 = 524288 words`

### 9.5 累积存活率预测

```cpp
// survRateGroup.cpp:110-120
void SurvRateGroup::finalize_predictions(const G1Predictions& predictor) {
  double accum = 0.0;
  double pred = 0.0;
  for (size_t i = 0; i < _stats_arrays_length; ++i) {
    pred = predictor.get_new_prediction(_surv_rate_pred[i]);
    if (pred > 1.0) pred = 1.0;     // 存活率不超过 100%
    accum += pred;
    _accum_surv_rate_pred[i] = accum;
  }
  _last_pred = pred;
}
```

`_accum_surv_rate_pred[n]` = 年龄 0 到 n 的存活率之和。在二分搜索中，通过 `accum_yg_surv_rate_pred(young_length - 1)` 获取所有年轻代 Region 的总预测存活率，进而算出需要复制的字节数：

```
bytes_to_copy = accum_surv_rate * GrainBytes
```

### 9.6 两个 SurvRateGroup

G1Policy 维护两个存活率组：

```cpp

```

## 10. IHOP 自适应控制

### 10.1 IHOP 是什么？

IHOP = Initiating Heap Occupancy Percent，即**触发并发标记的堆占用阈值**。当老年代占用超过此阈值时，启动并发标记。

### 10.2 静态模式 vs 自适应模式

```cpp
// g1Policy.cpp:787-798
G1IHOPControl* G1Policy::create_ihop_control(...) {
  if (G1UseAdaptiveIHOP) {  // 默认 true
    return new G1AdaptiveIHOPControl(InitiatingHeapOccupancyPercent,  // 45%
                                     old_gen_alloc_tracker, predictor,
                                     G1ReservePercent,      // 10
                                     G1HeapWastePercent);    // 5
  } else {
    return new G1StaticIHOPControl(InitiatingHeapOccupancyPercent, old_gen_alloc_tracker);
  }
}
```

### 10.3 静态模式

```
threshold = InitiatingHeapOccupancyPercent × target_occupancy / 100
          = 45% × 8GB = 3.6GB
```

当老年代占用超过 3.6GB 时触发并发标记。简单但不精确——没有考虑标记期间应用还会继续分配。

### 10.4 自适应模式

自适应 IHOP 尝试回答："**如果现在不开始标记，等标记完成时堆会不会满？**"

```cpp
// g1IHOPControl.cpp:123-143
size_t G1AdaptiveIHOPControl::get_conc_mark_start_threshold() {
  if (have_enough_data_for_prediction()) {
    double pred_marking_time = _predictor->get_new_prediction(&_marking_times_s);
    double pred_promotion_rate = _predictor->get_new_prediction(&_allocation_rate_s);
    size_t pred_promotion_size = (size_t)(pred_marking_time * pred_promotion_rate);

    size_t predicted_needed_bytes_during_marking =
      pred_promotion_size + _last_unrestrained_young_size;

    size_t internal_threshold = actual_target_threshold();
    size_t predicted_initiating_threshold =
      predicted_needed_bytes_during_marking < internal_threshold ?
        internal_threshold - predicted_needed_bytes_during_marking : 0;

    return predicted_initiating_threshold;
  } else {
    return (size_t)(_initial_ihop_percent * _target_occupancy / 100.0);  // 降级为静态
  }
}
```

**核心公式**：

```
threshold = actual_target - (pred_marking_time × pred_promotion_rate + last_unrestrained_young_size)
```

即：目标容量 - 标记期间预计增长量 - 年轻代需要的空间 = **必须在此之前开始标记**

### 10.5 actual_target_threshold

```cpp
// g1IHOPControl.cpp:100-116
size_t G1AdaptiveIHOPControl::actual_target_threshold() const {
  double safe_total_heap_percentage = MIN2(
    (double)(_heap_reserve_percent + _heap_waste_percent), 100.0);  // 10 + 5 = 15%

  return MIN2(
    max_capacity * (100.0 - 15.0) / 100.0,     // 8GB × 85% = 6.8GB
    _target_occupancy * (100.0 - 5.0) / 100.0   // 8GB × 95% = 7.6GB
  );
  // = min(6.8GB, 7.6GB) = 6.8GB
}
```

### 10.6 何时从静态切换到自适应？

```cpp
// g1IHOPControl.cpp:118-121
bool G1AdaptiveIHOPControl::have_enough_data_for_prediction() const {
  return ((size_t)_marking_times_s.num() >= G1AdaptiveIHOPNumInitialSamples) &&  // 默认 3
         ((size_t)_allocation_rate_s.num() >= G1AdaptiveIHOPNumInitialSamples);
}
```

需要至少 **3 次** 完整的并发标记周期 + 3 次分配速率样本后才启用自适应模式。在此之前使用 `InitiatingHeapOccupancyPercent=45%` 的静态值。

### 10.7 IHOP 数据更新时机

在 `record_collection_pause_end()` 中调用 `update_ihop_prediction()`：

```cpp
// g1Policy.cpp:800-836

}
```

## 12. GC 后统计更新：record_collection_pause_end()

这是 G1Policy 中**最复杂的方法**，每次 GC 暂停结束后调用，完成所有统计更新和状态转移。

### 12.1 完整流程

**步骤 1：基础信息记录**（604-650 行）

**步骤 3：各项耗时统计更新**（676-745 行）

```cpp
  _reserve_factor((double) G1ReservePercent / 100.0),   // 0.10
  _tenuring_threshold(MaxTenuringThreshold),             // 15
  _phase_times(new G1GCPhaseTimes(gc_timer, ParallelGCThreads)),
  ...
```

**初始化链**：
1. `G1Policy` 构造时创建所有子组件
2. `G1Policy::init()` 时关联到 `G1CollectedHeap` 和 `G1CollectionSet`
3. 调用 `update_young_list_max_and_target_length()` 计算初始年轻代大小
4. 首次 GC 前，所有预测使用种子默认值

## 14. need_to_start_conc_mark() — 并发标记触发决策

```cpp
// g1Policy.cpp:579-598
bool G1Policy::need_to_start_conc_mark(const char* source, size_t alloc_word_size) {
  if (about_to_start_mixed_phase()) return false;   // Mixed 阶段不启动新标记

  size_t threshold = _ihop_control->get_conc_mark_start_threshold();
  size_t cur_used = _g1h->non_young_capacity_bytes();
  size_t request = cur_used + alloc_word_size * HeapWordSize;

  if (request > threshold) {
    // 只在 Young Only 阶段且不在 Mixed 前夕才触发
    return collector_state()->in_young_only_phase()
        && !collector_state()->in_young_gc_before_mixed();
  }
  return false;
}
```

## 18. 设计哲学总结

### 18.1 "宁愿保守也不要超标"

整个预测模型设计遵循**保守原则**：
- 预测 = 平均 + 0.5σ（多留余量）
- 小样本时标准差估计更大（更保守）
- 复制空间需要 2.2× 安全系数
- `actual_target_threshold` 扣除 15% 保留空间

原因：暂停时间超标对延迟敏感应用是致命的，而偶尔小一点的年轻代只是轻微影响吞吐量。

### 18.2 "历史趋势 > 瞬时数据"

- 衰减平均（alpha=0.7）让预测自然跟踪趋势变化
- 不用最近一次的值（噪声太大），也不用全部历史平均（反应太慢）
- Young/Mixed 分别统计，避免数据污染

### 18.3 "自适应 > 手工配置"

- 年轻代大小自适应（默认）：让 GC 根据暂停时间自动调整
- IHOP 自适应（默认）：让 GC 根据分配速率自动决定何时标记
- 只有经验丰富的调优者才需要手动设置 `NewSize`/`MaxNewSize`/`NewRatio`

### 18.4 从 TruncatedSeq 到最终决策的数据流

```
GC 运行 → 记录原始耗时 → TruncatedSeq.add()
  → 衰减平均更新 (alpha=0.7)
    → G1Predictions.get_new_prediction() (davg + sigma*stddev)
      → G1Analytics.predict_*() (各项预测)
        → G1Policy.calculate_young_list_target_length() (二分搜索)
          → _young_list_target_length (最终决策)
```

这条管线把"过去发生了什么"转换成"未来应该怎么做"——这就是 G1 实现暂停时间可控的核心机制。
