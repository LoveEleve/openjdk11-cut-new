## 1. GC 日志配置详解

### 1.1 统一日志框架（Unified Logging）

JDK 9+ 使用统一的日志框架，格式如下：

```bash
-Xlog:[tag1][,tag2,...]:[output]:[decorators]:[output-options]
```

### 1.2 常用日志标签

| 标签 | 说明 | 使用场景 |
|-----|------|---------|
| `gc` | GC 基础信息 | 必开 |
| `gc+heap` | 堆状态变化 | 监控堆使用 |
| `gc+phases` | GC 各阶段详情 | 性能分析 |
| `gc+remset` | Remembered Set | RSet 调优 |
| `gc+marking` | 并发标记 | 标记分析 |
| `gc+humongous` | 大对象 | 大对象监控 |
| `gc+ergo` | 启发式决策 | 了解 GC 决策 |
| `gc+task` | 任务执行 | 并行度分析 |
| `gc+region` | Region 分配 | Region 监控 |
| `gc+liveness` | 存活率信息 | Cleanup 分析 |
| `gc+ref` | 引用处理 | 引用分析 |
| `gc+start` | GC 开始 | 基础信息 |
| `safepoint` | 安全点 | 暂停分析 |

### 1.3 日志级别

| 级别 | 说明 | 输出量 |
|-----|------|-------|
| `error` | 错误 | 极少 |
| `warning` | 警告 | 少 |
| `info` | 信息（默认） | 适中 |
| `debug` | 调试 | 多 |
| `trace` | 追踪 | 极多 |

### 1.4 装饰器选项

| 装饰器 | 说明 | 示例 |
|-------|-----|------|
| `time` | 绝对时间 | `2024-01-15T10:30:45.123+0800` |
| `uptime` | JVM 运行时间 | `12.345s` |
| `timemillis` | 毫秒时间戳 | `1705300245123` |
| `level` | 日志级别 | `[info]` |
| `tags` | 标签 | `[gc,phases]` |
| `pid` | 进程 ID | `12345` |
| `tid` | 线程 ID | `67890` |

### 1.5 输出选项

| 选项 | 说明 |
|-----|------|
| `filecount=5` | 保留 5 个滚动文件 |
| `filesize=100m` | 每个文件 100MB |
| `foldmultilines` | 折叠多行输出 |

## 2. 诊断参数汇总

### 2.1 RSet 诊断参数

| 参数 | 类型 | 默认值 | 说明 |
|-----|------|-------|------|
| `G1SummarizeRSetStatsPeriod` | diagnostic(intx) | 0 | 定期输出 RSet 统计周期（0=不输出） |
| `G1VerifyRSetsDuringFullGC` | diagnostic(bool) | false | Full GC 时验证 RSet |
| `G1MaxVerifyFailures` | develop(intx) | -1 | 最大验证失败输出数（-1=全部） |
| `G1HRRSUseSparseTable` | develop(bool) | true | 使用 Sparse Table |

```cpp
// src/hotspot/share/gc/g1/g1_globals.hpp:64-70, 183, 193-206

diagnostic(intx, G1SummarizeRSetStatsPeriod, 0,
        "The period (in number of GCs) at which we will generate "
        "update buffer processing info "
        "(0 means do not periodically generate this info); "
        "it also requires that logging is enabled on the trace"
        "level for gc+remset")

diagnostic(bool, G1VerifyRSetsDuringFullGC, false,
        "If true, perform verification of each heap region's "
        "remembered set when verifying the heap during a full GC.")

develop(intx, G1MaxVerifyFailures, -1,
        "The maximum number of verification failures to print. "
        "-1 means print all.")
```

### 2.2 堆验证参数

| 参数 | 类型 | 默认值 | 说明 |
|-----|------|-------|------|
| `VerifyDuringGC` | develop(bool) | false | GC 期间验证堆 |
| `G1VerifyBitmaps` | develop(bool) | false | 验证标记位图 |
| `G1VerifyCTCleanup` | develop(bool) | false | 验证 Card Table 清理 |

### 2.3 大对象诊断参数

| 参数 | 类型 | 默认值 | 说明 |
|-----|------|-------|------|
| `G1TraceEagerReclaimHumongousCandidates` | diagnostic(bool) | false | 追踪大对象回收候选 |
| `G1TraceReclaimDeadHumongousObjectsAtYoungGC` | diagnostic(bool) | false | 追踪 Young GC 大对象回收 |

### 2.4 其他诊断参数

| 参数 | 类型 | 默认值 | 说明 |
|-----|------|-------|------|
| `G1ConfidencePercent` | product(uintx) | 50 | MMU/暂停预测置信度 |
| `G1DummyRegionsPerGC` | develop(uintx) | 0 | 每次 GC 分配的虚拟 Region（测试用） |
| `G1ExitOnExpansionFailure` | develop(bool) | false | 堆扩展失败时退出 |

## 3. RSet 诊断

### 3.1 定期 RSet 统计

**启用方式**：

```bash
-XX:G1SummarizeRSetStatsPeriod=1 -Xlog:gc+remset=trace
```

**输出示例**：

```
[2024-01-15T10:30:45.123+0800][trace][gc,remset] Recent RSet update times (ms):
[2024-01-15T10:30:45.124+0800][trace][gc,remset]   [0..10): 15
[2024-01-15T10:30:45.124+0800][trace][gc,remset]   [10..20): 3
[2024-01-15T10:30:45.125+0800][trace][gc,remset]   [20..30): 1
[2024-01-15T10:30:45.125+0800][trace][gc,remset] Recent RSet update buffer sizes (entries):
[2024-01-15T10:30:45.126+0800][trace][gc,remset]   [0..50): 12
[2024-01-15T10:30:45.126+0800][trace][gc,remset]   [50..100): 5
```

**源码实现**：`src/hotspot/share/gc/g1/g1RemSet.cpp:877-890`

```cpp
void G1RemSet::print_periodic_summary_info(const char* header, uint period_count) {
  if ((G1SummarizeRSetStatsPeriod > 0) && log_is_enabled(Trace, gc, remset) &&
      (period_count % G1SummarizeRSetStatsPeriod == 0)) {
    
    G1RemSetSummary current(this);
    _prev_period_summary.subtract_from(&current);
    
    // 输出统计信息...
  }
}
```

### 3.2 RSet 验证

**启用 Full GC RSet 验证**：

```bash
-XX:+G1VerifyRSetsDuringFullGC
```

**作用**：在 Full GC 期间验证每个 Region 的 RSet 是否正确，帮助发现 RSet 相关 Bug。

### 4.2  evacuation 失败测试参数

| 参数 | 类型 | 默认值 | 说明 |
|-----|------|-------|------|
| `G1EvacuationFailureALot` | develop(bool) | false | 强制触发 evacuation 失败 |
| `G1EvacuationFailureALotCount` | develop(uintx) | 1000 | 失败计数 |
| `G1EvacuationFailureALotInterval` | develop(uintx) | 5 | 失败间隔 |
| `G1EvacuationFailureALotDuringYoungGC` | develop(bool) | true | Young GC 时触发 |
| `G1EvacuationFailureALotDuringMixedGC` | develop(bool) | true | Mixed GC 时触发 |
| `G1EvacuationFailureALotDuringConcMark` | develop(bool) | true | 并发标记时触发 |

**警告**：仅用于测试，生产环境绝对不要开启！

## 5. 性能分析工具

### 5.1 jstat 监控

```bash
# 基础 GC 监控
jstat -gc <pid> 1000 10

# 输出说明
# S0C/S1C: Survivor 区容量
# EC: Eden 区容量
# OC: Old 区容量
# YGC/YGCT: Young GC 次数/时间
# FGC/FGCT: Full GC 次数/时间
# GCT: 总 GC 时间

# 详细 GC 统计
jstat -gccapacity <pid> 1000

# GC 原因统计
jstat -gccause <pid> 1000
```

### 5.2 jcmd 诊断

```bash
# GC.run - 触发 GC
jcmd <pid> GC.run

# GC.heap_info - 堆信息
jcmd <pid> GC.heap_info

# GC.class_histogram - 类直方图
jcmd <pid> GC.class_histogram

# VM.flags - 查看 JVM 参数
jcmd <pid> VM.flags -all

# Thread.print - 线程 dump
jcmd <pid> Thread.print
```

### 5.3 JMX 监控

```java
// 获取 G1 收集器信息
import java.lang.management.*;
import javax.management.*;

public class G1Monitor {
    public static void main(String[] args) throws Exception {
        // 获取 GC MXBean
        for (GarbageCollectorMXBean gcBean : 
             ManagementFactory.getGarbageCollectorMXBeans()) {
            
            if (gcBean.getName().contains("G1")) {
                System.out.println("Collector: " + gcBean.getName());
                System.out.println("  Count: " + gcBean.getCollectionCount());
                System.out.println("  Time: " + gcBean.getCollectionTime() + "ms");
                
                // 获取 PoolNames
                for (String pool : gcBean.getMemoryPoolNames()) {
                    System.out.println("  Pool: " + pool);
                }
            }
        }
        
        // 获取内存池信息
        for (MemoryPoolMXBean pool : 
             ManagementFactory.getMemoryPoolMXBeans()) {
            
            if (pool.getName().contains("G1")) {
                MemoryUsage usage = pool.getUsage();
                System.out.println("Pool: " + pool.getName());
                System.out.println("  Used: " + usage.getUsed() / 1024 / 1024 + "MB");
                System.out.println("  Committed: " + usage.getCommitted() / 1024 / 1024 + "MB");
                System.out.println("  Max: " + usage.getMax() / 1024 / 1024 + "MB");
            }
        }
    }
}
```

## 6. 实战日志配置

### 6.1 生产环境推荐配置

```bash
# 基础 GC 日志
java \
  -Xlog:gc*:file=/var/log/app/gc.log:time,level,tags:filecount=10,filesize=100m \
  -jar application.jar
```

**说明**：
- `gc*`：所有 GC 相关标签
- `time`：显示时间戳
- `level,tags`：显示级别和标签
- 10 个滚动文件，每个 100MB

### 6.2 详细调优配置

```bash
# 详细调优日志
java \
  -Xlog:gc*:file=/var/log/app/gc.log:time,uptime,level,tags:filecount=5,filesize=50m \
  -Xlog:gc+phases=debug:file=/var/log/app/gc-phases.log:time,uptime,level,tags:filecount=5,filesize=50m \
  -Xlog:gc+remset=debug:file=/var/log/app/gc-remset.log:time,uptime,level,tags:filecount=5,filesize=50m \
  -Xlog:gc+ergo=debug:file=/var/log/app/gc-ergo.log:time,uptime,level,tags:filecount=5,filesize=50m \
  -Xlog:safepoint=debug:file=/var/log/app/safepoint.log:time,uptime,level,tags:filecount=5,filesize=50m \
  -jar application.jar
```

### 6.3 问题诊断配置

```bash
# 问题诊断专用配置
java \
  -Xlog:gc*:file=/var/log/app/gc.log:time,uptime,level,tags:filecount=20,filesize=100m \
  -Xlog:gc+phases=trace \
  -Xlog:gc+remset=trace \
  -Xlog:gc+marking=trace \
  -Xlog:gc+humongous=debug \
  -Xlog:gc+region=debug \
  -Xlog:gc+liveness=trace \
  -Xlog:safepoint=debug \
  -XX:G1SummarizeRSetStatsPeriod=1 \
  -jar application.jar
```

### 6.4 容器环境配置

```bash
# Docker/K8s 环境
java \
  -Xlog:gc:stdout:time,uptime,level,tags \
  -Xlog:gc*:file=/dev/shm/gc.log:time,uptime,level,tags:filecount=3,filesize=10m \
  -XX:G1SummarizeRSetStatsPeriod=10 \
  -XX:+UseContainerSupport \
  -XX:MaxRAMPercentage=75.0 \
  -jar application.jar
```

**说明**：
- 同时输出到 stdout（方便 `docker logs`）和文件
- 使用 `/dev/shm`（tmpfs）减少磁盘 I/O
- 较小的文件大小避免容器存储限制

### 6.5 日志配置对照表

| 场景 | 推荐配置 | 说明 |
|-----|---------|-----|
| 生产环境 | `gc*:file=gc.log:time,level,tags:filecount=10,filesize=100m` | 基础监控 |
| 性能测试 | 分文件记录 phases/remset/ergo | 详细分析 |
| 问题诊断 | 添加 trace 级别 | 最大化信息 |
| 容器环境 | 输出到 stdout + /dev/shm | 方便收集 |
| 大堆应用 | 增大文件大小到 500m+ | 避免过快滚动 |
