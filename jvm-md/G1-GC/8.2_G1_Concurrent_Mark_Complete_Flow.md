# G1 并发标记完整流程 - 从 Initial Mark 到 Cleanup

> 标准环境: `-Xms8g -Xmx8g -XX:+UseG1GC`, Region 大小 4MB, CardsPerRegion 8192

---

## 1. 设计哲学与核心问题

### 1.1 为什么需要并发标记？

**核心问题**：传统 STW 标记在大堆（数十 GB）下会导致长时间停顿。

```
问题分析：
- 32GB 堆中可能有数千万对象
- 串行标记可能需要数秒
- 应用长时间不可用，违反 SLA

解决方案：并发标记（Concurrent Marking）
- 在应用运行时并发扫描对象图
- 只保留短暂的 STW 阶段用于同步
- 总体标记时间更长，但停顿时间可控
```

### 1.2 SATB (Snapshot-At-The-Beginning) 算法

```
┌─────────────────────────────────────────────────────────────────────┐
│                      SATB 核心思想                                   │
└─────────────────────────────────────────────────────────────────────┘

并发标记开始时，创建堆的"快照"：
- 标记周期开始时存活的对象，都会被标记
- 允许新对象分配（隐式存活）
- 处理引用变更（写屏障记录旧值）

关键保证：
"如果对象在标记开始时是存活的，那么它会被标记"
（即使引用被并发修改）

与 CMS 的对比：
┌─────────────┬────────────────────┬────────────────────┐
│ 特性        │ CMS (Incremental)  │ G1 (SATB)          │
├─────────────┼────────────────────┼────────────────────┤
│ 算法        │ 增量更新           │ 快照               │
│ 浮动垃圾    │ 较少               │ 较多（容忍）       │
│ 实现复杂度  │ 高                 │ 中等               │
│ 暂停时间    │ 较短               │ 可控               │
│ 重复标记    │ 需要               │ 不需要             │
└─────────────┴────────────────────┴────────────────────┘
```

## 2. 核心数据结构

### 2.1 标记位图 (Mark Bitmap)

```
┌─────────────────────────────────────────────────────────────────────┐
│                    G1ConcurrentMarkBitMap                            │
└─────────────────────────────────────────────────────────────────────┘

位图大小计算（标准环境 8GB）：
- 堆大小：8GB = 2^33 bytes
- 对象最小对齐：8 bytes
- 最大对象数：8GB / 8B = 2^30 = 1G 对象
- 位图大小：1G bits = 128MB

实际位图（考虑 Region）：
- 每个 Region：4MB = 2^22 bytes
- Region 内对象槽数：4MB / 8B = 2^19 = 512K
- 每个 Region 位图：512K bits = 64KB
- 2048 Regions 总位图：2048 × 64KB = 128MB

位图结构：
┌────────────────────────────────────────────────────────────────────┐
│ G1CMBitMap (128MB total)                                           │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ Region 0 BitMap (64KB)                                       │  │
│  │  bit[0] = object at region[0].bottom()                       │  │
│  │  bit[1] = object at region[0].bottom() + 8                  │  │
│  │  ...                                                         │  │
│  │  bit[n] = 1 表示该位置的对象存活                            │  │
│  └──────────────────────────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ Region 1 BitMap (64KB)                                       │  │
│  └──────────────────────────────────────────────────────────────┘  │
│  ...                                                               │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ Region 2047 BitMap (64KB)                                    │  │
│  └──────────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────┘
```

## 3. 并发标记阶段详解

### 3.1 Phase 1: Initial Mark (初始标记)

**触发条件**：
```
IHOP 条件满足（默认堆占用 45%）
        │
        ▼
G1Policy::decide_on_conc_mark_initiation()
        │
        ▼
G1CollectedHeap::collect(GCCause::_g1_humongous_allocation 等)
        │
        ▼
VM_G1CollectFull/G1VMCollector::doit()
        │
        ▼
G1CollectedHeap::do_collection_pause_at_safepoint()
        │
        ▼
G1CollectedHeap::evacuate_collection_set()
        │
        ▼
G1ParTask::work() 中的初始标记代码
```

**执行内容**（STW）：

```cpp
// G1ConcurrentMark::pre_initial_mark()
void pre_initial_mark() {
    // 1. 重置标记状态
    reset();
    
    // 2. 设置 SATB 队列激活
    //    此后写屏障开始记录引用变更
    _active = true;
    
    // 3. 标记 GC Roots
    //    - 栈上的引用
    //    - 全局变量
    //    - JNI 引用
    //    - 等等
    
    // 4. 扫描 Survivor 区域作为根
    _root_regions.init(_g1h->survivor(), this);
}
```

**Initial Mark 时序**：

```
时间线    STW 线程              并发标记线程           SATB 队列
─────────────────────────────────────────────────────────────────
T0        开始暂停
              │
T1            ├── 设置 _active = true
              │   SATB 队列激活
              │
T2            ├── 标记 GC Roots
              │   根对象入标记栈
              │
T3            ├── 标记 Survivor 对象
              │   Survivor 对象入栈
              │
T4        结束暂停 ───────► 开始并发标记
                                   │
T5                                 ├── 弹出标记栈
                                   │   扫描对象引用
                                   │
T6        应用继续运行              │   (并发执行)
              │                    │
              └── 写屏障记录旧值 ──► SATB 队列
```

### 3.2 Phase 2: Root Region Scanning

**执行内容**：

```cpp
// G1ConcurrentMark::scan_root_regions()
void scan_root_regions() {
    // Survivor 区域作为根区域
    // 原因：Survivor 中的对象可能引用老年代
    //       这些对象在标记周期中可能被晋升/回收
    
    G1CMRootRegionScanTask task(this);
    _concurrent_workers->run_task(&task);
}

// 扫描单个 Root Region
void scan_root_region(HeapRegion* hr, uint worker_id) {
    G1RootRegionScanClosure cl(_g1h, this, worker_id);
    
    // 遍历 Region 中所有对象
    HeapWord* curr = hr->bottom();
    const HeapWord* end = hr->top();
    while (curr < end) {
        oop obj = oop(curr);
        // 标记对象并扫描其引用
        obj->oop_iterate(&cl);
        curr += obj->size();
    }
}
```

### 3.3 Phase 3: Concurrent Mark (并发标记)

**核心循环**：

```cpp
// G1CMConcurrentMarkingTask::work()
void work(uint worker_id) {
    G1CMTask* task = _cm->task(worker_id);
    
    do {
        // 执行标记步骤，目标时长 10ms
        task->do_marking_step(G1ConcMarkStepDurationMillis,
                              true  /* do_termination */,
                              false /* is_serial */);
        
        // 检查是否需要让出 CPU（Safepoint 同步）
        _cm->do_yield_check();
        
    } while (!_cm->has_aborted() && task->has_aborted());
}
```

**标记步骤详解**：

```cpp
// G1CMTask::do_marking_step()
void do_marking_step(double mark_step_duration_ms, ...) {
    double start_time_ms = os::elapsedVTime() * MILLIUNITS;
    
    // 1. 处理本地队列
    while (!has_aborted() && !local_queue_empty()) {
        G1TaskQueueEntry entry = pop_from_local_queue();
        
        if (entry.is_oop()) {
            // 普通对象：扫描其引用字段
            scan_object(entry.obj());
        } else {
            // 数组切片：处理数组的一部分
            process_array_slice(entry.slice());
        }
        
        // 检查时间限制
        double elapsed_ms = os::elapsedVTime() * MILLIUNITS - start_time_ms;
        if (elapsed_ms >= mark_step_duration_ms) {
            set_has_aborted(true);  // 时间到，退出
            return;
        }
    }
    
    // 2. 工作窃取（从其他线程偷任务）
    if (!has_aborted()) {
        steal_work_from_other_tasks();
    }
    
    // 3. 终止协议（同步所有线程）
    if (do_termination) {
        termination_protocol();
    }
}
```

**对象扫描过程**：

```cpp
// G1CMTask::process_grey_object()
void process_grey_object(oop obj) {
    // 获取对象的 Region
    HeapRegion* hr = _g1h->heap_region_containing(obj);
    
    // 根据对象类型扫描
    if (obj->is_objArray()) {
        // 大数组分片处理
        objArrayOop array = objArrayOop(obj);
        size_t len = array->length();
        
        if (len > (size_t)ObjArrayMarkingStride * 2) {
            // 大数组：分片入栈
            push_array_slices(array);
        } else {
            // 小数组：直接扫描
            array->oop_iterate(_cm->cm_oop_closure());
        }
    } else {
        // 普通对象：扫描所有引用字段
        obj->oop_iterate(_cm->cm_oop_closure());
    }
}
```

**SATB 处理**：

```cpp
// 写屏障在引用修改前执行
void satb_pre_write_barrier(oop* field, oop new_value) {
    // 只在并发标记阶段且 SATB 激活时执行
    if (!SATBMarkQueueSet::is_active()) return;
    
    // 读取旧值
    oop old_value = *field;
    if (old_value == NULL) return;
    
    // 将旧值加入 SATB 队列
    JavaThread* thread = JavaThread::current();
    SATBMarkQueue& queue = G1ThreadLocalData::satb_mark_queue(thread);
    
    if (!queue.is_full()) {
        queue.enqueue(old_value);
    } else {
        // 队列满：处理后再入队
        handle_full_satb_buffer(queue);
    }
}
```

**SATB 队列处理**：

```cpp
void drain_satb_buffers() {
    // 遍历所有 Java 线程
    for (JavaThreadIteratorWithHandle jtiwh; JavaThread *t = jtiwh.next(); ) {
        SATBMarkQueue& queue = G1ThreadLocalData::satb_mark_queue(t);
        
        // 处理该线程的 SATB 队列
        while (!queue.is_empty()) {
            oop obj = queue.dequeue();
            // 标记对象（如果尚未标记）
            if (!_mark_bitmap->is_marked(obj)) {
                mark_and_push(obj);
            }
        }
    }
    
    // 处理共享队列
    process_shared_satb_queue();
}
```

## 4. 关键机制详解

### 4.1 三色标记法

```
┌─────────────────────────────────────────────────────────────────────┐
│                        三色标记法                                    │
└─────────────────────────────────────────────────────────────────────┘

颜色定义：
  白色 = 未访问（垃圾候选）
  灰色 = 已访问，但引用未扫描（在标记栈中）
  黑色 = 已访问且引用已扫描（存活）

状态转换：

  白色对象 ──► 灰色对象 ──► 黑色对象
              (发现引用)    (扫描完成)
                 │              │
                 │              │
            标记栈           存活对象

并发标记的挑战：
  应用线程可能同时修改引用图，导致：
  
  问题 1: 白色对象被黑色对象引用（漏标）
    黑色对象 ──► 白色对象
    
  解决方案 (SATB):
    写屏障记录旧引用，确保白色对象被标记
    
  问题 2: 灰色对象引用被删除
    灰色对象 ──X──► 白色对象
    
  解决方案:
    同样通过 SATB 处理，白色对象会被重新扫描
```

### 4.2 工作窃取 (Work Stealing)

```cpp
// G1CMTask::steal_work()
bool steal_work() {
    // 尝试从其他线程的任务队列窃取
    for (uint i = 0; i < _cm->active_tasks(); i++) {
        if (i == _worker_id) continue;
        
        G1CMTask* other_task = _cm->task(i);
        G1TaskQueueEntry entry;
        
        // 尝试弹出其他队列的条目
        if (other_task->task_queue()->pop_global(entry)) {
            // 窃取成功，处理该条目
            process_entry(entry);
            return true;
        }
    }
    return false;
}
```

## 7. 总结

### 7.1 并发标记核心要点

| 阶段 | 时长 | 内容 | 关键操作 |
|-----|------|------|---------|
| **Initial Mark** | ~10ms (STW) | 标记 GC Roots | 激活 SATB，标记 Survivor |
| **Root Scanning** | ~10-50ms (并发) | 扫描 Survivor | 多线程并行扫描 |
| **Concurrent Mark** | 数秒 (并发) | 遍历对象图 | 标记栈处理，工作窃取 |
| **Preclean** | 可变 (并发) | 预处理 | 引用处理，SATB 处理 |
| **Remark** | ~50-100ms (STW) | 完成标记 | 处理所有 SATB 队列 |
| **Cleanup** | ~10ms (STW) | 统计与清理 | 存活统计，位图重置 |
