# Young GC 完整源码追踪 - 从触发到 Evacuation

> 标准环境: `-Xms8g -Xmx8g -XX:+UseG1GC`, Region 大小 4MB

---

## 1. 设计哲学与核心问题

### 1.1 Young GC 要解决什么问题？

```
核心问题：如何高效回收年轻代（Eden + Survivor）中的垃圾对象？

挑战：
1. 年轻代对象生命周期短，垃圾比例高（通常 > 90%）
2. 需要快速完成，避免影响应用响应时间
3. 存活对象需要复制到 Survivor 或晋升到老年代
4. 必须更新所有引用（包括跨 Region 引用）

G1 Young GC 特点：
- 并行执行：使用所有 GC 线程并行处理
- 复制算法：将存活对象从 Eden 复制到 Survivor
- 部分收集：只收集年轻代 Region（可能包含部分老年代 Region，即 Mixed GC）
- STW：整个 Young GC 过程是暂停的（目标 < 200ms）
```

### 1.2 Young GC 执行流程全景

```
┌─────────────────────────────────────────────────────────────────────┐
│                     Young GC 执行流程                                │
└─────────────────────────────────────────────────────────────────────┘

Phase 1: 触发与准备 (STW)
├─ 1.1 GC 触发条件检查
├─ 1.2 选择 Collection Set (CSet)
├─ 1.3 准备 GC 环境
└─ 1.4 进入安全点 (Safepoint)

Phase 2: 根扫描 (并行)
├─ 2.1 扫描 GC Roots
├─ 2.2 扫描线程栈
├─ 2.3 扫描全局变量
└─ 2.4 扫描 RSet (跨 Region 引用)

Phase 3: Evacuation (并行)
├─ 3.1 复制存活对象
├─ 3.2 更新引用
├─ 3.3 处理跨 Region 引用
└─ 3.4 更新 RSet

Phase 4: 后处理 (并行)
├─ 4.1 处理引用对象
├─ 4.2 清理 Card Table
├─ 4.3 释放空闲 Region
└─ 4.4 更新 GC 统计

Phase 5: 恢复 (STW)
└─ 5.1 退出安全点
```

## 2. Phase 1: GC 触发与准备

### 2.1 触发条件

```cpp
// G1CollectedHeap::attempt_allocation()
HeapWord* G1CollectedHeap::attempt_allocation(size_t word_size,
                                               uint* gc_count_before_ret,
                                               uint* gclocker_retry_count_ret) {
    // 1. 尝试在现有 Eden 分配
    HeapWord* result = _allocator->attempt_allocation(word_size);
    if (result != NULL) {
        return result;
    }
    
    // 2. Eden 已满，触发 GC
    return do_collection_pause(word_size, ...);
}
```

**触发条件流程**：

```
应用线程分配对象
        │
        ▼
TLAB 是否有足够空间? ──N──► 分配新 TLAB
        │ Y                        │
        ▼                          │
Eden Region 是否有空间? ──N──► 申请新 Eden Region
        │ Y                        │
        ▼                          │
直接分配 ◄─────────────────────────┘
        │
        │ (如果 Eden 申请失败)
        ▼
触发 Young GC
        │
        ▼
VMThread 执行 GC
```

### 2.2 选择 Collection Set

```cpp
// G1Policy::finalize_collection_set()
void G1Policy::finalize_collection_set(...) {
    // 1. 确定 Eden 和 Survivor Region
    //    所有 Eden Region 必须被回收
    //    Survivor Region 根据 GC 策略选择
    
    // 2. 计算目标暂停时间内的最大工作量
    double time_remaining_ms = max_pause_time_ms;
    
    // 3. 如果有并发标记周期，添加部分老年代 Region (Mixed GC)
    if (_g1h->concurrent_mark()->cm_thread()->during_cycle()) {
        add_old_regions_to_cset(time_remaining_ms);
    }
}
```

**CSet 选择策略**：

```
Young GC CSet:
┌──────────────────────────────────────────────────────┐
│ Collection Set (CSet)                               │
│ ┌──────────────────────────────────────────────────┐│
│ │ Eden Regions (全部)                              ││
│ │ ├── Eden Region 0                                ││
│ │ ├── Eden Region 1                                ││
│ │ └── ... (通常占年轻代 80-90%)                    ││
│ └──────────────────────────────────────────────────┘│
│ ┌──────────────────────────────────────────────────┐│
│ │ Survivor Regions (部分)                          ││
│ │ ├── Survivor Region 0 (如果存活率高可能不选)    ││
│ │ └── ...                                          ││
│ └──────────────────────────────────────────────────┘│
│ ┌──────────────────────────────────────────────────┐│
│ │ Old Regions (可选，Mixed GC)                     ││
│ │ ├── Old Region A (垃圾比例高)                   ││
│ │ └── Old Region B                                 ││
│ └──────────────────────────────────────────────────┘│
└──────────────────────────────────────────────────────┘
```

### 2.3 GC 入口函数

```cpp
// G1CollectedHeap::do_collection_pause_at_safepoint()
void G1CollectedHeap::do_collection_pause_at_safepoint(double target_pause_time_ms) {
    // 1. 准备工作
    g1_policy()->record_collection_pause_start();
    
    // 2. 确定 CSet
    g1_policy()->finalize_collection_set(target_pause_time_ms);
    
    // 3. 执行 Evacuation
    evacuate_collection_set(g1_policy()->evacuation_info());
    
    // 4. 后处理
    g1_policy()->record_collection_pause_end();
}
```

## 3. Phase 2: Evacuation (核心)

### 3.1 Evacuation 概述

```cpp
// G1CollectedHeap::evacuate_collection_set()
void G1CollectedHeap::evacuate_collection_set(G1EvacuationInfo& evacuation_info) {
    // 1. 创建并行任务
    G1ParTask g1_par_task(...);
    
    // 2. 启动 GC 工作线程
    workers()->run_task(&g1_par_task);
}
```

**Evacuation 核心思想**：

```
Before Young GC:
┌──────────────────────────────────────────────────────┐
│ Eden Region 0                                        │
│ ┌────────┬────────┬────────┬────────┐               │
│ │ 存活A  │ 垃圾   │ 存活B  │ 垃圾   │               │
│ └────────┴────────┴────────┴────────┘               │
│                                                      │
│ Eden Region 1                                        │
│ ┌────────┬────────┬────────┬────────┐               │
│ │ 垃圾   │ 存活C  │ 垃圾   │ 垃圾   │               │
│ └────────┴────────┴────────┴────────┘               │
└──────────────────────────────────────────────────────┘

After Young GC (Evacuation):
┌──────────────────────────────────────────────────────┐
│ Eden Region 0 - 已清空，可回收                       │
│                                                      │
│ Eden Region 1 - 已清空，可回收                       │
│                                                      │
│ Survivor Region S0                                   │
│ ┌────────┬────────┬────────┐                        │
│ │ 存活A  │ 存活B  │ 存活C  │ (从 Eden 复制而来)     │
│ └────────┴────────┴────────┘                        │
└──────────────────────────────────────────────────────┘
```

### 3.2 并行 GC 任务

```cpp
// G1ParTask::work()
void G1ParTask::work(uint worker_id) {
    // 1. 创建线程本地状态
    G1ParScanThreadState* pss = _g1h->par_scan_thread_state(worker_id);
    
    // 2. 扫描根对象
    G1EvacuationRootClosures* closures = ...;
    G1RootProcessor rp(...);
    rp.process_all_roots(closures);
    
    // 3. 扫描 CSet 中的 Region
    scan_collection_set_regions(pss, worker_id);
    
    // 4. 处理引用队列
    pss->trim_queue();
    
    // 5. 刷新统计信息
    pss->flush(_surviving_young_words);
}
```

### 3.3 G1ParScanThreadState (线程本地状态)

```cpp
class G1ParScanThreadState : public CHeapObj<mtGC> {
    G1CollectedHeap* _g1h;
    RefToScanQueue*  _refs;           // 对象引用队列
    DirtyCardQueue   _dcq;            // 脏卡队列
    G1PLABAllocator* _plab_allocator; // PLAB 分配器
    AgeTable         _age_table;      // 年龄表
    
public:
    // 处理对象引用
    template <class T> void do_oop_ext(T* ref) {
        T heap_oop = RawAccess<>::oop_load(ref);
        if (CompressedOops::is_null(heap_oop)) return;
        
        oop obj = CompressedOops::decode_not_null(heap_oop);
        
        // 检查对象是否在 CSet 中
        if (_g1h->is_in_cset_or_humongous(obj)) {
            // 需要复制对象
            oop forwardee = do_copy_to_survivor_space(obj);
            RawAccess<>::oop_store(ref, forwardee);
        }
    }
};
```

**G1ParScanThreadState 字段详解**：

| 字段 | 类型 | 用途 |
|-----|------|------|
| `_refs` | RefToScanQueue* | 待扫描的对象引用队列 |
| `_dcq` | DirtyCardQueue | 脏卡队列（记录跨 Region 引用） |
| `_plab_allocator` | G1PLABAllocator* | 晋升本地分配缓冲区 |
| `_age_table` | AgeTable | 对象年龄统计 |

### 3.4 对象复制过程

```cpp
// G1ParScanThreadState::do_copy_to_survivor_space()
oop do_copy_to_survivor_space(oop old_obj) {
    // 1. 检查对象是否已经被复制（有转发指针）
    oop forward_ptr = old_obj->forward_acquire();
    if (forward_ptr != NULL) {
        return forward_ptr;  // 其他线程已复制
    }
    
    // 2. 确定目标区域（Survivor 或 Old）
    InCSetState dest_state = dest(InCSetState(old_obj));
    
    // 3. 在目标区域分配空间
    HeapWord* obj_ptr = _plab_allocator->plab_allocate(...);
    if (obj_ptr == NULL) {
        // PLAB 满，使用共享分配
        obj_ptr = allocate_in_shared_space(...);
    }
    
    // 4. 复制对象数据
    Copy::aligned_conjoint_words(...);
    
    // 5. 设置转发指针
    oop new_obj = oop(obj_ptr);
    old_obj->forward_to(new_obj);
    
    // 6. 更新年龄
    if (dest_state.is_young()) {
        new_obj->incr_age();
    }
    
    // 7. 将对象加入扫描队列（处理其引用字段）
    _refs->push(new_obj);
    
    return new_obj;
}
```

**对象复制流程图**：

```
发现引用指向 CSet 中的对象
        │
        ▼
检查是否有转发指针? ──Y──► 返回转发后的对象
        │ N
        ▼
确定目标区域 (Survivor/Old)
        │
        ▼
在目标区域分配空间
        │
        ├── PLAB 分配 (TLAB 风格)
        └── PLAB 满? -> 共享分配
        │
        ▼
复制对象数据 (memcpy)
        │
        ▼
设置转发指针 (原对象 -> 新对象)
        │
        ▼
更新对象年龄
        │
        ▼
加入扫描队列 (处理引用字段)
        │
        ▼
返回新对象地址
```

### 3.5 PLAB (Promotion Local Allocation Buffer)

```cpp
// G1PLABAllocator - 类似于 TLAB，用于 GC 期间的对象分配
class G1PLABAllocator : public CHeapObj<mtGC> {
    // PLAB 大小
    static const size_t MinPLABSize = 32;
    static const size_t MaxPLABSize = 4096;
    
    // 当前 PLAB
    PLAB* _survivor_plab;  // Survivor 区域 PLAB
    PLAB* _old_plab;       // Old 区域 PLAB
};
```

**PLAB 作用**：

```
Without PLAB:
每个对象复制都需要同步申请空间
        │
        ▼
大量线程竞争 -> 性能瓶颈

With PLAB:
每个 GC 线程预先分配一大块内存 (PLAB)
        │
        ▼
对象复制在 PLAB 内 bump-the-pointer
        │
        ▼
无锁分配，仅当 PLAB 满时才需同步
```

## 4. Phase 3: 引用更新与 RSet 处理

### 4.1 引用更新

```cpp
// 更新引用指向新对象位置
template <class T> void update_reference(T* ref) {
    oop obj = RawAccess<>::oop_load(ref);
    
    // 检查对象是否在 CSet 中（是否被复制）
    if (_g1h->is_in_cset(obj)) {
        // 获取转发后的新地址
        oop new_obj = obj->forwardee();
        RawAccess<>::oop_store(ref, new_obj);
    }
}
```

### 4.2 跨 Region 引用处理

```cpp
// G1ParScanThreadState::update_rs()
template <class T> void update_rs(HeapRegion* from, T* p, oop o) {
    // 如果引用和对象在同一 Region，不需要更新 RSet
    if (HeapRegion::is_in_same_region(p, o)) return;
    
    // 如果引用来自年轻代，不需要更新 RSet
    // (年轻代 Region 的 RSet 不追踪)
    if (from->is_young()) return;
    
    // 获取目标 Region
    HeapRegion* to = _g1h->heap_region_containing(o);
    if (!to->rem_set()->is_tracked()) return;
    
    // 计算 Card Index
    size_t card_index = ct()->index_for(p);
    
    // 如果 Card 尚未加入队列，加入脏卡队列
    if (ct()->mark_card_deferred(card_index)) {
        dirty_card_queue().enqueue(
            (jbyte*)ct()->byte_for_index(card_index)
        );
    }
}
```

### 4.3 脏卡队列处理

```
引用更新时发现的跨 Region 引用
        │
        ▼
加入线程本地脏卡队列
        │
        ▼
队列满或 GC 结束
        │
        ▼
Refine 线程处理
        │
        ├─ 识别被引用的 Region
        ├─ 更新目标 Region 的 RSet
        └─ 清理 Card Table
```

```
典型 Young GC 暂停时间分布 (200ms 目标):
```

### 7.2 内存占用

```
Young GC 期间的额外内存占用:

PLAB 分配:
  - 每个 GC 线程: 2 × PLAB 大小 (Survivor + Old)
  - PLAB 默认大小: 4KB - 64KB
  - 8 个 GC 线程: ~1MB

引用队列:
  - RefToScanQueue: 每个线程一个
  - 队列容量: 通常数千个条目
  - 总计: ~数 MB

转发指针:
  - 每个被复制的对象需要一个转发指针
  - 存储在原对象头中，无额外开销
```

## 9. 总结

### 9.1 Young GC 核心要点

| 阶段 | 关键操作 | 性能考虑 |
|-----|---------|---------|
| **触发** | Eden 满，分配失败 | 尽量增加 Eden 大小，减少 GC 频率 |
| **CSet 选择** | 选择 Eden + 部分 Survivor | 控制 CSet 大小，满足暂停目标 |
| **根扫描** | 扫描 GC Roots | 并行执行，多线程加速 |
| **Evacuation** | 复制存活对象 | 使用 PLAB 减少同步，并行处理 |
| **引用更新** | 更新所有引用 | 延迟更新，批量处理 |
| **RSet 更新** | 脏卡队列处理 | 异步处理，减少暂停时间 |

### 9.2 关键数字

```
【标准环境 8GB/4MB】

Young GC 目标暂停:      200ms (MaxGCPauseMillis)
Eden 默认占比:          ~5-60% (动态调整)
Survivor 默认占比:      ~10% 年轻代
对象晋升年龄阈值:       6-15 (动态调整)
PLAB 大小:              4KB - 64KB
GC 工作线程数:          8 (ParallelGCThreads)
```
