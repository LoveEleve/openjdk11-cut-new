## 第 1 章: libsaproc.so 整体架构

### 1.1 一句话总结

libsaproc.so (Serviceability Agent PROCess library) 是 HotSpot Serviceability Agent 的核心原生库，通过 ptrace 系统调用 attach 到目标进程或 core dump，实现读取内存、获取寄存器、解析符号表等调试功能，是 HSDB、Clhsdb 等 JVM 调试工具的底层支撑。

### 1.3 工作流程图

```
HSDB attach 到目标 JVM:

1. Java: LinuxDebuggerLocal.attach0(pid)
   │
   └── JNI: Pgrab(pid)
       │
       ├── ptrace(PTRACE_ATTACH, pid) → attach 到目标进程
       ├── waitpid(pid) → 等待 SIGSTOP
       ├── /proc/<pid>/maps → 读取内存映射
       ├── /proc/<pid>/task/ → 枚举线程
       └── 填充 ps_prochandle 结构
   │
2. Java: readBytesFromProcess0(addr, len)
   │
   └── JNI: ps_pdread(ph, addr, buf, len)
       │
       ├── ptrace(PTRACE_PEEKDATA, addr) → 读取 8 字节
       └── 循环读取直到完成
   │
3. Java: lookupByName0("libjvm.so", "gHotSpotVMStructs")
   │
   └── JNI: lookup_symbol(ph, "libjvm.so", "gHotSpotVMStructs")
       │
       ├── build_symtab(fd) → 解析 ELF 符号表
       └── hsearch() → hash 表查找符号
   │
4. Java: getIntegerRegisterSet0(tid)
   │
   └── JNI: ptrace(PTRACE_GETREGS, tid) → 获取寄存器
```

## 第 6 章: 面试高频问题与深度答案

### Q1: HSDB 是如何 attach 到运行中的 JVM 的?

**答案**:
```
流程:
1. HSDB 调用 LinuxDebuggerLocal.attach0(pid)
2. JNI 层调用 Pgrab(pid)
3. Pgrab 内部:
   a. ptrace(PTRACE_ATTACH, pid) → 发送 attach 请求
   b. 目标 JVM 收到 SIGSTOP 信号并停止
   c. waitpid() 等待 SIGSTOP 确认
   d. /proc/<pid>/maps → 读取内存映射
   e. /proc/<pid>/task/ → 枚举所有线程
   f. 为每个共享库 build_symtab() → 解析符号表
4. HSDB 现在可以:
   - ps_pdread() → ptrace 读取内存
   - lookup_symbol() → 符号查找
   - ptrace(PTRACE_GETREGS) → 获取寄存器
```

### Q2: 为什么 ptrace 读取内存要按 word 对齐?

**答案**:
```
原因:
1. ptrace(PTRACE_PEEKDATA) 接口设计
   - 每次读取一个 machine word (4/8 字节)
   - 要求地址按 word 对齐

2. 非对齐处理 (process_read_data):
   a. 计算对齐地址: aligned_addr = addr & ~7
   b. 读取对齐地址的 8 字节
   c. 跳过开头: (addr - aligned_addr) 字节
   d. 复制需要的数据
   e. 结尾同样处理

示例: 读取 6 字节 @ 0x1003
   对齐地址: 0x1000
   读取 8 字节 @ 0x1000 → [XX XX XX B0 B1 B2 B3 B4]
   跳过前 3 字节，复制 B0-B5
```

### Q3: Serviceability Agent 如何解析符号表?

**答案**:
```
符号解析流程:
1. build_symtab(lib_fd)
   a. 读取 ELF header
   b. 找到 .symtab 或 .dynsym 节
   c. 读取符号表条目
   d. 读取字符串表 (.strtab)
   e. 创建 symtab_t 结构

2. 符号查找优化:
   a. 创建 hash 表 (hsearch_data)
   b. 符号名 → hash → 索引
   c. O(1) 查找复杂度

3. 地址计算:
   symbol_address = lib_base + symbol_offset
   
   lib_base: /proc/<pid>/maps 中获取
   symbol_offset: ELF 符号表中的 st_value

4. Debuginfo 分离支持:
   - .gnu_debuglink: 查找 .debug 文件
   - .build-id: 精确匹配 debuginfo
```

### Q4: 进程 attach 和 core dump attach 有什么区别?

**答案**:
```
进程 Attach:
- 使用 ptrace 系统调用
- 目标进程必须存活
- 可以读取实时内存状态
- 可以获取寄存器实时值
- attach 后目标进程暂停

core dump Attach:
- 直接读取 core 文件
- 目标进程可以不存在
- 读取的是崩溃时的快照
- 无法获取实时状态
- 不影响任何进程

代码层面的区别:
  进程: ph->ops = &proc_ops
        proc_ops.p_pread = process_read_data (ptrace)
  
  core: ph->ops = &core_ops
        core_ops.p_pread = core_read_data (pread from file)
```

### Q5: 为什么需要 LIBSAPROC_DEBUG 环境变量?

**答案**:
```
作用:
  export LIBSAPROC_DEBUG=1
  启用详细调试输出

输出内容:
  - attach 过程详细信息
  - ptrace 调用结果
  - 符号表加载信息
  - 内存读取日志

使用场景:
1. HSDB attach 失败时排查问题
2. 分析符号解析问题
3. 理解底层工作机制

代码实现:
  init_libproc(getenv("LIBSAPROC_DEBUG") != NULL)
  设置全局变量 is_debug = true
  print_debug() 宏根据 is_debug 决定是否输出
```

### Q6: Serviceability Agent 与 JVMTI 有什么区别?

**答案**:
```
| 特性 | Serviceability Agent | JVMTI |
|-----|------------------------|-------|
| 工作方式 | 外部 attach | Agent 加载 |
| 目标进程 | 可以已崩溃(core) | 必须正在运行 |
| 侵入性 | 无侵入 | 需要加载 Agent |
| 使用场景 | 调试、分析崩溃 | 监控、动态修改 |
| 典型工具 | HSDB, Clhsdb | Arthas, JProfiler |
| 权限要求 | ptrace 权限 | 动态 attach 权限 |

SA 的优势:
- 可以分析 core dump
- 不需要目标进程配合
- 可以读取任意内存地址
- 不占用目标进程资源

JVMTI 的优势:
- 可以动态修改字节码
- 事件回调机制
- 更丰富的 API
```
