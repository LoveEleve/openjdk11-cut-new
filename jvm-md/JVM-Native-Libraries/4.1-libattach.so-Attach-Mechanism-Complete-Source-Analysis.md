## 第 1 章: Attach 机制整体架构

### 1.1 一句话总结

JVM Attach 机制是一种进程间通信(IPC)机制，允许外部工具通过 Unix Domain Socket 动态连接到运行中的 JVM，执行诊断命令(如加载 Agent、dump 堆、线程分析等)。

### 1.2 核心组件关系图

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           JVM Attach 架构全景                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  外部工具 (如 Arthas/jcmd)                                                   │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │ VirtualMachineImpl (Java)                                           │   │
│  │ ├─ attach(pid) → 创建 .attach_pid<pid> 文件                          │   │
│  │ ├─ sendQuitTo(pid) → SIGQUIT 信号                                   │   │
│  │ ├─ socket() → Unix Domain Socket                                    │   │
│  │ └─ execute(cmd, args) → 发送命令                                     │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                              │                                              │
│                              │ Unix Domain Socket (/tmp/.java_pid<pid>)    │
│                              ▼                                              │
│  JVM 进程                                                                    │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │ AttachListener Thread (JVM 内部线程)                                 │   │
│  │ ├─ LinuxAttachListener::init() → 创建 socket                        │   │
│  │ ├─ LinuxAttachListener::dequeue() → accept() 等待连接               │   │
│  │ ├─ LinuxAttachListener::read_request() → 解析命令                   │   │
│  │ ├─ dispatch() → 执行对应操作 (load/threaddump/dumpheap/...)         │   │
│  │ └─ LinuxAttachOperation::complete() → 返回结果                      │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 1.3 核心流程图

```
外部工具 Attach 流程:

1. VirtualMachine.attach(pid)
   │
   ├── 检查目标进程是否存在
   │
   ├── 查找 socket 文件: /tmp/.java_pid<pid>
   │   ├── 存在? → 直接连接
   │   └── 不存在? → 启动 Attach 机制
   │       │
   │       ├── 创建 .attach_pid<pid> 文件
   │       ├── 发送 SIGQUIT 信号给目标 JVM
   │       ├── 等待 socket 文件创建 (超时 5s)
   │       └── 删除 .attach_pid<pid> 文件
   │
   └── 检查 socket 文件权限

2. 建立 Unix Domain Socket 连接

3. 发送命令协议数据:
   <version>\0<cmd>\0<arg0>\0<arg1>\0<arg2>\0

4. 读取执行结果

5. VirtualMachine.detach()
```

## 第 6 章: 面试高频问题与深度答案

### Q1: Attach 机制的工作原理是什么?

**答案**:
```
1. 外部工具创建 .attach_pid<pid> 文件
2. 发送 SIGQUIT 信号给目标 JVM
3. 目标 JVM 的 Signal Handler 检测到文件，启动 Attach Listener 线程
4. Attach Listener 创建 Unix Domain Socket (/tmp/.java_pid<pid>)
5. 外部工具连接到 socket，发送命令
6. Attach Listener 执行命令并返回结果
```

### Q2: 为什么用 SIGQUIT 而不是其他信号?

**答案**:
- SIGQUIT 默认行为是打印线程 dump，不会终止 JVM
- SIGQUIT 已有 handler，可以复用检查 `.attach_pid` 文件
- SIGUSR1/SIGUSR2 可能被应用程序使用
- SIGTERM/SIGINT 会导致 JVM 退出

### Q3: 如何防止未授权用户 attach?

**答案**:
**多层安全机制**:
1. **文件权限**: socket 文件权限 0600，只有所有者可读写
2. **SO_PEERCRED**: 检查连接者的 uid/gid，必须匹配或 root
3. **文件所有者检查**: `.attach_pid` 文件必须由目标进程所有者创建
4. **禁用 Attach**: `-XX:+DisableAttachMechanism` 完全禁用
5. **动态加载控制**: `-XX:-EnableDynamicAgentLoading` 禁止加载 Agent

### Q4: 容器环境下的 Attach 有什么特殊处理?

**答案**:
```
1. PID Namespace 解析:
   - 从 /proc/<pid>/status 读取 NSpid
   - 使用容器内部 PID 构造 socket 路径

2. Mount Namespace 处理:
   - 使用 /proc/<pid>/root/tmp/ 访问容器的 /tmp
   - 使用 /proc/<pid>/cwd/ 访问容器的工作目录

3. 文件创建:
   - 优先在目标 CWD 创建 .attach_pid
   - 失败则回退到 /tmp
```

### Q5: Attach Listener 线程为什么是守护线程?

**答案**:
- 守护线程不会阻止 JVM 退出
- Attach Listener 是服务线程，非业务线程
- 如果 Attach Listener 阻塞在 accept()，JVM 应该能正常退出
- 主线程结束时，守护线程自动终止

### Q6: 协议设计为什么选择二进制格式而不是文本协议?

**答案**:
```
实际协议是混合的:
- 请求: 二进制(0 分隔的字符串)
- 响应: 文本(方便人类阅读)

优点:
1. 简单: 无需复杂的序列化框架
2. 紧凑: 无冗余格式
3. 易于解析: 按 \0 分割即可
4. 向后兼容: 版本号便于扩展
```

### Q7: Attach 机制与 JVM TI 的关系是什么?

**答案**:
```
Attach 机制 vs JVM TI:
- Attach: 通信机制(IPC)
- JVM TI: 工具接口(API)

关系:
Attach 命令 "load" 调用 JVM TI:
  Attach Listener → JvmtiExport::load_agent_library → 
  dlopen Agent → Agent_OnAttach → JVM TI 功能

Arthas 工作原理:
1. 通过 Attach 连接到目标 JVM
2. 发送 "load" 命令加载 arthas-agent.jar
3. Agent 使用 JVM TI 注册 ClassFileLoadHook
4. 后续通过 Instrumentation API 修改字节码
```

## 第 8 章: 实战案例

### 8.1 手动实现 jstack

```java
import com.sun.tools.attach.VirtualMachine;

public class SimpleJStack {
    public static void main(String[] args) throws Exception {
        if (args.length != 1) {
            System.err.println("Usage: SimpleJStack <pid>");
            System.exit(1);
        }
        
        String pid = args[0];
        VirtualMachine vm = VirtualMachine.attach(pid);
        
        try {
            // 执行 threaddump 命令
            InputStream in = ((HotSpotVirtualMachine)vm).execute("threaddump", "-l");
            
            // 读取输出
            BufferedReader reader = new BufferedReader(new InputStreamReader(in));
            String line;
            while ((line = reader.readLine()) != null) {
                System.out.println(line);
            }
        } finally {
            vm.detach();
        }
    }
}
```
