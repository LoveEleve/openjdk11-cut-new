// thread.cpp
bool JavaThread::set_as_starting_thread() {
    // 创建 OSThread 对象
    _osthread = new OSThread(NULL, NULL);
    if (_osthread == NULL) {
        return false;
    }
    
    // 调用 OS 层创建主线程 (附加到当前 OS 线程)
    bool create_result = os::create_main_thread((JavaThread*)this);
    return create_result;
}

**栈保护机制**:
```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                        栈保护页 (Guard Pages) 机制                                │
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                   │
│  为什么需要保护页？                                                               │
│  - 栈溢出会导致内存破坏、安全漏洞                                                 │
│  - 硬件触发 SIGSEGV 比软件检查更高效                                             │
│                                                                                   │
│  三层保护机制：                                                                   │
│  ┌─────────────────────────────────────────────────────────────────────┐        │
│  │  Yellow Zone (警告区) - 约 2 页                                      │        │
│  │  ├── 进入时触发 StackOverflowError                                  │        │
│  │  ├── 允许执行异常处理代码                                            │        │
│  │  └── 可以通过 reguard 恢复                                          │        │
│  ├─────────────────────────────────────────────────────────────────────┤        │
│  │  Red Zone (危险区) - 约 1 页                                         │        │
│  │  ├── 进入时 VM 崩溃                                                 │        │
│  │  └── 保护 VM 关键数据                                               │        │
│  ├─────────────────────────────────────────────────────────────────────┤        │
│  │  Guard Page (硬保护页) - 操作系统级别                                │        │
│  │  ├── mprotect(addr, size, PROT_NONE)                                │        │
│  │  └── 访问触发 SIGSEGV 信号                                          │        │
│  └─────────────────────────────────────────────────────────────────────┘        │
│                                                                                   │
│  触发流程：                                                                       │
│  1. 栈增长触碰 Yellow Zone → JVM 捕获信号 → 抛出 StackOverflowError              │
│  2. 异常处理后 → reguard_stack() 恢复保护                                        │
│  3. 栈继续溢出到 Red Zone → VM 崩溃                                              │
│                                                                                   │
└─────────────────────────────────────────────────────────────────────────────────┘
```

## 🎯 面试高频问题

### Q1: JavaThread 与 OSThread 是什么关系？
- **JavaThread**: JVM 内部的 C++ 对象，包含线程的 Java 层面信息
- **OSThread**: 封装操作系统线程信息的 C++ 对象
- **关系**: JavaThread 持有 OSThread 指针，一一对应

### Q2: JavaThread 与 java.lang.Thread 是什么关系？
- **JavaThread**: C++ 对象，分配在 Native Heap
- **java.lang.Thread**: Java 对象，分配在 Java Heap
- **关系**: JavaThread 的 `_threadObj` 字段指向 java.lang.Thread 实例

### Q3: Thread::current() 是如何实现的？
- 使用 Thread Local Storage (TLS) 机制
- Linux 上通过 `pthread_getspecific()` 获取
- 每个 OS 线程有独立的 TLS 槽位存储 JavaThread 指针

### Q4: 为什么需要栈保护页？
- 检测栈溢出，防止内存破坏
- 硬件触发比软件检查更高效
- 分层保护：Yellow Zone 允许异常处理，Red Zone 防止 VM 崩溃
