4. 结论总结
================================================================================

4.1 _root_regions() 默认构造做了什么
-----------------------------------------
- 仅进行最基本的成员初始化
- 所有指针设为NULL
- 所有布尔值设为false
- 所有计数器设为0
- 这是一个"延迟初始化"模式，真正的初始化在init()中完成

4.2 _root_regions.init(_g1h->survivor(), this) 做了什么
-----------------------------------------
(a) _g1h->survivor() 返回什么:
    - 返回 G1CollectedHeap 对象的 _survivor 成员的地址
    - 类型: const G1SurvivorRegions*
    - 实际就是 &(_g1h->_survivor)
    - 这是一个嵌入式成员对象，不是堆分配的

(b) init() 方法执行:
    - _survivors = survivors  : 保存Survivor区域管理器的指针
    - _cm = cm               : 保存G1ConcurrentMark对象的指针(this)

4.3 G1SurvivorRegions 结构
-----------------------------------------
G1SurvivorRegions {
  _regions: GrowableArray<HeapRegion*>*  // 动态数组，存储Survivor区域指针
}

在JVM启动阶段（G1ConcurrentMark构造时）:
- _len = 0   : 没有Survivor区域（还没有发生过Young GC）
- _max = 8   : 初始容量为8个HeapRegion指针
- _data      : 已分配的数组内存

4.5 设计目的
-----------------------------------------
G1CMRootRegions的作用是管理"根区域"的扫描：

1. 什么是根区域(Root Regions)?
   - 在G1 GC中，根区域特指Young GC后产生的Survivor区域
   - 这些区域包含了从Eden区存活下来的对象

2. 为什么需要扫描根区域?
   - 并发标记开始前，必须先扫描Survivor区域
   - 因为Survivor区域中的对象可能引用Old区域的对象
   - 这些引用必须被识别为根，才能正确进行并发标记

3. _survivors指针的作用:
   - 指向G1CollectedHeap的_survivor成员
   - 通过它可以访问所有Survivor区域的列表
   - 不需要拷贝数据，只保存指针实现共享访问

4. _cm指针的作用:
   - 反向指向G1ConcurrentMark对象
   - 允许G1CMRootRegions调用G1ConcurrentMark的方法
   - 实现双向引用，方便协作
