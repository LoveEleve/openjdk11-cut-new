3. initialize() 内部计算过程
================================================================================

代码: g1ConcurrentMark.cpp:121-138
-----------------------------------------
bool G1CMMarkStack::initialize(size_t initial_capacity, size_t max_capacity) {
  guarantee(_max_chunk_capacity == 0, "G1CMMarkStack already initialized.");

  // TaskQueueEntryChunk 结构大小 / G1TaskQueueEntry 大小
  size_t const TaskEntryChunkSizeInVoidStar = sizeof(TaskQueueEntryChunk) / sizeof(G1TaskQueueEntry);
  // = 8192 / 8 = 1024 (每个chunk占1024个entry的空间，但实际只能存1023个)

  // 计算最大chunk数量
  _max_chunk_capacity = align_up(max_capacity, capacity_alignment()) / TaskEntryChunkSizeInVoidStar;
  // = align_up(16777216, ...) / 1024 = 16384 chunks

  // 计算初始chunk数量
  size_t initial_chunk_capacity = align_up(initial_capacity, capacity_alignment()) / TaskEntryChunkSizeInVoidStar;
  // = align_up(4194304, ...) / 1024 = 4096 chunks

  return resize(initial_chunk_capacity);  // 分配内存
}

================================================================================
8. 工作原理
================================================================================

8.1 内存布局
-----------------------------------------
_base 指向的内存区域:
┌──────────────────────────────────────────────────────────────┐
│ Chunk[0]   │ Chunk[1]   │ Chunk[2]   │ ... │ Chunk[4095]    │
│ (8KB)      │ (8KB)      │ (8KB)      │     │ (8KB)          │
└──────────────────────────────────────────────────────────────┘
│<──────────── 32MB (4096 * 8KB) ─────────────────────────────>│

每个Chunk结构:
┌────────────────────────────────────────────────────┐
│ next (8B) │ data[0] │ data[1] │ ... │ data[1022]  │
│           │ (8B)    │ (8B)    │     │ (8B)        │
└────────────────────────────────────────────────────┘
│<───────────────── 8192 bytes ──────────────────────>│

8.2 Push/Pop 操作
-----------------------------------------
- par_push_chunk(): 将本地队列中的entry批量推入全局栈
- par_pop_chunk(): 从全局栈批量取出entry到本地队列
- 使用chunk为单位操作，减少锁竞争
- 支持多线程并发访问

8.3 扩展机制
-----------------------------------------
- 当栈满时调用expand()
- 容量翻倍，直到达到_max_chunk_capacity
- 只能在STW暂停且栈为空时扩展


================================================================================
9. 设计目的
================================================================================

G1CMMarkStack 是并发标记过程中的"全局灰色对象栈":

1. 作用:
   - 存储"灰色对象"(已标记但未扫描其引用的对象)
   - 当任务本地队列满时，溢出的对象推入此全局栈
   - 当任务本地队列空时，从全局栈取对象

2. 为什么用chunk:
   - 批量操作减少锁竞争
   - 适合多线程并发访问
   - 内存分配效率高

3. 动态扩展:
   - 初始4096 chunks (可存4M对象引用)
   - 最大16384 chunks (可存16M对象引用)
   - 适应不同工作负载
