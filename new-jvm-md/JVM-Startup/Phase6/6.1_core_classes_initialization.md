## 第 0 部分：核心原理 ⭐

### 0.1 本质是什么？

本文分析 **Phase 6.1: 核心类初始化 (Core Classes Initialization)** 的初始化过程：JVM 启动时该组件如何被创建、配置和激活，以及初始化顺序的约束关系。

### 0.2 为什么需要？

JVM 初始化顺序有严格的依赖关系——某些组件必须在其他组件之前初始化。理解初始化顺序有助于排查启动失败问题，也能理解各组件的设计约束。

### 0.3 怎么解决？

追踪初始化函数的调用链，分析每个初始化步骤的前置条件和后置效果，识别关键的初始化顺序约束。

### 0.4 为什么这样设计？

初始化顺序的设计原则：「被依赖的先初始化」。例如内存管理必须在 GC 之前初始化，GC 必须在类加载之前初始化。

```cpp
static void initialize_class(Symbol *class_name, TRAPS) {
```

### 类的 6 种状态

```cpp

enum ClassState {
    allocated,           // 0: 已分配（但未链接）
    loaded,              // 1: 已加载并插入类层次结构（但未链接）
    linked,              // 2: 已成功链接/验证（但未初始化）
```

## 🔬 `initialize_impl()` 详细流程

```cpp
// 源码位置: src/hotspot/share/oops/instanceKlass.cpp:892
void InstanceKlass::initialize_impl(TRAPS) {
    HandleMark hm(THREAD);
    
    // Step 0: 确保类已链接
    link_class(CHECK);
    
    // Step 1-2: 获取初始化锁，等待其他线程完成初始化
    {
        Handle h_init_lock(THREAD, init_lock());
        ObjectLocker ol(h_init_lock, THREAD, h_init_lock() != NULL);
        
        // Step 2: 如果其他线程正在初始化，等待
        while(is_being_initialized() && !is_reentrant_initialization(self)) {
            ol.waitUninterruptibly(CHECK);
        }
        
        // Step 3: 递归初始化检测
        if (is_being_initialized() && is_reentrant_initialization(self)) {
            return;  // 允许递归初始化
        }
        
        // Step 4: 已初始化完成，直接返回
        if (is_initialized()) {
            return;
        }
        
        // Step 5: 错误状态，抛出 NoClassDefFoundError
        if (is_in_error_state()) {
            THROW_MSG(vmSymbols::java_lang_NoClassDefFoundError(), className);
        }
        
        // Step 6: 设置状态为 being_initialized
        set_init_state(being_initialized);
        set_init_thread(self);
    }
    
    // Step 7: 递归初始化父类和接口
    if (!is_interface()) {
        Klass* super_klass = super();
        if (super_klass != NULL && super_klass->should_be_initialized()) {
            super_klass->initialize(THREAD);  // 递归初始化父类
        }
        
        // 初始化实现的接口（如果接口有非静态具体方法）
        if (has_nonstatic_concrete_methods()) {
            initialize_super_interfaces(THREAD);
        }
    }
    
    // Step 8: 执行 <clinit> 方法
    call_class_initializer(THREAD);
    
    // Step 9: 设置状态为 fully_initialized 或 initialization_error
    if (!HAS_PENDING_EXCEPTION) {
        set_initialization_state_and_notify(fully_initialized, CHECK);
    } else {
        set_initialization_state_and_notify(initialization_error, THREAD);
    }
}
```

### 关键设计思想

1. **线程安全**：使用 `init_lock` 保证同一时间只有一个线程初始化
2. **递归初始化**：允许同一线程递归初始化（避免死锁）
3. **父类先初始化**：子类初始化前，必须先初始化父类
4. **错误传播**：初始化失败会被记录，后续访问会抛出 `NoClassDefFoundError`

```cpp
void InstanceKlass::call_class_initializer(TRAPS) {
    // 获取 <clinit> 方法
    methodHandle h_method(THREAD, class_initializer());
    
    if (h_method() != NULL) {

}
```

```cpp
// 源码位置: src/hotspot/share/classfile/javaClasses.cpp:236
void java_lang_String::set_compact_strings(bool value) {
    CompactStringsFixup fix(value);
    // 遍历 String 类的静态字段，找到 COMPACT_STRINGS 并设置值
    InstanceKlass::cast(SystemDictionary::String_klass())->do_local_static_fields(&fix);
}

class CompactStringsFixup : public FieldClosure {
    void do_field(fieldDescriptor* fd) {
        if (fd->name() == vmSymbols::compact_strings_name()) {
            // 找到 String.COMPACT_STRINGS 字段
            oop mirror = fd->field_holder()->java_mirror();
            mirror->bool_field_put(fd->offset(), _value);  // 设置值
        }
    }
};
```

### Q2: 类初始化的线程安全是如何保证的？

```cpp
// 使用初始化锁 + 状态机保证线程安全
{
    Handle h_init_lock(THREAD, init_lock());  // 获取初始化锁
    ObjectLocker ol(h_init_lock, THREAD);
    
    // 如果其他线程正在初始化，等待
    while(is_being_initialized() && !is_reentrant_initialization(self)) {
        ol.waitUninterruptibly(CHECK);  // 等待初始化完成
    }
    
    // 设置当前线程为初始化线程
    set_init_state(being_initialized);
    set_init_thread(self);
}
```

### Q3: 为什么允许递归初始化？

```
场景：String 类的 <clinit> 方法中访问了 String 的其他静态方法

如果不允许递归初始化：
  → 线程 A 初始化 String，进入 being_initialized 状态
  → String.<clinit> 调用 String.valueOf()
  → String.valueOf() 需要初始化 String
  → String 正在被初始化，线程 A 等待
  → 死锁！

解决方案：
  is_reentrant_initialization(self) 检测当前线程是否就是初始化线程
  如果是，允许递归，直接返回
```

## 📈 总结

### Phase 6.1 核心类初始化要点

| 要点 | 说明 |
|-----|------|
| **初始化顺序** | String → System → Class → ThreadGroup |
| **状态机** | allocated → loaded → linked → being_initialized → fully_initialized |
| **线程安全** | 使用 init_lock + 状态机保证 |
| **递归初始化** | 允许同一线程递归初始化，避免死锁 |
| **父类优先** | 子类初始化前，必须先初始化父类 |
| **CompactStrings** | 在 String 初始化后注入，启用字符串压缩 |
