# 3.3 TLAB 相关设置

## 概述

TLAB（Thread Local Allocation Buffer）是 JVM 为每个线程预先分配的一小块内存区域，用于快速分配小对象。`universe_init()` 中的 TLAB 初始化分为两步：

```cpp
// 步骤 1: 设置 TLAB 最大尺寸
ThreadLocalAllocBuffer::set_max_size(Universe::heap()->max_tlab_size());

// 步骤 2: 启动初始化
if (UseTLAB) {
    ThreadLocalAllocBuffer::startup_initialization();
}
```

## 1. TLAB 的作用

### 1.1 为什么需要 TLAB？

```
没有 TLAB 的对象分配:
┌────────────────────────────────────────────────────────────────────┐
│  Thread 1        Thread 2        Thread 3                          │
│     │               │               │                              │
│     ▼               ▼               ▼                              │
│  ┌──────────────────────────────────────────┐                      │
│  │            共享 Eden 区                  │                      │
│  │  ┌─────────────────────────────────────┐ │                      │
│  │  │       分配指针 (需要 CAS 竞争)      │ │                      │
│  │  └─────────────────────────────────────┘ │                      │
│  └──────────────────────────────────────────┘                      │
│                                                                     │
│  问题: 多线程分配需要 CAS 操作，存在竞争开销                        │
└────────────────────────────────────────────────────────────────────┘

有 TLAB 的对象分配:
┌────────────────────────────────────────────────────────────────────┐
│  Thread 1           Thread 2           Thread 3                    │
│     │                  │                  │                        │
│     ▼                  ▼                  ▼                        │
│  ┌─────────┐       ┌─────────┐       ┌─────────┐                   │
│  │ TLAB 1  │       │ TLAB 2  │       │ TLAB 3  │                   │
│  │ (私有)  │       │ (私有)  │       │ (私有)  │                   │
│  └─────────┘       └─────────┘       └─────────┘                   │
│      │                 │                 │                         │
│      └─────────────────┼─────────────────┘                         │
│                        ▼                                           │
│  ┌──────────────────────────────────────────┐                      │
│  │             Eden 区                      │                      │
│  └──────────────────────────────────────────┘                      │
│                                                                     │
│  优点: 每个线程在自己的 TLAB 内分配，无需同步!                      │
└────────────────────────────────────────────────────────────────────┘
```

### 1.2 TLAB 分配 vs 慢路径分配

| 分配方式 | 触发条件 | 性能 |
|----------|----------|------|
| **TLAB 分配** | 对象 ≤ TLAB 剩余空间 | 极快（指针碰撞） |
| **TLAB 外分配** | TLAB 剩余空间不足 | 较慢（需要同步） |
| **巨型对象分配** | 对象 ≥ Region/2 | 最慢（特殊路径） |

## 2. TLAB 最大尺寸设置

### 2.1 max_tlab_size() 计算

```cpp
// src/hotspot/share/gc/g1/g1CollectedHeap.cpp:2929
size_t G1CollectedHeap::max_tlab_size() const {
    return align_down(_humongous_object_threshold_in_words, MinObjAlignment);
}

// _humongous_object_threshold_in_words 的设置
// src/hotspot/share/gc/g1/g1CollectedHeap.cpp:1511
_humongous_object_threshold_in_words = humongous_threshold_for(HeapRegion::GrainWords);

// humongous_threshold_for 的定义
static size_t humongous_threshold_for(size_t region_size) {
    return (region_size / 2);  // Region 大小的一半
}
```

### 2.2 计算结果（8GB 堆）

```
Region 大小:
  HeapRegion::GrainWords = 4MB / 8 = 512K words

巨型对象阈值:
  _humongous_object_threshold_in_words = 512K / 2 = 256K words = 2MB

TLAB 最大尺寸:
  max_tlab_size = align_down(256K, MinObjAlignment)
                ≈ 256K words
                = 2MB

结论: TLAB 最大 2MB，确保 TLAB 内的对象永远不会触发巨型对象分配
```

### 2.3 为什么 TLAB 最大是 Region/2？

```
设计约束:
┌─────────────────────────────────────────────────────────────────────┐
│  1. 巨型对象定义: 大小 ≥ Region/2 的对象                            │
│  2. 巨型对象需要特殊处理（跨 Region 分配）                          │
│  3. TLAB 是为普通对象快速分配设计的                                 │
│  4. TLAB 内的对象必须 < 巨型阈值                                    │
│  5. 因此: TLAB 最大尺寸 = 巨型阈值 - 1 ≈ Region/2                  │
└─────────────────────────────────────────────────────────────────────┘

这样保证:
  - TLAB 分配走快速路径
  - 巨型对象走特殊路径
  - 两者互不干扰
```

## 3. ThreadLocalAllocBuffer 结构

### 3.1 类定义

```cpp
// src/hotspot/share/gc/shared/threadLocalAllocBuffer.hpp
class ThreadLocalAllocBuffer: public CHeapObj<mtThread> {
private:
  // 实例成员 (每个线程一份)
  HeapWord* _start;           // TLAB 起始地址
  HeapWord* _top;             // 下一个分配位置
  HeapWord* _pf_top;          // 预取水位线
  HeapWord* _end;             // 分配结束位置（可能是采样点）
  HeapWord* _allocation_end;  // 实际 TLAB 结束位置
  
  size_t _desired_size;       // 期望大小（动态调整）
  size_t _refill_waste_limit; // 浪费限制（换 TLAB 的阈值）
  
  // 统计信息
  unsigned _number_of_refills;
  unsigned _fast_refill_waste;
  unsigned _slow_refill_waste;
  unsigned _gc_waste;
  
  // 静态成员 (所有线程共享)
  static size_t _max_size;              // TLAB 最大尺寸上限
  static unsigned _target_refills;       // 期望重填次数
  static int _reserve_for_allocation_prefetch;  // C2 预取保留空间
};
```

### 3.2 内存布局

```
TLAB 内存布局:
┌─────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  _start                    _top        _end      _allocation_end    │
│     │                       │           │              │             │
│     ▼                       ▼           ▼              ▼             │
│  ┌──┼───────────────────────┼───────────┼──────────────┼──┐         │
│  │  │     已分配对象        │  可分配   │   保留区域   │  │         │
│  │  │  [obj1][obj2][obj3]   │   空间    │  (C2预取用)  │  │         │
│  └──┴───────────────────────┴───────────┴──────────────┴──┘         │
│     │                       │           │              │             │
│     │◄─────── used ────────►│           │              │             │
│     │                       │◄─ free ──►│              │             │
│     │◄──────────────────── _desired_size ─────────────►│             │
│                                                                      │
│  分配流程:                                                           │
│  1. 检查 _top + obj_size <= _end                                    │
│  2. 如果满足，分配对象: result = _top; _top += obj_size;            │
│  3. 如果不满足，尝试换一个新 TLAB                                   │
└─────────────────────────────────────────────────────────────────────┘
```

## 4. startup_initialization() 分析

### 4.1 核心逻辑

```cpp
// src/hotspot/share/gc/shared/threadLocalAllocBuffer.cpp:254
void ThreadLocalAllocBuffer::startup_initialization() {
  // 1. 计算目标重填次数
  _target_refills = 100 / (2 * TLABWasteTargetPercent);  // = 50
  _target_refills = MAX2(_target_refills, 2U);
  
  // 2. 创建全局统计收集器
  _global_stats = new GlobalTLABStats();
  
  // 3. 为 C2 编译器预留预取空间
#ifdef COMPILER2
  if (is_server_compilation_mode_vm()) {
    int lines = MAX2(AllocatePrefetchLines, AllocateInstancePrefetchLines) + 2;
    _reserve_for_allocation_prefetch = 
        (AllocatePrefetchDistance + AllocatePrefetchStepSize * lines) / HeapWordSize;
  }
#endif

  // 4. 重新初始化主线程的 TLAB
  Thread::current()->tlab().initialize();
}
```

### 4.2 _target_refills 的含义

```
目标重填次数计算:
  _target_refills = 100 / (2 * TLABWasteTargetPercent)
                  = 100 / (2 * 1)
                  = 50

含义:
  - 假设每个 TLAB 平均使用到一半时触发 GC
  - 目标是在两次 GC 之间，每个线程重填 50 次 TLAB
  - 这个值用于计算初始 TLAB 大小

初始 TLAB 大小计算:
  desired_size = Eden / (线程数 × _target_refills)
  
  例如: Eden = 400MB, 线程数 = 100
  desired_size = 400MB / (100 × 50) = 80KB
```

### 4.3 C2 预取空间

```
为什么需要预留空间?

C2 编译器会生成预取指令优化内存访问:
┌─────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  普通分配（不预取）:                                                 │
│  1. 分配对象位置                                                    │
│  2. CPU 等待内存准备好  ← 慢! 内存比 CPU 慢 100 倍                  │
│  3. 写入数据                                                        │
│                                                                      │
│  预取分配:                                                          │
│  1. 预取指令: "内存，提前准备后面的空间"                            │
│  2. 分配对象位置                                                    │
│  3. 写入数据  ← 内存已准备好，不用等!                               │
│                                                                      │
│  问题: 预取指令会访问 TLAB 末尾之后的内存                           │
│                                                                      │
│  TLAB 布局:                                                         │
│  ┌─────────────────────────────────┬────────────┐                   │
│  │         可分配区域              │  保留区    │                   │
│  │                                 │            │                   │
│  │  当前位置─────→ 预取这里 ───────→│←──────────→│                   │
│  │              ↑                  │ 安全空间   │                   │
│  │         可能越界!               │            │                   │
│  └─────────────────────────────────┴────────────┘                   │
│                                                                      │
│  如果没有保留区，预取指令可能访问 TLAB 外部，导致程序崩溃!          │
└─────────────────────────────────────────────────────────────────────┘

计算公式:
  _reserve_for_allocation_prefetch = 
      (AllocatePrefetchDistance + AllocatePrefetchStepSize × lines) / HeapWordSize
  
  典型值: 约 16-32 个 HeapWord (128-256 字节)
```

## 5. TLAB 浪费管理

### 5.1 refill_waste_limit

```cpp
// 初始浪费限制
size_t initial_refill_waste_limit() { 
    return desired_size() / TLABRefillWasteFraction;  // 默认 64
}

// 例如: desired_size = 2MB
// refill_waste_limit = 2MB / 64 = 32KB
```

### 5.2 浪费决策逻辑

```
场景: TLAB 快用完了，要分配一个 40KB 的对象

┌─────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  情况 1: 剩余空间 = 50KB (> 32KB 浪费限制)                          │
│  ┌──────────────────────────────────────────────┐                   │
│  │  [已分配对象]        [剩余 50KB]             │                   │
│  └──────────────────────────────────────────────┘                   │
│  决策: 不换 TLAB，在 Eden 慢路径分配这个 40KB 对象                  │
│  原因: 丢掉 50KB 太浪费了                                           │
│                                                                      │
│  情况 2: 剩余空间 = 20KB (< 32KB 浪费限制)                          │
│  ┌──────────────────────────────────────────────┐                   │
│  │  [已分配对象]                      [剩余20KB]│                   │
│  └──────────────────────────────────────────────┘                   │
│  决策: 换一个新的 TLAB                                              │
│  原因: 剩余空间不多，浪费可接受                                     │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

## 9. 关键要点总结

| 要点 | 说明 |
|------|------|
| **TLAB 作用** | 无锁快速分配，避免多线程竞争 |
| **最大尺寸** | Region/2 = 2MB（确保不触发巨型对象路径）|
| **目标重填次数** | 50 次（用于计算初始 TLAB 大小）|
| **浪费限制** | desired_size/64（决定是否换新 TLAB）|
| **预取保留** | ~256 字节（防止 C2 预取越界）|
