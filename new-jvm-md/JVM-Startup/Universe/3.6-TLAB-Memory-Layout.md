```
TLAB 本身是管理结构，不是 Java 对象

- TLAB 指向的内存区域在 Java 堆（Eden）
```

## 四、核心字段详解

### 4.1 _start - TLAB 起始地址

```cpp
HeapWord* _start;
```

**含义**: TLAB 在 Java 堆中的起始地址

**赋值时机**:
1. `startup_initialization()` 中初始化主线程 TLAB
2. 每次 TLAB refill 时从 Eden 分配新 TLAB

**GDB 查看**:
```gdb
(gdb) print Thread::current()->tlab().start()
$1 = (HeapWord*) 0x80000000

(gdb) x/4gx 0x80000000  # 查看 TLAB 起始内容
0x80000000: 0x0000000000000001  0x0000000000000000
0x80000010: 0x0000000000000000  0x0000000000000000
```

### 4.2 _top - Bump Pointer

```cpp
HeapWord* _top;
```

**含义**: 下一个对象的分配位置

**分配过程**:
```
分配前:
  _top = 0x80000100
  
分配一个 24 字节 (3 HeapWords) 的对象:
  新 _top = 0x80000100 + 24 = 0x80000118
  返回地址 = 旧的 _top = 0x80000100
  
分配后:
  _top = 0x80000118
```

**汇编级别** (快速分配):
```asm
; x86_64 汇编
mov    0x60(%r15),%rax      ; rax = _top (从线程局部存储读取)
lea    0x18(%rax),%rbx      ; rbx = new_top = top + 24
cmp    0x70(%r15),%rbx      ; compare with _end
ja     slow_path            ; if new_top > end, jump to slow path
mov    %rbx,0x60(%r15)      ; _top = new_top
; rax now holds the allocated object address
```

### 4.3 _end - 分配边界

```cpp
HeapWord* _end;
```

**含义**: 可分配的结束位置（可能包含采样点）

**特殊用途**: 堆采样 (Heap Sampling)
```cpp
// 设置采样点：将 _end 提前，触发分配时进入慢路径
void set_sample_end() {
  _end = _allocation_end - sample_interval;
}
```

**与 _allocation_end 的区别**:
- `_allocation_end`: 实际 TLAB 结束（物理边界）
- `_end`: 逻辑分配边界（可能因采样提前）

### 4.4 _desired_size - 动态调整

```cpp
size_t _desired_size;
```

**含义**: 期望的 TLAB 大小（HeapWords 单位）

**计算逻辑**:
```cpp
size_t initial_desired_size() {
  if (TLABSize > 0) {
    return TLABSize / HeapWordSize;  // 用户指定
  }
  
  // 自动计算
  unsigned nof_threads = global_stats()->allocating_threads_avg();
  size_t capacity = Universe::heap()->tlab_capacity(myThread()) / HeapWordSize;
  
  return capacity / (nof_threads * target_refills());
}
```

**调整策略**:
```
GC 后根据统计调整:
- 如果频繁 refill (浪费多) → 增大 _desired_size
- 如果 GC 时剩余多 → 减小 _desired_size
- 范围限制: min_size() ~ max_size()
```

### 4.5 _refill_waste_limit - 浪费控制

```cpp
size_t _refill_waste_limit;
```

**作用**: 判断是否应该保留当前 TLAB 还是 refill

**判断逻辑**:
```cpp
// 尝试分配对象，但剩余空间不足
if (obj_size > free()) {
  // 如果剩余空间 < 浪费限制，直接丢弃（浪费少）
  if (free() < refill_waste_limit()) {
    return false;  // 触发 refill
  }
  // 如果剩余空间 > 浪费限制，保留当前 TLAB，走慢分配
  // （剩余空间还能装下其他小对象）
}
```

**默认值**:
```cpp
size_t initial_refill_waste_limit() {
  return desired_size() / TLABRefillWasteFraction;  // 默认 /64
}
// 2MB / 64 = 32KB
```

## 五、静态成员详解

### 5.1 _max_size - 2MB 限制

```cpp
static size_t _max_size;  // = 262144 words = 2MB
```

**设置位置**: `Universe::initialize_heap()` L958
```cpp
ThreadLocalAllocBuffer::set_max_size(Universe::heap()->max_tlab_size());
```

**为什么是 2MB?**
```
G1 Region 大小 = 4MB
Humongous 对象阈值 = Region/2 = 2MB

TLAB 必须 < Humongous 阈值，因为:
1. TLAB 在单个 Region 内分配
2. TLAB 内对象都是普通对象（非 Humongous）
3. 如果 TLAB > 2MB，可能触发 Humongous 分配逻辑
```

### 5.2 _target_refills - 50 次的含义

```cpp
static unsigned _target_refills;  // 默认 = 50
```

**计算**:
```cpp
_target_refills = 100 / (2 * TLABWasteTargetPercent);
// TLABWasteTargetPercent 默认 = 1
// _target_refills = 100 / (2 * 1) = 50
```

**含义**: 期望两次 GC 之间，每个 TLAB 平均 refill 50 次

**推导逻辑**:
```
假设:
  - 每个 TLAB 平均使用 1/2 (另一半浪费)
  - 期望浪费比例 = 1% (TLABWasteTargetPercent)
  
计算:
  浪费比例 = 1/2 / refill次数 = 1%
  refill次数 = 1/2 / 0.01 = 50
```

## 七、面试常见问题

### Q1: TLAB 是什么？为什么需要 TLAB？

**答**: TLAB (Thread Local Allocation Buffer) 是线程私有的分配缓冲区，位于 Eden 区。需要 TLAB 是为了避免多线程分配时的 CAS 竞争——每个线程在自己的 TLAB 内用 bump-the-pointer 分配，无需同步。

### Q2: TLAB 的最大大小是多少？为什么？

**答**: 默认是 2MB。因为 G1 的 Humongous 对象阈值是 Region/2 = 2MB。TLAB 必须小于此阈值，确保 TLAB 内分配的都是普通对象，不会触发 Humongous 分配逻辑。

### Q3: TLAB 如何动态调整大小？

**答**: JVM 根据统计信息动态调整：
1. 如果频繁 refill（浪费多）→ 增大 TLAB
2. 如果 GC 时 TLAB 剩余多 → 减小 TLAB
3. 调整范围受限于 min_size (约 2KB) 和 max_size (2MB)

### Q4: 什么情况下会放弃 TLAB，走慢分配？

**答**: 
1. TLAB 剩余空间不足，且剩余 > waste_limit → 保留 TLAB，走慢分配
2. TLAB 剩余空间不足，且剩余 < waste_limit → 丢弃 TLAB，refill
3. 分配 Humongous 对象 → 直接在堆上分配

## 八、总结

| 要点 | 说明 |
|------|------|
| **位置** | TLAB 管理结构在 C 堆，指向的内存区域在 Java 堆 Eden |
| **大小** | 默认几百 KB 到 2MB，动态调整 |
| **核心机制** | bump-the-pointer 快速分配 |
| **关键字段** | `_start`, `_top`, `_end` 管理分配指针 |
| **静态配置** | `_max_size`=2MB, `_target_refills`=50 |
| **性能优势** | 无锁分配，比堆分配快 10 倍以上 |

**一句话总结**: TLAB 是每个线程的私有快速分配区，通过 bump-the-pointer 实现无锁分配，大小动态调整但不超过 2MB（Humongous 阈值）。
