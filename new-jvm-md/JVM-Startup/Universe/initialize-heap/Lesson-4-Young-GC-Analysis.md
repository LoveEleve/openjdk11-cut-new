#### 4.2.2 copy_to_survivor_space 源码

```cpp
// g1ParScanThreadState.cpp:214
// 对象复制到 Survivor 区

oop G1ParScanThreadState::copy_to_survivor_space(oop obj) {
    // 1. 计算对象大小
    size_t obj_size = obj->size();
    
    // 2. 尝试在 TLAB 分配
    HeapWord* dest = _plab->allocate(obj_size);
    
    // 3. 如果 TLAB 满了，分配新的
    if (dest == NULL) {
        dest = allocate_slow(obj_size);
    }
    
    // 4. 复制对象到新地址
    Copy::aligned_disjoint_words(obj, dest, obj_size);
    
    // 5. 更新对象头
    oop obj_end = oop(dest + obj_size);
    obj_end->set_mark(markWord::forwardee_mark());
    obj->forward_to(obj_end);
    
    // 6. 返回新地址
    return obj_end;
}
```

## 八、面试级 Q&A

### Q1：Young GC 和 Old GC 有什么区别？

**答**：

| 特性 | Young GC | Old GC (Mixed) |
|------|----------|----------------|
| **回收区域** | Eden + Survivor | Eden + 部分 Old |
| **触发条件** | Eden 满 | 老年代达到阈值 |
| **停顿时间** | 较短 | 较长 |
| **频率** | 高 | 低 |
| **存活对象** | 少 | 多 |

---

### Q2：对象分配流程是什么？

**答**：

```
1. TLAB 分配 → 快速路径 (~5ns)
2. 共享 TLAB → 次快
3. 新 TLAB → 稍慢
4. Humongous → 直接 Old
```

---

### Q3：对象晋升的条件是什么？

**答**：

```
1. 年龄达到 MaxTenuringThreshold (默认 15)
2. Survivor 区空间不足（动态提前晋升）
3. 大对象直接老年代
```

---

### Q4：GC Roots 包括哪些？

**答**：

```
1. 线程栈（局部变量）
2. 静态变量
3. JNI 句柄
4. 虚拟机栈
5. 监视器
6. 偏向锁
```

---

### Q5：为什么 Young GC 很快？

**答**：

```
1. 只扫描年轻代
2. 存活对象少（大多数死亡）
3. 使用 TLAB 快速分配
4. 多线程并行
5. 无需扫描老年代
```

---

### Q6：对象复制和引用的更新？

**答**：

```
1. 复制对象到新地址
2. 原对象头设置为 forward pointer
3. 遍历所有字段，更新引用
4. 形成对象链，继续遍历
```

---

### Q7：为什么需要 Survivor 区？

**答**：

```
1. 容纳年轻代存活对象
2. 年龄计算场所
3. 过滤短期存活对象
4. 减少老年代碎片
```

## 九、总结

### 9.1 核心要点

| 阶段 | 核心功能 |
|------|----------|
| **触发** | Eden 满 |
| **Roots 扫描** | 找到根对象 |
| **对象复制** | 复制存活对象到 Survivor |
| **引用更新** | 更新所有引用指针 |
| **清理** | 释放死亡对象空间 |

| 停顿时间 | 10-200ms |
| 存活对象比例 | < 10% |
| 对象复制占比 | 40-50% |
