# 3.4 压缩指针配置 (Compressed Oops)

## 概述

压缩指针（Compressed Ordinary Object Pointers）是 64 位 JVM 的重要优化，将 64 位对象指针压缩为 32 位存储，节省约 20-30% 的堆内存。

`initialize_heap()` 完成后，根据堆地址范围确定最终的压缩指针模式：

```cpp
// src/hotspot/share/memory/universe.cpp:960-991
if (UseCompressedOops) {
    // 1. 判断是否需要移位
    if (heap_end > UnscaledOopHeapMax) {     // > 4GB
        set_narrow_oop_shift(LogMinObjAlignmentInBytes);  // = 3
    }
    // 2. 判断是否可以用零基址
    if (heap_end <= OopEncodingHeapMax) {    // ≤ 32GB
        set_narrow_oop_base(0);
    }
}
```

## 1. 四种压缩指针模式

### 1.1 模式枚举

```cpp
// src/hotspot/share/memory/universe.hpp:405
enum NARROW_OOP_MODE {
    UnscaledNarrowOop   = 0,  // 32-bit
    ZeroBasedNarrowOop  = 1,  // Zero based
    DisjointBaseNarrowOop = 2,  // Non-zero disjoint base
    HeapBasedNarrowOop  = 3,  // Non-zero based
};
```

### 1.2 模式判断逻辑

```cpp
// src/hotspot/share/memory/universe.cpp:1127
NARROW_OOP_MODE Universe::narrow_oop_mode() {
    if (narrow_oop_base_disjoint()) {
        return DisjointBaseNarrowOop;   // 基址与堆不重叠
    }
    if (narrow_oop_base() != 0) {
        return HeapBasedNarrowOop;      // 需要基址偏移
    }
    if (narrow_oop_shift() != 0) {
        return ZeroBasedNarrowOop;      // 只需移位
    }
    return UnscaledNarrowOop;           // 无需任何计算
}
```

## 2. 四种模式详解

### 2.1 Unscaled 模式（堆 ≤ 4GB）

```
┌─────────────────────────────────────────────────────────────────────┐
│  条件: heap_end ≤ 4GB (UnscaledOopHeapMax)                          │
│  参数: base = 0, shift = 0                                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  编码: narrow_oop = (uint32_t)oop                                   │
│  解码: oop = (uint64_t)narrow_oop                                   │
│                                                                      │
│  地址空间:                                                          │
│  ┌────────────────────────────────────────────────────────────────┐ │
│  │  0GB              2GB              4GB                         │ │
│  │   │                │                │                          │ │
│  │   │   [保留]       │    堆(≤2GB)    │                          │ │
│  │   │                │◄──────────────►│                          │ │
│  └────────────────────────────────────────────────────────────────┘ │
│                                                                      │
│  示例:                                                              │
│    oop = 0x00000000_80000100 (2GB + 256)                            │
│    narrow_oop = 0x80000100                                          │
│    恢复: 0x80000100 → 0x00000000_80000100 ✓                         │
│                                                                      │
│  性能: 最优 (零开销)                                                │
│  限制: 堆大小 ≤ 4GB - HeapBaseMinAddress(2GB) ≈ 2GB                │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 ZeroBased 模式（4GB < 堆 ≤ 32GB）

```
┌─────────────────────────────────────────────────────────────────────┐
│  条件: heap_end ≤ 32GB (OopEncodingHeapMax), heap_end > 4GB        │
│  参数: base = 0, shift = 3                                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  编码: narrow_oop = oop >> 3                                        │
│  解码: oop = narrow_oop << 3                                        │
│                                                                      │
│  原理: 对象 8 字节对齐，低 3 位永远是 0                              │
│        32 位可表示 2^32 × 8 = 32GB 地址空间                         │
│                                                                      │
│  地址空间:                                                          │
│  ┌────────────────────────────────────────────────────────────────┐ │
│  │  0GB      4GB      8GB     16GB     24GB     32GB              │ │
│  │   │        │        │        │        │        │               │ │
│  │   │[保留]  │                                   │               │ │
│  │   │        │◄─────────── 堆 (≤30GB) ──────────►│               │ │
│  └────────────────────────────────────────────────────────────────┘ │
│                                                                      │
│  示例 (8GB 堆，起始 24GB):                                          │
│    oop = 0x00000006_00000100 (24GB + 256)                           │
│    narrow_oop = 0x600000100 >> 3 = 0xC0000020                       │
│    恢复: 0xC0000020 << 3 = 0x00000006_00000100 ✓                    │
│                                                                      │
│  性能: 较优 (一次位移)                                              │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.3 DisjointBase 模式（特殊情况）

```
┌─────────────────────────────────────────────────────────────────────┐
│  条件: base ≠ 0, 且 base 的高位与堆地址不重叠                       │
│  参数: base = 特定值, shift = 3                                     │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  编码: narrow_oop = oop >> 3                                        │
│  解码: oop = base + (narrow_oop << 3)                               │
│                                                                      │
│  特点: 编码时可以省略减去 base（因为位不重叠）                       │
│        解码时必须加上 base                                          │
│                                                                      │
│  判断条件 (is_disjoint_heap_base_address):                          │
│    (addr & 0x1FFFFFFF) == 0                                         │
│    即 base 的低 29 位全为 0                                         │
│                                                                      │
│  性能: 次优 (编码一次位移，解码位移+加法)                           │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.4 HeapBased 模式（堆 > 32GB）

```
┌─────────────────────────────────────────────────────────────────────┐
│  条件: heap_end > 32GB，且 base 与堆地址重叠                        │
│  参数: base = 堆起始地址, shift = 3                                 │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  编码: narrow_oop = (oop - base) >> 3                               │
│  解码: oop = base + (narrow_oop << 3)                               │
│                                                                      │
│  地址空间:                                                          │
│  ┌────────────────────────────────────────────────────────────────┐ │
│  │     32GB              64GB              96GB                   │ │
│  │      │                  │                 │                    │ │
│  │      │    堆 (>32GB)    │                 │                    │ │
│  │      │◄────────────────►│                 │                    │ │
│  │      ↑                                                         │ │
│  │     base                                                       │ │
│  └────────────────────────────────────────────────────────────────┘ │
│                                                                      │
│  示例:                                                              │
│    base = 0x00000008_00000000 (32GB)                                │
│    oop = 0x00000008_00000100 (32GB + 256)                           │
│    narrow_oop = (0x800000100 - 0x800000000) >> 3 = 0x20             │
│    恢复: 0x800000000 + (0x20 << 3) = 0x800000100 ✓                  │
│                                                                      │
│  性能: 最差 (编码加减法+位移，解码位移+加法)                        │
│  限制: 仍然只能寻址 32GB 堆                                         │
└─────────────────────────────────────────────────────────────────────┘
```

## 3. 模式对比表

| 模式 | 堆大小 | base | shift | 编码 | 解码 | 性能 |
|------|--------|------|-------|------|------|------|
| **Unscaled** | ≤ 4GB | 0 | 0 | 截断 | 零扩展 | ⭐⭐⭐⭐⭐ |
| **ZeroBased** | ≤ 32GB | 0 | 3 | >>3 | <<3 | ⭐⭐⭐⭐ |
| **DisjointBase** | >32GB | 特殊 | 3 | >>3 | base + (<<3) | ⭐⭐⭐ |
| **HeapBased** | >32GB | 堆起始 | 3 | -base >>3 | base + (<<3) | ⭐⭐ |

## 4. 关键常量

```cpp
// src/hotspot/share/utilities/globalDefinitions.hpp

// Unscaled 模式上限 = 4GB
const uint64_t UnscaledOopHeapMax = (uint64_t(max_juint) + 1);  // 0x100000000

// ZeroBased 模式上限 = 32GB
extern uint64_t OopEncodingHeapMax;  // = 4GB << 3 = 32GB

// 最小对象对齐 = 8 字节
LogMinObjAlignmentInBytes = 3;  // 2^3 = 8
```

### 4.1 OopEncodingHeapMax 的计算

```cpp
// src/hotspot/share/runtime/arguments.cpp:1639
OopEncodingHeapMax = (uint64_t(max_juint) + 1) << LogMinObjAlignmentInBytes;

```

## 5. 模式选择流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                    压缩指针模式选择流程                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  initialize_heap() 完成后:                                          │
│                                                                      │
│  1. 检查堆结束地址是否超过 4GB                                       │
│     if (heap_end > UnscaledOopHeapMax) {                            │
│         shift = 3;  // 需要移位                                     │
│     } else {                                                        │
│         shift = 0;  // Unscaled 模式                                │
│     }                                                               │
│                                                                      │
│  2. 检查堆结束地址是否在 32GB 内                                     │
│     if (heap_end <= OopEncodingHeapMax) {                           │
│         base = 0;   // 可以用零基址                                 │
│     } else {                                                        │
│         base = 堆起始地址;  // 必须用基址偏移                        │
│     }                                                               │
│                                                                      │
│  3. 最终模式判断:                                                   │
│     ┌─────────────────────────────────────────────────────────────┐ │
│     │  base=0, shift=0  →  Unscaled     (堆≤4GB)                  │ │
│     │  base=0, shift=3  →  ZeroBased    (4GB<堆≤32GB)             │ │
│     │  base≠0, disjoint →  DisjointBase (特殊情况)                │ │
│     │  base≠0, overlap  →  HeapBased    (堆>32GB)                 │ │
│     └─────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────┘
```

## 7. 隐式空指针检查

### 7.1 什么是隐式空指针检查？

```
显式空指针检查:
  if (obj == null) throw NullPointerException;
  obj.field = value;  // 两条指令

隐式空指针检查:
  obj.field = value;  // 一条指令
  // 如果 obj 是 null，访问 null.field 会触发 SIGSEGV
  // JVM 捕获信号并转换为 NullPointerException
```

### 7.2 保护页机制

```
堆布局（带保护页）:
┌─────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  ┌─────────┐ ┌───────────────────────────────────────────┐          │
│  │ 保护页  │ │                 Java 堆                   │          │
│  │ (4KB)   │ │                                           │          │
│  │ PROT_   │ │                                           │          │
│  │ NONE    │ │                                           │          │
│  └─────────┘ └───────────────────────────────────────────┘          │
│  │         │                                                        │
│  │ 不可访问│                                                        │
│  │         │                                                        │
│  ↓         ↓                                                        │
│  null.field 访问这里 → SIGSEGV → NullPointerException               │
└─────────────────────────────────────────────────────────────────────┘

条件: _use_implicit_null_checks = (heap_base 前有保护页)
```

## 9. 性能影响

### 9.1 编码/解码开销

```
Unscaled 模式:
  编码: mov eax, rdi        # 1 条指令，零开销
  解码: mov rdi, eax        # 1 条指令，零扩展

ZeroBased 模式:
  编码: shr rdi, 3          # 1 条指令
  解码: shl rax, 3          # 1 条指令

HeapBased 模式:
  编码: sub rdi, base; shr rdi, 3  # 2 条指令
  解码: shl rax, 3; add rax, base  # 2 条指令
```

### 9.2 内存节省

```
64 位不使用压缩指针:
  每个对象引用: 8 字节
  
使用压缩指针:
  每个对象引用: 4 字节
  节省: 50%

实际堆内存节省:
  典型应用: 约 20-30%
  引用密集型应用: 可达 40%
```

## 10. 关键要点总结

| 要点 | 说明 |
|------|------|
| **为什么 32GB 限制** | 32 位 × 8 字节对齐 = 32GB 寻址空间 |
| **最优配置** | 堆 ≤ 32GB，使用 ZeroBased 模式 |
| **8GB 堆典型** | 起始 24GB，ZeroBased 模式 (base=0, shift=3) |
| **超过 32GB** | 必须使用 HeapBased，性能略降 |
| **隐式空检查** | 需要堆前有保护页，节省一条指令 |
