# Phase 2: os::init_2() 深度分析

> 源码位置: `src/hotspot/os/linux/os_linux.cpp:5831`

## 1. 功能定位

### 1.1 一句话概括

**`os::init_2()` 是 JVM 启动时的操作系统模块二次初始化，在参数解析完成后执行，主要负责信号处理机制的建立、栈大小配置和文件描述符限制设置。**

### 1.2 在整体流程中的位置

```
Threads::create_vm()
    │
    ├── os::init()                    // Phase 0: OS 基础初始化（页大小、CPU 信息）
    ├── Arguments::parse()            // Phase 1: JVM 参数解析
    ├── Arguments::apply_ergo()       // Phase 1: 自动调优
    │
    ├──► os::init_2()                 // 【当前分析】Phase 2: OS 模块二次初始化
    │       ├── SR_initialize()       //   信号挂起/恢复机制
    │       ├── signal_sets_init()    //   信号集初始化
    │       ├── install_signal_handlers() // 安装信号处理器
    │       └── ...
    │
    ├── SafepointMechanism::initialize()  // Polling Page
    ├── vm_init_globals()             // VM 全局数据结构
    └── JavaThread* main_thread = new JavaThread() // Phase 3
```

### 1.3 为什么需要二次初始化？

| 原因 | 说明 |
|------|------|
| **依赖参数解析** | 栈大小（`-Xss`）、信号相关参数需要先解析 |
| **时序要求** | 信号处理器必须在创建线程之前就绑定好 |
| **资源限制** | 文件描述符限制需要在启动时调整 |

## 3. 核心子模块详解

### 3.1 SR_initialize() - 挂起/恢复机制

> 源码位置: `os_linux.cpp:4957`

#### 3.1.1 设计目的

**问题**: JVM 需要在某些场景下暂停特定线程（如 Profiling、JVMTI 调试）

**解决方案**: 使用 `SIGUSR2` 信号实现线程的挂起和恢复

#### 3.1.2 核心数据结构

```c++
// 全局变量
static int SR_signum = SIGUSR2;  // 默认使用 SIGUSR2 (信号 12)
static sigset_t SR_sigset;       // 包含 SR_signum 的信号集

// sigaction 结构体
struct sigaction {
    void (*sa_handler)(int);                      // 简单处理器
    void (*sa_sigaction)(int, siginfo_t*, void*); // 扩展处理器 ★
    sigset_t sa_mask;                             // 处理期间阻塞的信号
    int sa_flags;                                 // 标志位
};
```

#### 3.1.3 为什么使用 `sa_sigaction` 三参数形式？

```
void SR_handler(int sig, siginfo_t* info, void* ucontext)
                 │           │              │
                 │           │              └─► ucontext_t*: CPU 完整状态
                 │           │                    ├── PC (程序计数器)
                 │           │                    ├── SP (栈指针)
                 │           │                    └── 通用寄存器
                 │           │
                 │           └─► 信号详细信息
                 └─► 信号编号
```

**核心价值**: 通过 `ucontext_t` 可以获取线程被中断时的完整状态：
- 获取调用栈（Profiler）
- 检查是否在安全点
- 异常处理定位

#### 3.1.4 信号编号选择约束

```c++
// SR_signum 必须大于 SIGSEGV(11) 和 SIGBUS(7)
if (sig > MAX2(SIGSEGV, SIGBUS) && sig < NSIG) {
    SR_signum = sig;
}
```

**原因**: JVM 内部使用 SIGSEGV 实现：
- `NullPointerException` - 访问地址 0 触发
- `StackOverflowError` - 访问栈保护页触发  
- `Safepoint polling` - 访问受保护页触发

#### 3.1.5 与 Safepoint Polling 的区别

| 机制 | SR_signum (SIGUSR2) | Safepoint Polling Page |
|------|---------------------|------------------------|
| **触发方式** | 主动发送信号 | 线程检查 polling page |
| **停止位置** | 任意位置 | 安全点 |
| **使用场景** | Profiler、JVMTI、调试 | GC STW |
| **性能影响** | 信号发送开销 | 正常只是内存读取 |
| **可预测性** | 不可预测 | 仅在特定位置 |

> 源码位置: `os_linux.cpp:593`

#### 3.2.1 两种信号集

```
┌─────────────────────────────────────────────────────────────────────┐
│                        信号集分类                                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  unblocked_sigs (所有线程解除阻塞)                                   │
│  ┌─────────────────────────────────────────────────────────────┐    │
│  │ SIGILL(4)   │ 非法指令 → JIT 编译问题                        │    │

│  │ SIGBUS(7)   │ 总线错误 → 内存对齐问题                        │    │
│  │ SIGFPE(8)   │ 浮点异常 → ArithmeticException                │    │
│  │ SR_signum   │ SIGUSR2 → 线程挂起/恢复                       │    │

│                                                                      │
│  vm_sigs (仅 VMThread 解除阻塞)                                      │
│  ┌─────────────────────────────────────────────────────────────┐    │
│  │ BREAK_SIGNAL│ SIGQUIT(3) → Thread Dump (kill -3)            │    │
│  └─────────────────────────────────────────────────────────────┘    │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

#### 3.2.2 SIGSEGV 的多重用途

```
SIGSEGV 信号触发场景
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. NullPointerException
   ┌─────────────────────────────────────────────────┐
   │  Object obj = null;                             │
   │  obj.method();  // 访问地址 0x0                  │
   │       ↓                                         │
   │  SIGSEGV → JVM Signal Handler                   │
   │       ↓                                         │
   │  检测到地址 = 0 → 抛出 NullPointerException      │
   └─────────────────────────────────────────────────┘

2. StackOverflowError
   ┌─────────────────────────────────────────────────┐
   │  void recursive() { recursive(); }              │
   │       ↓                                         │
   │  栈增长触碰保护页                                │
   │       ↓                                         │
   │  SIGSEGV → JVM Signal Handler                   │
   │       ↓                                         │
   │  检测到保护页 → 抛出 StackOverflowError          │
   └─────────────────────────────────────────────────┘

3. Safepoint Polling
   ┌─────────────────────────────────────────────────┐
   │  GC 需要 STW                                    │
   │       ↓                                         │
   │  将 polling page 设为不可读                      │
   │       ↓                                         │
   │  线程执行到安全点，test(polling_page)            │
   │       ↓                                         │
   │  SIGSEGV → JVM Signal Handler                   │
   │       ↓                                         │
   │  检测到 polling page → 线程阻塞等待 GC           │
   └─────────────────────────────────────────────────┘
```

│                    信号链机制 (Signal Chaining)                       │
├──────────────────────────────────────────────────────────────────────┤

#### 3.3.2 安装的信号处理器一览

```c++
// 核心信号处理器
set_signal_handler(SIGSEGV, true);  // 段错误
set_signal_handler(SIGPIPE, true);  // 管道破裂
set_signal_handler(SIGBUS, true);   // 总线错误
set_signal_handler(SIGILL, true);   // 非法指令
set_signal_handler(SIGFPE, true);   // 浮点异常
set_signal_handler(SIGXFSZ, true);  // 文件大小超限
```

| 信号 | 编号 | 触发场景 | JVM 处理方式 |
|------|------|----------|-------------|
| SIGSEGV | 11 | 访问无效内存 | NPE/SOE/Safepoint |
| SIGPIPE | 13 | 写入已关闭管道 | 忽略，返回错误 |
| SIGBUS | 7 | 内存对齐错误 | MappedByteBuffer 异常 |
| SIGILL | 4 | 非法 CPU 指令 | JIT 编译问题处理 |
| SIGFPE | 8 | 整数除零 | ArithmeticException |
| SIGXFSZ | 25 | 文件超过 ulimit | 忽略，返回错误 |

## 6. 源码注释摘录

```c++
jint os::init_2(void) {
    // POSIX 通用初始化（打印日志）
    os::Posix::init_2();
    
    // 时钟初始化
    Linux::fast_thread_clock_init();

    // 初始化 suspend/resume 支持
    // 必须在 signal_sets_init() 之前！
    if (SR_initialize() != 0) {
        perror("SR_initialize failed");
        return JNI_ERR;
    }
    
    // 初始化两个信号集
    Linux::signal_sets_init();
    
    // 统一安装所有 JVM 需要的信号处理器
    Linux::install_signal_handlers();
    
    // 为 jdk.internal.misc.Signal API 提供底层支持
    if (!ReduceSignalUsage) {
        jdk_misc_signal_init();
    }

    // 栈大小配置 + Guard Zone
    if (Posix::set_minimum_stack_sizes() == JNI_ERR) {
        return JNI_ERR;
    }
    
    // 打印 libc 和 libpthread 版本信息
    Linux::libpthread_init();
    
    // 文件描述符上限
    if (MaxFDLimit) {
        struct rlimit nbr_files;
        getrlimit(RLIMIT_NOFILE, &nbr_files);
        nbr_files.rlim_cur = nbr_files.rlim_max;
        setrlimit(RLIMIT_NOFILE, &nbr_files);
    }

    // 初始化线程创建锁
    Linux::set_createThread_lock(new Mutex(Mutex::leaf, "createThread_lock", false));

    // 线程优先级初始化
    prio_init();
    
    return JNI_OK;
}
```

## 9. 总结

### 9.1 核心要点

1. **信号是 JVM 实现 Java 异常的关键机制**
   - SIGSEGV → NullPointerException / StackOverflowError / Safepoint
   - SIGFPE → ArithmeticException

2. **两套线程暂停机制**
   - `SIGUSR2`: 任意位置暂停（Profiler/调试）
   - `Safepoint Polling`: 安全点暂停（GC）

3. **信号链机制保证兼容性**
   - JNI 代码可以注册自己的信号处理器
   - libjsig.so 负责协调
