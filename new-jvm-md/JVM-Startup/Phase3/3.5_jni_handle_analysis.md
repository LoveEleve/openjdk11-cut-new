## 1. 功能定位

### 1.1 一句话概述

**JNI Handle** 是 Native 代码（C/C++）安全引用 Java 对象的机制，解决了 GC 移动对象导致指针失效的问题。

### 1.2 核心问题

```
问题：Native 代码为什么不能直接保存 Java 对象指针？
答案：
  1. GC 可能移动对象，导致原指针失效
  2. GC 需要知道哪些对象被引用，不能被回收
  
解决方案：通过 JNI Handle 间接引用
  - Native 代码持有 handle（句柄）
  - Handle 指向 JNIHandleBlock 中的槽位
  - 槽位存储真正的对象指针
  - GC 时更新槽位中的指针，handle 不变
```

```cpp
class JNIHandleBlock : public CHeapObj<mtInternal> {
private:
    enum SomeConstants {
        block_size_in_oops  = 32     // 每块 32 个 Handle 槽位
    };

    // ================== 核心字段 ==================
    oop             _handles[block_size_in_oops];  // Handle 数组 (32 个)
    int             _top;                          // 下一个未使用槽位的索引
    JNIHandleBlock* _next;                         // 链表指针，指向下一个 Block

    // ================== 链表头专用字段 ==================
    // (只有链表第一个 Block 使用)
    JNIHandleBlock* _last;                    // 链表中最后一个 Block
    JNIHandleBlock* _pop_frame_link;          // PushLocalFrame/PopLocalFrame 支持
    oop*            _free_list;               // 空闲槽位链表（复用已删除的槽位）
    int             _allocate_before_rebuild; // 重建 free_list 前可分配的 Block 数

    // ================== 全局静态字段 ==================
    static JNIHandleBlock* _block_free_list;  // 全局空闲 Block 链表
    static int      _blocks_allocated;        // 已分配的 Block 总数

public:
    // Handle 分配
    jobject allocate_handle(oop obj);
    
    // Block 分配/释放
    static JNIHandleBlock* allocate_block(Thread* thread = NULL);
    static void release_block(JNIHandleBlock* block, Thread* thread = NULL);
    
    // GC 支持
    void oops_do(OopClosure* f);
};
```

```cpp
JNIHandleBlock* JNIHandleBlock::allocate_block(Thread* thread) {
    assert(thread == NULL || thread == Thread::current(), "sanity check");
    JNIHandleBlock* block;
    
    // ================== 策略1：线程本地空闲列表（无锁，快速）==================
    if (thread != NULL && thread->free_handle_block() != NULL) {
        block = thread->free_handle_block();
        thread->set_free_handle_block(block->_next);
    } 
    // ================== 策略2：全局空闲列表（需要加锁）==================
    else {
        MutexLockerEx ml(JNIHandleBlockFreeList_lock,
                         Mutex::_no_safepoint_check_flag);  // 加锁
        
        if (_block_free_list == NULL) {
            // 全局空闲列表为空，创建新 Block
            block = new JNIHandleBlock();
            _blocks_allocated++;
            block->zap();  // 初始化（清零）
            
            #ifndef PRODUCT
            block->_block_list_link = _block_list;
            _block_list = block;
            #endif
        } else {
            // 从全局空闲列表获取
            block = _block_free_list;
            _block_free_list = _block_free_list->_next;
        }
    }
    
    // ================== 初始化 Block ==================
    block->_top = 0;
    block->_next = NULL;
    block->_pop_frame_link = NULL;
    block->_planned_capacity = block_size_in_oops;
    
    debug_only(block->_last = NULL);
    debug_only(block->_free_list = NULL);
    debug_only(block->_allocate_before_rebuild = -1);
    
    return block;
}
```

### 5.1 allocate_handle() 源码分析

```cpp
// 源码位置: src/hotspot/share/runtime/jniHandles.cpp:485-536

jobject JNIHandleBlock::allocate_handle(oop obj) {
    assert(Universe::heap()->is_in_reserved(obj), "sanity check");
    
    // ================== 策略1：直接在最后一个 Block 分配 ==================
    if (_last->_top < block_size_in_oops) {
        oop* handle = &(_last->_handles)[_last->_top++];
        NativeAccess<IS_DEST_UNINITIALIZED>::oop_store(handle, obj);
        return (jobject)handle;
    }

    // ================== 策略2：从空闲列表分配 ==================
    if (_free_list != NULL) {
        oop* handle = _free_list;
        _free_list = (oop*)*_free_list;  // 链表操作
        NativeAccess<IS_DEST_UNINITIALIZED>::oop_store(handle, obj);
        return (jobject)handle;
    }
    
    // ================== 策略3：使用下一个 Block ==================
    if (_last->_next != NULL) {
        _last = _last->_next;
        return allocate_handle(obj);  // 递归调用
    }

    // ================== 策略4：扩展或重建空闲列表 ==================
    if (_allocate_before_rebuild == 0) {
        rebuild_free_list();  // 重建空闲列表
    } else {
        // 分配新 Block
        Thread* thread = Thread::current();
        Handle obj_handle(thread, obj);  // 保护 obj 跨越可能的 GC
        _last->_next = JNIHandleBlock::allocate_block(thread);
        _last = _last->_next;
        _allocate_before_rebuild--;
        obj = obj_handle();  // 重新获取可能移动的 obj
    }
    
    return allocate_handle(obj);  // 递归重试
}
```

## 6. Local Handle 与 Global Handle 对比 ⭐⭐⭐

### 6.1 三种 Handle 类型对比

| 特性 | Local Handle | Global Handle | Weak Global Handle |
|------|-------------|---------------|-------------------|
| **作用域** | 当前方法调用 | 全局，直到显式删除 | 全局，直到显式删除 |
| **存储位置** | JNIHandleBlock | OopStorage | OopStorage |
| **线程安全** | 线程私有，无锁 | 全局共享，需要锁 | 全局共享，需要锁 |
| **GC 行为** | 阻止对象回收 | 阻止对象回收 | 不阻止回收，可能变 NULL |
| **创建方法** | make_local() | make_global() | make_weak_global() |
| **自动释放** | 方法返回时自动释放 | 需手动调用 DeleteGlobalRef | 需手动调用 DeleteWeakGlobalRef |

```cpp
jobject JNIHandles::make_local(oop obj) {
    if (obj == NULL) {
        return NULL;  // 忽略 null
    } else {
        Thread* thread = Thread::current();
        assert(oopDesc::is_oop(obj), "not an oop");
        assert(!current_thread_in_native(), "must not be in native");
        
        // 核心：从当前线程的 active_handles 分配
        return thread->active_handles()->allocate_handle(obj);
    }
}
```

## 7. GC 集成 ⭐⭐⭐

### 7.1 oops_do() 遍历

```cpp
// 源码位置: src/hotspot/share/runtime/jniHandles.cpp:449-475

void JNIHandleBlock::oops_do(OopClosure* f) {
    JNIHandleBlock* current_chain = this;
    
    // 遍历 Block 链表
    while (current_chain != NULL) {
        for (JNIHandleBlock* current = current_chain; 
             current != NULL;
             current = current->_next) {
            
            // 遍历每个 Block 的所有槽位
            for (int index = 0; index < current->_top; index++) {
                oop* root = &(current->_handles)[index];
                oop value = *root;
                
                // 只处理有效的堆指针（排除 NULL 和空闲列表指针）
                if (value != NULL && Universe::heap()->is_in_reserved(value)) {
                    f->do_oop(root);  // 让 GC 处理这个引用
                }
            }
            
            // 如果当前 Block 未满，后续 Block 都是空的
            if (current->_top < block_size_in_oops) {
                break;
            }
        }
        current_chain = current_chain->pop_frame_link();
    }
}
```

## 9. 面试高频问题 ⭐⭐⭐⭐

### Q1: 为什么 Native 代码需要通过 JNI Handle 访问 Java 对象？

**答案**：
1. **GC 移动问题**：GC 可能移动对象，直接指针会失效
2. **GC 可达性**：GC 需要知道哪些对象被引用，JNI Handle 是 GC Root
3. **间接引用**：通过 Handle 间接访问，GC 只需更新 Handle 中的指针

### Q2: Local Handle 和 Global Handle 有什么区别？

**答案**：
| 方面 | Local Handle | Global Handle |
|------|-------------|---------------|
| 生命周期 | 方法调用期间 | 直到显式删除 |
| 存储位置 | 线程私有 JNIHandleBlock | 全局 OopStorage |
| 性能 | 快（无锁） | 慢（需要锁） |
| 自动释放 | 是（方法返回时） | 否（需手动删除） |

### Q3: JNIHandleBlock 为什么使用链表结构？

**答案**：
1. **按需扩展**：每个 Block 固定 32 个槽位，不够时链接新 Block
2. **避免大内存分配**：小块分配比大块分配更高效
3. **复用机制**：释放的 Block 可以放入空闲列表复用

### Q4: 为什么有线程本地空闲列表？

**答案**：
1. **无锁快速路径**：线程本地访问不需要加锁
2. **减少竞争**：避免多线程争用全局空闲列表
3. **性能优化**：大多数情况下可以避免加锁操作

### Q5: JNI Handle 泄漏会导致什么问题？

**答案**：
1. **Local Handle 泄漏**：
   - 在循环中创建大量 Local Handle 会导致 OOM
   - 解决：使用 `PushLocalFrame`/`PopLocalFrame` 或手动 `DeleteLocalRef`

2. **Global Handle 泄漏**：
   - 对象永远不会被 GC 回收
   - 解决：确保每个 `NewGlobalRef` 都有对应的 `DeleteGlobalRef`
