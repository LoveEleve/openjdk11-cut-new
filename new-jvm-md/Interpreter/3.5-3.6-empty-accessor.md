# 3.5-3.6 empty 和 accessor（空方法和访问器入口）

## 概述

`empty` 和 `accessor` 是两种特殊的 MethodKind，用于识别可优化的简单方法。但在 **Template 解释器中，它们复用 zerolocals 入口**，没有单独的代码生成。

## is_empty_method() 定义

```cpp:498:501:src/hotspot/share/oops/method.cpp
bool Method::is_empty_method() const {
    return  code_size() == 1
        && *code_base() == Bytecodes::_return;
}
```

**判断条件**：
- 方法体大小 = 1 字节
- 唯一的字节码是 `return`

**匹配示例**：
```java
void doNothing() {
    return;  // 只有一个 return 指令
}
```

## is_getter() 定义

```cpp:660:665:src/hotspot/share/oops/method.cpp
bool Method::is_getter() const {
    if (code_size() != 5) return false;
    if (size_of_parameters() != 1) return false;  // 只有 this 参数
    if (java_code_at(0) != Bytecodes::_aload_0)  return false;
    if (java_code_at(1) != Bytecodes::_getfield) return false;
    // java_code_at(4) 是 return 指令
    // ...
}
```

**判断条件**：
- 方法体大小 = 5 字节
- 参数个数 = 1（只有 this）
- 字节码模式：`aload_0; getfield <field>; return`

**匹配示例**：
```java
class Point {
    int x;
    int getX() { return x; }  // aload_0, getfield, ireturn
}
```

## 为什么不生成特殊入口？

### 原因 1：JIT 编译更高效

这些简单方法很快会被 JIT 编译：
- C1/C2 编译器会内联 getter
- 空方法会被完全消除

### 原因 2：调用频率不高

- 空方法调用不多
- Getter 通常被内联

### 原因 3：Zero 解释器才有特殊实现

Zero 解释器（C++ 解释器）有专门的 `empty_entry` 和 `accessor_entry`，因为它没有 JIT。

## 总结

| 方面 | empty | accessor |
|------|-------|----------|
| 判断条件 | code_size=1, 只有 return | code_size=5, aload_0+getfield+return |
| Template 解释器入口 | 复用 zerolocals | 复用 zerolocals |
| 是否有单独代码 | 否 | 否 |
| 优化依赖 | JIT 内联/消除 | JIT 内联 |

**关键点**：在 Template 解释器中，`empty` 和 `accessor` 只是 MethodKind 分类标记，实际执行时使用普通的 `zerolocals` 入口。
