# 5. 方法调用字节码详解

> 源码位置: `src/hotspot/cpu/x86/templateTable_x86.cpp:3612`
>
> 方法调用是解释器最复杂的字节码实现，涉及常量池解析、vtable/itable 查找、栈帧构建等多个步骤。

## 1. 五种 invoke 指令概览

| 指令 | 操作码 | 字节长度 | 调用目标 |
|------|--------|----------|----------|
| `invokevirtual` | 0xB6 | 3 | 实例方法（支持多态） |
| `invokespecial` | 0xB7 | 3 | 构造器、私有方法、父类方法 |
| `invokestatic` | 0xB8 | 3 | 静态方法 |
| `invokeinterface` | 0xB9 | 5 | 接口方法 |
| `invokedynamic` | 0xBA | 5 | 动态调用点（lambda、方法句柄） |

## 2. 通用准备阶段: prepare_invoke()

所有 invoke 指令都调用 `prepare_invoke()` 进行通用准备：

```cpp
// templateTable_x86.cpp:3612
void TemplateTable::prepare_invoke(int byte_no,
                                   Register method,  // 输出: Method* 或 vtable index
                                   Register index,   // 输出: itable index 或 appendix
                                   Register recv,    // 输出: receiver
                                   Register flags    // 输出: flags
                                   ) {
    // 1. 保存 bcp（方法返回时需要恢复）
    __ save_bcp();
    
    // 2. 从 ConstantPoolCache 加载调用信息
    load_invoke_cp_cache_entry(byte_no, method, index, flags, ...);
    
    // 3. [invokedynamic/invokehandle] 可能需要 push appendix
    if (is_invokedynamic || is_invokehandle) {
        // appendix 可能是 MethodType、CallSite 等
        if (has_appendix) {
            __ push(appendix);
        }
    }
    
    // 4. 加载 receiver（非静态方法）
    if (load_receiver) {
        // 从参数栈中找到 receiver
        // receiver 位于: 栈底 + parameter_size - 1
        __ movl(recv, flags);
        __ andl(recv, ConstantPoolCacheEntry::parameter_size_mask);
        Address recv_addr = __ argument_address(recv, ...);
        __ movptr(recv, recv_addr);
    }
    
    // 5. 计算返回地址并 push
    // 根据返回类型查找 invoke_return_entry
    __ shrl(flags, ConstantPoolCacheEntry::tos_state_shift);
    address table = Interpreter::invoke_return_entry_table_for(code);
    __ movptr(flags, Address(table, flags * wordSize));
    __ push(flags);  // push 返回地址
    
    // 6. 恢复 flags（给后续步骤使用）
    __ restore_locals();  // 从 rbcp 恢复
}
```

### 2.1 ConstantPoolCache 结构

```
ConstantPoolCacheEntry (32 bytes):
┌─────────────────────────────────┐
│  _indices (4 bytes)             │ CP 索引 + bytecode
├─────────────────────────────────┤
│  _f1 (8 bytes)                  │ Method* 或 Klass*
├─────────────────────────────────┤
│  _f2 (8 bytes)                  │ vtable index 或 Method*
├─────────────────────────────────┤
│  _flags (4 bytes)               │ TOS state, parameter_size, flags
└─────────────────────────────────┘
```

**flags 字段位含义**:
| 位 | 名称 | 含义 |
|----|------|------|
| 0-7 | parameter_size | 参数个数（含 this） |
| 8-11 | tos_state | 返回值类型 |
| 16 | is_vfinal | final 方法标记 |
| 17 | has_appendix | 有附加参数 |
| 20 | is_forced_virtual | Object 方法通过 interface 调用 |

## 3. invokevirtual - 虚方法调用

```cpp
// templateTable_x86.cpp:3745
void TemplateTable::invokevirtual(int byte_no) {
    transition(vtos, vtos);
    
    prepare_invoke(byte_no,
                   rbx,    // method 或 vtable index
                   noreg,  // 不需要 itable index
                   rcx,    // receiver
                   rdx);   // flags
    
    invokevirtual_helper(rbx, rcx, rdx);
}

void TemplateTable::invokevirtual_helper(Register index, Register recv, Register flags) {
    // 1. 检查是否是 final 方法
    __ movl(rax, flags);
    __ andl(rax, (1 << ConstantPoolCacheEntry::is_vfinal_shift));
    __ jcc(Assembler::zero, notFinal);
    
    // === Final 方法路径 ===
    // rbx 中已经是 Method*，直接调用
    __ null_check(recv);
    __ profile_final_call(rax);
    __ jump_from_interpreted(method, rax);  // 跳转到目标方法
    
    // === 非 Final 方法路径 ===
    __ bind(notFinal);
    
    // 2. null 检查并获取 receiver 的 Klass
    __ null_check(recv, oopDesc::klass_offset_in_bytes());
    __ load_klass(rax, recv);  // rax = receiver->klass()
    
    // 3. 通过 vtable 查找目标方法
    // method = klass->vtable[vtable_index]
    __ lookup_virtual_method(rax, index, method);
    
    // 4. 跳转到目标方法
    __ jump_from_interpreted(method, rdx);
}
```

### 3.1 lookup_virtual_method 实现

```cpp
// macroAssembler_x86.cpp:4628
void MacroAssembler::lookup_virtual_method(Register recv_klass,
                                           RegisterOrConstant vtable_index,
                                           Register method_result) {
    const int base = in_bytes(Klass::vtable_start_offset());
    
    // vtable 条目结构: 每个 8 字节（x86-64），只存储 Method*
    // method = recv_klass + vtable_base + vtable_index * 8
    Address vtable_entry_addr(recv_klass,
                              vtable_index, Address::times_ptr,
                              base + vtableEntry::method_offset_in_bytes());
    movptr(method_result, vtable_entry_addr);
}
```

**vtable 内存布局**:
```
Klass:
┌─────────────────────────────────┐
│  ... (Klass 头部)               │
├─────────────────────────────────┤ ← vtable_start_offset()
│  vtable[0] = Method*            │  index=0: Object.hashCode
│  vtable[1] = Method*            │  index=1: Object.equals
│  vtable[2] = Method*            │  index=2: Object.toString
│  ...                            │
│  vtable[n] = Method*            │  index=n: 子类重写的方法
├─────────────────────────────────┤
│  itable (接口方法表)            │
└─────────────────────────────────┘
```

## 4. invokeinterface - 接口方法调用

```cpp
// templateTable_x86.cpp:3791
void TemplateTable::invokeinterface(int byte_no) {
    transition(vtos, vtos);
    
    prepare_invoke(byte_no,
                   rax,    // f1: interface Klass*
                   rbx,    // f2: Method* (私有接口方法) 或 itable index
                   rcx,    // receiver
                   rdx);   // flags
    
    // === 路径 1: Object 方法通过接口调用 ===
    // 例如: ((Comparable)obj).hashCode()
    Label notObjectMethod;
    __ movl(rlocals, rdx);
    __ andl(rlocals, (1 << ConstantPoolCacheEntry::is_forced_virtual_shift));
    __ jcc(Assembler::zero, notObjectMethod);
    invokevirtual_helper(rbx, rcx, rdx);  // 走 vtable
    
    __ bind(notObjectMethod);
    
    // === 路径 2: 私有接口方法 (Java 9+) ===
    Label notVFinal;
    __ movl(rlocals, rdx);
    __ andl(rlocals, (1 << ConstantPoolCacheEntry::is_vfinal_shift));
    __ jcc(Assembler::zero, notVFinal);
    
    // 子类型检查
    __ null_check(rcx, oopDesc::klass_offset_in_bytes());
    __ load_klass(rlocals, rcx);
    __ check_klass_subtype(rlocals, rax, rbcp, subtype);
    __ jmp(no_such_interface);  // 类型不匹配
    
    __ bind(subtype);
    __ jump_from_interpreted(rbx, rdx);  // rbx 已是 Method*
    
    __ bind(notVFinal);
    
    // === 路径 3: 普通接口方法 ===
    // 需要通过 itable 查找
    
    // 1. 获取 receiver 的 Klass
    __ null_check(rcx, oopDesc::klass_offset_in_bytes());
    __ load_klass(rdx, rcx);  // rdx = receiver->klass()
    
    // 2. 第一次 lookup: 验证 receiver 实现了接口
    __ lookup_interface_method(rdx, rax, noreg,
                               rbcp, rlocals,
                               no_such_interface,
                               /*return_method=*/false);
    
    // 3. 从 Method* 获取声明接口和 itable index
    __ movptr(rax, Address(rbx, Method::const_offset()));
    __ movptr(rax, Address(rax, ConstMethod::constants_offset()));
    __ movptr(rax, Address(rax, ConstantPool::pool_holder_offset_in_bytes()));
    __ movl(rbx, Address(rbx, Method::itable_index_offset()));
    __ subl(rbx, Method::itable_index_max);
    __ negl(rbx);  // rbx = itable_index
    
    // 4. 第二次 lookup: 获取实际 Method*
    __ lookup_interface_method(rlocals, rax, rbx,
                               rbx, rbcp,
                               no_such_interface);
    
    // 5. 检查 abstract method
    __ testptr(rbx, rbx);
    __ jcc(Assembler::zero, no_such_method);
    
    // 6. 调用
    __ jump_from_interpreted(rbx, rdx);
}
```

### 4.1 lookup_interface_method 实现

```cpp
// macroAssembler_x86.cpp:4553
void MacroAssembler::lookup_interface_method(Register recv_klass,
                                             Register intf_klass,
                                             RegisterOrConstant itable_index,
                                             Register method_result,
                                             Register scan_temp,
                                             Label& L_no_such_interface,
                                             bool return_method) {
    // itable 位于 vtable 之后
    // 计算 itable 起始地址
    movl(scan_temp, Address(recv_klass, Klass::vtable_length_offset()));
    lea(scan_temp, Address(recv_klass, scan_temp, times_ptr, vtable_base));
    
    // 线性扫描 itable 查找目标接口
    // for (scan = itable; scan->interface() != NULL; scan++) {
    //     if (scan->interface() == intf_klass) {
    //         method = klass + scan->offset() + itable_index * 8
    //     }
    // }
    Label search, found_method;
    
    // 循环第一次展开（优化）
    movptr(method_result, Address(scan_temp, itableOffsetEntry::interface_offset));
    cmpptr(intf_klass, method_result);
    jccb(Assembler::equal, found_method);
    
    bind(search);
    // 检查是否到达 itable 末尾
    testptr(method_result, method_result);
    jcc(Assembler::zero, L_no_such_interface);  // 未找到接口
    
    addptr(scan_temp, itableOffsetEntry::size());
    movptr(method_result, Address(scan_temp, itableOffsetEntry::interface_offset));
    cmpptr(intf_klass, method_result);
    jccb(Assembler::notEqual, search);
    
    bind(found_method);
    if (return_method) {
        // 计算目标方法地址
        movl(scan_temp, Address(scan_temp, itableOffsetEntry::offset_offset));
        movptr(method_result, Address(recv_klass, scan_temp, times_1, itable_index * 8));
    }
}
```

**itable 内存布局**:
```
Klass:
┌─────────────────────────────────┐
│  vtable[...]                    │
├─────────────────────────────────┤ ← itable 开始
│  itableOffsetEntry #0           │
│  ├─ interface: Klass*           │  实现的第一个接口
│  └─ offset: int                 │  该接口方法表相对 Klass 的偏移
├─────────────────────────────────┤
│  itableOffsetEntry #1           │
│  ├─ interface: Klass*           │  实现的第二个接口
│  └─ offset: int                 │
├─────────────────────────────────┤
│  itableOffsetEntry #N           │
│  ├─ interface: NULL             │  结束标记
│  └─ offset: 0                   │
├─────────────────────────────────┤
│  itableMethodEntry[] for #0     │  接口 #0 的方法表
│  ├─ Method* for method 0        │
│  ├─ Method* for method 1        │
│  └─ ...                         │
├─────────────────────────────────┤
│  itableMethodEntry[] for #1     │  接口 #1 的方法表
│  └─ ...                         │
└─────────────────────────────────┘
```

## 5. invokespecial - 特殊调用

```cpp
// templateTable_x86.cpp:3760
void TemplateTable::invokespecial(int byte_no) {
    transition(vtos, vtos);
    
    prepare_invoke(byte_no,
                   rbx,    // f1: Method*
                   noreg,
                   rcx);   // receiver (for null check)
    
    // null 检查
    __ verify_oop(rcx);
    __ null_check(rcx);
    
    // 直接调用（无 vtable 查找）
    __ profile_call(rax);
    __ jump_from_interpreted(rbx, rax);
}
```

**invokespecial 用于**:
- 构造器 `<init>`
- 私有实例方法
- `super.method()` 调用

## 7. jump_from_interpreted - 最终跳转

```cpp
// interp_masm_x86.cpp:777
void InterpreterMacroAssembler::jump_from_interpreted(Register method, Register temp) {
    // 1. 准备工作（保存状态）
    prepare_to_jump_from_interpreted();
    
    // 2. JVMTI 单步调试支持
    if (JvmtiExport::can_post_interpreter_events()) {
        Label run_compiled_code;
        
        // 检查 interp_only_mode（调试时强制解释执行）
        cmpb(Address(r15_thread, JavaThread::interp_only_mode_offset()), 0);
        jccb(Assembler::zero, run_compiled_code);
        
        // 调试模式：跳转到方法的解释器入口
        jmp(Address(method, Method::interpreter_entry_offset()));
        
        bind(run_compiled_code);
    }
    
    // 3. 正常路径：跳转到 from_interpreted 入口
    // 可能是解释器入口，也可能是 i2c 适配器（如果已编译）
    jmp(Address(method, Method::from_interpreted_offset()));
}
```

**Method 中的入口点**:
```cpp
class Method {
    // ...
    address _i2i_entry;           // 解释器 → 解释器
    address _from_interpreted_entry;  // 当前使用的入口
    // 如果方法已编译：from_interpreted_entry → i2c_adapter → compiled_code
    // 如果方法未编译：from_interpreted_entry → _i2i_entry → 解释器
};
```

## 8. 性能对比

| 指令 | 查找方式 | 性能 |
|------|----------|------|
| `invokestatic` | 直接调用 | 最快 |
| `invokespecial` | 直接调用 + null check | 快 |
| `invokevirtual` (final) | 直接调用 + null check | 快 |
| `invokevirtual` | vtable 查找 | 中等 |
| `invokeinterface` | itable 线性扫描 | 较慢 |

**优化技术**:
1. **内联缓存 (Inline Cache)**: JIT 编译器优化
2. **final 方法优化**: 编译期确定目标
3. **CHA (Class Hierarchy Analysis)**: 单态假设

## 9. 调用流程总结图

```
invoke* 字节码执行
        │
        ↓
┌──────────────────┐
│  prepare_invoke  │
│  - 保存 bcp      │
│  - 加载 CP cache │
│  - 获取 receiver │
│  - push 返回地址 │
└──────────────────┘
        │
        ↓
┌──────────────────────────────────────────────────────────┐
│                    分发到具体指令                          │
├────────────┬────────────┬────────────┬──────────────────┤
│invokestatic│invokespecial│invokevirtual│invokeinterface   │
│            │            │            │                  │
│ (无lookup) │ null_check │ vtable     │ itable           │
│            │            │ lookup     │ lookup           │
└─────┬──────┴─────┬──────┴─────┬──────┴────────┬─────────┘
      │            │            │               │
      └────────────┴────────────┴───────────────┘
                         │
                         ↓
              ┌────────────────────┐
              │ jump_from_interpreted │
              │ - JVMTI 检查         │
              │ - jmp from_interpreted │
              └────────────────────┘
                         │
                         ↓
              ┌────────────────────┐
              │   目标方法执行      │
              │   (解释器 或 编译码) │
              └────────────────────┘
                         │
                         ↓
              ┌────────────────────┐
              │  invoke_return_entry │
              │  - 恢复 caller 状态  │
              │  - dispatch_next    │
              └────────────────────┘
```
