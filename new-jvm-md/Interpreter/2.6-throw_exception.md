# 2.6 throw_exception（异常处理）

## 概述

`generate_throw_exception()` 生成解释器的核心异常处理逻辑，包含**异常分发**和**栈帧移除**的代码。这是解释器中最复杂的入口点之一，处理以下场景：

1. **重新抛出异常**（从被调用者返回时）
2. **抛出新异常**（在当前帧内）
3. **JVMTI PopFrame 支持**（调试器强制弹出栈帧）
4. **移除激活记录**（当前帧无法处理异常时）

## 生成的入口点

`generate_throw_exception()` 在一个 Codelet 中生成**4 个关键入口点**：

| 入口点 | 存储位置 | 用途 |
|--------|----------|------|
| `_rethrow_exception_entry` | `AbstractInterpreter` | 从被调用帧返回，重新抛出异常 |
| `_throw_exception_entry` | `TemplateInterpreter` | 在解释器代码内抛出新异常 |
| `_remove_activation_preserving_args_entry` | `TemplateInterpreter` | JVMTI PopFrame 支持 |
| `_remove_activation_entry` | `TemplateInterpreter` | 当前帧无法处理，移除并传播 |

## 源码分析

### 1. _rethrow_exception_entry（重新抛出入口）

```cpp:1506:1517:src/hotspot/cpu/x86/templateInterpreterGenerator_x86.cpp
void TemplateInterpreterGenerator::generate_throw_exception() {
  // Entry point in previous activation (i.e., if the caller was interpreted)
  Interpreter::_rethrow_exception_entry = __ pc();
  
  // 清理 last_sp
  __ movptr(Address(rbp, frame::interpreter_frame_last_sp_offset * wordSize), (int32_t)NULL_WORD);
  
  // rax: exception
  // rdx: return address/pc that threw exception
  __ restore_bcp();     // 恢复 r13 (bcp)
  __ restore_locals();  // 恢复 r14 (locals)
  LP64_ONLY(__ reinit_heapbase());  // 恢复 r12 (heapbase)
```

**使用场景**：当被调用的方法（compiled 或 interpreted）抛出异常返回时。

**寄存器约定**：
- `rax` = 异常对象
- `rdx` = 抛出异常的 PC

### 2. _throw_exception_entry（抛出异常入口）

```cpp:1518:1539:src/hotspot/cpu/x86/templateInterpreterGenerator_x86.cpp
  // Entry point for exceptions thrown within interpreter code
  Interpreter::_throw_exception_entry = __ pc();
  
  // rax: exception
  // r13: exception bcp (字节码位置)
  __ verify_oop(rax);
  LP64_ONLY(__ mov(c_rarg1, rax));  // 将异常对象移到参数寄存器
  
  // 清空表达式栈
  __ empty_expression_stack();
  
  // 调用 VM 查找异常处理器
  __ call_VM(rdx,
             CAST_FROM_FN_PTR(address, InterpreterRuntime::exception_handler_for_exception),
             rarg);
  // 返回值：
  // rax: exception handler entry point
  // rdx: preserved exception oop
  // r13: bcp for exception handler
  
  __ push_ptr(rdx);  // 将异常压栈（成为栈上唯一值）
  __ jmp(rax);       // 跳转到异常处理器
```

**核心调用**：`InterpreterRuntime::exception_handler_for_exception`

这个 VM 运行时函数：
1. 在当前方法的异常表中搜索匹配的 handler
2. 如果找到，返回 handler 的入口地址
3. 如果未找到，返回 `_remove_activation_entry`

### 4. _remove_activation_entry（移除激活记录）

```cpp:1699:1729:src/hotspot/cpu/x86/templateInterpreterGenerator_x86.cpp
  Interpreter::_remove_activation_entry = __ pc();
  
  // 保存异常对象
  __ pop_ptr(rax);
  __ movptr(Address(thread, JavaThread::vm_result_offset()), rax);
  
  // 移除当前栈帧（不抛出 IllegalMonitorStateException）
  __ remove_activation(vtos, rdx, false, true, false);
  
  // 恢复异常对象
  __ get_vm_result(rax, thread);
  
  // 保存异常和返回地址
  __ push(rax);  // 异常对象
  __ push(rdx);  // 返回地址
  
  // 查找调用者的异常处理器
  __ super_call_VM_leaf(CAST_FROM_FN_PTR(address,
                          SharedRuntime::exception_handler_for_return_address),
                        thread, rdx);
  
  __ mov(rbx, rax);  // 保存处理器地址
  __ pop(rdx);       // 恢复返回地址
  __ pop(rax);       // 恢复异常对象
  __ jmp(rbx);       // 跳转到调用者的异常处理器
```

**用途**：当当前帧没有匹配的异常处理器时，移除栈帧并将异常传播到调用者。

## remove_activation 详解

`remove_activation` 是移除解释器栈帧的关键函数：

```cpp
// 参数说明：
// state:                   TosState（栈顶状态）
// ret_addr:               返回地址寄存器
// throw_monitor_exception: 是否抛出 IllegalMonitorStateException
// install_monitor_exception: 是否安装 monitor 异常
// notify_jvmdi:           是否通知 JVMTI
__ remove_activation(vtos, rdx, false, true, false);
```

**执行步骤**：
1. 释放所有持有的 monitors（如果有 synchronized）
2. 恢复调用者的 rbp
3. 恢复调用者的 rsp
4. 设置返回地址到 rdx

## InterpreterRuntime::exception_handler_for_exception

```cpp:470:494:src/hotspot/share/interpreter/interpreterRuntime.cpp
IRT_ENTRY(address, InterpreterRuntime::exception_handler_for_exception(
    JavaThread* thread, oopDesc* exception))

  Handle h_exception(thread, exception);
  methodHandle h_method(thread, last_frame.method());
  int handler_bci;
  int current_bci = last_frame.bci();
  
  // 在异常表中查找匹配的 handler
  do {
    handler_bci = h_method->fast_exception_handler_bci_for(
        h_exception, current_bci, THREAD);
    // ...
  } while (should_repeat);
  
  if (handler_bci < 0) {
    // 没有找到处理器，返回 remove_activation_entry
    return Interpreter::remove_activation_entry();
  }
  
  // 找到处理器，返回 handler 入口
  return h_method->code_base() + handler_bci;
```

**异常表查找**：
- 遍历方法的异常表（ExceptionTable）
- 检查当前 bci 是否在某个 catch 块的范围内
- 检查异常类型是否匹配（或是 catch-all）

## 总结

| 入口点 | 大小估算 | 核心功能 |
|--------|----------|----------|
| `_rethrow_exception_entry` | ~100 bytes | 从子帧返回时重新抛出 |
| `_throw_exception_entry` | ~200 bytes | 查找并跳转到处理器 |
| `_remove_activation_preserving_args_entry` | ~3000 bytes | JVMTI PopFrame |
| `_remove_activation_entry` | ~500 bytes | 栈展开 |

**关键点**：
1. 这是解释器中**唯一**处理异常分发的 Codelet
2. 大量代码用于 JVMTI PopFrame 支持（约 50% 的空间）
3. 与 `SharedRuntime::exception_handler_for_return_address` 协作处理跨帧异常
