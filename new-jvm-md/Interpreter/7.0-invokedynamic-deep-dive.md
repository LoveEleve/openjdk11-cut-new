## 1. 设计背景与动机

### 1.1 为什么需要 invokedynamic？

**传统方法调用的局限**：

| 字节码 | 目标确定时机 | 限制 |
|--------|--------------|------|
| `invokevirtual` | 编译期确定接收者类型 | 需要继承关系 |
| `invokeinterface` | 编译期确定接口 | 需要实现接口 |
| `invokestatic` | 编译期完全确定 | 无法动态选择 |
| `invokespecial` | 编译期完全确定 | 仅私有/构造器/super |

**问题**：动态语言（如 JavaScript、Ruby）在 JVM 上运行时，方法调用目标需要在运行时动态决定。

**解决方案**：`invokedynamic`（JSR 292，Java 7 引入）

```
invokedynamic = 运行时可编程的方法调用
```

### 1.2 核心思想

```
┌──────────────────────────────────────────────────────────────┐
│                    invokedynamic 的核心思想                   │
├──────────────────────────────────────────────────────────────┤
│  "调用什么" 由用户定义的 Bootstrap Method 决定，而非 JVM      │
│  一旦首次解析完成，后续调用直接使用缓存的 CallSite            │
└──────────────────────────────────────────────────────────────┘
```

## 2. 核心数据结构

### 2.1 调用关系总览

```
invokedynamic 字节码
         │
         ▼
┌─────────────────┐
│   CallSite      │  ← 调用点，持有目标 MethodHandle
├─────────────────┤
│ target: MH ─────┼──────┐
└─────────────────┘      │
                         ▼
              ┌─────────────────┐
              │  MethodHandle   │  ← 方法句柄，类似 C 的函数指针
              ├─────────────────┤
              │ type: MT        │  ← 签名类型
              │ form: LF        │  ← LambdaForm（优化后的调用）
              └────────┬────────┘
                       │
                       ▼
              ┌─────────────────┐
              │  MemberName     │  ← 底层方法描述符
              ├─────────────────┤
              │ clazz           │
              │ name            │
              │ type            │
              │ vmtarget ───────┼───► 真正的 Method* 指针
              └─────────────────┘
```

### 2.2 CallSite - 调用点

**源码位置**：`src/hotspot/share/ci/ciCallSite.hpp`

```cpp
// ciCallSite
// The class represents a java.lang.invoke.CallSite object.
class ciCallSite : public ciInstance {
public:
  bool is_constant_call_site();   // ConstantCallSite
  bool is_mutable_call_site();    // MutableCallSite
  bool is_volatile_call_site();   // VolatileCallSite
```

**三种 CallSite 类型**：

| 类型 | 特点 | 使用场景 |
|------|------|----------|
| `ConstantCallSite` | target 不可变，JIT 可内联 | Lambda 表达式（默认） |
| `MutableCallSite` | target 可变，需同步访问 | 动态语言运行时 |
| `VolatileCallSite` | target 可变，volatile 语义 | 需要即时可见性 |

**Java 层定义**：
```java
// java.lang.invoke.CallSite (抽象基类)
public abstract class CallSite {
    // 目标方法句柄
    volatile MethodHandle target;
    
    // 获取/设置目标
    public MethodHandle getTarget();
    public void setTarget(MethodHandle newTarget);
    
    // 动态调用（核心！）
    public MethodHandle dynamicInvoker();
}
```

### 2.3 MethodHandle - 方法句柄

**功能**：类型安全的、可操作的方法引用（类似 C 的函数指针，但更安全）

**关键特性**：
1. **类型安全**：调用时检查参数/返回值类型
2. **可组合**：支持参数绑定、类型转换、过滤等
3. **高性能**：JIT 可以内联 MethodHandle 调用

**源码位置**：`src/hotspot/share/prims/methodHandles.cpp`

### 2.4 Bootstrap Method - 引导方法

**作用**：在 invokedynamic 首次执行时被调用，负责创建 CallSite

**签名格式**：
```java
static CallSite bootstrap(
    MethodHandles.Lookup caller,  // 调用者的查找上下文
    String name,                   // 方法名
    MethodType type,               // 方法签名
    Object... args                 // 额外参数（可选）

```

**Lambda 表达式的 Bootstrap Method**：
```java

    MethodHandles.Lookup caller,
    String invokedName,        // 函数式接口方法名（如 "accept"）
    MethodType invokedType,    // 工厂方法签名
    MethodType samMethodType,  // SAM 方法签名
    MethodHandle implMethod,   // 实现方法
    MethodType instantiatedMethodType
```


### 4.2 解释器模板 (x86-64)

**源码位置**：`src/hotspot/cpu/x86/templateTable_x86.cpp:3964`

```cpp
void TemplateTable::invokedynamic(int byte_no) {
  transition(vtos, vtos);
  assert(byte_no == f1_byte, "use this argument");

  const Register rbx_method   = rbx;
  const Register rax_callsite = rax;

  // 1. 准备调用（解析 CP Cache，获取 CallSite 和目标方法）
  prepare_invoke(byte_no, rbx_method, rax_callsite);

  // 此时:
  // rax: CallSite 对象（从 resolved_references[f1] 获取）
  // rbx: MH.linkToCallSite 方法（从 f2 获取）

  // 2. CallSite 已经被 prepare_invoke 压入栈中

  // 3. profile（用于 JIT 编译决策）
  __ profile_call(rbcp);
  __ profile_arguments_type(rdx, rbx_method, rbcp, false);

  // 4. 验证 CallSite 是有效的 oop
  __ verify_oop(rax_callsite);

  // 5. 跳转到目标方法（linkToCallSite）
  __ jump_from_interpreted(rbx_method, rdx);
}
```

**关键点**：
- `prepare_invoke` 负责解析常量池缓存
- `rax_callsite` 作为参数传给 `linkToCallSite`
- `jump_from_interpreted` 跳转到目标方法

### 4.3 首次解析流程

**源码位置**：`src/hotspot/share/interpreter/interpreterRuntime.cpp:961`

```cpp
// First time execution: Resolve symbols, create a permanent CallSite object.
void InterpreterRuntime::resolve_invokedynamic(JavaThread* thread) {
  Thread* THREAD = thread;
  LastFrameAccessor last_frame(thread);
  const Bytecodes::Code bytecode = Bytecodes::_invokedynamic;

  // 1. 解析方法
  CallInfo info;
  constantPoolHandle pool(thread, last_frame.method()->constants());
  int index = last_frame.get_index_u4(bytecode);  // 4 字节索引
  
  {
    JvmtiHideSingleStepping jhss(thread);
    // 2. 调用 LinkResolver 解析
    LinkResolver::resolve_invoke(info, Handle(), pool,
                                 index, bytecode, CHECK);
  }

  // 3. 将解析结果写入 CP Cache
  ConstantPoolCacheEntry* cp_cache_entry = pool->invokedynamic_cp_cache_entry_at(index);
  cp_cache_entry->set_dynamic_call(pool, info);
}
```

### 4.4 LinkResolver::resolve_invokedynamic

**源码位置**：`src/hotspot/share/interpreter/linkResolver.cpp:1730`

```cpp
void LinkResolver::resolve_invokedynamic(CallInfo& result, 
                                         const constantPoolHandle& pool, 
                                         int index, TRAPS) {
  Symbol* method_name      = pool->name_ref_at(index);
  Symbol* method_signature = pool->signature_ref_at(index);
  Klass* current_klass     = pool->pool_holder();

  // 1. 检查是否已解析
  ConstantPoolCacheEntry* cpce = pool->invokedynamic_cp_cache_entry_at(index);
  int pool_index = cpce->constant_pool_index();

  if (cpce->is_f1_null()) {
    // 2. 未解析 - 解析 Bootstrap Specifier
    oop bsm_info = pool->resolve_bootstrap_specifier_at(pool_index, THREAD);
    
    // ... 错误处理 ...
    
    bootstrap_specifier = Handle(THREAD, bsm_info);
  }
  
  // 3. 如果已解析，直接返回缓存结果
  if (!cpce->is_f1_null()) {
    methodHandle method(THREAD, cpce->f1_as_method());
    Handle appendix(THREAD, cpce->appendix_if_resolved(pool));
    Handle method_type(THREAD, cpce->method_type_if_resolved(pool));
    result.set_handle(method, appendix, method_type, THREAD);
    return;
  }

  // 4. 调用 Bootstrap Method 创建 CallSite
  resolve_dynamic_call(result, pool_index, bootstrap_specifier, 
                       method_name, method_signature, current_klass, THREAD);
  
  // ... 错误处理和缓存 ...
}
```

## 5. Lambda 表达式实现

### 5.1 编译阶段

```java
// 源代码
list.forEach(x -> System.out.println(x));

// 编译后伪代码
list.forEach(
    invokedynamic bootstrap=LambdaMetafactory.metafactory
                  name="accept"
                  desc="()Consumer"
                  args=[...]
);

// 同时生成私有静态方法（Lambda 体）
private static void lambda$main$0(Object x) {
    System.out.println(x);
}
```

### 5.2 运行时流程

```
1. 首次执行 invokedynamic
   │
   ▼
2. 调用 LambdaMetafactory.metafactory()
   │
   ├── 参数:
   │   ├── caller: Lookup (调用者上下文)
   │   ├── invokedName: "accept"
   │   ├── invokedType: ()Consumer
   │   ├── samMethodType: (Object)void
   │   ├── implMethod: MethodHandle[lambda$main$0]
   │   └── instantiatedMethodType: (Object)void
   │
   ▼
3. 动态生成内部类 (如 Main$$Lambda$1)
   │
   ├── 实现 Consumer 接口
   ├── accept() 方法调用 lambda$main$0
   └── 如果捕获变量，添加字段存储
   │
   ▼
4. 创建 ConstantCallSite
   │
   └── target = MethodHandle[构造器或单例获取器]
   │
   ▼
5. 缓存到 CP Cache
   │
   ▼
6. 后续调用直接使用缓存的 CallSite
```

### 5.3 无捕获 vs 有捕获

**无捕获变量（可单例化）**：
```java
// Lambda 不捕获外部变量
Runnable r = () -> System.out.println("Hello");

// 生成的类是单例
// 每次 invokedynamic 返回同一个实例
```

**有捕获变量（需创建实例）**：
```java
String msg = "Hello";
Runnable r = () -> System.out.println(msg);

// 生成的类需要存储 msg
// 每次 invokedynamic 创建新实例
class Main$$Lambda$1 implements Runnable {
    private final String arg$1;  // 捕获的变量
    
    Main$$Lambda$1(String msg) {
        this.arg$1 = msg;
    }
    
    public void run() {
        System.out.println(arg$1);
    }
}
```

## 7. 性能优化

### 7.1 常量池缓存

**首次调用后，CallSite 被缓存到 ConstantPoolCache**：

```
ConstantPoolCacheEntry for invokedynamic:
┌─────────────────────────────────────────┐
│ _indices: index 编码                    │
├─────────────────────────────────────────┤
│ _f1: Method* (linkToCallSite)           │
├─────────────────────────────────────────┤
│ _f2: resolved_references 中的索引        │ ← 指向 CallSite
├─────────────────────────────────────────┤
│ _flags: 调用信息                         │
└─────────────────────────────────────────┘
```

### 7.2 JIT 优化

**对于 ConstantCallSite**：
- JIT 可以将 CallSite.target 视为常量
- 内联整个 MethodHandle 调用链
- Lambda 调用可以达到普通方法调用的性能

```
// 优化前（解释执行）
invokedynamic → CallSite → MethodHandle → 目标方法

// 优化后（JIT 内联）
直接调用目标方法（无额外开销）
```

### 7.3 与传统方法调用的对比

| 方面 | invokevirtual | invokedynamic |
|------|---------------|---------------|
| 首次调用 | 类加载时解析 | 运行时调用 BSM |
| 后续调用 | vtable 查找 | 缓存的 CallSite |
| JIT 优化 | 内联缓存 | ConstantCallSite 可内联 |
| 灵活性 | 需要继承关系 | 完全动态 |

## 10. 总结

### 10.1 核心要点

| 概念 | 说明 |
|------|------|
| **invokedynamic** | 运行时可编程的方法调用字节码 |
| **CallSite** | 调用点，持有目标 MethodHandle |
| **Bootstrap Method** | 首次执行时调用，负责创建 CallSite |
| **MethodHandle** | 类型安全的方法引用 |
| **MemberName** | 底层方法描述符，包含 vmtarget |

### 10.2 执行流程要点

```
首次执行:
invokedynamic → resolve → 调用 BSM → 创建 CallSite → 缓存 → 调用目标

后续执行:
invokedynamic → 读取缓存 → 直接调用目标
```

### 10.3 与其他字节码的关系

```
┌─────────────────────────────────────────────────────────────┐
│                    方法调用字节码家族                         │
├─────────────────────────────────────────────────────────────┤
│  invokevirtual    → 虚方法调用（vtable）                     │
│  invokeinterface  → 接口方法调用（itable）                   │
│  invokestatic     → 静态方法调用                             │
│  invokespecial    → 特殊方法调用（private/构造器/super）     │
│  invokehandle     → MethodHandle 调用                        │
│  invokedynamic    → 动态调用（BSM + CallSite）  ← 本文分析   │
└─────────────────────────────────────────────────────────────┘
```
