## 1. 概述

### 1.1 为什么需要单独的 invoke_return_entry？

`return_entry` 是通用的返回入口，而 `invoke_return_entry` 针对三种 invoke 指令类型进行了优化：

| 入口数组 | 对应指令 | 指令长度 | 索引大小 |
|----------|----------|----------|----------|
| `_invoke_return_entry[]` | invokestatic/invokevirtual/invokespecial | 3 bytes | u2 (2字节) |
| `_invokeinterface_return_entry[]` | invokeinterface | 5 bytes | u2 (2字节) |
| `_invokedynamic_return_entry[]` | invokedynamic | 5 bytes | u4 (4字节) |


## 4. 三种入口的区别

### 4.1 参数差异

| 入口 | step (指令长度) | index_size | 说明 |
|------|-----------------|------------|------|
| `_invoke_return_entry` | 3 | 2 (u2) | 普通 invoke |
| `_invokeinterface_return_entry` | 5 | 2 (u2) | 接口调用 |
| `_invokedynamic_return_entry` | 5 | 4 (u4) | 动态调用 |

### 4.2 为什么 invokedynamic 使用 u4？

`invokedynamic` 使用 4 字节索引来引用 `CONSTANT_InvokeDynamic_info`，而其他 invoke 指令使用 2 字节索引。

```
invokestatic #index      ; 指令格式: B9 XX XX (3 bytes, u2 索引)
invokeinterface #index N ; 指令格式: B9 XX XX NN 00 (5 bytes, u2 索引)
invokedynamic #index     ; 指令格式: BA XX XX XX XX (5 bytes, u4 索引)
```

## 5. 使用场景

### 5.1 invokevirtual 返回流程

```
invokevirtual #method  ; 调用虚方法
│
├── 进入目标方法执行
│   └── 执行 ireturn
│
├── 查找返回入口
│   ├── 返回类型 = int → TosState = itos
│   └── 调用类型 = invokevirtual → _invoke_return_entry
│
└── 跳转到 _invoke_return_entry[itos]
    ├── step = 3 (invokevirtual 长度)
    ├── 恢复调用者栈帧
    └── dispatch_next(itos, 3)
```

### 5.2 invokeinterface 返回流程

```
invokeinterface #method N ; 调用接口方法
│
├── 进入目标方法执行
│   └── 执行 areturn
│
├── 查找返回入口
│   ├── 返回类型 = Object → TosState = atos
│   └── 调用类型 = invokeinterface → _invokeinterface_return_entry
│
└── 跳转到 _invokeinterface_return_entry[atos]
    ├── step = 5 (invokeinterface 长度)
    ├── 恢复调用者栈帧
    └── dispatch_next(atos, 5)
```
