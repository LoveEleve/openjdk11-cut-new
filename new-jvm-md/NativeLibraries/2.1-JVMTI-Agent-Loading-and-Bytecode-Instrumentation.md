## 1. 问题引入

### 1.1 场景：如何在不重启 JVM 的情况下监控线上应用？

想象一个线上生产环境：
- 某个 Java 服务出现性能问题，需要分析方法耗时
- 需要查看某个类的字节码，确认是否加载了增强版本
- 需要动态修改类的行为来快速修复问题

**核心问题**：JVM 运行后，如何"注入"监控代码？如何修改已加载的类？

### 1.2 传统方案的局限

| 方案 | 局限 |
|------|------|
| 代码埋点 | 需要预先修改代码，无法应对突发问题 |
| 日志分析 | 信息有限，无法获取运行时内部状态 |
| 重启添加 Agent | 生产环境不能随意重启 |

### 1.3 JVMTI 的解决方案

JVMTI（JVM Tool Interface）提供了**在 JVM 运行时动态介入**的能力：

## 2. 核心概念

### 2.1 JVMTI 是什么

**JVMTI（Java Virtual Machine Tool Interface）** 是 JVM 提供的一套原生编程接口，允许开发工具：

1. **检查（Inspection）**：查看 JVM 内部状态（类、对象、线程、栈等）
2. **控制（Control）**：控制 JVM 行为（修改类、触发 GC、设置断点等）
3. **事件（Events）**：接收 JVM 发生的各种事件通知

**与 JNI 的区别**：

| 特性 | JNI | JVMTI |
|------|-----|-------|
| 目的 | Java 调用 Native 代码 | 工具控制/观察 JVM |
| 调用方向 | Java → Native | Native → JVM |
| 使用方 | 应用程序 | 调试器/分析器（如 Arthas）|
| 入口函数 | `JNI_OnLoad` | `Agent_OnLoad` / `Agent_OnAttach` |

```cpp
jint JvmtiExport::load_agent_library(const char *agent, const char *absParam,
                                     const char *options, outputStream* st) {
  char ebuf[1024] = {0};
  char buffer[JVM_MAXPATHLEN];
  void* library = NULL;
  jint result = JNI_ERR;
  
  // Agent_OnAttach 入口函数名称（可能有多个变体）
  const char *on_attach_symbols[] = AGENT_ONATTACH_SYMBOLS;  
  // = {"Agent_OnAttach", "Agent_OnAttach_L"}
  
  // 是否为绝对路径
  bool is_absolute_path = (absParam != NULL) && (strcmp(absParam,"true")==0);
  
  // 创建 AgentLibrary 对象
  AgentLibrary *agent_lib = new AgentLibrary(agent, options, is_absolute_path, NULL);
  
  // 1. 查找静态链接的 Agent（编译进 JVM 的）
  if (!os::find_builtin_agent(agent_lib, on_attach_symbols, num_symbol_entries)) {
    
    // 2. 加载动态库
    if (is_absolute_path) {
      library = os::dll_load(agent, ebuf, sizeof ebuf);
    } else {
      // 从标准库目录查找
      if (os::dll_locate_lib(buffer, sizeof(buffer), Arguments::get_dll_dir(), agent)) {
        library = os::dll_load(buffer, ebuf, sizeof ebuf);
      }
      if (library == NULL) {
        // 尝试系统默认库路径
        if (os::dll_build_name(buffer, sizeof(buffer), agent)) {
          library = os::dll_load(buffer, ebuf, sizeof ebuf);
        }
      }
    }
    
    if (library != NULL) {
      agent_lib->set_os_lib(library);
      agent_lib->set_valid();
    }
  }
  
  // 3. 如果库加载成功，查找并调用 Agent_OnAttach
  if (agent_lib->valid()) {
    OnAttachEntry_t on_attach_entry = CAST_TO_FN_PTR(OnAttachEntry_t,
       os::find_agent_function(agent_lib, false, on_attach_symbols, num_symbol_entries));
    
    if (on_attach_entry == NULL) {
      // 没有找到入口函数，卸载库
      if (!agent_lib->is_static_lib()) {
        os::dll_unload(library);
      }
      st->print_cr("%s is not available in %s", on_attach_symbols[0], agent_lib->name());
    } else {
      // 4. 调用 Agent_OnAttach
      JavaThread* THREAD = JavaThread::current();
      {
        extern struct JavaVM_ main_vm;
        JvmtiThreadEventMark jem(THREAD);
        JvmtiJavaThreadEventTransition jet(THREAD);  // 线程状态转换
        
        result = (*on_attach_entry)(&main_vm, (char*)options, NULL);
      }
      
      // 处理可能的异常
      if (HAS_PENDING_EXCEPTION) {
        CLEAR_PENDING_EXCEPTION;
      }
      
      // 如果成功，添加到已加载 Agent 列表
      if (result == JNI_OK) {
        Arguments::add_loaded_agent(agent_lib);
      }
      
      st->print_cr("return code: %d", result);
    }
  }
  return result;
}
```

### 3.3 事件机制详解

#### 3.3.1 事件类型分类

JVMTI 定义了 50+ 种事件，可分为以下几类：

| 类别 | 事件示例 | 用途 |
|------|---------|------|
| **VM 生命周期** | VMInit, VMStart, VMDeath | 监控 JVM 启动/停止 |
| **类加载** | ClassFileLoadHook, ClassLoad, ClassPrepare | 字节码修改（Arthas 核心） |
| **线程** | ThreadStart, ThreadEnd | 线程监控 |
| **异常** | Exception, ExceptionCatch | 异常追踪 |
| **方法** | MethodEntry, MethodExit | 方法追踪（高 overhead） |
| **GC** | GarbageCollectionStart/Finish, ObjectFree | GC 分析 |
| **编译** | CompiledMethodLoad/Unload | JIT 分析 |

### 3.4 字节码 Instrumentation 详解

#### 3.4.1 ClassFileLoadHook 事件

这是 Arthas 实现 `jad`、`trace`、`watch` 等命令的核心机制：

```
┌─────────────────────────────────────────────────────────────────┐
│              ClassFileLoadHook 事件处理流程                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  类加载器读取 .class 文件                                         │
│         │                                                       │
│         ▼                                                       │
│  ┌──────────────────────────────┐                              │
│  │ JVM 调用 ClassFileParser     │                              │
│  └──────────────┬───────────────┘                              │
│                 │                                               │
│                 ▼                                               │
│  ┌──────────────────────────────────────────────────────┐      │
│  │ JvmtiExport::post_class_file_load_hook()             │      │
│  │ 触发 JVMTI_EVENT_CLASS_FILE_LOAD_HOOK 事件           │      │
│  └───────────────────────┬──────────────────────────────┘      │
│                          │                                      │
│                          ▼                                      │
│  ┌──────────────────────────────────────────────────────┐      │
│  │ Agent 回调函数（如 Arthas 的 Instrumentation）        │      │
│  │                                                      │      │
│  │ 1. 解析原始字节码（使用 ASM/ByteBuddy）               │      │
│  │ 2. 定位目标类和方法                                  │      │
│  │ 3. 插入增强代码（方法进入/退出钩子）                   │      │
│  │ 4. 生成新的字节码数组                                │      │
│  │ 5. 通过 new_class_data 返回新字节码                  │      │
│  └───────────────────────┬──────────────────────────────┘      │
│                          │                                      │
│                          ▼                                      │
│  ┌──────────────────────────────┐                              │
│  │ JVM 使用修改后的字节码创建 Klass │                            │

│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**回调函数签名**：

```cpp
typedef void (JNICALL *jvmtiEventClassFileLoadHook)(
    jvmtiEnv *jvmti_env,           // JVMTI 环境
    JNIEnv* jni_env,               // JNI 环境
    jclass class_being_redefined,  // 如果是 retransform，指向原类
```

## 5. 实战：编写简单 JVMTI Agent

### 5.1 示例：统计方法调用次数

```c
// agent.c - 简单的 JVMTI Agent
#include <jvmti.h>
#include <stdio.h>
#include <string.h>

// 方法调用计数
static jint method_count = 0;

// JVMTI 回调：方法进入
static void JNICALL MethodEntryCallback(jvmtiEnv *jvmti_env,
                                         JNIEnv* jni_env,
                                         jthread thread,
                                         jmethodID method) {
    method_count++;
    if (method_count % 1000 == 0) {
        printf("[Agent] Methods entered: %d\n", method_count);
    }
}

// Agent 初始化
JNIEXPORT jint JNICALL Agent_OnLoad(JavaVM *vm, char *options, void *reserved) {
    jvmtiEnv *jvmti = NULL;
    jvmtiError err;
    jvmtiCapabilities caps;
    jvmtiEventCallbacks callbacks;
    
    printf("[Agent] OnLoad called\n");
    
    // 1. 获取 JVMTI 环境
    (*vm)->GetEnv(vm, (void**)&jvmti, JVMTI_VERSION_1_2);
    
    // 2. 请求能力（CanGenerateMethodEntryEvents）
    memset(&caps, 0, sizeof(caps));
    caps.can_generate_method_entry_events = 1;
    err = (*jvmti)->AddCapabilities(jvmti, &caps);
    if (err != JVMTI_ERROR_NONE) {
        printf("[Agent] AddCapabilities failed: %d\n", err);
        return JNI_ERR;
    }
    
    // 3. 设置回调函数
    memset(&callbacks, 0, sizeof(callbacks));
    callbacks.MethodEntry = MethodEntryCallback;
    err = (*jvmti)->SetEventCallbacks(jvmti, &callbacks, sizeof(callbacks));
    if (err != JVMTI_ERROR_NONE) {
        printf("[Agent] SetEventCallbacks failed: %d\n", err);
        return JNI_ERR;
    }
    
    // 4. 启用事件
    err = (*jvmti)->SetEventNotificationMode(
        jvmti, JVMTI_ENABLE, JVMTI_EVENT_METHOD_ENTRY, NULL);
    if (err != JVMTI_ERROR_NONE) {
        printf("[Agent] SetEventNotificationMode failed: %d\n", err);
        return JNI_ERR;
    }
    
    printf("[Agent] Initialized successfully\n");
    return JNI_OK;
}

// 动态 attach 入口
JNIEXPORT jint JNICALL Agent_OnAttach(JavaVM* vm, char* options, void* reserved) {
    printf("[Agent] OnAttach called\n");
    return Agent_OnLoad(vm, options, reserved);
}
```

## 7. 性能开销分析

### 7.1 各事件的性能开销

| 事件类型 | 开销等级 | 说明 |
|---------|---------|------|
| ClassFileLoadHook | 中 | 类加载时触发，不影响运行时 |
| MethodEntry/Exit | 极高 | 每个方法调用都触发，禁用 JIT 内联 |
| SingleStep | 极高 | 每条指令触发，仅调试使用 |
| Exception | 低 | 仅异常发生时触发 |
| ThreadStart/End | 低 | 线程生命周期事件 |

### 7.2 优化建议

1. **避免 MethodEntry/Exit**：使用字节码植入（如 Arthas）替代
2. **谨慎使用 ClassFileLoadHook**：只修改需要的类
3. **按需启用事件**：不需要时及时禁用
4. **使用采样**：Async-Profiler 使用采样而非全量收集

## 9. 总结

### 9.1 核心要点

1. **JVMTI 是 JVM 的"后门"**：提供检查和控制 JVM 的能力，是 Arthas/Profiler 的基础

2. **Agent 两种加载方式**：
   - 命令行 `-agentlib`：启动时加载，功能最全
   - 动态 attach：运行时加载，Arthas 的核心机制

3. **事件机制是核心**：通过 `SetEventCallbacks` + `SetEventNotificationMode` 注册回调

4. **ClassFileLoadHook 是字节码修改入口**：Arthas 的 `trace`、`watch` 都依赖于此

5. **性能敏感**：MethodEntry/Exit 等事件开销极大，生产环境避免使用

### 9.2 关联知识

- 下一篇：文档 2.2 - VMStructs 与符号解析
- 前置知识：文档 1.1 - Unix 信号基础
- 实际应用：Arthas 源码分析 / Async-Profiler 源码分析

### 9.3 常见误解

| 误解 | 事实 |
|------|------|
| JVMTI 只能用于调试 | JVMTI 广泛用于性能分析、监控、AOP |
| Retransform 可以修改类结构 | 只能修改方法体，不能增删方法/字段 |
| Agent_OnAttach 可以注册 VMInit | VMInit 在 attach 之前已触发，无法捕获 |
| 所有 JVMTI 事件开销都很高 | ClassFileLoadHook 等一次性事件开销低 |
