## 1. 信号链（Signal Chaining）原理

### 1.1 为什么需要信号链

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      多库信号冲突问题                                     │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  场景：一个 Java 应用同时使用了多个 Native 库                             │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  问题描述：                                                       │   │
│  │                                                                  │   │
│  │  1. JVM 注册了 SIGSEGV 处理器（用于 NPE/SOE 转换）                │   │
│  │     → signal(SIGSEGV, JVM_handler)                               │   │
│  │                                                                  │   │
│  │  2. 某个 Native 库（如数据库驱动、加密库）也注册了 SIGSEGV 处理器   │   │
│  │     → signal(SIGSEGV, Native_handler)  // 覆盖了 JVM 的处理器！    │   │
│  │                                                                  │   │
│  │  3. 结果：                                                       │   │
│  │     - JVM 无法再捕获 SIGSEGV                                      │   │
│  │     - 空指针异常导致 JVM 崩溃（而不是抛出 NPE）                    │   │
│  │     - 或 Native 库的信号处理被破坏                                 │   │
│  │                                                                  │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  解决方案：信号链（Signal Chaining）                                     │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  libjsig.so 的作用：                                              │   │
│  │                                                                  │   │
│  │  • 拦截 signal() 和 sigaction() 调用                              │   │
│  │  • 保存所有的信号处理器到一个链表中                                 │   │
│  │  • 当信号发生时，按顺序调用链中的所有处理器                         │   │
│  │  • 这样 JVM 和 Native 库都能处理信号                               │   │
│  │                                                                  │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.2 libjsig.so 实现机制

#### 核心数据结构

```c
// libjsig.so 内部实现（简化版）

// 信号处理器链表节点
typedef struct sigaction_node {
    int sig;                           // 信号编号
    struct sigaction action;           // 信号处理配置
    struct sigaction_node* next;       // 下一个节点
} sigaction_node;

// 全局链表头
static sigaction_node* sigaction_chain = NULL;

// 原始 signal/sigaction 函数指针
static sighandler_t (*orig_signal)(int, sighandler_t) = NULL;
static int (*orig_sigaction)(int, const struct sigaction*, struct sigaction*) = NULL;
```

#### 拦截机制

```c
// libjsig.so 通过 LD_PRELOAD 加载，拦截 signal/sigaction

// 包装后的 sigaction
int sigaction(int sig, const struct sigaction* act, struct sigaction* oldact) {
    // 1. 如果这是第一次调用，保存原始的 sigaction 函数
    if (orig_sigaction == NULL) {
        orig_sigaction = dlsym(RTLD_NEXT, "sigaction");
    }
    
    // 2. 查找信号链中是否已有该信号的处理配置
    sigaction_node* node = find_in_chain(sig);
    
    if (node == NULL) {
        // 3. 新信号，创建节点并添加到链表
        node = malloc(sizeof(sigaction_node));
        node->sig = sig;
        memcpy(&node->action, act, sizeof(struct sigaction));
        node->next = sigaction_chain;
        sigaction_chain = node;
    } else {
        // 4. 已有该信号，更新处理器（但不要覆盖，而是添加）
        // 实际 libjsig 的实现更复杂，会维护多个处理器
    }
    
    // 5. 调用原始的 sigaction 注册处理器
    // 这里会设置一个统一的入口处理器 signal_chaining_handler
    struct sigaction wrapper;
    wrapper.sa_sigaction = signal_chaining_handler;
    wrapper.sa_flags = SA_SIGINFO;
    sigemptyset(&wrapper.sa_mask);
    
    return orig_sigaction(sig, &wrapper, oldact);
}

// 统一的信号入口处理器
void signal_chaining_handler(int sig, siginfo_t* info, void* context) {
    // 遍历信号链，调用所有注册的处理器
    sigaction_node* node = sigaction_chain;
    while (node != NULL) {
        if (node->sig == sig && node->action.sa_handler != SIG_DFL) {
            if (node->action.sa_flags & SA_SIGINFO) {
                node->action.sa_sigaction(sig, info, context);
            } else {
                node->action.sa_handler(sig);
            }
        }
        node = node->next;
    }
}
```

### 1.3 使用 libjsig.so

#### 启动时加载

```bash
# 使用 LD_PRELOAD 加载 libjsig.so
export LD_PRELOAD=$JAVA_HOME/lib/libjsig.so
java -cp . MyApp

# 或者在命令行中
LD_PRELOAD=$JAVA_HOME/lib/libjsig.so java -cp . MyApp
```

#### 与 -Xrs 选项的配合

```bash
# -Xrs：减少 JVM 的信号使用（Reduce Signal usage）
# 用于嵌入场景，JVM 不处理 SIGINT/SIGTERM

java -Xrs -cp . MyApp
```

**注意**：
- `-Xrs` 会让 JVM 不安装某些信号处理器
- 与 libjsig.so 配合使用时要注意顺序

### 2.3 关键源码分析

#### VMError::report_and_die()

```cpp
// src/hotspot/share/utilities/vmError.cpp

void VMError::report_and_die(Thread* thread, unsigned int sig, address pc, 
                              void* siginfo, void* context) {
    // 1. 防止递归调用（如果崩溃处理中又崩溃）
    if (recursive_error_reported) {
        // 简单记录后退出
        ::write(STDERR_FILENO, "Recursive crash\n", 16);
        ::abort();
    }
    recursive_error_reported = true;
    
    // 2. 创建日志文件 hs_err_pid<pid>.log
    int fd = create_log_file();
    
    // 3. 打印头部信息
    report_header(fd);
    
    // 4. 打印崩溃原因
    report_cause(fd, sig, pc);
    
    // 5. 打印寄存器状态
    report_registers(fd, context);
    
    // 6. 打印栈回溯
    report_stack_trace(fd, context);
    
    // 7. 打印线程信息
    report_thread_info(fd, thread);
    
    // 8. 打印内存映射
    report_memory_map(fd);
    
    // 9. 打印系统信息
    report_system_info(fd);
    
    // 10. 关闭日志文件
    ::close(fd);
    
    // 11. 触发 core dump（如果启用）
    if (CreateCoredumpOnCrash) {
        create_core_dump();
    }
    
    // 12. 终止 JVM
    os::die();
}

// Async-Profiler 信号处理（简化版）

// 1. 初始化 perf_event
void PerfEvents::setup(int event_type, int sample_rate) {
    struct perf_event_attr attr = {};
    attr.type = event_type;           // PERF_TYPE_HARDWARE / PERF_TYPE_SOFTWARE
    attr.config = PERF_COUNT_HW_CPU_CYCLES;
    attr.sample_period = sample_rate;  // 采样周期
    attr.sample_type = PERF_SAMPLE_CALLCHAIN;
    attr.disabled = 1;
    attr.wakeup_events = 1;
    
    // 为每个 CPU 核心创建 perf_event
    for (int cpu = 0; cpu < num_cpus; cpu++) {
        int fd = syscall(__NR_perf_event_open, &attr, -1, cpu, -1, 0);
        
        // 设置信号通知
        fcntl(fd, F_SETFL, O_RDWR | O_NONBLOCK | O_ASYNC);
        fcntl(fd, F_SETSIG, SIGPROF);  // 使用 SIGPROF 信号
        fcntl(fd, F_SETOWN, getpid());
        
        // 启动计数
        ioctl(fd, PERF_EVENT_IOC_RESET, 0);
        ioctl(fd, PERF_EVENT_IOC_ENABLE, 0);
    }
    
    // 注册信号处理器
    struct sigaction sa = {};
    sa.sa_sigaction = signal_handler;
    sa.sa_flags = SA_SIGINFO | SA_RESTART;
    sigaction(SIGPROF, &sa, NULL);
}

```

│  问题 1：与 JVM 信号冲突                                                  │
│                                                                         │
│  场景：                                                                  │
│  • Async-Profiler 使用 SIGPROF 进行采样                                  │

## 4. 实战案例

### 案例 1：JVM 崩溃分析

```java
// CrashTest.java - 故意制造崩溃
public class CrashTest {
    public static void main(String[] args) {
        // 使用 Unsafe 直接访问非法地址
        sun.misc.Unsafe unsafe = getUnsafe();
        unsafe.putInt(0xdeadbeefL, 0);  // 写入非法地址
    }
    
    private static sun.misc.Unsafe getUnsafe() {
        try {
            java.lang.reflect.Field f = sun.misc.Unsafe.class.getDeclaredField("theUnsafe");
            f.setAccessible(true);
            return (sun.misc.Unsafe) f.get(null);
        } catch (Exception e) {
            throw new RuntimeException(e);
        }
    }
}
```

## 5. 面试高频题

### Q1: 什么是信号链（Signal Chaining）？为什么需要它？

**答案要点：**
1. **问题**：多个库（JVM 和 Native 库）都需要处理相同信号（如 SIGSEGV），后注册的会覆盖先注册的
2. **信号链**：libjsig.so 拦截 signal/sigaction 调用，维护一个处理器链表
3. **实现**：通过 LD_PRELOAD 加载，统一入口处理器按顺序调用链中所有处理器
4. **使用**：`LD_PRELOAD=$JAVA_HOME/lib/libjsig.so java App`
5. **场景**：Native 库（如数据库驱动）与 JVM 的信号冲突

### Q2: 如何分析 hs_err_pid.log？

**答案要点：**
1. **崩溃原因**：SIGSEGV/SIGBUS 等信号类型，程序计数器（PC）地址
2. **寄存器状态**：RAX/RBX/RCX 等寄存器值，分析参数和返回值
3. **栈回溯**：
   - Native frames：找到 C/C++ 代码位置
   - Java frames：找到 Java 方法调用链
4. **线程信息**：崩溃线程的状态（_thread_in_native 等）
5. **内存映射**：确认崩溃地址是否合法内存区域

### Q3: Async-Profiler 如何实现 CPU 采样？

**答案要点：**
1. **perf_event_open()**：创建硬件性能计数器（如 CPU 周期）
2. **信号通知**：配置计数器溢出时发送 SIGPROF 信号
3. **信号处理**：注册 sigaction 处理器，接收 siginfo_t 和 ucontext_t
4. **获取 PC**：从 ucontext_t 提取程序计数器（PC/RIP）
5. **栈回溯**：使用 FP-based 或 DWARF-based 遍历栈帧
6. **记录采样**：将 (PC, stack_trace) 写入 ring buffer，生成 JFR

### Q4: 信号处理中如何保证性能？

**答案要点：**
1. **异步信号安全**：只使用 async-signal-safe 函数（write、_exit）
2. **避免分配内存**：使用预分配缓冲区，禁止 malloc
3. **快速返回**：信号处理函数尽快完成，复杂操作延迟到安全点
4. **批量处理**：使用 ring buffer 缓冲采样，批量写入
5. **降低频率**：合理设置采样间隔（默认 10ms），避免过高频率

### Q5: 如何排查信号冲突问题？

**答案要点：**
1. **现象识别**：NPE 导致崩溃、信号处理器不生效、程序行为异常
2. **诊断工具**：
   - `strace -e trace=signal` 跟踪信号注册
   - `cat /proc/<pid>/status | grep Sig` 查看信号掩码
3. **解决方案**：
   - 使用 libjsig.so 启用信号链
   - 更换信号类型（如 SIGUSR1 替代 SIGPROF）
   - 使用 wall-clock 模式（不依赖信号）
