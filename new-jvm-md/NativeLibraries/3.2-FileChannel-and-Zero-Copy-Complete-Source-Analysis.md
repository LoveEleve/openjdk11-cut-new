## 第 1 章: FileChannel 整体架构

### 1.1 一句话总结

FileChannel 是 Java NIO 中用于文件操作的通道类，支持传统 IO、内存映射(mmap)和零拷贝(sendfile)三种数据传输模式。

### 1.2 核心类关系图

```
java.nio.channels.FileChannel (抽象类)
    │
    └── sun.nio.ch.FileChannelImpl (实现类)
            │
            ├── FileDescriptor fd          // 文件描述符
            ├── FileDispatcher nd          // 平台相关分发器
            ├── Unmapper                   // 内存映射清理器
            │
            ├── map()    → mmap 系统调用   // 内存映射
            ├── transferTo() → sendfile    // 零拷贝
            └── read/write() → read/write  // 传统 IO
```

## 第 5 章: 零拷贝技术深度解析

### 5.1 传统 IO 的数据拷贝过程

```
┌─────────────┐    read()    ┌─────────────┐    write()   ┌─────────────┐
│   磁盘文件   │ ──────────── │  用户缓冲区  │ ──────────── │   Socket    │
└─────────────┘              └─────────────┘              └─────────────┘
      │                            │                            │
      ▼                            ▼                            ▼
┌─────────────┐              ┌─────────────┐              ┌─────────────┐
│  内核页缓存  │              │   用户空间   │              │ Socket缓冲区 │
└─────────────┘              └─────────────┘              └─────────────┘

拷贝次数: 4 次
  1. 磁盘 → 内核页缓存 (DMA)
  2. 内核页缓存 → 用户缓冲区 (CPU 拷贝)
  3. 用户缓冲区 → Socket 缓冲区 (CPU 拷贝)
  4. Socket 缓冲区 → 网卡 (DMA)

上下文切换: 4 次
  1. 用户态 → 内核态 (read)
  2. 内核态 → 用户态 (read 返回)
  3. 用户态 → 内核态 (write)
  4. 内核态 → 用户态 (write 返回)
```

### 5.2 sendfile 零拷贝的数据拷贝过程

```
┌─────────────┐    sendfile()    ┌─────────────┐
│   磁盘文件   │ ─────────────── │   Socket    │
└─────────────┘                  └─────────────┘
      │                                │
      ▼                                ▼
┌─────────────┐                  ┌─────────────┐
│  内核页缓存  │ ─────────────── │ Socket缓冲区 │
└─────────────┘   (DMA gather)   └─────────────┘

拷贝次数: 2 次
  1. 磁盘 → 内核页缓存 (DMA)
  2. 内核页缓存 → Socket 缓冲区 (DMA gather，无需 CPU 拷贝)
  3. Socket 缓冲区 → 网卡 (DMA)

上下文切换: 2 次
  1. 用户态 → 内核态 (sendfile)
  2. 内核态 → 用户态 (sendfile 返回)
```

## 第 6 章: 面试高频问题与深度答案

### Q1: 为什么 mmap 需要页对齐？

**答案**:
1. **硬件限制**: MMU(内存管理单元) 以页为单位管理内存映射
2. **TLB 设计**: 地址转换缓存(TLB)的最小粒度是页
3. **权限控制**: 页表项存储权限位(PROT_READ/PROT_WRITE)，无法对页内部分设置不同权限
4. **性能优化**: 页对齐可以充分利用硬件预取和缓存行

### Q2: FileChannel.map() 返回的 MappedByteBuffer 是如何管理的？

**答案**:
```
创建流程:
1. FileChannel.map() 调用 native map0()
2. map0() 调用 mmap64() 创建映射
3. 创建 Unmapper 对象，注册到 Cleaner
4. 返回 DirectByteBuffer(MappedByteBuffer 的子类)

生命周期:
1. 用户持有 MappedByteBuffer 引用
2. GC 时，如果 buffer 不可达
3. Cleaner 线程调用 Unmapper.run()
4. Unmapper 调用 munmap() 解除映射
5. 关闭复制的文件描述符
```

### Q3: 为什么 sendfile 比传统 IO 快？

**答案**:
| 维度 | 传统 IO | sendfile |
|-----|---------|----------|
| 拷贝次数 | 4 次 | 2 次 |
| CPU 拷贝 | 2 次 | 0 次 |
| 上下文切换 | 4 次 | 2 次 |
| CPU 参与 | 是 | 否 (DMA 完成) |

**关键优化**:
- 避免用户态和内核态之间的数据拷贝
- 减少上下文切换开销
- 利用 DMA 引擎直接传输

### Q4: MappedByteBuffer.force() 和 FileChannel.force() 有什么区别？

**答案**:
```
MappedByteBuffer.force():
  - 调用 msync() 系统调用
  - 只同步指定映射区域
  - 只对 READ_WRITE 模式有效

FileChannel.force():
  - 调用 fsync() 或 fdatasync() 系统调用
  - 同步整个文件
  - 适用于所有写入操作

使用场景:
  - 只修改了部分内容 → MappedByteBuffer.force()
  - 修改了多处或不确定 → FileChannel.force()
```

### Q5: 为什么 MappedByteBuffer.load() 要逐页读取？

**答案**:
1. **madvise 只是建议**: 内核可能延迟加载
2. **强制页错误**: 逐页读取触发 Page Fault，确保数据加载
3. **防止编译器优化**: XOR 校验和防止 JIT 删除 "无用" 代码
4. **真实需求**: 大数据场景下，预加载避免后续访问延迟

### Q6: Cleaner 和 finalize() 有什么区别？

**答案**:
| 特性 | Cleaner | finalize() |
|-----|---------|------------|
| 执行线程 | Cleaner 线程 | Finalizer 线程 |
| 执行时机 | 更可预测 | 不确定，可能延迟 |
| 性能 | 更好 | 差，影响 GC |
| 多次调用 | 不会 | 可能(如果复活对象) |
| Java 版本 | Java 9+ | Java 9 标记废弃 |

### 8.1 大文件传输性能对比

// 传统方式 - 慢
public void traditionalCopy(String src, String dst) throws IOException {
    try (FileInputStream fis = new FileInputStream(src);
         FileOutputStream fos = new FileOutputStream(dst)) {
        byte[] buffer = new byte[8192];
        int n;

public void zeroCopy(String src, String dst) throws IOException {
    try (FileChannel source = new FileInputStream(src).getChannel();
         FileChannel target = new FileOutputStream(dst).getChannel()) {
        source.transferTo(0, source.size(), target);
    }
}

    try (RandomAccessFile file = new RandomAccessFile(path, "r");
         FileChannel channel = file.getChannel()) {

## 总结

### 核心知识点回顾

1. **内存映射(mmap)**:
   - 页对齐要求
   - Unmapper + Cleaner 自动清理
   - 三种模式: READ_ONLY / READ_WRITE / PRIVATE

2. **零拷贝(sendfile)**:
   - 2 次拷贝 vs 4 次拷贝
   - 适用于文件到 Socket 传输
   - 内核自动优化

3. **性能优化**:
   - 大文件用 mmap
   - 网络传输用 transferTo
   - 刷盘操作谨慎使用
