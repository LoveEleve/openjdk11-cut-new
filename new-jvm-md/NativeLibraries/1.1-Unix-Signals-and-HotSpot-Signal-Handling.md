## 1. Unix 信号机制回顾

### 1.1 信号概念与类型

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         Unix 信号是什么？                                │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  信号（Signal）是 Unix/Linux 系统中用于进程间通信和控制的一种机制：        │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  信号的产生方式：                                                │   │
│  │  • 硬件异常（CPU 检测到非法操作）                                │   │
│  │    - 除零错误 → SIGFPE                                          │   │
│  │    - 非法内存访问 → SIGSEGV                                     │   │
│  │  • 软件条件                                                      │   │
│  │    - 闹钟超时 → SIGALRM                                         │   │
│  │    - 用户按键 Ctrl+C → SIGINT                                   │   │
│  │  • 其他进程发送                                                  │   │
│  │    - kill -9 <pid> → SIGKILL                                    │   │
│  │    - kill -SIGUSR1 <pid>                                        │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

**常用信号对照表：**

| 信号 | 编号 | 默认行为 | JVM 处理方式 | 触发场景 |
|------|------|----------|--------------|----------|
| **SIGSEGV** | 11 | 终止+core | 转换为 NPE | 空指针解引用 |
| **SIGBUS** | 7 | 终止+core | 转换为 SOE | 栈溢出/对齐错误 |
| **SIGILL** | 4 | 终止+core | Safepoint 轮询 | 非法指令（伪指令） |
| **SIGFPE** | 8 | 终止+core | 算术异常 | 除零/浮点溢出 |
| **SIGUSR1** | 10 | 忽略 | 线程 Dump | kill -USR1 |
| **SIGUSR2** | 12 | 忽略 | 堆 Dump | kill -USR2 |
| **SIGTERM** | 15 | 终止 | 优雅关闭 | kill 默认信号 |
| **SIGKILL** | 9 | 终止 | 无法捕获 | kill -9 |

### 1.2 信号处理 API

#### 传统 API：signal()

```c
// 简单但不推荐的 API
#include <signal.h>

typedef void (*sighandler_t)(int);
sighandler_t signal(int signum, sighandler_t handler);

// 使用示例
signal(SIGSEGV, SIG_IGN);  // 忽略 SIGSEGV（危险！）
signal(SIGINT, my_handler); // 注册自定义处理器
```

**signal() 的问题：**
- 不同 Unix 实现行为不一致
- 无法获取信号产生的上下文信息
- 信号处理期间不会阻塞同类型信号

#### 现代 API：sigaction()

```c
// HotSpot 使用的标准 API
#include <signal.h>

int sigaction(int signum, const struct sigaction *act, struct sigaction *oldact);

struct sigaction {
    void     (*sa_handler)(int);           // 简单处理器
    void     (*sa_sigaction)(int, siginfo_t *, void *); // 带上下文处理器
    sigset_t   sa_mask;                     // 信号掩码
    int        sa_flags;                    // 标志位
    void     (*sa_restorer)(void);          // 已废弃
};
```

**关键字段说明：**

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      struct sigaction 详解                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  sa_handler / sa_sigaction                                              │
│  ├── sa_handler:  简单处理器，只接收信号编号                              │
│  └── sa_sigaction: 增强处理器，接收 siginfo_t 和 ucontext_t（HotSpot使用） │
│                                                                         │
│  sa_mask                                                                │
│  ├── 信号处理期间要阻塞的信号集                                          │
│  └── 防止信号处理函数被其他信号中断                                       │
│                                                                         │
│  sa_flags                                                               │
│  ├── SA_SIGINFO: 使用 sa_sigaction 而非 sa_handler                      │
│  ├── SA_RESTART: 被信号中断的系统调用自动重启                             │
│  ├── SA_NODEFER: 不自动阻塞当前信号（危险）                               │
│  └── SA_ONSTACK: 使用备用信号栈（处理栈溢出）                             │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.3 异步信号安全（Async-Signal-Safe）

**关键概念：**

```
┌─────────────────────────────────────────────────────────────────────────┐
│                  什么是 Async-Signal-Safe？                              │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  Async-Signal-Safe 函数：可以在信号处理函数中安全调用的函数               │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  信号处理函数的执行特点：                                        │   │
│  │  • 可能随时中断主程序执行（异步）                                │   │
│  │  • 可能持有锁的状态不确定                                        │   │
│  │  • 可能处于 malloc/free 的中间状态                               │   │
│  │                                                                  │   │
│  │  因此，信号处理函数中禁止：                                      │   │
│  │  ❌ 调用 malloc/free（可能破坏堆状态）                           │   │
│  │  ❌ 调用 printf（可能持有 stdout 锁）                            │   │
│  │  ❌ 调用 pthread_mutex_lock（可能死锁）                          │   │
│  │  ❌ 调用非 async-signal-safe 函数                                │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  安全的操作：                                                            │
│  ✅ 修改 volatile sig_atomic_t 变量                                     │
│  ✅ 调用 write() 写入文件描述符（如写入 pipe）                          │
│  ✅ 调用 _exit() 立即退出                                               │
│  ✅ 发送信号给另一个进程（kill）                                         │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

**Async-Signal-Safe 函数列表（部分）：**

```c
// 可安全调用：
_exit(), _Exit()          // 立即退出
alarm(), ualarm()         // 设置闹钟
chdir(), chmod()          // 文件操作
close(), read(), write()  // IO操作
exec 系列                  // 执行新程序
fork()                    // 创建进程（小心）
getpid(), getppid()       // 获取进程ID
kill(), raise()           // 发送信号
pipe()                    // 创建管道
sigaction(), sigpending() // 信号操作
```

```cpp
void os::signal_init() {
  // 初始化信号处理相关的全局状态
  if (!signal_handlers_are_installed) {
    // 安装所有信号处理器

void install_signal_handlers() {
  // 设置 SIGUSR1 处理器（线程 Dump）
  set_signal_handler(SIGUSR1, true);

  set_signal_handler(SIGUSR2, true);

  set_signal_handler(SIGPIPE);  // 管道破裂

  // ...
}
```

#### set_signal_handler() 方法

```cpp
// src/hotspot/os/posix/os_posix.cpp

void set_signal_handler(int sig, bool do_check = false) {
  struct sigaction sigAct;
  
  // 填充 sigaction 结构
  sigemptyset(&sigAct.sa_mask);  // 清空信号掩码
  
  // 使用 sa_sigaction 而非 sa_handler（获取更多信息）
  sigAct.sa_sigaction = signal_handler;
  sigAct.sa_flags = SA_SIGINFO | SA_RESTART;
  
  // 对于栈溢出处理，需要使用备用信号栈
  if (sig == SIGSEGV || sig == SIGBUS) {
    sigAct.sa_flags |= SA_ONSTACK;  // 使用备用信号栈
  }
  
  // 注册信号处理器
  int ret = sigaction(sig, &sigAct, NULL);
  assert(ret == 0, "sigaction failed");
}
```

#### 信号处理器入口

```cpp
// src/hotspot/os/posix/os_posix.cpp

void signal_handler(int sig, siginfo_t* info, void* uc) {
  // uc: ucontext_t，包含信号发生时的完整上下文
  //      - 寄存器状态
  //      - 程序计数器（PC）
  //      - 栈指针（SP）
  
  ucontext_t* context = (ucontext_t*)uc;
  
  // 判断信号类型并分发处理
  switch (sig) {
    case SIGSEGV:
    case SIGBUS:
      // 段错误/总线错误处理
      // 可能是：NPE、SOE、或真正的崩溃
      JVM_handle_posix_signal(sig, info, uc, true);
      break;
      
    case SIGILL:
    case SIGFPE:
      // 非法指令/浮点异常
      JVM_handle_posix_signal(sig, info, uc, true);
      break;
      
    case SIGUSR1:
      // 线程 Dump
      AttachListener::vm_attach_operation(info, uc);
      break;
      
    case SIGUSR2:
      // 堆 Dump（或用户自定义）
      // ...
      break;
      
    default:
      // 其他信号，使用默认处理
      // ...
      break;
  }
}
```

## 3. 关键信号处理详解

### 3.1 SIGSEGV → NullPointerException

```
┌─────────────────────────────────────────────────────────────────────────┐
│              SIGSEGV 转换为 NullPointerException 机制                    │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  场景：Java 代码中发生空指针解引用                                        │
│                                                                         │
│  Java 代码：                                                            │
│      Object obj = null;                                                 │
│      obj.hashCode();  // 触发 NPE                                       │
│                                                                         │
│  字节码：                                                               │
│      aload_1       // 加载 null 到栈顶                                 │
│      invokevirtual java/lang/Object.hashCode ()I                       │
│                                                                         │
│  执行过程：                                                             │
│       │                                                                 │
│       ▼                                                                 │
│  尝试访问 obj 的 vtable（虚函数表）                                       │
│  地址 = 0 + offset（因为 obj = null）                                    │
│       │                                                                 │
│       ▼                                                                 │
│  CPU 尝试读取地址 0x0（或很小的地址）                                    │
│       │                                                                 │
│       ▼                                                                 │
│  触发 SIGSEGV（段错误）                                                  │
│       │                                                                 │
│       ▼                                                                 │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  JVM 信号处理器捕获 SIGSEGV                                      │   │
│  │                                                                  │   │
│  │  1. 检查信号地址                                                  │   │
│  │     if (addr < 4096) {  // 空指针特征                            │   │
│  │        // 这是一个 NullPointerException，不是崩溃                  │   │
│  │     }                                                            │   │
│  │                                                                  │   │
│  │  2. 创建 NullPointerException 对象                               │   │
│  │     - 在信号处理上下文中安全地创建对象                              │   │
│  │     - 使用预分配的异常对象（避免 malloc）                          │   │
│  │                                                                  │   │
│  │  3. 跳转到异常处理代码                                             │   │
│  │     - 修改 ucontext_t 中的 PC（程序计数器）                        │   │
│  │     - 跳转到异常分发代码                                           │   │
│  │                                                                  │   │
│  │  4. 恢复执行                                                       │   │
│  │     - 从信号返回                                                   │   │
│  │     - Java 代码继续执行，进入异常处理                               │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 关键源码：JVM_handle_posix_signal

```cpp
// src/hotspot/os/posix/os_posix.cpp

int JVM_handle_posix_signal(int sig, siginfo_t* info, void* ucVoid, int abort_if_unrecognized) {
  ucontext_t* uc = (ucontext_t*)ucVoid;
  address addr = (address)info->si_addr;  // 触发信号的地址
  
  // 判断是否为空指针异常（地址小于一页大小）
  if (sig == SIGSEGV && addr < (address)os::vm_page_size()) {
    // 这是一个 NullPointerException
    // 而不是真正的崩溃
    
    // 获取触发信号的线程
    Thread* t = Thread::current_or_null();
    if (t != NULL && t->is_Java_thread()) {
      JavaThread* jt = (JavaThread*)t;
      
      // 构建异常对象（使用预分配的异常）
      Handle exception = jt->threadObj()->_preallocated_NPE;
      if (exception.is_null()) {
        // 没有预分配，需要创建（极少见）
        exception = Exceptions::new_exception(...);
      }
      
      // 设置异常到线程
      jt->set_pending_exception(exception());
      
      // 修改 PC 到异常处理代码
      // 这会将执行流转到异常处理器
      os::Posix::ucontext_set_pc(uc, StubRoutines::throw_NPE_stub());
      
      return true;  // 信号已处理，不要终止进程
    }
  }
  
  // 不是 NPE，可能是真正的崩溃或栈溢出
  // ... 其他处理
}
```

### 3.3 SIGILL/SIGFPE → Safepoint 轮询

```
┌─────────────────────────────────────────────────────────────────────────┐
│              伪指令异常与 Safepoint 轮询机制                             │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  问题：JVM 如何让线程在安全点（Safepoint）暂停？                          │
│                                                                         │
│  方案：使用 SIGSEGV 或 SIGILL 作为轮询机制                                │
│                                                                         │
│  实现方式（以 SIGSEGV 为例）：                                           │
│                                                                         │
│  1. 设置轮询页                                                          │
│     - 分配一页内存                                                       │
│     - mprotect(PROT_NONE) 设置不可访问                                   │
│     - 将页地址存入 _polling_page                                         │
│                                                                         │
│  2. 编译器在循环/方法返回处插入轮询代码                                   │
│     - 读取 _polling_page 地址                                            │
│     - 如果页被保护（mprotect），触发 SIGSEGV                             │
│                                                                         │
│  3. 进入 Safepoint 时                                                   │
│     - mprotect(_polling_page, PROT_NONE)                                │
│     - 所有执行轮询代码的线程触发 SIGSEGV                                  │
│     - 信号处理器中暂停线程                                                │
│                                                                         │
│  4. 退出 Safepoint 时                                                   │
│     - mprotect(_polling_page, PROT_READ)                                │
│     - 轮询代码正常执行，继续运行                                          │
│                                                                         │
│  汇编伪代码：                                                           │
│      ; 轮询检查（编译器插入）                                            │
│      mov rax, [_polling_page]  ; 尝试读取轮询页                          │
│      ; 如果页被保护，触发 SIGSEGV                                        │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 5. 面试高频题

### Q1: JVM 如何将 SIGSEGV 转换为 NullPointerException？

**答案要点：**
1. JVM 通过 `sigaction()` 注册 SIGSEGV 的信号处理器
2. 当发生空指针解引用时，CPU 尝试访问地址 0（或很小地址），触发 SIGSEGV
3. 信号处理器 `JVM_handle_posix_signal` 捕获信号
4. 检查触发地址：如果 `addr < os::vm_page_size()`（通常是 4KB），则判断为 NPE
5. 在信号处理上下文中创建 `NullPointerException` 对象（使用预分配实例）
6. 修改 `ucontext_t` 中的 PC（程序计数器），跳转到异常分发代码
7. 恢复执行，Java 代码进入异常处理流程

### Q2: 为什么需要 Yellow Zone 和 Red Zone？

**答案要点：**
- **Yellow Zone（黄色警戒区）**：栈空间即将耗尽时抛出 StackOverflowError，给程序处理机会
- **Red Zone（红色禁区）**：真正的保护页，使用 `mprotect(PROT_NONE)` 保护
- **作用**：
  1. 区分可恢复的 SOE 和真正的栈溢出崩溃
  2. Yellow Zone 抛出 SOE，程序可 catch 处理
  3. Red Zone 触发 SIGBUS，确保栈溢出不会破坏其他内存

### Q3: 信号处理中为什么不能用 malloc？

**答案要点：**
1. **异步信号安全**：信号处理函数可能在任何时候中断主程序执行
2. **malloc 非安全**：
   - malloc 内部持有锁（分配 arena 的锁）
   - 如果信号发生时主程序正在 malloc，会导致死锁
   - malloc 可能修改全局数据结构，信号处理中再次调用会损坏状态
3. **JVM 解决方案**：
   - 使用预分配的异常对象（`_preallocated_NPE`）
   - 使用信号安全的函数（如 `write()`）
   - 修改寄存器/上下文直接返回，不分配内存

### Q4: Safepoint 轮询是如何工作的？

**答案要点：**
1. **轮询页（Polling Page）**：分配一页内存，初始可读
2. **编译器插入**：在循环和方法返回处插入读取轮询页的代码
3. **进入 Safepoint**：`mprotect(polling_page, PROT_NONE)`
4. **触发信号**：所有执行到轮询代码的线程触发 SIGSEGV
5. **信号处理**：处理器中暂停线程，等待 Safepoint 操作完成
6. **退出 Safepoint**：`mprotect(polling_page, PROT_READ)`，线程继续执行

### Q5: 如何分析 hs_err_pid.log？

**答案要点：**
1. **崩溃原因**：查看 `SIGSEGV (0xb) at pc=...`，确定信号类型和地址
2. **寄存器状态**：查看 `Registers:` 部分，确定崩溃时的寄存器值
3. **栈回溯**：
   - 原生栈：`Native frames:`
   - Java 栈：`Java frames:`
4. **内存映射**：`Memory map:` 查看进程内存布局
5. **线程信息**：`Current thread:` 查看崩溃线程状态
6. **系统信息**：`vm_info:` 查看 JVM 版本和参数
