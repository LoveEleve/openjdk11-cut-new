# 并发标记 (Concurrent Mark) 深度分析

> **源码位置**: `src/hotspot/share/gc/g1/g1ConcurrentMark.hpp/cpp`
> **重要程度**: ⭐⭐⭐⭐⭐ (G1 最核心的并发技术)
> **功能**: 在应用运行时并发标记存活对象，为 Mixed GC 提供数据

## 第 0 部分：核心原理 ⭐

### 0.1 本质是什么？

并发标记的本质是**在应用线程运行时，并发地遍历对象图，用 `_next_mark_bitmap` 标记所有存活对象**：Initial Mark（STW）→ Root Region Scan（并发）→ Concurrent Mark（并发）→ Remark（STW）→ Cleanup（STW）→ Concurrent Cleanup（并发），六个阶段完成一次完整的并发标记周期。

### 0.2 为什么需要？

Mixed GC 需要知道 Old Region 中哪些对象存活（计算存活率，决定是否值得回收）。但扫描整个 Old 区需要 STW，停顿时间不可接受（数十 GB 的 Old 区可能需要数秒）。并发标记在应用线程运行时并发完成大部分标记工作，只有三个短暂 STW（Initial Mark/Remark/Cleanup）。

### 0.3 怎么解决？

**SATB + 双缓冲 Bitmap + 多线程 Work Stealing**：
- **SATB 保证正确性**：Pre 写屏障记录旧引用，Remark 处理 SATB 队列，确保漏标不发生
- **双缓冲 Bitmap**：`_next_mark_bitmap` 记录本次标记，`_prev_mark_bitmap` 记录上次标记（供 Mixed GC 使用）
- **多线程并发**：`G1CMTask` 多线程并发标记，Work Stealing 实现负载均衡
- **TAMS 保护新对象**：TAMS 以上的对象是标记期间新分配的，默认存活

### 0.4 为什么这样设计？

- **为什么需要 SATB 而不是增量更新（IU）？** SATB 只需 Pre 屏障（记录旧值），IU 需要 Post 屏障（记录新值）；SATB 的 Remark 代价更低（只处理被删除的引用），IU 需要重新扫描所有新引用
- **为什么 Cleanup 是 STW 而不是并发？** Cleanup 需要交换 Bitmap 双缓冲（原子操作）和统计存活字节（需要一致快照），必须 STW

## 1. 为什么需要并发标记？

### 1.1 问题背景

```
传统串行标记:
├── STW 暂停
├── 遍历整个堆标记存活对象
├── 暂停时间长（堆越大时间越长）
└── 应用卡顿

问题：几十 GB 的堆，标记需要几秒甚至几十秒
```

### 1.2 G1 的解决方案

```
并发标记:
├── 初始标记（STW，很短）
├── 并发标记（与应用线程并行执行）
├── 重新标记（STW，处理并发期间的变更）
└── 清理（STW，很短）

优势：
- 大部分工作在并发阶段完成
- STW 时间可控
- 不影响应用响应
```

## 2. SATB 算法（Snapshot-At-The-Beginning）

### 2.1 核心思想

```
问题：并发标记时，应用线程修改了对象引用，如何保证标记正确？

方案：记录变更前的引用值（快照）

示例:
时间线:  T0          T1          T2
         │           │           │
         ▼           ▼           ▼
      开始标记    应用修改    标记完成
                  A.next = B
                  
SATB 处理:
- T0: 记录 A.next = C（旧值）
- T1: 应用修改为 A.next = B
- T2: 确保 C 被标记（通过 SATB 队列）

结果：C 被标记（可能浮动垃圾），但不会漏标
```

### 2.2 SATB 写屏障

```cpp
// 引用赋值前执行
void G1BarrierSet::write_ref_field_pre_work(oop* field, oop new_val) {
    // 1. 获取旧值
    oop pre_val = RawAccess<>::oop_load(field);
    
    // 2. 将旧值加入 SATB 队列
    if (pre_val != NULL && _satb_mark_queue_set.is_active()) {
        enqueue(pre_val);
    }
}

// 实际入队
void G1BarrierSet::enqueue(oop pre_val) {
    Thread* thr = Thread::current();
    // 线程本地队列
    G1ThreadLocalData::satb_mark_queue(thr).enqueue(pre_val);
}
```

### 2.3 SATB 队列处理

```
线程本地 SATB 队列:
┌─────────────────────────────────────┐
│  Thread 1 SATB Queue                │
│  ┌─────────────────────────────┐   │
│  │ [obj A] → [obj B] → [obj C] │   │
│  └─────────────────────────────┘   │
│           ↓ 满了                   │
│  批量提交到全局队列                 │
└─────────────────────────────────────┘
           ↓
┌─────────────────────────────────────┐
│  Global SATB Queue Set              │
│  ┌─────────────────────────────┐   │
│  │ Thread1队列 → Thread2队列   │   │
│  └─────────────────────────────┘   │
│           ↓ GC 线程处理             │
│  标记队列中的对象                   │
└─────────────────────────────────────┘
```

## 3. 并发标记阶段

### 3.1 完整流程图

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         并发标记完整流程                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  1. 初始标记 (Initial Mark)                                                 │
│     ├── STW 暂停                                                             │
│     ├── 标记 GC Roots 直接引用的对象                                         │
│     ├── 启动并发标记线程                                                     │
│     └── 暂停时间短（与 Young GC 一起执行）                                   │
│         │                                                                    │
│         ▼                                                                    │
│  2. 根区域扫描 (Root Region Scanning)                                       │
│     ├── 扫描 Survivor 区中的对象                                            │
│     ├── 这些对象可能是老年代的引用来源                                       │
│     └── 必须在并发标记前完成                                                 │
│         │                                                                    │
│         ▼                                                                    │
│  3. 并发标记 (Concurrent Mark) ★★★                                         │
│     ├── 与应用线程并行执行                                                   │
│     ├── 遍历对象图，标记存活对象                                             │
│     ├── 使用 SATB 处理引用变更                                              │
│     └── 耗时最长，但不 STW                                                   │
│         │                                                                    │
│         ▼                                                                    │
│  4. 重新标记 (Remark)                                                       │
│     ├── STW 暂停                                                             │
│     ├── 处理 SATB 队列中剩余的引用                                           │
│     ├── 处理弱引用                                                           │
│     └── 暂停时间较短                                                         │
│         │                                                                    │
│         ▼                                                                    │
│  5. 清理 (Cleanup)                                                          │
│     ├── STW 暂停                                                             │
│     ├── 计算每个 Region 的存活对象大小                                       │
│     ├── 排序 Region（按回收效率）                                            │
│     └── 重置数据结构                                                         │
│         │                                                                    │
│         ▼                                                                    │
│  6. 并发清理 (Concurrent Cleanup)                                           │
│     ├── 并发执行                                                             │
│     ├── 清理空 Region                                                        │
│     └── 返回给空闲列表                                                       │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 阶段详解

#### 阶段 1: 初始标记

```cpp
// 在 Young GC 中执行
void G1ConcurrentMark::pre_initial_mark() {
    // 1. 标记 GC Roots
    mark_from_roots();
    
    // 2. 激活 SATB 队列
    _satb_mark_queue_set.set_active_all_threads(true);
    
    // 3. 启动并发标记线程
    _cm_thread->start_concurrent_cycle();
}
```

#### 阶段 3: 并发标记

```cpp
void G1ConcurrentMark::mark_from_roots() {
    // 1. 创建标记任务
    G1CMConcurrentMarkingTask task(this);
    
    // 2. 多线程并行标记
    _concurrent_workers->run_task(&task);
}

// 标记任务
void G1CMConcurrentMarkingTask::work(uint worker_id) {
    G1CMTask* task = _cm->task(worker_id);
    
    // 循环处理标记队列
    do {
        // 从队列获取对象
        task->do_marking_step();
        
        // 处理 SATB 队列
        _cm->drain_satb_buffers();
        
    } while (!task->is_termination());
}
```

#### 阶段 4: 重新标记

```cpp
void G1ConcurrentMark::remark() {
    // 1. 处理所有 SATB 队列
    drain_all_satb_buffers();
    
    // 2. 完成标记
    finalize_marking();
    
    // 3. 处理弱引用
    process_weak_refs();
}
```

## 4. 三色标记算法

### 4.1 颜色定义

| 颜色 | 含义 | 状态 |
|------|------|------|
| **白色** | 未访问 | 可能是垃圾 |
| **灰色** | 已访问，但引用未处理 | 需要继续扫描 |
| **黑色** | 已访问，引用已处理 | 存活对象 |

### 4.2 标记过程

```
初始状态:
┌─────┐     ┌─────┐     ┌─────┐
│Root │────→│  A  │────→│  B  │
│(黑) │     │(白) │     │(白) │
└─────┘     └─────┘     └─────┘

步骤 1: 标记 Root 为黑色，A 为灰色
┌─────┐     ┌─────┐     ┌─────┐
│Root │────→│  A  │────→│  B  │
│(黑) │     │(灰) │     │(白) │
└─────┘     └─────┘     └─────┘

步骤 2: 处理 A，标记 A 为黑色，B 为灰色
┌─────┐     ┌─────┐     ┌─────┐
│Root │────→│  A  │────→│  B  │
│(黑) │     │(黑) │     │(灰) │
└─────┘     └─────┘     └─────┘

步骤 3: 处理 B，标记 B 为黑色
┌─────┐     ┌─────┐     ┌─────┐
│Root │────→│  A  │────→│  B  │
│(黑) │     │(黑) │     │(黑) │
└─────┘     └─────┘     └─────┘

完成：白色对象可被回收
```

### 4.3 并发标记的问题

```
问题：并发期间应用修改引用，可能导致漏标

场景:
1. 标记线程: 已标记 A 为黑色
2. 应用线程: A.next = B（新增引用）
3. 标记线程: 不会重新扫描 A（已处理过）
4. 结果: B 未被标记（白色）→ 被错误回收！

解决方案（SATB）:
- 记录 A 的原始引用值
- 确保原始引用指向的对象被标记
- 允许少量浮动垃圾，但不允许漏标
```

## 5. 位图标记（Bitmap）

### 5.1 标记位图结构

```
堆内存:     每个对象对应一个 bit
┌─────────────────────────────────────┐
│ Region 0                            │
│ ┌─────┐ ┌─────┐ ┌─────┐            │
│ │ Obj │ │ Obj │ │ Obj │ ...         │
│ └─────┘ └─────┘ └─────┘            │
└─────────────────────────────────────┘
           ↓
标记位图:
┌─────────────────────────────────────┐
│ Bit 0   Bit 1   Bit 2   ...         │
│  1       0       1                  │
│  ↑标记  ↑未标记 ↑标记               │
└─────────────────────────────────────┘

优势:
- 空间效率高（1 bit per object）
- 可并行访问
- 不影响对象头
```

### 5.2 两个位图

```cpp
class G1ConcurrentMark {
    G1CMBitMap* _prev_mark_bitmap;  // 上次标记结果
    G1CMBitMap* _next_mark_bitmap;  // 本次标记结果
};

使用场景:
- 并发标记期间：使用 _next_mark_bitmap
- 判断对象存活：使用 _prev_mark_bitmap（上次完整标记结果）
- 标记完成后：交换两个位图
```

## 7. 总结

### 核心要点

1. **SATB 算法**: 记录引用变更前的值，确保不漏标
2. **三色标记**: 白（未访问）、灰（处理中）、黑（完成）
3. **并发执行**: 大部分标记工作与应用程序并行
4. **位图标记**: 高效的标记存储结构

### 并发标记 vs 串行标记

| 特性 | 并发标记 | 串行标记 |
|------|----------|----------|
| 暂停时间 | 短（初始+重新+清理） | 长（整个标记过程） |
| 应用影响 | 小 | 大 |
| 复杂度 | 高（SATB、写屏障） | 低 |
| 吞吐量 | 略低（有额外开销） | 高 |
