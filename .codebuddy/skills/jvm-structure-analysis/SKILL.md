# JVM 数据结构深度分析规范

当用户要求分析 JVM 中的某个数据结构时，**必须**按照以下完整流程进行分析，确保把每个知识点都讲透。

## 分析流程

### 第一步：识别所有关联结构

分析任何 JVM 数据结构时，首先要识别出**所有关联的子结构**，不能遗漏。

例如分析 `SymbolTable` 时，必须同时分析：
- SymbolTable 本身
- Arena（内存分配器）
- Chunk（Arena 管理的内存块）
- HashtableBucket（哈希桶数组）
- HashtableEntry（哈希表条目）
- Symbol（实际存储的符号对象）

**关键点**：递归找出所有被引用的结构，直到到达基本类型为止。

### 第二步：逐个结构深入分析

对每个结构，必须包含以下内容：

#### 2.1 创建位置
- 在哪个源文件、哪个函数中创建
- 提供精确的代码位置（文件路径 + 行号）
- 说明创建时机（启动阶段 / 运行时 / 类加载时等）

#### 2.2 内存分配方式
- 使用什么分配器（C heap / Arena / Metaspace / Java heap 等）
- 分配大小是固定的还是动态计算的
- 如果是动态计算，给出计算公式

#### 2.3 字段含义
- 列出结构的**所有字段**
- 每个字段的类型、大小、用途
- 特别注意平台相关的差异（32位 vs 64位，大端 vs 小端）

#### 2.4 内存布局图
为每个结构画出精确的内存布局，包括：
- 每个字段的偏移量
- 字段大小
- 对齐填充（padding）

示例格式：
```
+------------------+
| 字段名 (大小)     | offset: 0x00
+------------------+
| 字段名 (大小)     | offset: 0x08
+------------------+
| padding (大小)   | offset: 0x10
+------------------+
总大小: XX 字节
```

### 第三步：GDB 验证

使用 GDB 验证实际运行时的数据，证明分析的正确性：

1. 给出断点位置
2. 提供 GDB 命令
3. 展示实际输出
4. 解释输出含义

示例：
```bash
# 断点
b SymbolTable::lookup_only

# 查看结构
p *_the_table
x/8gx bucket_address

# 解释输出
# 0x00007fff12345678 是 _entry 指针，指向链表头
```

### 第四步：结构关联图

最后，画出所有结构之间的关联关系图，使用 ASCII 或 Mermaid 格式：

```
┌─────────────┐
│ SymbolTable │
│  _the_table ─────────────────────────────────────┐
│  _arena ────────┐                                │
└─────────────┘   │                                │
                  ▼                                ▼
            ┌─────────┐                    ┌──────────────────┐
            │  Arena  │                    │ HashtableBucket[]│
            │ _chunk ─────┐                │   [0] _entry ────────► Entry → Entry → NULL
            └─────────┘   │                │   [1] _entry ────────► NULL
                          │                │   ...                │
                          ▼                └──────────────────┘
                    ┌─────────┐
                    │  Chunk  │
                    │ _bottom │ ──► Symbol 对象存储区
                    │ _hwm    │
                    │ _max    │
                    └─────────┘
```

## 检查清单

完成分析后，用以下清单自检：

- [ ] 是否识别了所有关联结构？
- [ ] 每个结构是否说明了创建位置？
- [ ] 每个结构是否说明了内存分配方式？
- [ ] 每个结构是否列出了所有字段及含义？
- [ ] 每个结构是否画出了内存布局图？
- [ ] 是否提供了 GDB 验证命令和输出？
- [ ] 是否画出了结构关联图？

## 注意事项

1. **不要遗漏任何子结构**：用户问 SymbolTable，不能只讲 SymbolTable 本身
2. **不要只画图不解释**：图和文字说明必须配合
3. **不要省略内存布局细节**：padding、对齐、平台差异都要说清楚
4. **不要跳过 GDB 验证**：理论分析必须用实际数据验证
5. **考虑标准配置**：基于 -Xms8g -Xmx8g, G1 GC, 非 NUMA, 非大页的标准条件分析
