JVM 启动流程 - 基础环境初始化

Phase 1 深度解析 | thread.cpp:3876-3915 | OpenJDK 11

🎯 核心原理

本质是什么？

Phase 1 是 JVM 启动的最底层基础设施准备阶段，目标是建立 JVM 运行所需的最小操作系统级环境。

为什么需要？

JVM 依赖底层能力：获取当前线程（TLS）、输出日志、感知硬件能力（CPU/内存）、系统调用准备（时钟/随机数）。

怎么解决？

1. TLS 预初始化 → 2. 流系统初始化 → 3. 启动器属性处理 → 4. OS 信息采集

为什么这样设计？

TLS 必须在 OS 初始化前完成（后续代码需要 Thread::current()）；流系统必须在 OS 初始化前完成（否则出错无法报告）。

🎯 Phase 1 核心要点

  • 最底层准备：Phase 1 是 JVM 的地基，所有后续阶段依赖它建立的基础设施
  • 零依赖设计：Phase 1 的函数只能使用 OS 提供的原始能力，不能依赖 JVM 的其他子系统
  • 失败即终止：任何一步失败都会导致 JVM 启动失败（没有容错空间）
  • 信息收集为主：Phase 1 主要是"感知环境"而非"构建功能"
