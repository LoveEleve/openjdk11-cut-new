一、目标函数源码

功能：创建一个可变的字符串性能计数器，存储在 PerfMemory 共享内存区域，供外部工具（如 jstat）读取。
// perfData.cpp:422-443 PerfStringVariable* PerfDataManager::create_string_variable( CounterNS ns, // 命名空间枚举（如 SUN_GC） const char* name, // 计数器名称（如 "cause"） int max_length, // 最大长度（如 80，实际分配 max_length+1） const char* s, // 初始值（如 "No GC"） TRAPS // 异常处理宏 ) { // Step 1: 处理默认长度 if (max_length == 0 && s != NULL) max_length = (int)strlen(s); assert(max_length != 0, "PerfStringVariable with length 0"); // Step 2: 创建对象（触发5层构造函数链） PerfStringVariable* p = new PerfStringVariable(ns, name, max_length, s); // Step 3: 验证分配是否成功 if (!p->is_valid()) { delete p; THROW_0(vmSymbols::java_lang_OutOfMemoryError()); } // Step 4: 注册到全局列表 add_item(p, false); // false = 不需要 StatSampler 定期采样 return p; }

二、执行流程详解

1
处理默认长度
如果 max_length 为 0 且提供了初始字符串，则根据字符串长度自动计算。
后续分配时会 +1 用于存储 '\0' 终止符。
2
创建 PerfStringVariable 对象
触发 5层构造函数链，从基类到子类依次初始化， 最终在 PerfMemory 共享内存中分配存储空间。
3
验证分配结果
检查 _valuep != NULL 确认 PerfMemory 分配成功。
失败则删除对象并抛出 OutOfMemoryError。
4
注册到管理列表
将对象添加到 PerfDataManager 的全局列表 _all 中。
如果是常量类型，还会添加到 _constants 列表。

四、核心算法：create_entry

关键函数：在 PerfMemory 共享内存中分配条目，这是 PerfData 系统的核心。
void PerfData::create_entry(BasicType dtype, size_t dsize, size_t vlen) { // 1. 计算数据长度（向量长度默认为1） size_t dlen = vlen==0 ? 1 : vlen; // 2. 计算总大小 = 条目头 + 名称 + 填充 + 数据 size_t namelen = strlen(name()) + 1; // 包含 '\0' size_t size = sizeof(PerfDataEntry) + namelen; size_t pad_length = ((size % dsize) == 0) ? 0 : dsize - (size % dsize); size += pad_length; size_t data_start = size; // 数据区起始偏移 size += (dsize * dlen); // 数据区大小 // 3. 8字节对齐 int align = sizeof(jlong) - 1; size = ((size + align) & ~align); // 4. 从 PerfMemory 分配（失败则回退到 C Heap） char* psmp = PerfMemory::alloc(size); if (psmp == NULL) { psmp = NEW_C_HEAP_ARRAY(char, size, mtInternal); _on_c_heap = true; // 标记为 C Heap 分配 } // 5. 计算各字段地址 char* cname = psmp + sizeof(PerfDataEntry); // 名称地址 void* valuep = (void*)(psmp + data_start); // 数据地址 // 6. 复制名称到共享内存 strcpy(cname, name()); // 7. 填充 PerfDataEntry 头 PerfDataEntry* pdep = (PerfDataEntry*)psmp; pdep->entry_length = (jint)size; pdep->name_offset = (jint)((uintptr_t)cname - (uintptr_t)psmp); pdep->vector_length = (jint)vlen; pdep->data_type = (jbyte)type2char(dtype); pdep->data_units = units(); pdep->data_variability = variability(); pdep->flags = (jbyte)flags(); pdep->data_offset = (jint)data_start; // 8. 记录到对象 _pdep = pdep; _valuep = valuep; // ★ 指向共享内存中的数据区 // 9. 标记 PerfMemory 已更新 PerfMemory::mark_updated(); }

5.2 PerfData 字段详解

字段名 类型 大小 说明
_vftable void** 8 bytes 虚函数表指针（C++ 对象头）
_name char* 8 bytes 完整计数器名称（C Heap 分配）
_v Variability 4 bytes 可变性：Constant/Monotonic/Variable
_u Units 4 bytes 单位：Bytes/Ticks/Events/String/Hertz
_on_c_heap bool 1 byte 是否从 C Heap 分配（失败回退）
_flags Flags 1 byte 标志：F_Supported（接口稳定性）
_pdep PerfDataEntry* 8 bytes 指向共享内存中的条目头
_valuep void* 8 bytes 指向共享内存中的数据区（★关键）
_length jint 4 bytes PerfByteArray 新增：数组长度

5.3 PerfDataEntry（共享内存中的条目头）

字段名 类型 偏移 说明
entry_length jint 0x00 条目总长度（字节）
name_offset jint 0x04 名称字符串的偏移
vector_length jint 0x08 向量长度（标量为0/1）
data_type jbyte 0x0C 数据类型（B=byte, J=long）
data_units jbyte 0x0D 单位（1=None, 2=Bytes...）
data_variability jbyte 0x0E 可变性（1=Constant, 2=Monotonic, 3=Variable）
flags jbyte 0x0F 标志位
data_offset jint 0x10 数据区的偏移

sizeof(PerfDataEntry) = 32 bytes (0x20)，与 jlong 对齐

七、CounterNS 命名空间

枚举值 字符串 稳定性 用途示例
JAVA_NS (0) "java" 稳定，支持 java.* 计数器
COM_NS (1) "com.sun" 不稳定，支持 com.sun.* 计数器
SUN_NS (2) "sun" 不稳定，不支持 sun.* 计数器（内部使用）
SUN_GC (5) "sun.gc" 不稳定，不支持 GC 相关计数器（如 cause）
SUN_CI (8) "sun.ci" 不稳定，不支持 编译器相关计数器
命名规则：完整名称 = 命名空间前缀 + "." + 计数器名称
例如：SUN_GC + "cause" = "sun.gc.cause"

八、核心要点总结

1
双层内存结构
C++ 对象（堆分配）：包含元数据、指向共享内存的指针
PerfMemory 条目（共享内存）：实际存储名称和数据，可被外部进程读取
2
5层构造函数链
CHeapObj → PerfData → PerfByteArray → PerfString → PerfStringVariable
每层负责特定初始化：内存标记 → 名称分配 → 长度设置 → 数据复制 → 类型标记
3
失败回退机制
如果 PerfMemory 耗尽，自动回退到 C Heap 分配
通过 _on_c_heap 标记，析构时正确释放内存
4
共享内存布局
[PerfDataEntry 头 | 名称字符串 | padding | 数据区 | padding]
所有条目 8 字节对齐，便于外部工具解析
