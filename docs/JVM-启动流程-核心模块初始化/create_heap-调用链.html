Universe::create_heap() 调用链分析

从 Universe 到 G1CollectedHeap 的完整创建流程 | OpenJDK 11

🎯 核心原理

本质是什么？

多态工厂模式：通过 GCConfig 根据 JVM 参数（-XX:+UseG1GC）决定创建哪种类型的堆对象，返回 CollectedHeap 抽象基类指针。

创建了什么？

1. G1CollectorPolicy（策略对象）
2. G1CollectedHeap（堆对象，包含 2048 个 Region 的引用）

关键设计

延迟初始化：create_heap() 只分配 C++ 对象，真正的内存分配（mmap 8GB）在 _collectedHeap->initialize() 中完成。

🎭 多态分发机制

GCConfig::arguments() 根据 JVM 参数返回不同的 GCArguments 子类：

  • -XX:+UseG1GC → 返回 G1Arguments
  • -XX:+UseParallelGC → 返回 ParallelArguments
  • -XX:+UseSerialGC → 返回 SerialArguments
  • -XX:+UseZGC → 返回 ZArguments

⚠️ 重要说明

此时堆内存还未分配！

Universe::create_heap() 只完成了 C++ 对象的创建，真正的内存分配在下一步：

// Universe::initialize_heap() 中的调用顺序 _collectedHeap = create_heap(); // 第1步：创建 C++ 对象（本文档） _collectedHeap->initialize(); // 第2步：mmap 8GB、创建 2048 个 Region（下一步）

设计原因：分离"对象创建"和"资源初始化"，便于错误处理和状态管理。
